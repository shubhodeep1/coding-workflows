- **Release notes are filled from the changelog fragments each release folds.** Since the `changelog.d/` fragment workflow began, every GitHub release body read "No changelog entry found for vX.Y.Z." (v1.47.5 and v1.47.6 among them), because the assembler folds fragments under `## [Unreleased]` and the release step only looked for a `## [vX.Y.Z]` heading.

`scripts/assemble_changelog.py assemble` takes a new optional `--notes-out PATH`. It writes the bodies of exactly the fragments being folded, grouped under `### <Category>` in Keep a Changelog order (a plain list in date-heading repos), also under `--dry-run`, as an empty file when nothing usable was folded, and capped at 120,000 characters with a `...and N more; see CHANGELOG.md.` line (a single fragment that alone passes the cap is instead cut to it, marked `...(truncated; see CHANGELOG.md)` and counted as written). The summary line gains `notes_written=<n>` only when the flag is passed, so consumer syncs (`update_workflows.yml`) and the `CHANGELOG.md` format are unchanged. The release job of `test-and-mark-stable.yml` and `mark-stable.yml` passes the flag, and "Extract changelog for this version" now uses a hand-written `## [vX.Y.Z]` section first, then the fragment notes, then the reworded placeholder "No changelog fragments were folded for vX.Y.Z." `main`'s `ci.yml` also drops two "Stable-only wiring" lines that ran three test files a second time alongside the `tests-system-python` catch-all.
