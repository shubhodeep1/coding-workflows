- **A `.github/ai/<file>` that the issue's trusted `files_touched` list names exactly can now be written by the pipeline.** Before, every new file under `.github/ai/` was dropped at commit time and kept out of the review and heal editor sandboxes, so an issue that needed one (for example #9111's `.github/ai/chatgpt_pool.json`) waited for a human. Now `scripts/implement_commit_changes.sh` stages such a file in any repository, and the review editor and the heal editor may create or edit it. The grant comes only from the existing automation-path grant (`files_touched_scope_guard.py`): a trusted author or the pipeline login, exact direct children of `.github/ai/` only, never a glob, directory, `..`, nested path, symlink or open pipeline grant. Every staged path still passes the automation-path and deletion guards, and with `ALLOW_WORKFLOW_EDITS` off nothing is staged. New log prefixes: `IMPLEMENT_GITHUB_AI_GRANT` and `REVIEW_GITHUB_AI_GRANT`. Set the `GITHUB_AI_PLAN_GRANT_WRITE_ENABLED` repository variable to `false` to restore the old behaviour.

Refs #9920. Related to #9650.
