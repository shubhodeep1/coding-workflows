- **Every hosted workflow job now runs on the pinned `ubuntu-26.04` runner, and a nightly canary runs all of CI on `ubuntu-latest` to catch the next runner image change.**

GitHub moved `ubuntu-latest` to the `ubuntu-26.04` image (Python 3.14) on 2026-11-10, and `scripts/render_prompt.py` crashed on every clarify, plan, review and judge run until #9200 fixed it. A floating label lets the next image change do the same without warning, so every `runs-on: ubuntu-latest` in `.github/workflows/` and in the consumer templates (`ai-implement.yml`, `ai-plan.yml`, `ai-review.yml`) is now `runs-on: ubuntu-26.04`; the three jobs already pinned to `ubuntu-24.04` are unchanged. `ci.yml` can now be called as a reusable workflow with an optional `runner_image` input (empty means the pin), and the new `runner-image-canary` job in the Nightly Validation Self-Test workflow calls it with `runner_image: ubuntu-latest` every night. Under that call `ci.yml` first runs `python3 scripts/render_prompt.py --help` on the image's own system `python3`, before `actions/setup-python` replaces it, because that interpreter is the one that broke in #9200. When the canary fails, the Nightly run fails and the workflow failure heal intake files one heal issue, as it already does for that workflow. Set the repository variable `RUNNER_IMAGE_CANARY_ENABLED=false` to turn the canary off. `tests/test_runner_image_pin_contract.py` fails CI when a floating `runs-on` label comes back, and `.github/actionlint.yaml` declares the `ubuntu-26.04` label that actionlint 1.7.12 does not know yet.

What this means for consumer repos: after the next `@stable` sync the synced wrappers run on `ubuntu-26.04`. A consumer that runs actionlint 1.7.12 on its own workflows needs the same one-label `.github/actionlint.yaml`.
