- **Activation verification reconciles a failed write against its marker instead of dropping the verdict.** In `scripts/activation_verify.sh`, a failed verdict-comment POST now lists the target issue's comments once: when a trusted comment already ends in the exact marker this run posts, the verdict counts as posted (`outcome=verdict_comment_reconciled`); when none does, the POST is retried exactly once (`op=verdict_comment_retry`); when the listing itself fails, nothing is retried and the existing `reason=verdict_comment_failed` path runs, so no duplicate verdict can appear. A failed activation-fix issue create reruns the existing marker search once (now the shared `activation_lookup_fix_issue` helper) and continues as `outcome=fix_issue_reused reason=create_failed_recheck` when the issue landed; the create itself is never retried, because search indexing lag could hide the issue it opened. Both lookups share one author trust rule, and existing log keys, Telegram messages and exit codes are unchanged (CONSIST-001, workflow-optimization-2026-10-08). Refs #9099.
