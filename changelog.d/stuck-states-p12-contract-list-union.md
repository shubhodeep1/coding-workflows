- **The integration sync now merges `db/contracts` entrypoint-list appends itself instead of dispatching the LLM conflict resolver (stuck-states P12, Refs #8291).** When syncing the default branch into an `orchestrator/project-*` branch returns a merge conflict and every conflicting path is a `db/contracts/*.yml` file where both sides only appended entries to `read_entrypoints` or `write_entrypoints`, the poller merges locally, keeps the entries from both sides, pushes `chore: sync <default> into <integration>` and posts `✅ Integration sync auto-resolved (contract list union)`. The tracking state records `last_sync_outcome=merged-deterministic` with `last_list_union_paths` and `last_list_union_at`. Any other conflict (another file, a changed key, a removed entry, invalid YAML, missing PyYAML) falls back to the existing resolver dispatch unchanged. This removes the resolver run, review cycle and dispatch-budget slot that a two-line list append used to cost (consumer #3862). The new helper is `scripts/sync_contract_list_union.py`; the poll job installs `pyyaml==6.0.2` when it is missing, without failing the job. Logs: `SYNC_LIST_UNION_V1`, `SYNC_LIST_UNION_INELIGIBLE_V1`.

  What this means for operators: nothing to do. To turn it off, set the repository variable `ORCH_SYNC_CONTRACT_LIST_UNION_ENABLED=false`.
