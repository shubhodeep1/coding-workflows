- **Test-only workflow-heal plans are auto-approved, and implement is locked to their files.** A heal plan whose `HEAL_COUNTERFACTUAL` line is `UNVERIFIED` (which a plan for a flake always says) is no longer held when its `## Files likely to change` section lists only exact `tests/` files and `changelog.d/*.md` fragments inside the issue's verified heal scope. `scripts/files_touched_scope_guard.py --heal-test-only-check` decides, in plan.yml's "Auto-approve clear plan" step and in the poller's stall recovery, and logs `AI_PHASE_GATE_V1 phase=plan|stall_recovery gate=heal_test_only outcome=approve|hold reason=<token>`. Before `/approved` the pipeline posts `<!-- ai:heal-test-only-approval:v1 issue=<n> plan_comment=<id> paths=<list> -->`; a failed post holds. The implement heal preflight reads the newest trusted marker for the latest plan, narrows the heal scope to its paths and sets `HEAL_TEST_ONLY_LOCK_FILE`, and the isolated heal editor refuses (before any host write) an edit that deletes a file, has fewer test functions or asserts, adds a skip, xfail, `pytest.exit`, hook or collection control, or adds or changes a pytest config file. `FAIL`, missing lines and unknown routes still hold. The poller's batched issue query now also reads `lastEditedAt`. Set `HEAL_TEST_ONLY_AUTO_APPROVE_ENABLED=false` to turn the approval off (default `true`). Refs #8352. Refs #8808.
