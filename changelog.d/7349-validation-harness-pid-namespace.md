<!-- changelog: security -->
- **Generated validation tests now run in their own PID namespace and can no longer see the runner's processes.** The validation harness sandbox already ran tests as a separate user with an allowlisted environment, but in the runner's PID namespace, so a test could list every runner process and read its command line. `scripts/validation_harness_sandbox.sh` now starts the harness, and a second self-check probe, inside a new PID and mount namespace created by root (`unshare --pid --fork --mount-proc --kill-child`) before dropping to the sandbox user. The sandbox user's rootless Docker daemon now starts in its own PID namespace too (rootlesskit `--pidns`), so a test cannot list runner processes by starting a `--pid=host` container. `selfcheck` fails closed with `docker_pid_namespace_shared` when that daemon runs in the runner's PID namespace.

  If a runner cannot create the namespace, `provision`, `selfcheck` and `run` fail closed with `reason=pid_namespace_unavailable` and the validation reports `harness_error`; tests never run without it. Cleanup now kills only the `unshare` process root recorded in the root-owned `VALIDATION_HARNESS_SANDBOX_PIDNS_STATE_DIR` (default `/run/ai-validation-harness`), after checking it is still that process, and no longer reads the process-group file the sandbox user writes. New failure reasons: `pid_namespace_launch_failed`, `pidns_state_dir_failed`, `invalid_pidns_state_dir`, `pid_namespace_shared`, `caller_pid_visible`, `host_init_visible`, `pid_namespace_unverifiable` and `docker_pid_namespace_shared`. `VALIDATION_HARNESS_SANDBOX_PIDNS_STATE_DIR` must have at least two path components, and an existing directory is used only if it is already root-owned with mode 0700; it is never chmodded or chowned.
