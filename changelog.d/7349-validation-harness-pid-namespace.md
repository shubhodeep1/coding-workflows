<!-- changelog: security -->
- **Generated validation tests now run in their own PID namespace and can no longer see the runner's processes.** The validation harness sandbox already ran tests as a separate user with an allowlisted environment, but in the runner's PID namespace, so a test could list every runner process and read its command line. `scripts/validation_harness_sandbox.sh` now starts the harness, and a second self-check probe, inside a new PID and mount namespace created by root (`unshare --pid --fork --mount-proc --kill-child`) before dropping to the sandbox user.

  If a runner cannot create the namespace, `provision`, `selfcheck` and `run` fail closed with `reason=pid_namespace_unavailable` and the validation reports `harness_error`; tests never run without it. Cleanup now kills only the `unshare` process root recorded in the root-owned `VALIDATION_HARNESS_SANDBOX_PIDNS_STATE_DIR` (default `/run/ai-validation-harness`), after checking it is still that process, and no longer reads the process-group file the sandbox user writes. New failure reasons: `pid_namespace_launch_failed`, `pidns_state_dir_failed`, `invalid_pidns_state_dir`, `pid_namespace_shared`, `caller_pid_visible`, `host_init_visible` and `pid_namespace_unverifiable`.
