- **The conflict resolver's guard-hook template merge now covers all five paired live hooks even when the trusted support checkout's pair list cannot be read.** Before, that fallback handled only `pr_merge_status_guard.py`.

Integration PR #8436 (run 42355218108) parked with `sandbox_path_host_only` on `.claude/hooks/prepush_affected_tests.py`. #9014 made `scripts/review_conflict_prepare.sh` read the pairs from `PAIRED_LIVE_COPIES` in the trusted support checkout. When that read fails (`Guard-hook template merge: pair_source=fallback reason=<support_missing|read_failed|no_valid_pairs>`), the script now uses a static `GUARD_HOOK_TEMPLATE_PAIRS` array that lists the same five pairs. A new test, `test_static_pair_list_equals_paired_live_copies`, keeps the array equal to `PAIRED_LIVE_COPIES`, and a regression test covers `gh_api_write_guard.py`. Every per-pair check is unchanged, as are the `CONFLICT_GUARD_HOOK_TEMPLATE_MERGE_ENABLED` kill switch, the log text, return codes 0/1/2 and the integration-sync deferral.
