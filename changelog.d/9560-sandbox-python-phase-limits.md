- **`tests-sandbox-python` now times and bounds each phase of its test step instead of running into the job timeout.** The `review` leg ran past its 20-minute `timeout-minutes` in run 43771105041 and was cancelled with no message. The "Sandbox-image Python tests" step now prints one `sandbox-python timing family=<family> phase=<phase> elapsed_secs=<n> rc=<rc>` line for each of its three phases and bounds each one with GNU `timeout`: image resolution (`CI_SANDBOX_PYTHON_IMAGE_TIMEOUT_SECS`, default 300 s), the derived python3-pytest `docker build` (`CI_SANDBOX_PYTHON_DERIVE_TIMEOUT_SECS`, default 180 s) and the pytest `docker run` (`CI_SANDBOX_PYTHON_PYTEST_TIMEOUT_SECS`, default 480 s); values outside 1-9999 fall back to the default. A phase that hits its limit fails the leg with a `::error::` line naming the family and the phase. The pytest container is now named, killed on timeout and removed on exit, and pytest runs with `-o faulthandler_timeout=300 --durations=15` so a hanging test is named in the log. Job, matrix, step names, step `env:` and `timeout-minutes: 20` are unchanged, as are the container's security options. Consumer repositories are not affected: `ci.yml` is this repository's own CI. Refs #9560.
