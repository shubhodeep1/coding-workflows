- **A PR whose branch is behind its base in `ci.yml` is updated before its final CI runs, so it no longer fails falsely or misses `ci/final`.** The final CI runs the branch's own copy of the workflow with the base's scripts. Before dispatching it, `_pr_ensure_final_ci` (`scripts/pr_checks_lib.sh`) now checks whether the base has commits to that workflow file that the branch lacks. If so, the pipeline updates the branch once from its base (merge lease, head-bound update, `ai:merge-base-sync:v1` marker) and runs the final CI on the new head. When GitHub refuses the update, it leaves one comment on the PR and the head waits. The blocked-merge guard sends a green head blocked only by `ci/final (missing)` through the same update. A PR that only edits `ci.yml` itself is not forced to update, and a failed comparison dispatches as before. Logged as `REVIEW_FINAL_CI_WIRING`. Set `FINAL_CI_WIRING_BEHIND_UPDATE_ENABLED=false` to restore the old behaviour. Refs #9993
