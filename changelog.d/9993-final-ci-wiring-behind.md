- **A PR whose branch is behind its base in `ci.yml` is updated before its final CI runs, so it no longer fails falsely or misses `ci/final`.** The final CI runs the branch's own copy of the workflow with the base's scripts. Before dispatching it, `_pr_ensure_final_ci` (`scripts/pr_checks_lib.sh`) now checks whether the base has commits to that workflow file that the branch lacks. If so, the pipeline updates the branch once from its base (merge lease, head-bound update, `ai:merge-base-sync:v1` marker) and runs the final CI on the new head. When GitHub refuses the update because of a conflict, it leaves one comment on the PR and the head waits; a refusal without a reported conflict leaves a note and is retried once. The blocked-merge guard and the poller's final merge send a green head blocked only by `ci/final (missing)` through the same update. The review step's exits that never merge (auto-merge off, `e2e-smoke-test`) check only: a behind head gets no final CI on the stale workflow and is not updated there. A PR that only edits `ci.yml` itself is not forced to update, and a failed comparison dispatches as before. Logged as `REVIEW_FINAL_CI_WIRING`. Set `FINAL_CI_WIRING_BEHIND_UPDATE_ENABLED=false` in the job environment to restore the old behaviour. Refs #9993
