- **Budget and progress governor, behind `PERSIST_BUDGET_ENABLED` (default off).** With the repo variable on, the poller runs the new `scripts/persist_budget.py` over each open standalone issue and each open issue in the current orchestrator wave, using the issue's attempt journal. After `PERSIST_REPLAN_AFTER_FAILED_ROUNDS` failed rounds (default 3), two failed rounds with no progress, `PERSIST_MAX_ROUNDS` rounds on one approach ending in a failed round (default 5) or a failed check after merge, it re-triggers planning with a new approach. An issue whose pull request is still open is escalated instead, because planning skips it. Once `PERSIST_MAX_APPROACHES` approaches have been tried (default 3), or the work has run longer than `PERSIST_MAX_HOURS` (default 48), it escalates the issue to `ai:needs-human` with a comment instead. Security items, issues already waiting for a person and orchestrator issues owned by another handler (blocked, validating, capacity wait and similar) are left alone, an issue the governor acted on gets no stall recovery in the same tick, and at most 5 decisions act per tick. With the variable off nothing changes. Phase P6 of the persistent unattended workflows plan; Refs #8427.
