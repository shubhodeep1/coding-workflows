- **The review autofix sweep now cancels review runs stuck in `queued` (P11b, root cause 9; refs #8291).** GitHub can leave a run `queued` for months, and a normal cancel answers 409. Until now `review_autofix_sweep.yml` only stopped such a run from blocking dispatch (`SWEEP_STALE_QUEUED_MINUTES`). The sweep's enumerate step now sources `scripts/review_autofix_sweep_reaper.sh` from the trusted default-branch checkout. The helper takes the `internal-review.yml` and `review_autofix.yml` runs the sweep already listed (it makes no second listing call), cancels each one queued longer than `ZOMBIE_RUN_MAX_QUEUED_HOURS` (default `24`), and force-cancels when the cancel returns 409. It handles at most 10 runs per sweep, oldest first, and logs `ZOMBIE_RUN_REAPED run= workflow= age_h= result=cancel|force_cancel|failed` plus one `ZOMBIE_RUN_REAPER_END` summary. Reaper errors never fail the sweep, an invalid hour value cancels nothing, `dry_run` only reports, and a tick whose run listing was incomplete skips the reaper.

  What this means for operators: nothing needs to be run by hand. Set the repository variable `ZOMBIE_RUN_REAPER_ENABLED=false` to turn the reaper off, or `ZOMBIE_RUN_MAX_QUEUED_HOURS` to change the age limit. Wedged runs in other workflows are not covered, because the sweep does not list them.
