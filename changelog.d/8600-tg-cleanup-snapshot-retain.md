- **Telegram cleanup no longer skips tracking comments on busy issues or loses message IDs when Telegram fails.** `tg_cleanup_msgs` and `tg_cleanup_phase_msgs` in `scripts/tg_helpers.sh` used to delete tracking comments while paging through the issue's comments. On an issue with more than 100 comments, later comments moved up a page and were skipped, so their Telegram messages stayed. Both functions now read every page first and delete nothing if any page read fails or returns something that is not a comment list; they log the same `aborting cleanup` warning as before. A tracking comment is now kept when deleting one of its Telegram messages fails transiently (transport error, HTTP 429 or 5xx, or an unreadable response), so the next cleanup retries it. One `::warning::` per cleanup call gives the number of kept comments and failed message IDs. Messages that are already gone or cannot be deleted ("message to delete not found", HTTP 400, other `ok: false` replies) count as done. Each Telegram delete call now times out after 10 seconds, and after 3 transient failures in a row a cleanup call stops calling Telegram and keeps the remaining comments. `tg_delete_msg` keeps its signature and still always returns 0. Refs #8598.
