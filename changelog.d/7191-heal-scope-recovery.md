- Add `HEAL_SCOPE_RECOVERY_ENABLED` (default `false`) so the workflow failure heal intake can replace a heal issue that the pipeline filed without a scope marker, which implement refuses to run. When the variable and `HEAL_INTAKE_SCOPE_GUARD_ENABLED` are both `true`, a report with a verified identity that matches such an issue opens a replacement whose scope comes from the verified runs and passes the scope guard. The original gets a comment pointing at the replacement and is closed as not planned; its body is not copied or edited. Later reports for the same failure are recorded on the replacement. With the variable off, nothing changes.
