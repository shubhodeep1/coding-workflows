- **Review merges no longer land a pull request that was closed after its review gate passed.** Every merge path in the review workflow now re-reads the PR right before it merges: the deterministic-skip merge, the auto-merge helper, the review-blocked judge's three merge sites and the final-CI merge resume. The deterministic-skip merge, the auto-merge helper and the review-blocked judge also check before they take the merge lease, update the branch or wait on checks, and the final-CI merge resume reads the PR before it takes the lease. The judge's direct-merge fallback and its retries after a GitHub server error also refuse a PR that is not open or whose state cannot be read. A PR that is closed, a draft, or no longer on the reviewed head is not merged and gets no merge labels. The run logs `AUTOFIX_MERGE_SKIPPED pr=<n> head_sha=<sha> reason=<pr_closed|pr_draft|head_moved|pr_state_unavailable> closed_at=<iso|-> stage=<start|pre_merge>`, and a closed PR gives up the merge lease it holds. If the PR cannot be read, nothing is merged (`reason=pr_state_unavailable`). AI Cancel on PR Close now also cancels a closed PR's review runs that GitHub no longer links to it, matching on the PR's exact head SHA and only for runs created before the close, so the runs the close itself starts (AI Issue PR Status, the post-merge AI Review) keep running. tele-funtoken-msg-scoring PR #5800 was merged 22 minutes after it was closed through this gap (Refs #10049).
