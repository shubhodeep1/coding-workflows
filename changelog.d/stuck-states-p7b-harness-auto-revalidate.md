- **A parked harness-broken project revalidates once after its heal issue merges (stuck-states P7b, Refs #8291).** When a tracking issue sits in `failed` with `ai:validation-failed` and `ai:harness-broken`, has no active harness hold and no pending `/revalidate`, the orchestrator poller reads the heal issue named by the newest trusted validation routing marker. Once that issue is closed with `ai:merged` and the project's pinned `validate.yml` release is no older than that close, so the fix is in the harness that will run, the poller posts one `/revalidate` comment carrying `<!-- AI_HARNESS_HEAL_REVALIDATE_V1 heal=<n> -->` and runs the normal `/revalidate` reset on the same tick. The marker limits this to one try per heal issue. Comments by other users are ignored for both the routing marker and the marker, and the step logs `HARNESS_HEAL_AUTO_REVALIDATE`. Set the repository variable `HARNESS_HEAL_AUTO_REVALIDATE_ENABLED=false` to keep such projects parked; `orchestrate_poll.yml` forwards it.
