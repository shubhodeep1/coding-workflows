- **Merged `/deploy-activate` activation logs no longer raise human-steps entries.** Activation verification now skips a merged PR whose every changed file is under `docs/deploy-activation/`, the folder `/deploy-activate` writes its progress logs to.

Activation verification read a log's open runbook lines (for example "set MAIN_PUSH_DEPLOY_ENABLED=true") as unmet operator steps. In shubhodeep1/hylifegroup.com, PRs #147 and #148 only added activation logs, and each one raised a new `ai:operator-step` entry (`pr-147`, `pr-148`) asking for the same deploy gate on a project the owner had scrapped. The daily activation routine then worked those entries and wrote more logs, a loop with no end. The default of `ACTIVATION_VERIFY_EXEMPT_GLOBS` is now `docs/plans/**,docs/deploy-activation/**` (was `docs/plans/**`), in `scripts/activation_verify.sh` and in `.github/workflows/issue_pr_status.yml`. A log-only merge gets no model call, verdict comment, fix issue or operator-step entry, and logs `ACTIVATION_VERIFY mode=pr item=<n> outcome=skip reason=exempt_paths exempt_files=<count>`. A PR that also changes other files is still verified on those files. Project-mode verification, the `ai:skip-activation-verify` label and the path matcher are unchanged.

What this means for consumer operators: after the next `@stable` sync, activation-log merges are skipped with no action needed. Repos that set the `ACTIVATION_VERIFY_EXEMPT_GLOBS` variable themselves keep their value, which replaces the default, so add `docs/deploy-activation/**` to it. Setting the variable to `docs/plans/**` restores the old behaviour.
