- **The review loop converges from round 3 on.** From round `REVIEW_CONVERGENCE_FROM_ROUND` (default `3`; round = autofix commits counted toward `MAX_AUTOFIX_ITERATIONS`, plus one), a consolidated finding starts another fix round only when at least `REVIEW_CONVERGENCE_MIN_REVIEWERS` (default `2`) reviewers raised it, it carries a `FLOOR_CRITICAL_KEYWORD:*` floor tag, or its lens is a security lens (`SECURITY & INPUT VALIDATION` or `IMPLICIT-EXECUTION & TRUST-BOUNDARY RISKS`, matched case-insensitively by keyword; an empty or unknown lens also blocks). A CI failure on the head still blocks in every round. The reviewer count is checked against each reviewer's own file in the reviewer bundle, never taken from the consolidator's `FLAGGED_BY` alone; a reviewer whose file supports the finding counts even when `FLAGGED_BY` leaves it out. Any other finding is classified `advisory-lone`: the editor gets only an `=== ADVISORY ISSUE ===` stub and lists it as ignored, the per-PR ledger records it with `CONVERGENCE:` lines, the editor summary comment lists it under "Not blocking (one reviewer)", and the review-blocked judge sees it as a CONVERGENCE ADVISORY NOTES block. Rounds 1 and 2, panels with fewer than `REVIEW_CONVERGENCE_MIN_REVIEWERS + 1` reviewers, and CI-failure gates are unchanged. Each run logs `REVIEW_CONVERGENCE pr=<n> round=<r> blocking=<k> advisory_lone=<m> outcome=continue|approve applied=<0|1> reason=<...>`. `REVIEW_CONVERGENCE_ENABLED=false` restores the previous behaviour (Refs #10056).
