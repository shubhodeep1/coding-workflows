<!-- changelog: changed -->
- **Clarify now runs every support script from one verified commit (stuck-states plan P2a).** Before this change, the "Stage workflow support files" step of `clarify.yml` copied a hand-kept list of scripts into the issue checkout. Any helper missing from that list ran from the target branch, so a heal issue on `stable` ran stable's helpers under main's YAML, and heal plans crashed with `codex_stall_guard.sh: unknown option: --engine` (run 37406961564).
  - The step now calls the new `scripts/stage_support_for_phase.sh clarify`. The helper first checks that the support checkout is the commit `SCRIPT_REF` names. It then runs the `review_autofix.yml` bundle stager (`scripts/stage_workflow_support.sh`) from a scratch directory and adds clarify's own scripts and sandbox Dockerfile from the same commit, under `RUNNER_TEMP`. It writes no executables into the checkout.
  - If a non-SHA `SCRIPT_REF` (for example `stable` after the support checkout fell back to `main`) does not resolve in the support checkout, the helper stages that checkout's HEAD with a warning. It also writes `SUPPORT_SCRIPTS_VERIFY` (`exact`, `ref` or `head_only`) to `GITHUB_ENV`, so a later step can check for this case.
  - Every later call uses `"${SUPPORT_SCRIPTS_DIR:-scripts}/<helper>"`, and `clarify_isolated_run.sh` reads its sandbox files from `CLARIFY_ISOLATION_SUPPORT_DIR`.
  - `scripts/tg_helpers.sh` now sources `gh_helpers.sh` from `SUPPORT_SCRIPTS_DIR` when that is set, before trying the checkout's `scripts/`.
  - Setting the repository variable `SUPPORT_SCRIPTS_UNIFIED_ENABLED=false` (default `true`) restores the previous copy loop and bare paths. A support ref without the helper also falls back to the old loop, with a warning.
  - `tests/test_support_script_single_source.py` pins the contract. Its fixture proves that the bundle's stall guard runs even when the target branch's copy rejects `--engine`.
