- **The review-blocked judge now acts only on the pull request head it evaluated.** After the judge runs, `scripts/review_rb_judge.sh` compares the live head from the PR read it already makes with the head named in the judge prompt. When the head moved during the judge call (any other head than the evaluated one, including a force-push back to an older commit; only the head the run checked out, behind its own unpushed commit, does not count), every action is skipped before any comment, label, status or close (`judge_skip_reason=stale_head`, log line `RB_JUDGE_STALE_HEAD pr= judged_head= live_head= action=`). When the live head cannot be read, `fix` and `close_and_reissue` are refused (`judge_skip_reason=head_unverified`), including a merge that open security findings convert to `fix`; merge actions are unchanged because `--match-head-commit` already binds them. A spot-fix reissue now keeps the evaluated head as its baseline instead of re-reading the live head, which removes one `gh pr view` call; when the evaluated head is the run's own unpushed commit, the baseline is the PR head the run checked out, because a baseline the closed PR never carried is ignored. Before this, a push during the judge call could get the head-gate success status and `ai:ready-to-merge` for an unjudged head, or preserve unjudged code as a reissue baseline.
