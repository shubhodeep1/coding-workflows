- **The auto-release check now reports a stuck `stable` release to the workflow heal intake (stuck-states P4, Refs #8291).** `scripts/auto_release_stable.sh` sends one `release_blocker` heal report per tick when the gate budget has been spent on the `stable` tip for a day (`last_gate_failed`, with the failed gate run in `run_refs`), when a gate, promote or mark-stable run has been in flight for six hours (`release_in_flight`), or when unreleased work on `stable` has waited a day (`stable_release_stale`). The report is always sent before the tick's unchanged `AUTO_RELEASE_*` line, and on the dispatch path the gate is still dispatched. Reports carry an OIDC report identity (`auto-release-stable.yml` now grants `id-token: write`) and log `RELEASE_BLOCKER_REPORTED`. A report that could not be built or sent logs `RELEASE_BLOCKER_REPORT_SKIPPED reason=payload_invalid|dispatch_denied` and sends a Telegram WARNING. The ages come from the run lists, the tag object and the compare response the tick already reads, so the only new API call is the dispatch itself. Thresholds: `RELEASE_BLOCKER_GATE_FAILED_MIN_AGE_SECS` (86400), `RELEASE_BLOCKER_IN_FLIGHT_MIN_AGE_SECS` (21600) and `RELEASE_BLOCKER_STABLE_STALE_SECS` (86400). Kill switch: `RELEASE_BLOCKER_HEAL_ENABLED=false`.
