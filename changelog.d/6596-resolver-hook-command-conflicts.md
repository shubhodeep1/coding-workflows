- **The conflict resolver no longer refuses merges that conflict on the merged-PR safety hook (when its template conflicts too) or on a `.claude/commands/` file with a trusted template twin, and it now logs which path it refused.** PR #6498 failed 18+ review runs in a row with `reason=sandbox_path_unsupported` and no indication of which path caused it.

The resolver's pre-model path check was stricter than the sandbox it guards: it admitted no `.claude/commands/<name>.md` file even when the editor snapshot would, and it always refused `.claude/hooks/pr_merge_status_guard.py`. It now uses the same trusted-twin rule as the snapshot for commands. It admits the live safety hook only when `workflow-templates/.claude/hooks/pr_merge_status_guard.py` is conflicted in the same merge. The model resolves only the template; the host copies it over the live hook after the attempt's scope checks and refuses to commit unless both are staged with the same blob and mode. The live hook still never enters a sandbox, and an unpaired live-hook conflict, `.github/ai/*`, `.claude/settings.json`, `.env*`, secret paths and symlinks are still refused.

Each refused path is now logged as `REVIEW_SANDBOX_PATH_REFUSED path=<name> reason=<code>`. Unsafe names are logged as `redacted`, and at most 20 lines are printed. The existing `AI_ENGINE_FALLBACK … reason=sandbox_path_unsupported action=fail_closed` line is unchanged.
