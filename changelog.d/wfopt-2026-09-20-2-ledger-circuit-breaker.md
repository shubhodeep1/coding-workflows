- **A job stops waiting on an unreachable memory store after the first failure.** `scripts/ledger_emit_substate.sh` now opens a job-scoped circuit breaker when a `record-run-event` call times out or fails authentication, and later substate emissions in the same job return at once instead of each waiting up to 120 seconds.

Before this change every substate emission tried the memory store again, so one unreachable store or one bad credential cost the full `LEDGER_EMIT_TIMEOUT_SECONDS` bound on every call; eight slow reviews logged 610 such timeouts. The helper now writes a sentinel file `circuit_open` in its per-job marker directory when a call times out, or when the failure text names an authentication error (`Authentication failed`, `could not read Username`, `Bad credentials`, `HTTP 401`, `HTTP 403`, `returned error: 403`, `Permission to ... denied`). It prints one `::warning::ledger_emit_substate circuit opened (reason=timeout|auth); later substates in this job are skipped` line, and later calls in the job skip silently. Other failures keep today's per-call warning and leave the circuit closed. Skipped events are dropped, as timed-out events were before, and the helper still exits 0 on every telemetry failure.

What this means for operators: after the circuit-opened warning, the rest of that job's run-substate events are missing from the ledger; a new job or a re-run starts with the circuit closed. Set `LEDGER_EMIT_CIRCUIT_BREAKER_ENABLED=false` to turn the breaker off; any value other than unset, empty, `true` or `false` also turns it off, with a warning.
