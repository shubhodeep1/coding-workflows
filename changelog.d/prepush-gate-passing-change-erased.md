- **The review pre-push gate no longer lets a repair turn erase an editor change that already passed its tests.** A repair that leaves no change at all is now reverted, and the editor's change kept, when the result it was repairing passed with no PR-caused failure.

In review/autofix run 43517436284 (PR #9451), the editor made a one-line fix and the gate's tests passed with it (`initial=pass failures=0`). The repair loop still ran one repair turn, because a plan done-check was unmet, and that turn put the file back to `HEAD`. The commit step then found nothing to commit and posted "Editor changes lost (retry unavailable)". `scripts/review_autofix_step_prepush_test_gate.sh` now reverts such a repair (`PREPUSH_TEST_GATE phase=review outcome=repair_reverted reason=passing_change_erased`, summary `Repair turn: reverted (it removed the whole change while no failure was caused by it)`) and keeps the pre-repair result, so the unmet done-check is still reported. When the before or after state cannot be read, or the result's status is anything other than `pass` (`fail`, `unverified` or `skipped`), the gate behaves as before. Every repair turn also logs a new `PREPUSH_REPAIR_CHANGES` line with the files changed before and after the repair, so the next occurrence can be diagnosed from the log. The lint-only guard (`reason=lint_only_change_erased`), the changes-lost retry budget and the test selection are unchanged.

What this means for consumer repos: after the next `@stable` sync, review/autofix runs with the repair loop on keep the editor's passing change instead of ending in "Editor changes lost".
