- **Polling loops read with the job's `GITHUB_TOKEN` instead of `GH_PAT`.** The per-tick reads of the promote cycle's gate waits (`scripts/promote_main_cycle.sh`), the heal intake queue (`scripts/workflow_failure_heal_queue.sh`), the release gate's dispatch watcher, review wait and orchestrate-cancel status poll (`scripts/dispatch_and_watch_workflow_run.sh`, `scripts/stable_e2e_step_wait_review.sh`, `scripts/stable_orchestrate_cancel_dispatched_run.sh`) and the reviewer/editor PR-state watchdog (`gh_review_pr_state`) now go through the new `gh_read` helper in `scripts/gh_helpers.sh` (or its self-contained twin `gh_api_safe_job_token_read` / `gh_api_safe_quiet_print_read` in `scripts/comprehensive_test_and_release_gh_api.sh`). They use `GH_READ_TOKEN` (the job token, exported by the steps and jobs that run these loops), which has its own budget of 1,000 calls per hour per repository, so the shared `GH_PAT` (5,000 per hour) stops running out every hour. Only reads of the job's own repository move. A 401, 403, 404 or rate limit falls back once to the PAT and logs `GH_READ_FALLBACK reason=<401|403|404|rate_limit> caller=<script>`, and a 401 or permission 403 keeps the rest of the job on the PAT. Writes (dispatches, comments, labels, merges, cancels) stay on the PAT, and the helpers refuse any write. `test-and-mark-stable.yml` gains the read-only scopes `actions: read`, `pull-requests: read` and `issues: read`. Kill switch: set the repository variable `GH_READ_TOKEN_ENABLED` to `false`. Without `GH_READ_TOKEN` (older consumer copies), behaviour is unchanged. Refs #9888, Refs #5504.
