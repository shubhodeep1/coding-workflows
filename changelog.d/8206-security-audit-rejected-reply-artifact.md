- **A failed security audit in a private repository keeps the refused Claude reply for 3 days (Refs #8204).** When the audit rejected Claude's reply as `malformed_output` or `schema_mismatch`, the weekly and dispatched runs of `security-audit.yml` logged only a short redacted excerpt, so nobody could see what the model actually returned. The `Run security audit` step now sets `SECURITY_AUDIT_CLAUDE_REJECTED_OUT` to a file under the runner's temp directory, and a new `Upload rejected Claude audit reply` step uploads that file as an artifact when the job fails. It uploads only when the event reports the repository as private, keeps the artifact for 3 days, and skips quietly when no reply was kept. Public repositories, and scheduled events whose payload does not say the repository is private, get no artifact; they keep the log excerpt. How the audit checks and refuses replies is unchanged.

  The audit prompt (`prompts/mode-security-audit.txt` and its template) now also says that the final message must be only the JSON array, that a clean audit is exactly `[]`, and that each finding uses the key `finding_id`.
