- **The label sync now closes the open issues and PRs that still carry a retired label before deleting it, and it runs weekly in this repository (Refs #8291).** `scripts/ai_labels.py` used to delete each label in `retired_labels` (`.github/ai/label_contract.v1.json`) and only warn about the open items that still carried it, so those items were left orphaned with no queue to pick them up. This repository also never called the label sync, so 10 queue issues stayed open on retired labels.

  With `RETIRED_LABEL_DRAIN_ENABLED` on (the default, both in the script and in `.github/workflows/sync_ai_labels.yml`), the sync now does the following before deleting a retired label. It lists the open items that carry it, reading up to two 100-item pages. It posts one explanation comment on each item, with a durable marker so a re-run never comments twice. It then closes the item: issues as `not_planned`, PRs as closed. At most 10 items are handled per run. The label is deleted only once a complete listing shows nothing open. A failed or incomplete listing, a failed comment or close, or leftover items keep the label for the next run. A dry run only reads. The output JSON keys and the exit status are unchanged. The new `.github/workflows/internal-sync-ai-labels.yml` runs the local sync workflow every Monday at 05:23 UTC, and it can also be started by hand with a `dry_run` input. `sync_ai_labels.yml` keeps its `contents: read` / `issues: write` permissions so consumer callers keep starting. Those permissions also cap `github.token`, so draining PRs needs `GH_PAT`; without it PRs that carry a retired label stay open and keep the label.

  What this means for operators: nothing needs to be run by hand. The first scheduled run after this merges closes the orphaned queue issues, up to 10 per week, each with a comment that explains why. An item that cannot be commented on (for example a locked issue) stays open and keeps its label, and shows up as a `drain_comment` error in the run summary every week until someone handles it. To go back to the old warn-then-delete behaviour, set the repository variable `RETIRED_LABEL_DRAIN_ENABLED=false`.
