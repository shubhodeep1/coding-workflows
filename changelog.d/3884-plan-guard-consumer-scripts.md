- **The AI Plan scope guard no longer rejects plans that edit consumer-repo-owned files under `scripts/`.** Only the runtime-fetched helper scripts listed in the generated `scripts/.gitignore` (plus `.github/prompts/` and `.github/scripts/`) are still rejected.

The `Guard plans targeting template-owned paths` step in the AI Plan workflow (`.github/workflows/plan.yml`) blanket-matched any `scripts/` path in a plan's "Files likely to change" section, while `scripts/implement_commit_changes.sh` had already moved to per-file exclusion via the runtime-generated `scripts/.gitignore`. Plans the implement phase could commit, such as an edit to a consumer repo's own validation entry script, failed the plan phase with "AI Plan phase failed before posting the implementation plan". This is what stalled `drhyg_ecommerce_automation` issue #27 in run 33249264125. The guard now mirrors the commit helper's contract exactly, and falls back to the legacy blanket `scripts/` rejection only when `scripts/.gitignore` is missing, the same fallback the commit helper uses.

What this means for operators: orchestrator-managed issues that target consumer-owned `scripts/` files (for example `scripts/run_validation_repo_checks.sh`) now plan and implement without human rerouting; guard rejections for genuinely template-owned helper scripts keep the same rejection comment flow, with wording that names the per-file rule.
