- **Unblock judge closes orchestrator sub-issues that planning found nothing to implement for.** Planning can stop an orchestrator-managed issue with `work is already on the planning ref; nothing to implement`. When that happens, the unblock judge now closes the issue as completed with `ai:closed` instead of posting `/answer`. A resume would only stop planning again. It closes the issue after a done fix-up or, with no fix-up, on its main path without a model call. The orchestrator poller then counts the sub-issue done. A trusted implementation plan posted after the block still resumes the issue.

Before this change only standalone issues were closed this way, so items such as #9769 (Refs #9421) looped between planning and resume. Set `UNBLOCK_ORCHESTRATOR_NOTHING_TO_IMPLEMENT_CLOSE_ENABLED=false` in the judge's environment to restore the resume. It defaults to `true`. Any value other than `true` or `false` also restores the resume and logs a warning. The new log line is `UNBLOCK_JUDGE ... op=nothing_to_implement_orchestrator`. Standalone issues behave as before.
