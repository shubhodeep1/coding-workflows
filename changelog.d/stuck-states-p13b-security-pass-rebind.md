- **The project security pass no longer re-audits a clean pass after a clean sync merge (stuck-states P13B, Refs #8291).** When a project's recorded clean security pass is invalidated only because `chore: sync <default> into <integration>` merges advanced the integration head, and every new commit is a merge commit whose combined diff (`git show --cc`) is empty, the poller rebinds the pass to the new head without a model run and logs `SECURITY_PASS_REBOUND`. Any non-merge commit, any merge that edits code in its resolution, any git error or any unusable state pointer falls through to the existing re-audit, logged as `SECURITY_PASS_REBIND_SKIPPED reason=<r>`. The rebind's checks use local git only, and its own state write sets only the existing `security_pass_status`, `security_pass_head_sha` and `security_pass_last_audited_sha` fields; a successful rebind then makes the same hash-gated tracking-body reconcile and state comment a clean audit already makes, and no other GitHub API call.

  What this means for operators: nothing to do. To turn it off, set the repository variable `SECURITY_PASS_REBIND_ENABLED=false`.
