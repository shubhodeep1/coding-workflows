<!-- changelog: fixed -->
- **Invalid UTF-8 in embedded prompt content no longer crashes the reviewers or breaks prompt-input truncation.** `load_prompt` in `scripts/render_prompt.py` now replaces invalid UTF-8 bytes in a prompt file with U+FFFD and prints one stderr warning (`WARNING: prompt file '<path>' contains invalid UTF-8 at byte <N>; replaced with U+FFFD`) instead of exiting with an uncaught `UnicodeDecodeError` traceback (the PR #9180 `reviewers_failed` crash); valid prompts render byte-identically. An undecodable persona source or contract now fails with a clean, path-bearing `ERROR:` line instead of a traceback. `_embed_input_file` in `scripts/gh_helpers.sh` now steps a `head`/`diff` truncation back to a UTF-8 character boundary (at most 3 bytes, via the new private `_embed_utf8_safe_cut` helper), so a truncated prompt input never ends mid-character; the `[... TRUNCATED ...]` marker and the prompt budget count the bytes actually shown. `scripts/render_prompt.sh` also decodes with `errors="replace"` when it collects `{{NAME}}` placeholders, so invalid bytes no longer drop the env-derived values on trusted template renders. When a caller sets `RENDER_PROMPT_INPUT_ALREADY_ASSEMBLED` (the reviewer and editor bodies that embed untrusted PR text), the wrapper no longer fills arbitrary `{{NAME}}` tokens from process environment variables, because such a token could pull a secret into the model prompt; only `WORKFLOW_EDIT_RESTRICTION`, `SEMBLE_PREFETCH`, `SERENA_TOOL_HINTS` and `MODEL_FAMILY_OVERLAY` are substituted on that path, and any other `{{NAME}}` stays as literal text.

This supersedes the exit-1 `ERROR: Unable to decode prompt file ...` behaviour described in `changelog.d/9341-render-prompt-readable-errors.md`: a non-UTF-8 prompt now renders with the `WARNING:` line above and exits 0.
