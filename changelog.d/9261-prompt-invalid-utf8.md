<!-- changelog: fixed -->
- **Invalid UTF-8 in embedded prompt content no longer crashes the reviewers.** `scripts/render_prompt.py` `load_prompt` now decodes with `errors="replace"`, so stray bytes from untrusted PR diff or comment text become U+FFFD instead of raising an uncaught `UnicodeDecodeError` (the PR #9180 `reviewers_failed` crash). An undecodable persona source or contract now fails with a clean, path-bearing `ERROR:` line instead of a traceback. `_embed_input_file` in `scripts/gh_helpers.sh` drops a trailing incomplete UTF-8 sequence (at most 3 bytes) after a `head`/`diff` truncation, and the TRUNCATED marker and prompt-budget total use the trimmed byte count. `scripts/render_prompt.sh` also decodes with `errors="replace"` when it collects `{{NAME}}` placeholders, so invalid bytes no longer drop the env-derived values on trusted template renders. When a caller sets `RENDER_PROMPT_INPUT_ALREADY_ASSEMBLED` (the reviewer and editor bodies that embed untrusted PR text), the wrapper no longer fills arbitrary `{{NAME}}` tokens from process environment variables, because such a token could pull a secret into the model prompt; only `WORKFLOW_EDIT_RESTRICTION`, `SEMBLE_PREFETCH`, `SERENA_TOOL_HINTS` and `MODEL_FAMILY_OVERLAY` are substituted on that path, and any other `{{NAME}}` stays as literal text. Refs #9261.
