- The release gate no longer waits out the full inactivity timeout when clarify has already failed. "Phase 1: Wait for clarify to complete" in `test-and-mark-stable.yml` now ends at once with `status=clarify_failed` when an OWNER, MEMBER or COLLABORATOR comment on the smoke issue starts with "AI clarification workflow failed". `clarify.yml` posts that comment as the `GH_PAT` user, so the old `github-actions[bot]` check never saw it. The check reuses the step's existing comments read, so each poll makes no extra API call, and it never prints a comment body. On timeout, Phase 1 and the alt-model wait step now print the issue URL and at most one Clarify run URL. The run lookup is a single read, and it fails open: a failed lookup or any value that is not an `https://.../actions/runs/<id>` URL prints no run URL, and the step still ends with its usual timeout result. Refs #9223.
