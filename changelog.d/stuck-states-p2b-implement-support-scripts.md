<!-- changelog: changed -->
- **Implement now runs every support script from one verified commit (stuck-states plan P2b).** Before this change, the "Stage workflow support files" step of `implement.yml` copied a hand-kept list of scripts into the issue checkout, and the steps before the editor ran `scripts/<helper>` from that checkout. In this repository those installs also overwrote an integration branch's tracked helpers.
  - The step now calls `scripts/stage_support_for_phase.sh implement`, a new phase of the helper. It checks that the support checkout is the commit `SCRIPT_REF` names, stages the review bundle from a scratch directory, and adds the implement scripts (the scope guard among the required ones), the optional groups (Serena, events mirror, transcript archive, Semble) and `claude_settings.json.tmpl` from the same commit under `RUNNER_TEMP`. The overlay loader goes to `${RUNTIME_DIR}/host_python` as before. No executable is written into the checkout.
  - As in `plan.yml`, the step first runs the read-only `stage_support_for_phase.sh implement --list` as a capability probe. A support ref (for example an older `stable`) whose helper has no `implement` case, or has no helper, falls back to the previous copy loop with a warning instead of failing the run.
  - The trusted run dir (`IMPLEMENT_STAGED_SUPPORT_RUN_DIR`), the guard-block handler copy and its `gh_helpers.sh` are now filled from the bundle. The step reads the bundle path back from `GITHUB_ENV` and fails closed unless it is a real directory under `RUNNER_TEMP`. A consumer-tracked `scripts/templates/serena_project.yml.j2` still replaces the bundle's Serena template.
  - Pre-editor steps call `"${SUPPORT_SCRIPTS_DIR:-scripts}/<helper>"`; steps after the editor keep running from the run dir. `scripts/implement_heal_preflight.sh` finds `workflow_failure_heal.py` in its own directory (`WORKFLOW_HEAL_PY` still overrides it).
  - Consumer commit exclusions are unchanged: `scripts/.gitignore` is written from the `--list` names plus `codex_model_catalog.json`, keeping only names the bundle actually holds, so an optional helper the support commit lacks never hides a consumer-owned `scripts/<name>` from the commit. In this repository the staged-support ledger no longer records script overwrites in unified mode, because no script is installed into the checkout; prompts, schemas and instruction files are still staged into the checkout and ledgered as before.
  - Setting the repository variable `SUPPORT_SCRIPTS_UNIFIED_ENABLED=false` (default `true`) restores the previous copy loop and bare paths for implement as it already does for clarify, plan and clarify-respond.
  - `tests/test_support_script_single_source.py` now covers `implement` too, including the run dir filled from the bundle, a self-repo tracked helper left untouched, and the caller-owned Serena template.
