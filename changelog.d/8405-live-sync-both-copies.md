- **A PR that edits both copies of a `.claude/` file differently no longer leaves `main`'s CI red (#8405).** #8316 changed `workflow-templates/.claude/hooks/prepush_affected_tests.py` and its live `.claude/` copy in one commit, and the two ended up different. PR CI tolerated the drift because the PR changed the template, and the post-merge sync skipped the path because the live copy changed in the same push (`CLAUDE_LIVE_SYNC nothing_to_sync`), so strict push CI failed on every later push to `main`. PR-mode parity (`tests/claude_template_drift.py` `pending_template_paths()`) now refuses to tolerate a drifted path when the PR changed both its template and its live copy. The real sync in `scripts/sync_claude_live_copies.py` now copies the template over the live file when a push (or, for a skipped or failed earlier run, the same last commit) changed both copies and they still differ, logging `CLAUDE_LIVE_SYNC both_changed path=... action=template_wins`. Those paths still go through the existing provenance routing unchanged; because the live copy's last commit is the both-changed commit, there are no later template commits to authorize, so the path lands on the held draft PR (`reason=no_template_commits`) for a human to merge. `sync --dry-run` (CI parity prep) does not apply this recovery and logs `action=left_for_parity`, so PR CI stays strict. A push that changed only the live copy is still left alone, and allowlisted divergent paths are unaffected. Refs #8405.
