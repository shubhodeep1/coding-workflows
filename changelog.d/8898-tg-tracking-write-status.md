- **A failed Telegram tracking-comment write is now reported instead of being dropped.** `tg_store_msg_id` and `tg_store_phase_msg_id` in `scripts/tg_helpers.sh` used to treat an HTTP 4xx/5xx from GitHub as success, so the Telegram message ID was never recorded and cleanup could never delete that message. Each write now checks the HTTP status, is bounded by a 30-second timeout, and on a non-2xx status or a curl failure prints `::warning::TG_TRACKING_WRITE_FAILED issue=<n> op=<append|create> phase=<phase|none> msg_id=<id> http=<code>` (`http=000` for a transport failure or timeout). The append PATCH is retried once after 2 seconds; the create POST is never retried, because a timed-out POST may already have created the comment. The helpers still return 0, and marker formats, trusted-author checks and the comment cap are unchanged. Refs #8895.
