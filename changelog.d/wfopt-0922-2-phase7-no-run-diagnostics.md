- **Release gate Phase 7 logs why no cancel-on-close run appeared.** When the `test-and-mark-stable.yml` step "Phase 7: Close PR and verify cancel_on_pr_close fires" finds no new `internal-cancel-on-pr-close` run, it now prints a "Phase 7 no-run diagnostic" log group before the unchanged `no_run` error. The group shows the PR number, close time, the last run id before the close, the number of polls, the seconds waited, every run in the last listing (id, event, status, conclusion, head SHA, creation time) and the workflow's `state` from one extra read made only on this path (`unknown` when that read fails). Run fields that start with a workflow command are printed with a `[neutralised]` prefix. The poll waits 3 s for the first 30 s, then 10 s, 20 s and 30 s, never past the 10-minute budget, so a step that finds no run makes about 25 run listings instead of about 60. The 10-minute budget stays, because the scheduled cleanup run the step also accepts often registers about 12 minutes after the close. Source: `analysis/workflow-optimization-2026-09-22-2.md` (Reliability 4 and the GH API call audit's Phase 7 hotspot).
