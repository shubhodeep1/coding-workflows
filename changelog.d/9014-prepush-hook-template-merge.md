- **A merge conflict on the pre-push gate hook is now resolved from its template on the runner, so PR #8436's conflict shape no longer needs a manual merge.** `scripts/review_conflict_prepare.sh` (`_conflict_prepare_guard_hook_template_merge`) now runs the host-only template merge on every live/template pair in `review_untrusted_workspace.PAIRED_LIVE_COPIES`, not only `.claude/hooks/pr_merge_status_guard.py`. When `.claude/hooks/prepush_affected_tests.py` conflicts, each side's live copy equals that side's template (same blob, same mode), and the `workflow-templates/` twin merged cleanly, the template's merged entry is staged for the live path. On integration-sync (`orchestrator/project-*`) branches the commit still waits for the integration fingerprint check. Every per-pair check, the return codes and the `CONFLICT_GUARD_HOOK_TEMPLATE_MERGE_ENABLED` kill switch (default `true`) are unchanged. The pair list is read only from the trusted support checkout (`${SUPPORT_SCRIPTS_DIR}/review_untrusted_workspace.py`), and each pair must have the form `.claude/hooks/<name>` -> `workflow-templates/.claude/hooks/<name>`. When the list cannot be read, only the built-in `pr_merge_status_guard.py` pair is handled, as before (`Guard-hook template merge: pair_source=fallback reason=<support_missing|read_failed|no_valid_pairs>`). `skipped reason=...` log lines now end with `path=<live>`. The strict xfail `test_prepush_hook_integration_sync_conflict_is_resolved_from_template` is now an ordinary test. Refs #9014, refs #8973.
