- **A refused Claude fallback with reason `no_credential` now says why the pool had no account.** The engine fallback report adds the Claude pool step's own reason (for example `crashed`, `cli_missing` or `broker_refused_workflow_sha_unverifiable`) as `pool_reason=<token>` to its log line, its Telegram alert and the step summary.

`no_credential` covers many different pool step outcomes: an install failure of the Claude CLI, a broker refusal or outage, failed account probes, or a missing OIDC token. Until now the report named none of them, so a heal issue such as the one for binance-blessings run 40951784257 could not tell which one happened. `scripts/ai_engine_fallback_report.sh` now reads the reason file the pool step writes (`${RUNNER_TEMP}/claude-pool-reason`, or `CLAUDE_POOL_REASON_FILE`) with the same rules as `ai_engine_no_account_reason`: no symlinks, at most 64 bytes, and only a token matching `[a-z0-9_]{1,60}` is shown. A missing, symlinked or malformed file shows `pool_reason=unavailable`. The key is added only to `no_credential` pairs, before `detail=` on the `skip_dispatch` lines so `detail` stays last.

What this means for operators: open the run named in a `no_credential` heal issue and read the `AI_ENGINE_FALLBACK_REPORT` line, the alert or the step summary to see the pool outcome. Routing does not change: `no_credential`, the fallback record format, the heal payload and its fingerprint are the same as before. Known limitation: the heal intake payload still does not carry the pool reason, so every `no_credential` cause still shares one heal fingerprint.

### For contributors

Tests in `tests/test_ai_engine.py`: `test_report_names_the_pool_reason_for_no_credential` (fails without the fix; also checks the dispatched payload is identical with and without the reason file), `test_report_pool_reason_unavailable_when_unreadable`, `test_report_pool_reason_only_labels_no_credential`, `test_report_pool_reason_keeps_detail_last_on_a_denied_dispatch` and `test_no_account_reason_output_is_unchanged_by_the_pool_reason`. The `agents.md` key list for `AI_ENGINE_FALLBACK_REPORT` does not name `pool_reason=` yet.
