- **The workflow log analysis report is now checked for structure before it is published (Refs #9116).** In `workflow-log-analysis.yml`, the `Run workflow log analysis` step runs the new `scripts/check_workflow_analysis_report.py` on each non-empty report. The check needs the 11 required `## ` headings in the prompt's order, a `### ` subsection in `## Per-Repo Breakdown` for every repository in the collector's `scope.repositories` (repositories whose run listing failed are exempt: `coverage.repositories_failed` when present, otherwise the collector's `errors[]` exception entries; a max-runs cap or a repository with no runs in the window does not exempt), and at least 2,000 bytes. It logs one `WORKFLOW_LOG_ANALYSIS_REPORT_CHECK` line and never echoes report text. An invalid report is retried like empty output; after the last attempt it fails with the new mode `report_structure_invalid` through the existing failure handler, is not committed, and is kept as the new `workflow-log-analysis-report` artifact (the upload step also keeps every valid report, 30 days). A checker error accepts the report. When the `workflow-log-output` directory is missing or cannot be staged for the analysis, the step logs `WORKFLOW_LOG_ANALYSIS_COVERAGE logs=missing` and adds `> Data gap: full workflow logs were unavailable for this run.` to the top of the report. Set the new repo variable `WORKFLOW_LOG_ANALYSIS_REPORT_CHECK_ENABLED` (default `true`) to `false` to go back to the plain non-empty check. No new GitHub API calls.
