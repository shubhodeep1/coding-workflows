- **The review-blocked judge and the deterministic-skip merge path now run the security follow-up guard before they merge.** A PR whose base is a standalone PR's head branch is no longer merged by `scripts/review_rb_judge.sh` (the `merge`, final-attempt `fix` and `merge_with_followup` merge sites) or by the `deterministic-skip-merge` job of `review_autofix.yml` while that branch's current head has a clean single-issue security audit as its latest completed result. Before, only the "Enable auto-merge on PR" step ran the guard, so these paths depended on report-side follow-up retirement alone, and a superseded follow-up PR could still merge into the clean-audited head when that retirement failed. Any result other than `allow` skips the merge and posts no success status. The judge's transient merge retry runs the guard again before each retried merge, so a clean audit recorded during the retry delay stops the retry; the guard sees the PR's live base, and an attempt whose PR read returns no base merges nothing (`note=base_unverified`). The judge logs `RB_JUDGE_SECURITY_FOLLOWUP_GUARD ... action=skip_merge` and leaves the PR in `ai:review-blocked`. The skip path logs `AUTOFIX_DET_SKIP_MERGE_BOUND ... reason=security_followup_guard_<result>`. Both paths reuse a PR payload they already hold, and a missing base ref or default branch fails closed. PRs into the default branch or an orchestrator integration branch still make no extra API call. The "Enable auto-merge on PR" step now receives the raw `SINGLE_ISSUE_SECURITY_PASS_ENABLED` repository variable, so an explicit `false` turns the guard off there too; unset keeps it on. Its refusal line gains a `phase=pre_status|post_wait` key. Refs #9671.
