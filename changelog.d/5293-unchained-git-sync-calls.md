- **Unattended Claude stage and fixer sessions run the chain's git fetch, checkout, merge, and push commands unchained.** An allowlisted git call no longer reaches the Auto-mode classifier because the session appended redirects, pipes, and status reads to it.

Issue #5293 recorded an `/implement-plan-claude` review-round session that ran `git fetch … 2>&1 | tail -1 && git merge --no-edit … 2>&1 | tail -3; git status -sb | head -3; git log --oneline -3`. Each git part is allowlisted in `.claude/settings.json`, but the chained command matched no allow rule, so the Auto-mode classifier saw it and denied it as `[Modify Shared Resources]`. The Helpers intro of `/implement-plan-claude` now says to run the git commands it names (`git fetch`, `git checkout -B`, `git merge --no-edit`, `git push`) exactly as written, with no `2>&1`, no pipe into `tail` or `head`, and no chained `git status` or `git log` reads, and to check the branch state in a separate call. Step 5 of `/fix-claude-pr` says the same for its fetch, checkout, and conflict merge.

What this means for consumer repos: the updated command files arrive with the next `@stable` sync of `.claude/commands/`. No allow rule, hook, or setting changes.
