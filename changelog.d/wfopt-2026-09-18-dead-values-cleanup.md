- **The poller now logs whether a branch rebuild after resolver escalation was skipped, and why.** `_attempt_branch_rebuild_after_escalation` in `scripts/orchestrate_poll_process.sh` prints `BRANCH_REBUILD_THRESHOLD_DECISION tracking_issue=<n> skip_reason=<reason|none> last_rebuild_at=<ts|none>` after every threshold check, so a project waiting on the threshold or the cooldown shows the reason in its run log. The unused `WAVE_COUNT` value in `orchestrate.yml`'s summary step and the unused `BLOB_CONTENT` value in `test-and-mark-stable.yml` are removed. Behaviour is unchanged. Refs #7355.
