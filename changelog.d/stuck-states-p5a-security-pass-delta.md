- **Single-issue security pass re-audits only what changed since the last audited head (stuck-states P5a, Refs #8291).** With `SINGLE_ISSUE_SECURITY_PASS_DELTA_ENABLED` (default `true`), a later cycle of the per-PR security pass dispatches the audit with `audit_diff_since` (and `prior_findings` after a findings result), new optional inputs of `security-audit.yml` and the `ai-security-audit.yml` consumer wrapper. The audit treats them as a request: it verifies them against the pipeline's own PR markers, the commit ancestry and the stored findings' sha256 before narrowing the scope, and otherwise audits in full. Prior findings are re-verified by the model; one that is not re-reported, whose file is untouched and whose follow-up is still open is carried forward, so a delta audit cannot report `clean` while it stays unfixed. A wrapper without the new inputs falls back to today's dispatch once instead of losing a cycle, and the final exhausted-head audit stays a full audit. Set the variable to `false` to restore today's behaviour exactly.
