- **The token broker can now hand a ChatGPT credential to a trusted job (ChatGPT account reviewer trial, Phase 1).** Nothing uses it yet: the broker's ChatGPT workflow allowlist is empty, so every caller is refused. `.github/ai/chatgpt_pool.json`, the action's default config, is not shipped yet, so the action answers `available=false reason=config_missing` on its default path. A later phase adds that file (with `reviewer_slot_enabled` `false`) and the reviewer slot; turning the slot on is a separate human pull request.

What was added:

- `POST /v1/chatgpt` on the `claude-pool-broker` Worker (`tools/claude-pool-broker/src/index.ts`). It runs the same GitHub OIDC checks as `/v1/pool` (signature, issuer, expiry, a token at most 10 minutes old, owner, consumer registry, workflow ref or SHA ancestry), with its own audience `coding-workflows-chatgpt-pool` and its own allowlist `CHATGPT_ALLOWED_WORKFLOW_FILES`. A token minted for one endpoint is refused by the other. It answers 200 with `access_token`, `id_token`, `account_id` and `expires_at`, 403 on a refusal and 503 on broker-side trouble. `/v1/pool` is unchanged.
- The `ChatgptPoolStore` Durable Object (binding `CHATGPT_POOL`, migration tag `v1` in `wrangler.toml`) keeps the credential. It is seeded from the `CHATGPT_POOL_SEED` secret, and a new secret value re-seeds it. It refreshes the credential when it nears expiry, one refresh at a time, and saves the rotated refresh token before anything else. The refresh token never leaves the object. The refresh endpoint and client id are the `CHATGPT_REFRESH_URL` and `CHATGPT_OAUTH_CLIENT_ID` vars, empty by default: with them empty, refresh is off and a credential near expiry is refused (503 `refresh_not_configured`). An `invalid_grant` answer latches the credential as rejected until the seed changes; a 401 (a wrong client id or URL) fails without latching, so fixing the var is enough.
- `.github/actions/chatgpt-pool-token` and `scripts/chatgpt_pool_token.sh`, modelled on `claude-pool-token`. The action requests the job's OIDC token (the job needs `id-token: write`), masks the access and id tokens as soon as they are parsed, and writes a 0600 `auth.json` under `$RUNNER_TEMP/chatgpt-pool`. Its outputs are `available`, `reason`, `auth_dir`, `auth_file` and `expires_at`. It never fails the job, and its post step deletes the credential directory. Logs carry the `CHATGPT_POOL` prefix and never a token.

What this means for operators: nothing changes until the Worker is deployed and `wrangler secret put CHATGPT_POOL_SEED` is run. Until then `/v1/chatgpt` answers 503 `credential_not_seeded` (after the 403 every caller gets from the empty allowlist).
