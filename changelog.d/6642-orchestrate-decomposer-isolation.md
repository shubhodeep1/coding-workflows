- **The orchestrate decomposer now runs on Claude with read-only tools, and Claude refuses to start if its account pool sits inside the model's workspace.**

The decomposer reads an untrusted project description. On Claude it already ran in the credential-free, network-isolated container, with the host relay as the only reader of the account token. It now also gets the read profile (`Read`, `Grep`, `Glob` over a read-only copy), the same as its codex fallback, and no inherited `--include` mounts. Its plan still comes back through the host-captured transcript. `claude_run` now resolves the account pool directory, the workdir and every include path, symlinks included, before any snapshot. If the pool overlaps any of them, it stops with status 1 and logs `CLAUDE_POOL ... outcome=refused reason=pool_overlap`. This status does not trigger the codex fallback. Contract tests in `tests/test_codex_agent_isolation_contract.py` pin both behaviors, along with the credential stripping and host-only token handling.

What this means for operators: nothing changes with the default `CLAUDE_ENGINE_POOL_DIR` under `RUNNER_TEMP`. A pool configured inside the checkout or an include path now fails the Claude run instead of exposing token files to the model.
