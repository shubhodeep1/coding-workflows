- **The review-blocked judge now names the required checks that block a merge, and re-runs cancelled ones once.** When the judge approves a PR but the check-runs gate refuses the merge (`judge_skip_reason=blocking_check_runs`, unchanged) and nothing on the head is still running, the judge writes `judge_blocking_checks_settled=true` and `judge_blocking_check_names`. The review-blocked comment then reads "merge gated by failed required check-runs" and lists each `name:conclusion`, instead of saying the checks are in flight. When every blocking run was cancelled or timed out, the judge requests one `rerun-failed-jobs` per Actions run, at most once per head and run, using a marker comment. `scripts/pr_checks_lib.sh` exposes the blocking names and run ids as `PR_CHECKS_LAST_BLOCKING_NAMES` / `PR_CHECKS_LAST_BLOCKING_RUN_IDS`. Set `RB_JUDGE_SETTLED_CHECK_DIAGNOSTICS_ENABLED=false` in the judge step's environment to turn it off (default on); no repository variable sets it yet. Refs #10137, #9502.
