- **The Claude token broker now hands the account pool only to the exact coding-workflows workflows that use it, run from `main` or from a commit already on `main` or `stable`.** Before, any workflow file under `shubhodeep1/coding-workflows/.github/workflows/` received the pool, including a new one pushed to an unprotected branch.

`tools/claude-pool-broker` checks `job_workflow_ref` against `ALLOWED_WORKFLOW_FILES` (the ten reusable workflows that call `.github/actions/claude-pool-token`; `tests/test_claude_pool_token.py` keeps the list in step). It accepts `@refs/heads/main`, or a 40-hex SHA that equals the signed `job_workflow_sha` and that GitHub's compare API reports as behind or identical to `main` or `stable`. Trusted SHAs are cached for 6 hours. Everything else gets `403` with a reason code: `workflow_not_allowed`, `workflow_ref_not_allowed` (feature branches, tags, and `refs/heads/stable` given as a branch), `workflow_sha_mismatch`, `workflow_sha_unverified`, or `workflow_sha_unverifiable` when the check fails, times out or is rate limited. The job then reports `available=false reason=broker_refused_<code>` and runs codex, so the single-issue security pass and smoke runs dispatched from a branch now use codex. An optional Worker secret `BROKER_GITHUB_READ_TOKEN` authenticates the compare calls. The change takes effect when the Worker is redeployed with `wrangler deploy`.
