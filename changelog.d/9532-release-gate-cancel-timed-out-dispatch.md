- When the release gate gives up waiting for a child run it dispatched, it now cancels that run. In release run 43590943288 the `validation-refresh`, `validate` and `orchestrate` children stayed queued for 3 to 4.7 hours with no runner, the watches timed out, and the children ran hours later anyway: the orchestrate child then created a smoke tracking issue and Wave 1 issues that the gate's cleanup could not see. The three dispatch steps of `test-and-mark-stable.yml` ("Dispatch & watch — validation-refresh", "Dispatch internal-orchestrate.yml with multi-issue project", "Dispatch internal-validate.yml standalone") now read the timed-out child's jobs once, print a `::warning::` with the number of jobs and how many are queued with no runner, and cancel the child. Both calls only warn when they fail, and the step still fails with the watcher's exit code. Set `DISPATCH_WATCH_CANCEL_ON_TIMEOUT=false` in the step environment to skip the cancel. The cause of that run was most likely runner starvation, so re-run the release gate once the runner queue clears. Refs #9532.
