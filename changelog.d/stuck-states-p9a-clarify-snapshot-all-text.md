- **Clarify's read-only snapshot now holds every tracked text file (#8341, Refs #8291).** The snapshot built by `scripts/clarify_isolated_run.sh` for clarify, clarify-respond, plan, check-failure triage and the unblock judge used to copy only a fixed list of top-level directories and file suffixes, so agents reported real tracked files (for example `Makefile`, `*.sol` contracts or `*.j2` templates) as missing (#6194). The legacy set is still copied first with its old limits; every other tracked text file is added after it. Binary files outside the legacy set, files over 2 MiB and files past the 5000-file / 64 MiB limits are left out instead of rejecting the whole snapshot, counted in a `CLARIFY_SNAPSHOT_EXCLUDED` log line, and listed for the agent in a delimited block appended to a copy of the prompt. The sensitive-path filters are unchanged, and the added files also skip credential stores such as `.npmrc`, `.netrc`, `id_rsa` and `*.jks`, and secret-named files such as `prod_secret.json` or `db-credentials.yaml`.

  What this means for operators: nothing to do. Set the repository variable `CLARIFY_SNAPSHOT_ALL_TEXT_ENABLED` to `false` to restore the old roots/suffix filter at every caller.
