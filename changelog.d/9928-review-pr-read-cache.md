- **The review job reads each PR resource once.** The codex-agent job of `review_autofix.yml` now reads the PR payload, issue comments, reviews, review comments and files through a run-local cache (`gh_pr_cached_read` in `scripts/gh_helpers.sh`), so later steps reuse the first read instead of calling `GH_PAT` again. Entries are keyed by head SHA; the PR payload and entries with no head SHA expire after 120 s (check-run reads stay live: the helper's `check_runs` kind has no call site yet); a closed PR is never cached, and every PR write made through `gh_retry`, `gh_retry_to_file` or `gh_api_retry` (labels, comments, update-branch, merge), plus the push step, evicts the PR's entries. Any cache error falls back to a live read. Merge authorisation keeps every `pulls/N` read in `scripts/review_enable_auto_merge.sh` live, and `--match-head-commit` stays the guard; the merge-base freshness gate it calls (`_pr_base_fresh_for_merge`) reads the PR files and sync comments through the cache. The reviewer pre-flight reads the PR state through the cache, whose 120 s expiry counts from the live fetch, rather than trusting the payload file's mtime. The job end logs `GH_PR_READ_CACHE hits=<n> misses=<n> job=codex-agent`; set the repo variable `REVIEW_RUN_READ_CACHE_ENABLED=false` to restore live reads. Refs #9928
