- **The `orchestrate-poll` CI job's time limit goes from 20 to 30 minutes.** On 2026-11-21, after #9641 moved the pre-push gate step out of group 3, shards still took 15-17 minutes on a passing run (#9867, run 44914391485). Slow runners were cancelled at the 20-minute cap with no code fault: run 44915291684 (#9839, shards 0 and 3 at 20.2 min) and run 44917124015 (#9854, shard 0). The repository owner chose to raise the limit for this one job, overriding the budget-watch advice not to raise `timeout-minutes`. Budget-watch still warns at 0.75 of the limit, so it now warns at 22m30s. Every other CI job stays capped at 20 minutes; `tests/test_ci_job_split_contract.py` pins `orchestrate-poll` as the only exception. Refs #9639, #9641, #9839, #9854, #9916.
