<!-- changelog: changed -->
- **Claude-fixer checkers never ask a human, holds say why and ask on the pull request, and a conflict in `.claude/**` goes to the GPT resolver.** Held pull requests are polled every 3 hours instead of hourly, and an `/implement-plan-claude` project that stops on a held pull request resumes on its own once it merges.

`.claude/scripts/check_in_status.py` now adds `retry_after_minutes` to every JSON line: 60, or 180 for a held head (`CLAUDE_CHECK_IN_HELD_RETRY_MINUTES`, clamped to 60–1440), and both the CLAUDE.md §26 checker and the `/implement-plan-claude` project checker re-arm with it. Its plain PR mode also reports a hold on a `claude/implement-plan-*` head as `state: held`, so a project checker keeps waiting on a held pull request instead of starting a review round. Every hold, in `/fix-claude-pr` and `/implement-plan-claude`, first posts one `<!-- ai:claude-blocked:v1 -->` PR comment with the finding-by-finding reasoning and the question, then a hold claim whose new `--reason` names the cause (`claude_fix_claim.py post --kind hold --reason <text>`; `--reason cap` and no `--reason` keep the old "reached the cap" sentence). A plan-mode stage that stops at `Status: BLOCKED` on a held pull request still arms the project checker on it. In `review_autofix.yml`, a merge conflict on a `claude/*` head whose unmerged paths include `.claude/**` now runs the GPT conflict resolver, since an unattended Claude session cannot edit those files; when the resolver fails, the `kind=conflict` hand-off names the protected paths and the fixer holds. Issue-mode projects now build on the default branch unless the code they fix exists only on the branch the issue names, and a project whose base pull request closes without merging is rebuilt on the default branch.

What this means for operators: a held Claude-fixer pull request now carries its question in an `ai:claude-blocked:v1` comment, so you can answer without opening the session, and the hold comment states the real cause. After you merge a held project pull request by hand, the next stage starts within 3 hours without a nudge. A `.claude/**` conflict such as the one that stopped PR #4610 is resolved in Actions; set `CLAUDE_FIXER_PROTECTED_CONFLICT_RESOLVER_ENABLED=false` to hand it to the Claude session as before. Consumer repos get the workflow change on the next `@stable` release and the `.claude/` changes through the existing `claude_sync`.

### For contributors

The protected-conflict route lives in the Claude-fixer branch of `scripts/review_autofix_step_merge_topology_gate.sh`, which already lists the unmerged paths; Claude-fixer heads never ran "Detect merge conflicts", and the hand-off step runs before the resolver. The route requires `CAN_PUSH=true`. "Detect merge conflicts", both resolver steps, "Telegram conflict resolution message", "Push all pending commits" and "Re-trigger review via workflow_dispatch" gain the clause `(env.CLAUDE_FIXER_MODE != 'true' || env.CLAUDE_FIXER_PROTECTED_CONFLICT == 'true')`; the editor, the review-blocked judge and auto-merge keep their Claude-fixer guards. The fallback step "Hand unresolved protected conflict to Claude session" (`scripts/review_autofix_step_claude_fixer_protected_conflict.sh`) re-sources the hand-off script with `CLAUDE_FIXER_PROTECTED_CONFLICT_FALLBACK=true`. To stay under the plan's 470,000-byte cap, the body of "Re-trigger review via workflow_dispatch" moved verbatim to `scripts/review_autofix_step_retrigger_review.sh`, with `github.workflow_ref` passed as `REVIEW_RETRIGGER_CALLER_WORKFLOW_REF`. Tests: `tests/test_check_in_status.py`, `tests/test_check_in_status_hand_back.py`, `tests/test_review_autofix_claude_fixer_mode.py`, `tests/test_implement_plan_claude_command.py`, and `tests/test_implement_issue_claude_command.py`.
