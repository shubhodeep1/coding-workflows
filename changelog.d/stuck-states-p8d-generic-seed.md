- **Dependency-wait seeding now skips blocked issues that a person is holding with any human-latch label (Refs #8291).** `scripts/dependency_wait_resume.py` moves an `ai:blocked` issue that declares exactly one `Depends on: #N` to `ai:waiting-on-dependency`, and once #N closes it posts `/answer [auto-answered-by-poller]`. Before this change it skipped only `ai:needs-human` (plus `ai:security` and `ai:orchestrator-managed`). An issue that also carried another human latch, such as `ai:scope-blocked` or `ai:destructive-blocked`, was seeded anyway and later auto-answered past that latch. Seeding now skips all eight human-latch labels: `ai:needs-human`, `ai:check-triage-escalated`, `ai:destructive-blocked`, `ai:scope-blocked`, `ai:harness-broken`, `ai:resolver-escalated`, `ai:security-pass-failed` and `ai:workflow-heal-escalated`. The set is the union of `workflow_failure_heal.HUMAN_NEEDED_LABELS` and `orchestrate_lib.STALL_RECOVERY_LATCH_LABELS`, and a test keeps them aligned. When a person removes the latch and the issue is still `ai:blocked`, the next poller tick seeds it as usual. No new GitHub call, env var, marker or log value is added.
