- **The unblock judge no longer re-issues an issue whose own pull request is green or waiting for the merge lease, and a re-issue now closes the old pull request.** A `reissue` used to create the replacement and close the source issue but leave its `ai/issue-<n>` pull request open, so the old pull request kept running through review, final CI and the merge lease next to its replacement (#9519 / PR #9562, #9887 / PR #9899). The judge now reads the issue's open same-repository `ai/issue-<n>` pull requests opened by the pipeline login (one GraphQL read per judged issue) and shows them to the model. A `reissue` is refused while one of them has a pipeline `ai-review/head-gate` success on its current head or carries `ai:merge-lease-wait`, or when the read failed: the item gets one comment, held as an `item_closed` wait on that pull request (no round is spent), and nothing is created or closed. A `reissue` that goes ahead comments `Superseded by #<new>` on each such pull request and closes it, so `cancel_on_pr_close.yml` cancels its runs and releases its lease. The merge-lease tick also no longer grants a waiter on `ai/issue-<n>` whose issue `<n>` is closed as not planned (one batched read per base; a failed read grants as before), and such a pull request's own review or update run no longer takes a free lease. New switches `UNBLOCK_REISSUE_OWN_PR_GUARD_ENABLED` and `MERGE_LEASE_SOURCE_ISSUE_GUARD_ENABLED`, both default `true`; `false` restores the old behaviour. Operators have nothing to do; the two existing orphaned pull requests are left to their owner.

Refs #10121, Refs #9892.
