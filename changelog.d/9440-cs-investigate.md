- **CS ticket investigation workflow.** New reusable `.github/workflows/cs_investigate.yml` (`workflow_call`: `ticket_id`, `mode`, `attempt`, `hub_url`; output `verdict`) investigates one CS ticket on the new `CS_INVESTIGATE` engine role (Claude pool, read profile, codex fallback) with a read-only checkout of the caller's default branch, fetches the ticket and up to 5 photos from the CS hub with an OIDC token (audience `cs-hub`), sends the agent's database queries from the runner through `scripts/cs_bridge_query.sh` (OIDC audience `agent-db-bridge`, fixed bridge host, at most 3 rounds of 5 requests), and returns a verdict checked against `scripts/templates/cs_verdict.v1.schema.json`, or `{"ticket_id":…,"outcome":"invalid_verdict"}`. The workflow holds no write credentials and is not propagated to consumers; the Claude pool broker allows `cs_investigate.yml` (redeploy the broker for it to take effect), and the broker refuses `refs/tags/stable`, so an `@stable` caller runs on codex (the workflow fixes `AI_ENGINE_FALLBACK_POLICY` to `always`) and a 40-hex pin gets the Claude pool. The caller repository must set `CS_HUB_ALLOWED_HOSTS` (`host` or `host:port`); an empty list fails the job before the `cs-hub` token is fetched. Refs #9440.
