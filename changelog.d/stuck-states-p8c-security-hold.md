- **Security-dependency holds escalate after `DEPENDENCY_WAIT_ESCALATE_DAYS` and release on an unmerged predecessor (stuck-states P8c, Refs #8291).** A generated security follow-up held on `- Depends on: #N` no longer waits forever. The standalone poller records when the hold started in the issue's stall-state comment and, after `DEPENDENCY_WAIT_ESCALATE_DAYS` (default `7`), labels the follow-up `ai:needs-human` once with a comment naming the dependency chain; the hold itself stays. When the predecessor is closed without `ai:merged`, `scripts/security_dependency.py` now returns `ready` and the poller posts one `/reclarify` carrying `<!-- AI_SECURITY_DEPENDENCY_RELEASED_V1 reason=predecessor_unmerged issue=<n> depends_on=<N> -->`, so clarify re-checks whether the finding still applies. On release the poller also removes the hold's own `ai:needs-human` latch. Only markers written by the pipeline login count. Set the repository variable `DEPENDENCY_WAIT_RESUME_ENABLED=false` to keep the previous hold-only behaviour; `orchestrate_poll.yml`, `clarify.yml` and `implement.yml` forward it.
