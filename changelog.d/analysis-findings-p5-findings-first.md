- **Workflow analysis checks prior findings first.** The default (non-retro) mode of the workflow optimization analyst prompt (`prompts/mode-workflow-analysis.txt` and its render source `prompts/_templates/mode-workflow-analysis.txt`) now runs a findings-first check before it recommends anything: evidence in the window, then the current repository code (findings already fixed on the ref are dropped), then the prior verdicts in `analysis/recommendation-processing-report.md` (`applied`/`already-implemented` findings return only when the problem recurs; `rejected` ones only when new evidence answers the recorded reason). Each recommendation ends with a `Finding check: <new|recurring|reopened|unverified> — <evidence>` line, and the `## Metrics Appendix` gains a `Findings check` table with per-status and dropped counts. The check fails open when the processing report is missing. No report heading is added, removed or reordered and retro mode is unchanged, so apply-analysis and other parsers in consumer repos keep working; consumer reports simply carry the extra line and table after the next release. Refs #9116.
