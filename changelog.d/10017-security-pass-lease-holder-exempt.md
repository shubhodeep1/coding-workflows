<!-- changelog: changed -->
- **A PR that holds the merge lease no longer waits behind the security-audit throttle.** When `SECURITY_PASS_MAX_CONCURRENT_AUDITS` is reached, the single-issue security pass now reads the base branch's merge lease once; a live lease holder gets its audit dispatched at once (logged `throttle=lease_holder_exempt`), bounded to `MERGE_LEASE_MAX_HOLDERS` extra audits. Other PRs, and any lease read failure, are throttled as before. The codex-agent and deterministic-skip security-pass gate steps now receive `MERGE_LEASE_ENABLED` and `MERGE_LEASE_MAX_HOLDERS`. Refs #10017.
