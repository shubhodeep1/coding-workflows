- **Implement runs stay inside an issue's `files_touched` list.** The implement prompt the workflow sends used to tell the editor to update every test listed under the advisory "Expected files" section, and it said nothing about the issue's `files_touched` list. An editor that followed it could change a test outside that list, and the commit-time scope guard then refused the commit and marked the issue `ai:scope-blocked`. The prompt now says to stay inside `files_touched` plus the issue's own `changelog.d/` and `agents.d/` fragments, to update only the listed tests inside that scope, and to report an out-of-scope test in the summary instead of editing it. On a workflow heal issue it names the verified `ai:workflow-heal-scope:v1` marker's `paths=` list as the scope, which is the list the heal-route scope guard checks. The scope guard is unchanged.

  For contributors: `tests/test_implement_inline_prompt_files_touched_scope.py` pins the new wording in the inline prompt in `.github/workflows/implement.yml`.
