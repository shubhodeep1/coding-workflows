<!-- changelog: fixed -->
- **The `REVIEW_HEAD_CHECKOUT` timing fields no longer drop to `na` on ubuntu-26.04 runners, and two CI tests pass there again.** The "Checkout PR head branch" step (`scripts/review_autofix_step_checkout_pr_head_branch.sh`) now reads the clock from bash's `EPOCHREALTIME` first, as the orchestrator poller already does (#9200). On the new image `date +%s%3N` gave readings that went backwards within a run, so `fetch_ms` and `switch_ms` came out negative and were printed as `na`. The line format is unchanged, and `date` is still the fallback for bash older than 5. A new regression test fakes a `date` clock that goes backwards, so the fix is checked on every host with bash 5 or newer (the test is skipped on older bash, which has no `EPOCHREALTIME`).

`tests/test_gh_retry_stdout_isolation.py::test_closed_reader_does_not_rerun_a_successful_command` now reads one byte with bash's `read -n 1` instead of `head -c 1`. The uutils `head` on ubuntu-26.04 did not close the pipe early, so the test saw `rc=0` even though `gh_retry` behaved correctly. `gh_retry` itself is unchanged.
