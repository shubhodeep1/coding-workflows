- **The poller test sandbox's fake `gh`, `git` and `python3` now lock and atomically write their shared mock store.** When fakes overlap inside one poller run (process substitution, background calls, or a fake that starts another fake), the external-finalize branch-deleted security-pass test can no longer lose a fetch or PR-read count or read a half-written store (Refs #9869). Each poller run keeps its store in its own temp directory, so separate tests and parallel shards never shared it; the lock guards overlap within a run.

Ten local runs of that test did not reproduce the shard-3 failure from release gate run 44843326673, so no failing assertion or message could be recorded. Because the failure is intermittent, this change makes the test fixture deterministic rather than changing `scripts/orchestrate_poll_process.sh`. The test's asserts and expected values are unchanged. No gate has yet recorded a passing run of it (the pre-push gate timed out on this test file), so CI on a full checkout still has to confirm the fix.

Each fake, and the `tg_cleanup_msgs` / `tg_send_tracked` test helpers, takes an exclusive lock on `<store>.lock` before it loads `GH_MOCK_STORE` and replaces the file atomically when it saves. A fake started by another fake inherits `GH_MOCK_STORE_LOCK_HELD=1`, so it does not wait on its parent. The wait is capped at 30 seconds (tests can shorten it with `GH_MOCK_STORE_LOCK_WAIT_SECONDS`); after that the fake carries on unlocked, as before this change, and says so on stderr, and a test now checks that message. Only the test fixture changed; production scripts and workflows did not.

What this means for consumer repos: nothing; this changes tests only.
