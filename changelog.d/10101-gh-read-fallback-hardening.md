- **The promote cycle's gate-run reads now fall back to the PAT when the job token fails with a 5xx or a non-HTTP error.** Before, the gate-idle check and the gate-wait loop in `scripts/promote_main_cycle.sh` wrapped `gh_read` in `gh_retry`, and `gh_read` only falls back to the PAT on 401, 403, 404 or a rate limit. So an HTTP 502 or a connection error from the job token retried the job token alone: the idle check skipped the whole cycle as `guard_unavailable`, and a long outage in the wait loop ended as `smoke_gate_timeout`. The new `promote_cycle_gate_runs_read` tries the job token once and, on any failure, runs the bounded `gh_retry` loop on the PAT. The output of a failed attempt is thrown away, and the `GH_READ_FALLBACK` stderr filter is kept. With `GH_READ_TOKEN` unset or `GH_READ_TOKEN_ENABLED` off, the reads behave exactly as before. `tests/test_gh_read.py` now lists every `test-and-mark-stable.yml` step that exports `GH_READ_TOKEN`. For each call site those steps reach, plus the promote cycle's reads, it checks under `set -euo pipefail` that the PAT output is used after an HTTP 403, a rate limit, an HTTP 502 or a non-HTTP failure, and that no token value is printed. Shared helpers, helper names and env defaults are unchanged. Refs #10101, Refs #9888.
