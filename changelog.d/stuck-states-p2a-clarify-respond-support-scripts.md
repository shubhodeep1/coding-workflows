<!-- changelog: changed -->
- **Clarify-respond now runs every support script from one verified commit (stuck-states plan P2a).** Before this change, the "Stage workflow support files" step of `orchestrate_clarify_respond.yml` copied a hand-kept list of scripts into the issue checkout, and every later step ran `scripts/<helper>` from that checkout. A helper missing from the list, or a stale copy on a heal branch, ran from the target branch with the job's `GH_PAT`.
  - The step now calls `scripts/stage_support_for_phase.sh clarify_respond`, a new phase of the helper. It checks that the support checkout is the commit `SCRIPT_REF` names, stages the review bundle from a scratch directory, and adds the clarify-respond scripts and the sandbox Dockerfile from the same commit under `RUNNER_TEMP`. It writes no executables into the checkout. `CLARIFY_ISOLATION_SUPPORT_DIR` points `clarify_isolated_run.sh` at the bundle.
  - As in `plan.yml`, the step first runs the read-only `stage_support_for_phase.sh clarify_respond --list` as a capability probe: a support ref (for example an older `stable`) whose helper cannot stage `clarify_respond`, or has no helper, falls back to the previous copy loop with a warning instead of failing the run. The consumer `scripts/.gitignore` is written from the `--list` names plus `codex_model_catalog.json` and `clarify_sandbox/`, so it drops no name. The overlay loader in the staging step runs from the verified `.codex-workflow-src`.
  - Every later call in `orchestrate_clarify_respond.yml` uses `"${SUPPORT_SCRIPTS_DIR:-scripts}/<helper>"`, and `write_codex_config.sh` gets `--catalog-path` for the bundle's model catalog. Prompt templates and the static instruction files are still read from the checkout.
  - Setting the repository variable `SUPPORT_SCRIPTS_UNIFIED_ENABLED=false` (default `true`) restores the previous copy loop and bare paths for clarify-respond as it already does for clarify and plan.
  - `tests/test_support_script_single_source.py` now covers `clarify_respond` too, including the stall-guard fixture, the `--list` contract, the `.gitignore` superset check and the fallback for a helper without the `clarify_respond` case.
