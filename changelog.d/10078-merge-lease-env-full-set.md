- **Every poller and sweep path that can grant or renew a merge lease now honours the merge-lease repository variables.** The steps "Process each tracking issue", "Run standalone stall recovery without active projects" and "Run standalone PR sweeps without active projects" in `orchestrate_poll.yml`, and "Enumerate open PRs and dispatch internal-review.yml" and "Ensure the final CI run on reviewed PR heads" in `review_autofix_sweep.yml`, passed only some lease settings. A lease they wrote used the built-in default of `scripts/pr_checks_lib.sh` instead: on 2026-11-24 PR #9970's lease was renewed at 22:38 UTC for 240 minutes while `MERGE_LEASE_TTL_MINUTES` was set to 480. These steps now pass `MERGE_LEASE_ENABLED`, `MERGE_LEASE_TTL_MINUTES`, `MERGE_LEASE_WAIT_LABEL`, `MERGE_LEASE_REVOKE_ENABLED`, `MERGE_LEASE_IDLE_MINUTES`, `MERGE_LEASE_PRIORITY_HEAD_PREFIXES`, `MERGE_LEASE_SOFT_PATHS` and `MERGE_LEASE_MAX_HOLDERS` with the same defaults as every other lease step (the sweep's final-CI step keeps its deliberate `MERGE_LEASE_SOFT_PATHS: none`). Defaults and lease behaviour are unchanged (Refs #10078).

The new contract test `tests/test_merge_lease_env_contract.py` fails when a workflow env block passes some lease settings but not all, uses a default that differs from `scripts/pr_checks_lib.sh`, passes an unlisted literal, or wires one of the settings that are not repository variables (`MERGE_LEASE_MAX_HOLD_MINUTES`, `MERGE_LEASE_REF_PREFIX`, `MERGE_LEASE_METRICS_ENABLED`).
