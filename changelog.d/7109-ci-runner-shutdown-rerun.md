- **The review sweep now re-runs a PR's CI once when a runner shut down mid-job.** Issue #7109, from PR #6682's run 38090075498: the `static-checks` runner received a shutdown signal during ShellCheck, the `lint` aggregate failed with it, and nothing re-ran the run because the sweep only recovered `cancelled` and `startup_failure` runs.

`scripts/ci_cancelled_rerun.py` now also considers a current-head `failure` run that passes every existing guard (attempt 1 only, no active run, current head). It reads the run's attempt-1 jobs and each failed job's check-run annotations, and re-runs the failed jobs only when every failed job carries the annotation `The runner has received a shutdown signal`, with the `lint` aggregate accepted only when it names such jobs or cancelled ones. The decision is logged as `CI_CANCELLED_RERUN … action=rerun reason=runner_shutdown`. A real failure still logs `reason=other_conclusion`; unreadable, malformed or over-cap evidence logs `reason=runner_shutdown_unverified` and re-runs nothing. Classification costs one jobs read plus at most 10 annotation reads per run and runs for at most 5 runs per tick, so the sweep job now holds `checks: read`. A step that prints the shutdown text itself can earn its head one re-run of the same workflow, which an empty push already allows; the existing one-retry-per-head rule still applies. `CI_CANCELLED_AUTO_RERUN_ENABLED=false` turns it off with the rest of the recovery.
