- **Stall recovery now explains an `ai:needs-human` escalation on the issue itself.** Once `ai:needs-human` is confirmed on a stalled issue, the poller (`scripts/orchestrate_poll_process.sh`) posts one comment on that issue headed `## Stall recovery: human input needed`. The comment gives the stall judge's justification (or a default reason), the phase and how long it was stuck, a pointer to the tracking issue, and the resume step (remove `ai:needs-human`). It ends with the marker `<!-- ai:stall-escalate-human:v1 issue=<N> phase=<P> -->` and is logged as `STALL_ESCALATE_HUMAN_COMMENT ... outcome=posted|write_failed`. A failed write never changes the recovery result. Re-implements #9821. Refs #9853. Consumers get this with the next sync, and no variable needs to be set.
