- **Heads that already have a verdict and only wait to merge are no longer re-reviewed or re-judged.** The review sweep (`.github/workflows/review_autofix_sweep.yml`) skips a PR whose current head has `ai-review/head-gate` success and carries `ai:final-ci-merge-pending`, or has auto-merge enabled while the final CI run is in flight or already succeeded (a required check is missing), or carries a review-blocked judge merge verdict (with or without head-gate success) with nothing relevant changed since (`AUTOFIX_SWEEP_SKIP ... reason=verdict_waiting wait=<reason>`, counted as `skipped_verdict_waiting`). The judge records a deferred merge verdict as the commit status `ai-review/rb-judge-verdict` (`RB_JUDGE_VERDICT_STATUS`), and stall recovery no longer re-dispatches the judge for that head until the head, the lease, the merge state, a failed check on the head or the base under the PR's files changes (`STALL_SKIP ... reason=rb_judge_verdict_unchanged`); a base that moved without overlap is recorded on the verdict once. Skipped dispatches create no run, so they are not review rounds; a head whose verdict changed still counts toward the round cap. A head (including one waiting for the merge lease) that has waited `VERDICT_MERGE_WAIT_ALERT_HOURS` (default 6) raises one Telegram warning naming the blocker, deduplicated by the `ai-review/merge-wait-alert` status (`VERDICT_MERGE_WAIT_ALERT`). No new API call per PR in the sweep or the stall loop beyond the documented ones; `VERDICT_WAIT_DISPATCH_SKIP_ENABLED=false` restores the previous dispatches. Refs #9991, Refs #9987, Refs #9939.
