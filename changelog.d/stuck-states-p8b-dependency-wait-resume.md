- **Issues waiting on a dependency now resume on their own (stuck-states P8b, Refs #8291).** A new poller step, "Resume dependency waits" in `orchestrate_poll.yml`, runs `scripts/dependency_wait_resume.py` on every tick, even when no orchestrator project is open. For each issue labelled `ai:waiting-on-dependency` it reads the trusted `AI_DEPENDENCY_WAIT_V1` marker and checks the dependency: when the PR merged, the issue closed with `ai:merged`, or `@stable` contains the PR, it posts one `/answer [auto-answered-by-poller]`; when the PR or issue closed without merging, it posts one `/reclarify`. After `DEPENDENCY_WAIT_ESCALATE_DAYS` (default `7`) a wait that is still open gets `ai:needs-human` once, with a comment naming the dependency, and still resumes on its own later. Open `ai:blocked` issues that declare one `Depends on: #N` line are moved to `ai:waiting-on-dependency` once. Only markers written by the pipeline login count, and the step never fails the poll. With nothing waiting it makes one GraphQL call per tick. Set the repository variable `DEPENDENCY_WAIT_RESUME_ENABLED=false` to turn it off; waiting issues then move back to `ai:blocked` with a note asking for `/answer`.
