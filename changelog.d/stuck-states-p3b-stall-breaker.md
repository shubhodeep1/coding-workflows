- **Stall recovery no longer closes issues on exhaustion, and a failure-signature breaker stops repeated identical failures (stuck-states P3b, Refs #8291).** When `MAX_STALL_RECOVERIES_PER_ISSUE` is exhausted, both the standalone and the managed stall loops now add `ai:needs-human`, verify it, comment the recovery history and leave the issue and its linked PR open for the unblock judge (`STALL_EXHAUSTED_ESCALATED`), instead of closing both with `ai:closed`. The poller also reads `AI_FAILURE_FINGERPRINT_V1` markers posted by the pipeline's own login and, once the same (phase, fingerprint) repeats `STALL_FINGERPRINT_REPEAT_MAX` (default `2`) times in a row, labels a standalone issue `ai:plan-failed` / `ai:clarify-failed` (other phases, and orchestrator-managed issues, `ai:needs-human`) and posts an `AI_FAILURE_FINGERPRINT_BREAKER_V1` comment (`STALL_FINGERPRINT_BREAKER`), so a failing plan that flips back to `ai:clarification` is no longer retriggered forever. Set `STALL_FINGERPRINT_BREAKER_ENABLED=false` to restore the previous skip-and-close behaviour.
