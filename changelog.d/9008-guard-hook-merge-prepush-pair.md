- **An integration-branch merge conflict on the pre-push gate hook is now settled from its template.** `scripts/review_conflict_prepare.sh` used to run the host-only template merge only for `.claude/hooks/pr_merge_status_guard.py`, so a conflict on `.claude/hooks/prepush_affected_tests.py` failed the resolver closed with `sandbox_path_host_only` on every run (PR #8436, run 42355218108). The merge now runs once for each live/template pair that the script reads at runtime from `PAIRED_LIVE_COPIES`, in registry order, with the same checks, kill switch (`CONFLICT_GUARD_HOOK_TEMPLATE_MERGE_ENABLED`) and `orchestrator/project-*` wait for the integration fingerprint check. The strict expected-failure marker on `test_prepush_hook_integration_sync_conflict_is_resolved_from_template` is gone, and the new test `test_both_paired_hooks_conflicting_are_resolved_in_one_pass` checks that two conflicted paired hooks are both resolved in one pass and committed as one two-parent merge. Refs #8973.
