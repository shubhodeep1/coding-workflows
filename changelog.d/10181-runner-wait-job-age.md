- **The release runner-wait check measures how long a job has waited, not how old a queued run is.** `release_gate_oldest_queued_wait` (`scripts/gh_helpers.sh`) still lists the live queued runs created at least `RELEASE_GATE_MAX_RUNNER_WAIT_MINUTES` ago, then reads the jobs of the oldest 3 of them (`GET repos/<repo>/actions/runs/<id>/jobs?per_page=100&filter=latest`) and answers `outcome=long` only when a job with status `queued` has waited the limit or longer. A run held by a `concurrency:` group (no jobs yet) and a long run whose newest job was just created no longer count, so a held `CI` push run no longer skips the promote cycle or the auto-release with `runner_wait_long` while runners are free. When more than 3 candidate runs exist and none of the 3 read is long, the output line ends with `runs_unread=<n>`, and the `AUTO_RELEASE_RUNNER_WAIT_CHECK` / `PROMOTE_CYCLE_RUNNER_WAIT_CHECK outcome=clear` lines carry it too. A failed jobs read still fails open (`outcome=read_failed`, the release proceeds). Refs #10181.
