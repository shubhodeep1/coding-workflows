- **Plan and clarify failure comments now carry a failure-fingerprint marker, so the failure-signature breaker can trip (Refs #8291).** The poller's breaker (stuck-states P3b) reads `<!-- AI_FAILURE_FINGERPRINT_V1 phase=<p> fp=<fp> run=<id> -->` markers, but nothing wrote them, so a plan or clarify run that kept failing the same way still looped on the stall ladder. The "Comment on issue failure" step of `plan.yml` and `clarify.yml` now appends one marker as the last line of the failure comment it already posts. The fingerprint is a 12-character hash of the phase, the failed step name and the first non-generic error annotation with volatile tokens (digits, SHAs, URLs, temp paths) removed; the step name and error text are never posted. A marker is added only when the job failed (not when it was cancelled) and `STALL_FINGERPRINT_BREAKER_ENABLED` is on (`1`, `true`, `yes` or `on` in any letter case, the same rule the poller uses; the default is `true`). It costs two REST reads on a failed run. Any lookup error posts the comment without a marker, as before. Set `STALL_FINGERPRINT_BREAKER_ENABLED=false` to stop both the markers and the breaker.
