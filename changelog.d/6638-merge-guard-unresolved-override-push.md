- **The merged-PR guard no longer judges a push with an unresolvable Git directory override by the session checkout.** A push such as `GIT_DIR+=<path> git push`, `env -C "$OTHER" git push` or `git --git-dir=$X push` names a repository the guard cannot resolve. Until now the guard checked the session checkout's pull requests instead, so a clean checkout could let through a push that stacks on a merged branch in another repository.

The guard now blocks these pushes with a fixed message that names no paths or remote URLs, and never queries the session checkout's PR history for them. Setting `UNRESOLVED_GIT_OVERRIDE_PUSH_ENABLED=true` in the session environment turns the block into a confirmation prompt; a `UNRESOLVED_GIT_OVERRIDE_PUSH_ENABLED=true` prefix in the command itself has no effect. A push whose directory is uncertain only because of shell control flow (an unresolved `cd`, `pushd`, `&` or `||`) is still checked against the session checkout, which can block, and otherwise asks. `tests/test_pr_merge_status_guard.py` covers both flag states, the control-flow case and the appended `GIT_DIR+=` case.

What this means for operators: such pushes stop with a block message until you rerun them with a literal, resolvable directory, or set `UNRESOLVED_GIT_OVERRIDE_PUSH_ENABLED=true` to be asked instead. Consumer repos get the change on the next `@stable` sync.
