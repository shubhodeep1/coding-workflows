- **The release gate's Phase 4 review wait now says why an inactivity timeout happened.** On the inactivity-timeout path, `scripts/stable_e2e_step_wait_review.sh` still writes `status=timeout` unchanged and now also writes a `timeout_reason` step output: `review_run_never_started` when the watched review run stayed queued, pending, waiting or requested with no started job for the whole wait (an environmental runner or concurrency hold), and `inactivity` otherwise. The check follows the run being watched: after a cancelled run pivots to a successor, only the successor counts, and its jobs are read afresh instead of from the cancelled run's cached jobs. It also prints one `E2E_REVIEW_TIMEOUT_REASON` line with the run id, run status and job id/status pairs. The check reuses the run and job data the loop already fetches, so it adds no GitHub API call. The wall-clock deadline timeout writes no `timeout_reason`; treat a missing value as unknown. `REVIEW_TIMEOUT`, the Phase 3c dispatch and the cleanup cancel block are unchanged. Refs #9418.
