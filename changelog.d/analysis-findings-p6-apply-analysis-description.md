- **Apply-analysis projects check findings first.** The `project_description` that `scripts/apply_analysis_on_main.sh` hands to the orchestrator now makes a per-finding verdict against the current default branch (`applied-candidate`, `already-implemented`, or `rejected` with the reason) the required first step, before any implementation issue is planned; only `applied-candidate` findings get implementation issues, and a project with no `applied-candidate` finding becomes a single PR that deletes the source doc and appends its verdict table to the processing report. The repository guardrails now decide what counts as `applied-candidate`. The title line, scope paragraph, marker comment, log lines, env defaults and API calls are unchanged. Refs #9116.
