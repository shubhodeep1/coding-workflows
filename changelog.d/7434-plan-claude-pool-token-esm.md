- **Planning no longer loses its Claude credential in consumers whose root `package.json` sets `"type": "module"` (#7434).** In such a repository Node loaded the `claude-pool-token` action's CommonJS `main.js` and `post.js` as ES modules, so they crashed on `require`, no account pool was written, and every plan run ended with `AI_ENGINE_FALLBACK_REFUSED role=PLAN reason=no_credential` (`shubhodeep1/digital_pa#145`, `shubhodeep1/hylifegroup.com#96`). `plan.yml` now has a "Pin claude-pool-token action module type" step, run before the write-guard snapshot, that writes `{"type":"commonjs"}` as `package.json` into the action directory of the support checkout. It never overwrites an existing `package.json` or follows a symlink, logs `CLAUDE_POOL_MODULE_PIN outcome=written|skip reason=present|action_dir_unavailable`, and does nothing once the action ships its own `package.json`. Only the plan job is covered: clarify, implement, review, the poller judges and the other Claude roles still fail the same way in those consumers until a separately scoped issue commits `.github/actions/claude-pool-token/package.json`. The refusal of `no_credential` is unchanged. After this reaches a stable release and the consumer syncs, a stuck issue plans again on `/answer` or the stall poller's next retry.
