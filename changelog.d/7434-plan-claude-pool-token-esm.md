- **Planning no longer loses its Claude credential in consumers whose root `package.json` sets `"type": "module"` (#7434).** In such a repository Node loaded the `claude-pool-token` action's CommonJS `main.js` and `post.js` as ES modules, so they crashed on `require`, no account pool was written, and every plan run ended with `AI_ENGINE_FALLBACK_REFUSED role=PLAN reason=no_credential` (`shubhodeep1/digital_pa#145`). `plan.yml` now has a "Pin claude-pool-token action module type" step, run before the write-guard snapshot, that writes `{"type":"commonjs"}` as `package.json` into the action directory of the support checkout (#7476 adds the same step to clarify). It never overwrites an existing `package.json` or follows a symlink, and logs `CLAUDE_POOL_MODULE_PIN outcome=written|skip|failed reason=present|action_dir_unavailable|write_failed`. The action itself now ships `package.json` (#7432), which fixes every Claude role, so the step normally logs `reason=present` and only writes for a staged action copy that lacks the file. The refusal of `no_credential` is unchanged. After this reaches a stable release and the consumer syncs, a stuck issue plans again on `/answer` or the stall poller's next retry.
