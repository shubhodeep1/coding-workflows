- **Synced-file security reports now skip retired files by name and accept common category spellings.** A finding on a file listed in the release's `workflow-templates/retired_files.txt` is skipped with `WORKFLOW_HEAL skip reason=retired_file` instead of failing every time at `skip reason=scope_unresolved` with a Telegram WARNING. Categories such as `A01: Broken Access Control`, `A03 Injection` or `STRIDE: Tampering` are no longer dropped.

Before, retired files passed the managed-path check in `scripts/workflow_failure_heal_intake.sh` but mapped to no source path in coding-workflows, so no heal issue could ever open for them and each report raised a warning. The consumer's own `@stable` sync deletes byte-identical retired files, so the intake now skips them before the budget decision and the skip does not raise the alert level. `normalize_synced_security_category` in `scripts/workflow_failure_heal.py` now accepts `A01`..`A10` with or without the `:2021` year, an optional `STRIDE:` prefix, and the first term of a slash-separated list. It still rejects other OWASP years such as `A01:2017`, whose numbering differs, and it still publishes only the canonical name.

What this means for operators: synced-file security alerts no longer fire for retired files, and findings the audit labels in a slightly different format reach coding-workflows instead of being counted as `dropped`.
