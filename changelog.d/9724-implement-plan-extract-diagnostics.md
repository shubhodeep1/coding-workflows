- **Implement now says why it found no approved plan.** When the "Extract implementation plan" step cannot find a trusted plan comment posted before the triggering `/approved`, it still fails as before, and now also prints one `::error::IMPLEMENT_PLAN_NOT_FOUND reason=<token>` line plus a `::warning::IMPLEMENT_PLAN_CANDIDATE` line for every plan-like comment it saw.

Implement run 44292180289 (issue #9718) failed with only `Process completed with exit code 1.`, and the heal intake could not tell whether the plan comment had been deleted, edited, posted after the approval, or written by an untrusted author. The reason token now names which: `approval_not_found`, `no_plan_comment`, `plan_after_approval`, `plan_author_untrusted` or `plan_body_mismatch`. Candidate lines, one for every such comment, give each comment's id, time, author, author type and association, and whether it still has the `Implementation plan` heading or only the `<!-- ai:plan-proposal:v1 -->` marker. The `plan_candidates=<n>` count on the error line equals the number of candidate lines, and the error line comes after them, so it stays in workflow-heal evidence even when the heal log filter trims an oversized log from the front. A comment that was edited to remove both the heading and the marker gets no candidate line, so a missing line alone does not prove the comment was deleted. If the diagnostic query itself fails, a `::warning::IMPLEMENT_PLAN_DIAGNOSTICS_UNAVAILABLE reason=jq_failed` line says so. Comment bodies are never printed. Which plan is accepted, and the step's exit status, are unchanged. No GitHub API calls are added.

What this means for consumer repos: after the next `@stable` sync, a failed plan lookup in implement names its cause in the job log and in workflow-heal evidence. Because the new `::error::` line becomes this failure's error signature, the workflow-heal fingerprint for a plan-lookup failure changes from the one built on `Process completed with exit code 1.`, so a recurrence starts a new heal lineage rather than joining an existing one. Nothing to configure.
