- **CI `static-checks` runs its validation self-test modules in concurrent lanes.** `static-checks` took 14m21s of its 15-minute timeout on main (run 43139141266), so the "Validation self-test unit tests" step in `.github/workflows/ci.yml` now runs its 22 module commands across four background lanes instead of one after another. Lane 0 runs `tests/test_security_audit_workflow_contract.py` alone and the other 21 commands go round-robin to lanes 1-3. Each command keeps its exact earlier invocation, and the job id, step name and `timeout-minutes` are unchanged. The step fails closed: every lane is reaped before any result is judged, and a missing or non-numeric exit code or an unknown command kind counts as a failure. A failing module no longer stops the later ones; the step reports every failure at the end. New `CI_SUBTEST_START`/`CI_SUBTEST_END`/`CI_SUBTEST_HEARTBEAT` lines time each module, and module output is printed with a `| ` prefix. The expected saving is an estimate, not a measurement. `ValidationSelftestConcurrencyContractTest` in `tests/test_ci_poll_test_sharding.py` pins the command table and lane layout and runs the real step body against stub modules. Refs #9362.
