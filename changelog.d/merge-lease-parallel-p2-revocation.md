- **The merge lease no longer stays with a PR that cannot merge, and is granted only to a PR that can.** The merge-train tick now revokes the lease from a holder that is a draft, has `[skip ai]` in its title, has a pipeline `ai-review/head-gate` failure, has failed final CI, or has had no CI running on its head for `MERGE_LEASE_IDLE_MINUTES` (default 60) since its last lease write. A holder whose head has no head-gate yet (its review is re-running after a branch update) keeps the lease for the same window. When the lease is free, the tick checks waiters in queue order (up to 10 per base per tick) and grants it to the first one that is eligible; an ineligible waiter loses its `ai:merge-lease-wait` label and the next one is tried. A PR released for being expired or ineligible is recorded in the lease record as a `skip=<pr>:<head>` line and is passed over, by the tick and by the update-mode gate, until its head SHA changes. When no other waiter is left, the tick removes its `ai:merge-lease-wait` label so the review sweep picks it up again, and the update-mode gate lets it acquire as the only caller. CI runs that were only cancelled do not count as a final-CI failure, and `MERGE_LEASE_IDLE_MINUTES=0` turns off only the idle test (a holder with no head-gate is still revoked after 60 minutes).

`MERGE_LEASE_REVOKE_ENABLED=false` turns all of this off and writes the lease record in the old format; `MERGE_LEASE_IDLE_MINUTES=0` turns off the idle test. Both defaults live in `scripts/pr_checks_lib.sh`. Every read failure counts as eligible (fail-open), so a GitHub hiccup never revokes a lease or blocks a grant. Records written before this change, and records with the new `skip=` lines, are read the same way by old and new code. New `MERGE_LEASE` tokens: `outcome=skipped` and the reasons `revoked_draft`, `revoked_skip_ai`, `revoked_no_head_gate`, `revoked_final_ci_failed`, `revoked_idle`, `skip_head_unchanged`, `draft`, `skip_ai`, `no_head_gate`, `final_ci_failed` and `no_eligible_waiter`; `MERGE_LEASE_METRIC` gains `event=skipped`.

What this means for consumer repos: after the next `@stable` sync, a stuck lease holder hands the lease on within one poll tick instead of holding it until its TTL (240 minutes) expires. Nothing needs to be done; set the repo variable `MERGE_LEASE_REVOKE_ENABLED=false` to keep the old behaviour.
