- **Review findings the autofix editor cannot reach no longer keep the loop running.** After consolidation, `scripts/review_issue_ledger.sh` checks each finding's cited path against the editor's own write rules: the `review_editor` write guard (`.git/**`, and `.github/workflows/**` unless `ALLOW_WORKFLOW_EDITS=true`), the consumer protected paths `scripts/review_commit_changes.sh` unstages, and review-sandbox admission (new read-only `scripts/review_untrusted_workspace.py editor-reachable` subcommand built on `allowed()`). A match is recorded once as the sticky ledger status `unreachable`; `scripts/review_apply_fixes.sh` opens one `ai:clarification` follow-up issue per PR (linked with `Refs`, never an auto-close keyword) or comments on it, with at most one call per round and the number kept in the ledger header. Non-security findings are replaced by `UNREACHABLE ISSUE` stubs, so they start no fix round, and are listed under their own heading in the editor-summary comment; security findings stay in the editor input with `UNREACHABLE: security-hold` and keep the PR blocked. A finding that names a failing check on the PR head is never unreachable. Cancelled and timed-out check-runs are listed as `no_result[]` in reviewer/editor context instead of as failures (the merge probe and `check_failure_triage.sh` are unchanged). The review-blocked judge sees `prior_decision=unreachable-followup` with `followup=` and `security_hold=`, also when `REVIEW_LEDGER_REREVIEW_ENABLED` is off, and an unreachable security finding keeps the head from being marked `review-autofix-clean` and stops `scripts/review_enable_auto_merge.sh` from enabling auto-merge or adding merge labels (it also withdraws an auto-merge armed earlier) and the review-blocked judge from merging through any merge path (`reason=unreachable_security_hold`, read from the ledger, so it also holds after a same-head partial resume, where the unreachable hand-off files are now rebuilt from the ledger and the follow-up issue still carries the reviewer text). A follow-up issue whose create output could not be parsed is found again by its title and marker instead of being opened a second time. Kill switch `REVIEW_UNREACHABLE_FOLLOWUP_ENABLED` (default `true`). Refs #10057.
