- **Check-failure triage and review autofix now see the failing step in a job log, not the post-job teardown output after it.** In `shubhodeep1/fun-token-multi-chain`, three triage issues were filed for one CI failure (a contract over the EIP-170 size limit) and none showed the error. The 16 KiB `failed[i].log_tail` held only the Postgres service container's teardown dump, and the triage traceback comment started at the first Postgres `ERROR:` line, which came from tests that expect the database to reject a write. `scripts/collect_pr_check_runs_context.py` now scans up to 256 KiB from the end of the log, with the same three requests, and ends the window at the first `##[error]` line when there is one. `scripts/check_triage_resolution.py` now picks its excerpt in this order: a test-failure line, then the step `##[error]` line with the lines before it, then a Python traceback, then the old patterns. It also names the chosen tier in an `Excerpt anchor` line. Both cut lines over 2,000 characters, so one huge line cannot crowd out the cause line. The triage gate redacts secrets before it cuts any line. Logs without a `##[error]` line get the same tail as before, plus a `log_tail_anchor: end_of_log` line. Refs #8799.
