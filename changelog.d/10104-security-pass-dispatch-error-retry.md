- **The single-issue security pass now records why a security-audit dispatch failed, and retries a transient failure in the same run.**

Before this change, `scripts/review_single_issue_security_pass.sh` discarded the error from the dispatch command. It then posted "could not be dispatched" and waited for the next review run. Now each failed attempt prints a filtered `::warning::` excerpt of up to 200 characters, with tokens removed, and classifies the failure as `rate_limited`, `server_error`, `network`, `rejected`, `auth` or `other`. A `rate_limited`, `server_error` or `network` failure is retried up to `SECURITY_PASS_DISPATCH_RETRIES` times (default `2`), waiting `SECURITY_PASS_DISPATCH_RETRY_DELAY_SECS` seconds (default `20`) before each retry. The "could not be dispatched" comment names the class. The note about an outdated consumer `ai-security-audit.yml` wrapper now appears only for `rejected`. Failed dispatches still count toward cycles and head attempts as before. Refs #10017
