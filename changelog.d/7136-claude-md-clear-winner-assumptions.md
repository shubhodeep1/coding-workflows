- **Interactive Claude Code sessions stop asking questions that have an obvious answer.** CLAUDE.md §2 gains a "Clear-Winner Assumptions" rule: a decision with one clearly correct option is taken and listed under an **Assumed** heading instead of being asked.

Before this change §0 and §2 sent every decision to the user as a `Q1: A` question, even when one option was required by repo convention or followed from an earlier answer, because the format marks one option `(RECOMMENDED)` on every question. Now a decision counts as a clear winner only when one option is clearly correct, it is a cheap-to-undo change on the working branch, it is not about what to build or a tradeoff, and nothing else in CLAUDE.md makes it ask-first (§6 renames, §10 DB contracts, §12.D, §18.A/§18.D, §22.B, §23.C, §24.D, §29.B, data deletion). Assumptions keep the Q-ID numbering, so `Q3: B` still overrides one, and they appear before any work starts. When no open questions remain, the session gives the Assumed list at the top of its reply and proceeds. Consumer repos receive the rule with the root `CLAUDE.md` at the next `@stable` sync of `update_workflows.yml`.

What this means for people driving interactive sessions: fewer question rounds for decisions with one sensible answer, and every such choice is still shown with an override before work begins. The unattended pipelines read `unattended_system_instructions.md` and are unaffected.
