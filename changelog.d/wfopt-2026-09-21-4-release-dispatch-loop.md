- **Both stable release jobs now check every `consumer_repos.json` entry before they send `coding-workflows-stable-released`, so a malformed entry can no longer turn into extra dispatch targets.** Before, `mark-stable.yml` and `test-and-mark-stable.yml` looped over the registry with an unquoted `for REPO in $REPOS`, so an entry with a space split into two targets and an entry with `*` expanded against files in the checkout.

Each entry is now read on its own line and must be a plain `owner/repo`, with no `.` or `..` segment. Anything else, including a non-string entry or one with an embedded newline, is skipped with `::warning::Skipping malformed consumer registry entry #<n>`; the rejected value is never printed. The two steps are now identical apart from comments: `test-and-mark-stable.yml` sources `scripts/gh_helpers.sh` as `mark-stable.yml` already did, and both send the dispatch through `GH_RETRY_IDEMPOTENT=true gh_retry`, so a 5xx or network error is retried instead of failing on the first attempt. A repeated event is harmless, because the consumer updater always renders the current `stable` commit and ignores the payload SHA. The payload fields and the fail-open warning for a consumer that rejects the dispatch are unchanged.

What this means for consumers: nothing changes for a valid registry, and a transient API error no longer drops a release notification.
