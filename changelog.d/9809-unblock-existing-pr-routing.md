- **Unblock and stall recovery now resume an issue on its open implementation PR.** When a blocked issue already has an open implementation PR, the unblock judge's reset posts its note on that PR, dispatches the PR's review and removes the issue's stop label. Stall recovery's `auto_approve` and `retrigger_implement` actions dispatch that PR's review. Neither posts `/approved` any more, because `implement.yml` refuses it with `existing_pr` while the PR is open, so the issue used to loop back to `needs-human`.

The judge finds the PR with one GraphQL read (`unblock_actions.py impl-pr`). It accepts an open `ai/issue-<n>` head PR in the same repository, or exactly one open same-repository PR, written by the pipeline or a repository member, whose body closes the issue. A fork PR or an outside author never qualifies, and a failed or ambiguous lookup keeps today's reset. Switch `UNBLOCK_EXISTING_PR_ROUTING_ENABLED` (default `true` in every script and workflow that reads it); `false` restores `/approved`. Refs #9733.
