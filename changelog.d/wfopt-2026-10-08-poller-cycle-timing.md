- **The orchestrator poller now logs a per-cycle timing summary.** `scripts/orchestrate_poll_process.sh` prints exactly one `ORCH_POLL_CYCLE_SUMMARY` line per run from its EXIT trap, with the wall-clock milliseconds, the number of tracking projects seen and processed, the milliseconds spent in the script's existing sleep sites, the exit code and a terminal reason (`completed`, `no_projects` or `error`), plus one `ORCH_POLL_PROJECT_TIMING tracking_issue=<n> elapsed_ms=<n>` line per project processed. The wave-dispatch gate's temporary EXIT trap now chains to the same handler instead of replacing it. Values are integers, enum tokens or `unknown`; the record adds no GitHub API calls, no new or longer sleeps, never changes the exit code and changes no decision, dispatch or cadence. This gives the Speed #2 analysis in analysis/workflow-optimization-2026-10-08.md the split it needs before any cadence change. Refs #9099.
