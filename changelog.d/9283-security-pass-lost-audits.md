- **The single-issue security pass no longer gets stuck on audits that were cancelled before they ran.** Past the cycle cap, a pending head attempt whose audit run is provably lost (every run for the PR in its window completed at least 10 minutes ago without a result) no longer counts toward `SECURITY_PASS_EXHAUSTED_HEAD_AUDIT_ATTEMPTS`, up to `SECURITY_PASS_LOST_AUDIT_RETRIES` (new, default `2`; `0` restores the old counting) per head. The one audit-run listing now reaches back to the oldest post-cap pending marker, and anything it cannot prove (failed, truncated or empty listing) still counts the attempt. The review-blocked judge's CRITICAL alert for `exhausted_without_completed_audit` now pages once per head (marker `rb-judge-security-hold:v1`) and is DEBUG on later rounds. Refs #9283, #9942.
