- **Operator steps the pipeline can see are done now tick themselves every day, and an empty operator-step issue closes.** Refs #9650 (plan `docs/plans/pipeline-human-wait-elimination-plan.md`, Phase 9; issue #10118).

  - The daily 06:00 run of `workflow-log-analysis.yml` (job `collect-logs`) runs a new step, "Tick observable operator steps" (`scripts/operator_step_daily_tick.sh`), which calls `scripts/operator_step_issue.py tick --observable` with `GH_PAT`.
  - An `ai:operator-step` entry with no source commit is ticked when every unticked step is one the pipeline can check and the check passes: the pull requests a step names (`stable` contains `#N`) are merged and in the `stable` tag; the repository allows auto-merge; a workflow that requires the named secret succeeded in the last 7 days (a review run for `GH_PAT`; a review or security-audit run for `OPENROUTER_API_KEY`, since the security audit runs without `GH_PAT`); or the step applies only when a command is used. A step naming anything else (another variable or secret, rotation, scopes or permissions), or a credential step that hands the secret to someone or somewhere else (a vendor, a consumer or other repository, `--repo`/`-R` naming another repository or a value that is not a literal `OWNER/REPO`, including the attached `-RVALUE` form, an organisation, environment, Dependabot, Codespaces or user secret), keeps the whole entry open. When no unticked step is left, the issue is closed as completed, with the same safeguards the poller's close already uses.
  - The nightly promote cycle's tick is unchanged.
  - Switch: `OPERATOR_STEP_DAILY_TICK_ENABLED` (default `true`). Set it to `false` to restore today's behaviour.

What this means for consumer repos: nothing changes; the daily step runs only in this repository's `workflow-log-analysis.yml`.
