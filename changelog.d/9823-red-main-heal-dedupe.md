- **A red default branch keeps one heal issue, and check-failure triage no longer routes a fix to a branch that lacks the failing files.** The heal intake gives every failed `push` CI run on the default branch a red-main group key (workflow name, failing job, branch). Before any fingerprint match it looks for an open `ai:workflow-heal` issue carrying `<!-- workflow-failure-heal:red-main-group=<key> -->` and records the new head and run there as an occurrence, so a red `main` whose error text changes no longer opens a second heal issue. New red-main heal issues carry the marker. Check-failure triage, with `CHECK_TRIAGE_PR_BRANCH_ROUTING_ENABLED` on, drops the `Target branch:` line when none of the failing files exist on the PR head branch but all exist on the default branch; the check is a local `git cat-file -e` with no API call, against a depth-1 default-branch checkout the triage job takes only while that routing is on, and the base-branch gate the PR-branch route skipped runs before such a fallback is filed. Rollback: `WORKFLOW_HEAL_RED_MAIN_GROUPING_ENABLED=false` and `CHECK_TRIAGE_TARGET_FILES_GUARD_ENABLED=false` (both default `true`). Refs #9823.
