- **A needs-human parking now pages at most once, and the attempt is recorded on the item (Refs #8291).** The CRITICAL alert for an item parked in the needs-human digest used to be sent whenever one digest read said the item was newly parked. Nothing recorded the attempt, so two judge runs for the same item could both page. Before any Telegram call, the unblock judge and the poller's project park now post a claim comment on the item (`<!-- ai:unblock-park-alert:v1 item=N parked=<stamp|overflow> state=attempted -->`). Only the earliest claim by the pipeline login sends, once and with no retry, and a successful send records the Telegram message id in that comment (`state=confirmed message=ID`). When Telegram is not configured (no token, no chat ID, or `ALERT_MSG_LEVEL=SILENT`) or the project is a smoke fixture, no claim is made, so the next park of the item can still page. A failed claim write or re-read never pages, and the digest stays the durable notice. `needs-human park` also prints `parking`, and there are two new subcommands, `needs-human alert-claim` and `needs-human alert-confirm`. Log prefix `NEEDS_HUMAN_ALERT`. An item parked before this change has no claim comment, so the first time it is parked again it can be paged one more time; after that its claim keeps it to one page. Nothing needs to be run by hand.
