- Merge gate: a failed `review / gate` check-run on a PR head no longer blocks auto-merge forever once a later review has passed that same commit. When the newest `review / gate` run on the head failed (for example rate-limited in the PR's first review run, as on PR #9168) and the head carries an `ai-review/head-gate` commit status of `success` created after that failure for the exact head SHA, the shared checks gate stops counting that check-run as blocking and logs `PR_CHECKS_GATE_SUPERSEDED ... outcome=superseded`. Every other case keeps blocking and logs `outcome=skip reason=<token>`; the extra commit-statuses read happens only when the gate failed. Refs #9212.
