- **The daily promote cycle no longer waits forever on a human-latched tracking issue (stuck-states P4, Refs #8291).** `scripts/promote_main_cycle.sh` still skips with `PROMOTE_CYCLE_SKIPPED reason=cycle_in_flight` while an `ai:comprehensive-test-pending` tracking issue is open, but an issue carrying `ai:harness-broken`, `ai:validation-failed`, `ai:security-pass-failed`, `ai:blocked` or `ai:needs-human` whose newest latch label event is at least `PROMOTE_CYCLE_HOLD_MAX_HOURS` (default `24`) old stops holding: the tick logs `PROMOTE_CYCLE_HOLD_RELEASED`, sends a Telegram WARNING and continues with the remaining guards. Latch ages come from one batched GraphQL read made only when a latch label is present; any doubtful history keeps the hold. While the `promote-cycle-frozen` tag still freezes `promote-candidate`, an issue past the cap keeps holding, so a new cycle never proves the parked cycle's old pipeline code. A tick that released an issue runs the cycle unpinned, because the parked cycle may still own the `promote-cycle-frozen` tag. Set `PROMOTE_CYCLE_HOLD_RELEASE_ENABLED=false` to restore the unbounded hold.
