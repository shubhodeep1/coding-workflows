- **Per-reviewer finding counts in review runs and the workflow analysis report.** The existing "Write review findings record" step (`scripts/review_findings_record.py`) now prints one `REVIEWER_FINDINGS pr=<n> round=<r> reviewer=<model> raised=<a> lone=<b> lone_rejected=<c> lone_accepted=<d> shared=<e>` line per reviewer that ran, counted from the consolidator's `FLAGGED_BY` field and the editor summary, or `outcome=unavailable reason=<consolidator_disabled|consolidator_missing|flagged_by_missing>` when the counts cannot be trusted. The workflow log collector parses the lines from the log archives it already downloads (trusted-origin runs only), `analysis_context.json` carries a per-reviewer `reviewer_findings` aggregate, and the analysis run appends a code-built "Reviewer Findings" table to `analysis/workflow-optimization-<date>.md`, with percentages only for reviewers with at least 20 lone findings in the window. Measurement only: no review decision changes, and there are no new API calls, jobs, workflows or settings (Refs #10058).
