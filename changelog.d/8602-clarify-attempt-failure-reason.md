- **A failed clarify attempt now prints why it failed on a line the workflow failure heal keeps.** Before, the heal report for a clarify failure could not name the cause, so the diagnosis came back inconclusive.

On shubhodeep1/btc_sweeper#248 clarify failed three times with `Claude clarify failed after 3 attempts.`, and the heal intake classified it `inconclusive`. The intake's log filter drops the attempt loop's `##[warning]` lines and the Claude runner's `CLAUDE_POOL run … outcome= reason=` line, which carry the cause. The "Run Codex" step of `clarify.yml` now copies the Claude runner's stderr to a runtime file (the job log still shows it live). After each failed or empty attempt it prints one `CLARIFY_ENGINE_ATTEMPT_FAILED engine= attempt= max_attempts= kind=nonzero_exit|empty_output exit_code= pool_role= pool_account= pool_outcome= pool_reason= pool_exit_code=` line. The pool fields come from the last `CLAUDE_POOL run` line of that attempt: only those five keys are kept, each value is limited to letters, digits, `_`, `.` and `-` (64 characters at most), and a field with no value reads `unknown`, as do all of them after a fallback to Codex. The heal filter already keeps `*_FAILED` lines, so the next heal report names the reason.

Exit codes, retries, sleeps and the existing warning and error lines are unchanged. The heal filter itself (`scripts/workflow_failure_heal.py`) is not changed here.
