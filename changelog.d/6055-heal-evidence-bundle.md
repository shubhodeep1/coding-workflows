- **Workflow-heal issues now carry the failing runs' logs, artifacts and provenance to the agents that fix them.** Clarify, plan and implement add an evidence folder for every trusted `ai:workflow-heal` issue, and the heal intake reads review/autofix runs it used to skip.

The heal pipeline's agents cannot open GitHub Actions logs: the web UI needs a sign-in and the clarify sandbox has no token. A survey of the 51 heal issues opened between 2026-09-21 and 2026-10-04 found most diagnoses resting on guesses. Issues #4412, #4416, #4487 and #6055 blocked on "logs are sign-in only", and the intake had read no log at all for 8 review/autofix reports (`runs=0`), because those review runs conclude success. A trusted step in `clarify.yml`, `plan.yml` and `implement.yml` now runs `scripts/workflow_failure_heal_evidence.py collect` before the agent. It writes step-sliced job logs, the diagnostic files of the review artifacts, the source PR's state, the failing head against `main` and the target branch, the earlier heals of the same lineage with whether each fix reached `main`, the other runs on the failing head, and the GitHub rate limit and OpenRouter key balance. Clarify's prompt gets `=== WORKFLOW HEAL EVIDENCE (UNTRUSTED) ===` and its sandbox a read-only copy at `/evidence`. Plan and implement, whose editors have network access, get only bounded structured fields (run, job and step identities, conclusions, exit codes, crash file and line, and SHA-256 fingerprints of step names and error signatures), and implement rejects a heal commit outside the issue's or plan's `files_touched` allowlist even when `ALLOW_OUT_OF_SCOPE_FILES` is set. Review/autofix heals for pull requests in coding-workflows now target the branch the review's support scripts came from (`main` or `stable`) instead of the pull request's head branch, which had stranded the same fix twice (#4478, #4585) on branches that never reached `main`.

What this means for operators: heal issues should stop blocking on missing logs, and a heal fix for a review/autofix failure in coding-workflows now lands where the failing code lives. The intake's fingerprints are unchanged, so open lineages continue. Nothing new needs configuring; every part of the evidence step fails open and records what it skipped in `manifest.json`. The plan and implement editors now run without git credentials, and that part fails closed: if the editor changed a checkout's origin, push URL, URL rewrites, proxy or credential helper, the step stops instead of putting the token back.

### For contributors

Artifact members in the heal evidence folder now contain only bounded, allowlisted diagnostic lines. Environment assignments and credential-like key/value pairs are dropped before writing, and legacy raw artifact copies are removed when a run is re-collected (including on a low-rate skip); job-log slicing remains unchanged.

`slice-log` replaces only what the diagnosis prompt reads; `filter_log` still feeds the fingerprint. Run links come only from leading structured `runs=` markers in the issue body and occurrence comments by the intake account, limited to the issue's and the source repository. Heal issue bodies and occurrence comments must be authored and edited only by the intake account; every run, including same-repo runs, must match its reported repository, head SHA and workflow name, plus the PR or head branch (a run linked to a different PR than the source pull request is rejected, and runs for a source issue are bound by branch), and must have failed (a successful or unfinished run counts only for its review job). Unverifiable runs are skipped without blocking other evidence. Cross-repository reads require that source to be registered in `.github/ai/consumer_repos.json`; an absent registry skips them. Each stage collects its own evidence; nothing is cached between stages, because Actions caches saved on the default branch are readable by pull-request runs, and the gate purges any `heal-evidence-*` caches best-effort. `scripts/editor_git_credentials.sh hide` strips the origin URL's credentials and the `http.<url>.extraheader` entries before each editor run and refuses (exit 1) on a pushurl, URL rewrite, proxy, credential helper, include directive or untrusted origin. `restore` checks every checkout against its trusted repository (`GITHUB_REPOSITORY` for the workspace, `shubhodeep1/coding-workflows` for the support checkouts) before injecting any token, and scopes the restored header to the origin URL. A `script_ref` equal to the pull request's head SHA still targets the pull request's branch; otherwise a SHA contained by both `stable` and `main` targets `stable`, whose hotfix is forwarded to `main`. A vanished support branch also falls back to `stable` if it exists. Log prefix: `WORKFLOW_HEAL_EVIDENCE`. Tests: `tests/test_workflow_failure_heal_evidence.py`, `tests/test_heal_evidence_editor_isolation.py`, and the new targeting and review-job cases in `tests/test_workflow_failure_heal.py`.
