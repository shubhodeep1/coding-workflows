- Hourly alert triage (alert triage Phase 2, Refs #9394): the new `Alert Triage` workflow reads the alerts stored on `ai/alert-inbox`, groups repeats by fingerprint, asks the new read-only `ALERT_TRIAGE` engine role for one JSON diagnosis per new group, and routes it: noise and environmental alerts are marked done, `healable` ones go to the workflow-failure heal as the new `alert_triage` report kind (accepted only from this repository's own triage run, labelled `ai:alert-triage`), pipeline-blocking ones go to `alert-self-fix.yml` when `ALERT_TRIAGE_SELF_FIX_ENABLED` is on, and anything unsure is escalated once on Telegram. Off by default (`ALERT_TRIAGE_ENABLED=false`) and dry run by default (`ALERT_TRIAGE_DRY_RUN=true`); consumer repositories see no change. Adds the `ALERT_TRIAGE` log prefix and `HEAL_ALERT_TRIAGE_KIND_ENABLED`.
