<!-- changelog: fixed -->
- **Dependabot no longer opens bump PRs against the managed wrappers.** The `@stable` sync now adds the wrappers it owns to `exclude-paths` in the consumer's own root `github-actions` entries in `.github/dependabot.yml` (or `.github/dependabot.yaml`).

Dependabot `github_actions` PRs against files such as `.github/workflows/ai-review.yml` failed `coding-workflows/workflow-integrity` by design ("Managed wrappers differ from release"), could not be rebased on the protected branch, and piled up until closed by hand (shubhodeep1/mongo-explorer#68). The new step "Sync Dependabot exclusions for managed wrappers" in `update_workflows.yml` runs `scripts/sync_dependabot_exclusions.py` from the release checkout. It excludes the same set the integrity check compares: the `WORKFLOW_PROFILE` profile entries, `ai-workflow-integrity.yml`, and `ai-update-workflows.yml` when the consumer has it. It never creates the file or a `github-actions` entry, keeps every other key, item and comment as written, rebuilds only `.github/workflows/<template>` items so the list follows profile changes, and leaves a layout it cannot edit safely untouched with a `DEPENDABOT_EXCLUDE_SYNC outcome=skipped` line. The signed sync manifest now allows both Dependabot config paths, and the PR-delivery `verify` job reproduces the edit on the PR's parent tree. Both jobs run the helper only when the release's attested `release-manifest.v1.json` lists it. coding-workflows itself now has a `.github/dependabot.yml` (`github-actions`, `directory: "/"`, weekly). It keeps the action pins in this repository's own `.github/workflows/` current; Dependabot does not scan `workflow-templates/*.yml`, so the pins in the wrapper templates that consumers receive still need a separate bump.

Activation: `scripts/release_manifest.py` lists the helper as an optional `SURFACE_RULES` file rule, so releases built from this change on attest it and the next `@stable` sync applies the exclusions. A release whose manifest does not attest the helper (any release cut before this change), and every run with `UPDATER_VERIFY_RELEASE_MANIFEST=false`, logs `DEPENDABOT_EXCLUDE_SYNC outcome=skipped reason=helper_unattested` and changes nothing.

What this means for consumer repos: from the first `@stable` sync of a release that attests the helper, a consumer with a root `github-actions` Dependabot entry gets a one-time edit of its Dependabot config, and Dependabot stops proposing bumps for the managed wrappers. A consumer without that entry sees no change. Bump PRs that are already open are not closed. `exclude-paths` items of the form `.github/workflows/<template>` (any top-level `workflow-templates/*.yml` name) are owned by the sync: an item naming a template outside the consumer's current profile is removed, so a consumer that wants Dependabot to skip such a wrapper should exclude it with a glob or another path form.
