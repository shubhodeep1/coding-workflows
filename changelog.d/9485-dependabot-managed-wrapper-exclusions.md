- **Dependabot no longer opens bump PRs against the managed wrappers.** The `@stable` sync now adds the wrappers it owns to `exclude-paths` in the consumer's own root `github-actions` entries in `.github/dependabot.yml` (or `.github/dependabot.yaml`).

Dependabot `github_actions` PRs against files such as `.github/workflows/ai-review.yml` failed `coding-workflows/workflow-integrity` by design ("Managed wrappers differ from release"), could not be rebased on the protected branch, and piled up until closed by hand (shubhodeep1/mongo-explorer#68). The new step "Sync Dependabot exclusions for managed wrappers" in `update_workflows.yml` runs `scripts/sync_dependabot_exclusions.py` from the release checkout. It excludes the same set the integrity check compares: the `WORKFLOW_PROFILE` profile entries, `ai-workflow-integrity.yml`, and `ai-update-workflows.yml` when the consumer has it. It never creates the file or a `github-actions` entry, keeps every other key, item and comment as written, rebuilds only `.github/workflows/<template>` items so the list follows profile changes, and leaves a layout it cannot edit safely untouched with a `DEPENDABOT_EXCLUDE_SYNC outcome=skipped` line. The signed sync manifest now allows both Dependabot config paths, and the PR-delivery `verify` job reproduces the edit on the PR's parent tree. Both jobs run the helper only when the release's attested `release-manifest.v1.json` lists it. coding-workflows itself now has a `.github/dependabot.yml` (`github-actions`, `directory: "/"`, weekly), so action bumps reach consumers through `@stable` releases.

Activation: `scripts/release_manifest.py` does not list the helper yet, so a consumer that verifies the release manifest (the default, `UPDATER_VERIFY_RELEASE_MANIFEST` unset or `true`) logs `DEPENDABOT_EXCLUDE_SYNC outcome=skipped reason=helper_unattested` and nothing changes until a release attests it; adding `scripts/sync_dependabot_exclusions.py` to that file's `SURFACE_RULES` is the follow-up that switches it on.

What this means for consumer repos: once the helper is active, a consumer with a root `github-actions` Dependabot entry gets a one-time edit of its Dependabot config, and Dependabot stops proposing bumps for the managed wrappers. A consumer without that entry sees no change. Bump PRs that are already open are not closed.
