- **A clean review now clears a stale `ai:review-blocked` label from the PR.** The identical-failure cap labels the PR itself, and no review path removed the label again, so a PR capped by a harness failure (for example the Python 3.14 `render_prompt.py` crash) kept it after the harness fix and a clean re-review (PR #9218, PR #9229). After the editor summary posts its `review-autofix-clean:v1` marker, `scripts/review_autofix_step_post_editor_summary.sh` makes one GraphQL read and removes `ai:review-blocked` when the newest trusted `review-autofix-failure-cap:v1` marker names a different head or review-support SHA. A label with no trusted cap marker (the review-blocked judge or a human) is kept, and any lookup or DELETE failure keeps the label and logs `REVIEW_BLOCKED_STALE_CLEAR outcome=error` without failing the step. Refs #9369.
