- **A regression test now locks the conflict resolver's pairing of the pre-push gate hook with its template.** When an integration-sync merge leaves both `.claude/hooks/prepush_affected_tests.py` and its `workflow-templates/` twin unmerged with identical index stages, the resolver merges the template and the runner copies it byte for byte onto the live hook, which stays outside the sandbox.

`PAIRED_LIVE_COPIES` in `scripts/review_untrusted_workspace.py` now lists this hook next to `pr_merge_status_guard.py`, and `test_prepush_hook_pair_is_listed_in_paired_live_report` (`tests/test_review_conflict_resolve_sandbox_only.py`) is an ordinary regression test that fails if the pair is dropped or remapped. The guard tests still check that the live hook is never admitted to the sandbox and never taken from the base branch on `orchestrator/project-*` or with `IS_INTEGRATION_SYNC=true`. The host-only template merge in `scripts/review_conflict_prepare.sh` (`_conflict_prepare_guard_hook_template_merge`) still handles only `pr_merge_status_guard.py`, and is out of scope for this heal issue. The strict xfail `test_prepush_hook_integration_sync_conflict_is_resolved_from_template` (`tests/test_conflict_guard_hook_template_merge.py`) marks that gap; once the merge is generalised, strict mode fails CI until the marker is removed. Until then, a conflict on only the live pre-push hook, with a template that merged cleanly, needs a manual merge, and PR #8436 is not shown to be unblocked by this change. Refs #8973.
