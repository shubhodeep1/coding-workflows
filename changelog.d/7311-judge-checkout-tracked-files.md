- **The orchestrator's wave judge now reviews the integration branch's own scripts instead of the poller's copies.**

When the judge's checkout of an integration branch hit local changes, the poller force-checked it out and then copied its own `scripts/`, `prompts/` and `.github/ai/` over the result. In this repository that happened on every tick: the "Stage workflow support files" step of `.github/workflows/orchestrate_poll.yml` installs each support script with mode `0755`, and `scripts/pr_checks_lib.sh` is tracked as `0644`. The judge then saw `main`'s code next to the branch's tests and changelog fragments, decided the script changes were lost, and filed restore issues for project #7126 (#7296, #7306, #7307). Each of them closed or merged without restoring anything, because the code was already there. The fallback now keeps every file the target branch tracks and restores only support files the branch does not have. Each forced checkout logs `JUDGE_CONTEXT_CHECKOUT tracking=<n> outcome=forced kept_target=<count>`. The project security pass still keeps the poller's own support files, because it runs `scripts/security_audit.sh` from that checkout with the poller's credentials; its forced checkouts log `outcome=forced_overlay_kept reason=trusted_support`.

What this means for operators: a project whose judge kept asking to restore code that is already on its integration branch should stop doing so after this ships.
