- `scripts/ci_cancelled_rerun.py` `classify_runner_shutdown` has a fourth transient class, `abandoned` (#9146). It applies only when no non-`lint` job failed (`shutdown_ids` is empty), the `lint` aggregate's annotations pass the existing aggregate checks, and every non-success job the aggregate names is `cancelled` (GitHub reports a job it abandoned that way). Each named cancelled job, deduplicated by id in `aggregate_cancelled`, must pass `shutdown_only_annotations` (every failure annotation is `RUNNER_SHUTDOWN_PREFIX` text or exactly `SHUTDOWN_COMPANION_MESSAGE`; none also counts), else the run is `genuine`. These reads count against `MAX_FAILED_JOBS_CLASSIFIED` (`len(failed) + len(aggregate_cancelled)`, checked before any extra read; over the cap or unreadable is `unverified`). Mixed runs keep their existing verdicts. The off switch is `CI_ABANDONED_JOB_RERUN_ENABLED`, forwarded by `review_autofix_sweep.yml`.

<!-- agents: section="Stable log prefixes (contractual)" -->
- `CI_CANCELLED_RERUN` also logs `action=rerun reason=abandoned` (#9146, `scripts/ci_cancelled_rerun.py`) when a current-head `failure` run's only failed job is the `lint` aggregate and every job it names was abandoned by GitHub (reported `cancelled`, with only runner-shutdown or "The operation was canceled." failure annotations, or none).
