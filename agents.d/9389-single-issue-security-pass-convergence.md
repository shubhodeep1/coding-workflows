- **Single-issue security pass convergence (#9389).** Audits dispatched with `pr_number` run in per-PR concurrency groups (`security-audit-reusable-<repo>-pr-<n>` in `security-audit.yml`, `security-audit-<repo>-pr-<n>` in the `ai-security-audit.yml` wrapper; distinct prefixes avoid the caller/callee deadlock, and runs without a PR share `-default`). Both set `run-name` to `... (PR #<n>)`. The gate (`scripts/review_single_issue_security_pass.sh`) makes at most one audit-runs listing per run, shared by two checks. (1) A pending marker at least `SECURITY_PASS_PENDING_CANCEL_CHECK_MINUTES` old whose PR-titled runs all completed 10+ minutes ago without a result is retried at once (`outcome=retry reason=audit_run_lost`). (2) Before a dispatch, `SECURITY_PASS_MAX_CONCURRENT_AUDITS` queued or running audits hold with `audit_throttled`, with no marker and no cycle used. The cycle budget counts only cycles that posted a result, or that have no marker at all (`single_pass_cycle_accounting`). Every dispatch, reported or not, is capped by `SECURITY_PASS_MAX_AUDIT_ATTEMPTS`, and the marker's `cycle=` keeps numbering attempts. The audit's scope step calls the trusted copy's `since` subcommand to set `SECURITY_AUDIT_DIFF_SINCE` to the newest trusted clean-audited ancestor head, and falls back to the full range on any doubt.
