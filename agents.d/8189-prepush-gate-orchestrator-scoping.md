- **Orchestrator scoping (P2, issue #8189, landed).** The "Validate decomposition JSON" step of `.github/workflows/orchestrate.yml` runs `scripts/orchestrate_lib.py augment-files-touched --decomposition <file> --repo-root "${GITHUB_WORKSPACE}" --gate-module <module> --write-back [--timeout-secs N]` after `validate` and before `check-partition`, so the partition guard, `compute-waves --write-back`, the tracking body and `pending_issue_defs` all see the added paths. The module is always the trusted support copy `.codex-workflow-src/workflow-templates/.claude/hooks/prepush_affected_tests.py`, never the repository checkout, run as `python3 -I -B ... select --paths-file` with a per-issue timeout (default 60 s, clamped 5-300) and only `PATH`, `HOME`, `LANG` in its environment.
  - Each issue's planned `files_touched` gets the module's `affected_tests[].path` first, then `companion_files`, until the list holds 50 entries (`validate_decomposition`'s cap). Paths that are absolute, contain `..`, whitespace, a backtick, `<`, `>`, `\` or control characters, or sit under `.git/` are dropped. An empty `files_touched` stays empty.
  - The top-level decomposition key `prepush_augmented_paths` (`{issue id: [added paths]}`) records what was added; only the remaining planned paths go to the module, so a second run adds nothing and the selection never expands transitively. Because the key arrives in model-written JSON, it is trusted for an issue only when some planned path remains and every recorded path is still selected from the remaining ones; otherwise the whole list is planned and `issue=<id> outcome=marker_ignored` is logged.
  - Logs: `PREPUSH_TEST_GATE phase=augment issue=<id> added=<n> truncated=<n>`, or `outcome=skipped reason=module_absent|decomposition_unreadable|decomposition_invalid|module_failed|timeout|output_missing|malformed_json|module_error|post_validate_failed|write_failed|internal_error`. A timeout is a no-op for that issue only; later issues still run, each with its own timeout. `internal_error` adds `error=<exception class>`. A marker entry that is ignored, or that belongs to an issue with an empty `files_touched`, is dropped rather than written back, also when nothing was added (the key is removed when no entry is left). A module response missing `affected_tests` or `companion_files` is `malformed_json`. A symlinked module counts as `module_absent`. Every failure leaves the decomposition unchanged and exits 0; the write-back is atomic and leaves the file mode `0644`.
  - Switch `PREPUSH_TEST_GATE_MODE` (`vars.PREPUSH_TEST_GATE_MODE || 'repair'`, shell default `repair`): `off` skips the augmentation (`reason=mode_off`); `report` and `repair` run it; any other value logs `PREPUSH_TEST_GATE outcome=mode_invalid` and runs as `repair`.
  - `scripts/orchestrate_lib.py render-expected-files --paths-json-file <file|->` renders an advisory **Expected files** section from a JSON array of paths (backticked bullets, nothing when the list is empty or unreadable). The three child-creation sites call it before the `---` / "Orchestrator metadata" footer: "Create Wave 1 issues only" in `orchestrate.yml` and both `pending_issue_defs` creation sites in `scripts/orchestrate_poll_process.sh`. The section is not an allowlist: its heading never names `files_touched`, so `scripts/files_touched_scope_guard.py` still finds no allowlist block (exit 10) and enforcement is unchanged (plan D5, Q18). It is rendered whatever the mode; issues whose `pending_issue_defs` came from `rebuild-state` have no `files_touched` and get no section.
  - No GitHub API calls are added. Tests: the `augment_files_touched`, `render_expected_files` and wiring-contract cases in `tests/test_orchestrate_lib.py`.
