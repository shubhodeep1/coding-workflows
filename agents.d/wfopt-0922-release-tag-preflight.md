- Release tag credential preflight (analysis/workflow-optimization-2026-09-22.md, Speed #4 / Reliability #2; release run 35639756385 spent about 94 minutes before the tag push was refused). The `resolve-version` job of `test-and-mark-stable.yml` (`!inputs.dry_run && !inputs.gate_only`) and `mark-stable.yml` (`!inputs.dry_run`) runs `scripts/release_tag_preflight.sh` with `GH_TOKEN=secrets.GH_PAT` (no `github.token` fallback) and the range `refs/tags/stable^{commit}..HEAD`. It makes one `gh api -i user` call and reads only the `X-OAuth-Scopes` header. It fails (`result=fail error_class=workflow_scope`, `::error::` with the fix) only when the header is present (classic PAT), lacks `workflow`, and `git diff --name-only` of the range lists a path under `.github/workflows/`. No GH_PAT, no header (fine-grained PAT or App token), an API, git or input error, or a commit without the script give `result=unknown` and the run proceeds; the publish-time `RELEASE_TAG_PUBLISH error_class=workflow_scope` stop still applies. `STABLE_RELEASE_ENABLED` or `RELEASE_TAGGING_ENABLED` off skips it (`reason=publishing_disabled`). Switch `RELEASE_TAG_PREFLIGHT_ENABLED` (repository variable, defaulted in the script): unset, empty or `true` (any case) on, `false` off, any other value off with a `::warning::` that does not print the value. The token, the response body and the scope value are never printed.
