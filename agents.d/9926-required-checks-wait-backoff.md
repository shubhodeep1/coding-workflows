**Required-checks wait: cached reads, back-off, read routing (#9926).** `_pr_wait_for_required_checks` in `scripts/pr_checks_lib.sh` declares wait-scoped locals (`_pr_wait_memo_active`, `_pr_wait_required_*`, `_pr_wait_statuses_*`, `_pr_wait_route_reads`) that `_pr_checks_completed` and `_pr_head_ci_runs_pending` see by bash dynamic scope; standalone callers never see them and behave as before. Inside a wait, the required set (branch protection) is resolved once per base ref, and the gate-supersede statuses read is cached per head SHA unless a returned status is `pending` (a failed read is never cached). `PR_CHECKS_LAST_CHECK_RUNS_FP` (set only inside a wait) plus digests of the runs listing and statuses form the snapshot that drives the back-off: `AUTO_MERGE_CHECKS_POLL_SECONDS` doubling to `AUTO_MERGE_CHECKS_POLL_MAX_SECONDS` (default `180`; invalid or below base turns it off) while unchanged, reset on change, every sleep clamped to the remaining budget (`_pr_wait_clamp_sleep`). The no-check-runs grace counts two ticks at the base interval. `_pr_checks_wait_read` routes the per-poll GET reads through `gh_read --same-repo-only api` only when the wait has a budget and `gh_read` is defined; protection, `GET user`, `_pr_ensure_final_ci` and every write stay on `gh_retry _safe_gh_jq`. No log prefix was added. Tests: `tests/test_pr_checks_lib_wait_backoff.py`.
