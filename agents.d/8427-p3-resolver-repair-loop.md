### Resolver repair loop (`PERSIST_REPAIR_LOOP_ENABLED`, P3 of #8427)

Follow-up to the repair loop above (plan P3 item 5). `_resolver_prepush_test_gate` in `scripts/review_conflict_resolve.sh` runs the loop itself, because its repair is the resolver's sandbox attempt with `check_resolver_diff.sh`, the fingerprint verifier and an index revert, not the review editor turn. With the switch off the resolver's gate argv, single repair (`run1`, at most one repair, `run2`) and log lines are unchanged.

- **Shared pieces.** The gate step script `scripts/review_autofix_step_prepush_test_gate.sh` adds three subcommands, so the clamp and the trusted-helper lookup live in one place: `persist-config` prints `<on> <max_turns>` (the 1..5 clamp, default 3); `acceptance-files IN OUTDIR` runs `acceptance_check.py gate-files` into `OUTDIR/tests.txt` and `OUTDIR/baseline_fail.txt` and prints the count; `acceptance-score IN RESULT` runs `gate-result` into `${RUNTIME_DIR}/acceptance_result.json` and prints `<met|unmet|not_run|none> <extra_unmet>`. `repair-prompt` adds the unmet done-check block only with `PREPUSH_TEST_GATE_PROMPT_DONE_CHECK=true` (default `false`) and the switch on, so the integration test repair's prompt never picks up a stale `acceptance_result.json`.
- **Done-check source.** The resolver step holds the token; the gate container never does. The resolver reuses review's `${RUNTIME_DIR}/prepush_gate/acceptance.json` (0 API calls); otherwise it runs one `acceptance_check.py fetch-plan` from the absolute `SUPPORT_SCRIPTS_DIR` (`python3 -I -B`, 120 s timeout, only when `gate_wall + 750` s remain) into `prepush_gate_resolver/acceptance.json`: at most one comments read plus the cached identity read. Only `tests.txt` / `baseline_fail.txt` reach the gate, through `--tests-file` / `--expect-baseline-fail-file`.
- **Loop.** Same order as `review_prepush_test_gate_persist_loop`: stop `report_mode`, then `clean`/`met` when `pr_caused + extra_unmet` is 0, `no_progress` when it did not strictly drop, `max_turns`, and `budget` when `gate_attempt_secs + gate_wall + 630` s no longer fit before the 9000 s mark. A repair that is not plain `ran` (`reverted ...`, `skipped ...`, `ran (no edits)`) ends the loop (`stop=reverted` or `stop=skipped`). Each turn takes its own `git write-tree` as the revert point, so earlier staged repairs survive a reverted later turn. Runs land in `prepush_gate_resolver/run1..run6` with `runN.status`; `repair=` reads `ran_x<N>` (plus `;_<last reason>`). The `[ai-merge-resolve]` commit always follows. In review_autofix.yml the resolver step runs after "Sync done-check label", so its `acceptance_result.json` overwrite is never read as a mixed state.
- **Journal.** `scripts/review_commit_changes.sh` records the attempt journal's gate fields from the newest of `prepush_gate/run6..run1/result.json`, as implement.yml does.
