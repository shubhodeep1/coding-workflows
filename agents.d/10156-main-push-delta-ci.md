**Delta suite on a push to `main`, full suite on a timer (issue #10156, Refs #10097).**
- A push to `main` runs `static-checks`, `tests-main-delta` and `lint` (plus the advisory `budget-watch`). The seven gated test jobs (`tests-hooks-and-orchestrator`, `tests-heal-plan-and-validation`, `tests-promote-stall-and-review`, `tests-release-and-log-analysis`, `orchestrate-poll`, `tests-system-python`, `tests-sandbox-python`) carry `needs: tests-main-delta` and a `!cancelled()` gate that skips them on a push to `main` unless `MAIN_PUSH_DELTA_CI_ENABLED` is `false` or `tests-main-delta` succeeded with `outputs.full_required == 'true'`. In every other run `tests-main-delta` is skipped at once, so the seven jobs still start together.
- `scripts/ci_main_delta.sh select` makes one `actions/workflows/ci.yml/runs?branch=main&status=completed&per_page=30` read and takes the head of the push or scheduled run that finished last (`updated_at`, then `created_at`; cancelled and skipped runs dropped) as the base when it succeeded. A red run stays the result until a green run started after it finished (`run_started_at`, else `created_at`, >= its `updated_at`), so a delta push that chose its base while a scheduled full run was still running cannot clear that run's failure, while a push queued behind the red run in `ci-push-main` can; the range therefore covers a push whose waiting run `ci-push-main` replaced. It diffs base..head, runs `workflow-templates/.claude/hooks/prepush_affected_tests.py select`, and adds the `CI_SYNC_QUICK_WIRING_PATHS` tests. Any untrusted selection (read failure, which also logs `reason=read_failed_category category=auth|not_found|other`, invalid response, red newest run, no green run, base not an ancestor, selector error, malformed entry or missing `affected_tests`, an empty CI-structure list, over `MAIN_PUSH_DELTA_MAX_TEST_FILES`, a sharded test: `tests/test_orchestrate_poll_process.py`, `tests/test_workflow_failure_heal.py`, `tests/test_review_merge_train.py`) writes `full_required=true` and exits 0, so the full suite runs on that commit in the same run. `run-tests` runs whole files (ci.yml's `python3 <file>` style where ci.yml uses it, pytest otherwise, bash for `.sh`) under one 10-minute deadline (`CI_MAIN_DELTA_TEST_TIMEOUT_SECS`, default 600, below budget-watch's 15-minute warning); a timeout also writes `full_required=true`. A failed `GITHUB_OUTPUT` write fails the job, so `lint` never reads a missing output as a passed delta.
- `lint` accepts the seven jobs' `skipped` in a push run on `main` only when `tests-main-delta` succeeded with `full_required` exactly `false`; elsewhere it accepts `tests-main-delta`'s `skipped`. `ci/final` gets ` (delta suite)` / ` (full suite)` on `main` (`CI_FINAL_STATUS_RUN_KIND`).
- `ci.yml` gains `schedule: 30 4,10,16,22 * * *` (concurrency `ci-schedule-<ref>`, never cancelled); `budget-watch` and heal intake (`workflow-failure-heal-intake.yml`, `verify_run_provenance`) act on scheduled runs on the default branch.
- Readers of the base result count scheduled `ci.yml` runs too, without a new call: `scripts/check_failure_triage.sh` (base gate: `runs?branch=<base>&per_page=10`; pending when the newest push or schedule run is in progress, else the completed one that finished last, unless a red run has no green run started after it finished), `scripts/check_triage_resolution.py` (`per_page=20`, same red-wins rule; a delta push run that cannot resolve the failed jobs falls back to the newest scheduled run in the listing, which must be green), `scripts/review_final_ci_sweep.sh` (`review_final_ci_sweep_base_ci_red`, ordered by `updated_at` with the same red-wins rule as the triage readers and the same red set, so a `timed_out` or `startup_failure` run is red, so an overlapping delta push cannot hide a red scheduled run), `scripts/orchestrate_poll_process.sh` heal-stale read (no `event=push` filter for `ci.yml`) and `heal_stale_decision` (a page holding a scheduled run needs a green scheduled run after the anchor, else `no_full_run_in_window`). Other workflows keep the push-only reads.
- Tests: `tests/test_ci_main_delta.py`, `tests/test_ci_job_split_contract.py`, `tests/test_ci_docs_only_final_ci.py`, `tests/test_ci_budget_watch.py`, `tests/test_ci_final_status.py`, `tests/test_check_failure_triage_workflow_security.py`, `tests/test_check_triage_resolution.py`, `tests/test_review_final_ci.py`, `tests/test_orchestrate_poll_process.py`, `tests/test_workflow_failure_heal.py`.
