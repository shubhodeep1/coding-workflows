**Existing implementation PR routing (#9809).** `implement.yml` stops at `existing_pr` while an issue has an open implementation PR, so a `/approved` posted for such an issue does nothing (#9733). Two places now send the work to the PR instead:

- `scripts/unblock_actions.py` `reset_ops`: for an issue whose stop is in `EXISTING_PR_ROUTED_STOPS` (`needs-human`, `blocked`, `implement-diagnose-failed`, `scope-blocked`, `destructive-blocked`) and whose context carries `implementation_pr`, it emits a `comment` on the PR (`Unblock judge instructions for #<n> (stop ...): <note>`), a `dispatch_review` for it, and a `remove_label` for the stop label on the issue. This covers `plan` (`retry_budget`, `accept_with_followup`), `followup`, `hold-followup` and `regrant`. `override_guard` still calls `_approve` directly.
- `scripts/unblock_judge.sh` `unblock_resolve_implementation_pr` runs right after `context.json` is written, for an issue in those stops only. It makes one GraphQL read (open `ai/issue-<n>` head PRs plus the issue's cross-referencing PRs) and runs `unblock_actions.py impl-pr`, which accepts a same-repository `ai/issue-<n>` head (the highest number wins), else exactly one open PR whose base `repository` and head are both this repository, by the pipeline login or an OWNER/MEMBER/COLLABORATOR whose body closes the issue (implement.yml's `closing_kw_re`). The result is `{"pr", "reason": head_branch|closes|none|ambiguous|unreadable}`. Log: `UNBLOCK_JUDGE item=<n> op=impl_pr outcome=found|none|unavailable|disabled pr=<p> reason=<token>`. A failed or ambiguous read leaves `context.json` unchanged.
- `scripts/orchestrate_poll_process.sh` `_stall_route_open_impl_pr` runs in `execute_stall_recovery_action`'s `auto_approve` and `retrigger_implement` arms, after the no-op cap, and at the top of the same two arms of `run_standalone_stall_recovery` (before the plan gate; rc 0 sets `took_action`, rc 2/3 take no action, rc 1 keeps `/approved`). It reuses `_resolve_issue_implementation_pr`, needs `.state == "open"`, and calls `_dispatch_review_for_conflicts` (default branch only). rc 0 logs `STALL_RECOVERY issue=<n> reason=open_impl_pr pr=<p> phase=<ph> action=dispatch_review override_from=<action>` and counts a recovery attempt; an active review logs `STALL_SKIP ... reason=open_impl_pr_review_active` and a failed dispatch `STALL_SKIP ... reason=open_impl_pr_dispatch_failed`, neither counted. No open PR or an inconclusive lookup keeps today's `/approved`.

Switch `UNBLOCK_EXISTING_PR_ROUTING_ENABLED`, defaulted to `true` in all three scripts and forwarded by `unblock_judge.yml` and both stall-recovery steps of `orchestrate_poll.yml`. Unset, empty or `true` (any case) is on; `false` is off; any other value is off with a warning. These lines use the existing `UNBLOCK_JUDGE`, `STALL_RECOVERY` and `STALL_SKIP` prefixes; no new prefix.
