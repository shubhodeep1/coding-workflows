- **Merge-lease hold labels (Refs #9969).** `_merge_lease_pr_eligible` takes an optional 8th argument `<labels_nl>` (newline-separated label names). When one of them is a hold label, it returns 1 with `MERGE_LEASE_INELIGIBLE_REASON=hold_label`. This check runs after draft and `[skip ai]` and before any API read. `_merge_lease_hold_labels` prints the configured list from `MERGE_LEASE_HOLD_LABELS`. The default, `ai:needs-human,ai:security-pass-failed,ai:review-blocked,ai:scope-blocked`, is set in the helper with `${VAR-default}`, which applies only when the variable is unset, so an empty value stays empty. The `''|none|off` case branch in `_merge_lease_hold_labels` (whitespace removed, case ignored) is what turns the check off. A `none` or `off` entry inside a list is dropped too, so `none,` turns the check off and `off,<label>` keeps `<label>`. An entry equal to `MERGE_LEASE_WAIT_LABEL` is dropped. `_merge_lease_has_hold_label <labels_nl>` matches whole lines with fixed strings, ignoring case (`grep -Fxi -f`), and never logs label names.
  - `_mt_merge_lease_tick` and `_mt_merge_lease_tick_multi` (`scripts/review_merge_train.sh`) pass the labels from the `_mt_list_open_prs` row at all four eligibility calls (holder revoke and waiter grant). The existing paths then give unlabel plus `outcome=skipped reason=hold_label` for a waiter, and `revoked_hold_label` with a `skip=<pr>:<head>:revoked_hold_label` entry for a holder (the two-field `skip=<pr>:<head>` form only with a library that lacks the three-field skip helpers). That entry is hard: a later head-gate success does not clear it, so a PR whose hold label is removed without a push stays skipped until its head changes. No API call is added. An older library ignores the 8th argument, and an older train script never passes it; either way the behaviour is the same as before.
  - The check follows `MERGE_LEASE_REVOKE_ENABLED`: when it is `false`, no eligibility runs. The variable is wired as a repo variable only in the merge-train release steps of `orchestrate_poll.yml` and `cancel_on_pr_close.yml`. The update-mode gate does not call eligibility.
