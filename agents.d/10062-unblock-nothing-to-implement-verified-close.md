- **Unblock judge verified nothing-to-implement close (#10062, plan `docs/plans/pipeline-human-wait-elimination-plan.md` Phase 8b).** `unblock_nothing_to_implement_close` in `scripts/unblock_judge.sh` has a verified mode, selected by an empty `<fixup>` argument and called from `unblock_main` after the Q129 check-triage gate and before the #9659 `unblock_triage_superseded_note` (a pending fix-up wait still runs first). Eligibility is the fix-up mode's: a standalone `ai:blocked` issue whose newest trusted "Planning blocked" comment gives the nothing-to-implement reason with no later trusted implementation plan (`unblock_nothing_to_implement_blocked`). In addition, `unblock_nothing_to_implement_verified` must find a comment by the pipeline login whose last non-blank line is exactly `<!-- ai:implement-success-noop:v1 issue=<item> -->` (posted by `scripts/plan_nothing_to_implement_verify.sh` when its tests pass but its close fails) and whose `created_at` is after the second-newest trusted block, so a later block makes it stale. It reads only the `item_comments.json` the run already fetched. Writes are comment (once, marker `<!-- ai:unblock-nothing-to-implement:v1 item=<n> verified -->`), `ai:closed` label, close `state_reason=completed`; a failed write logs `outcome=skip` and the next run retries without re-posting. Log: `UNBLOCK_JUDGE item= kind= stop= fixup=none op=nothing_to_implement outcome=closed reason=verified_noop` (or `outcome=skip reason=comment_failed|label_failed|close_failed`). Switches: `PLAN_NOTHING_TO_IMPLEMENT_VERIFY_ENABLED` (default `true` in the script, parsed like the plan-side script: `""|1|true|yes|on` is on; forwarded by `unblock_judge.yml`) and `UNBLOCK_NOTHING_TO_IMPLEMENT_CLOSE_ENABLED`; either off restores today's judging. Blocks without the marker (from before Phase 8a) still clear through the judge's `reset` verdict, which re-plans so the plan-side verify runs.
