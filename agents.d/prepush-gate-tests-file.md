- **Explicit test list: `run --tests-file` (issue #8461, heal reproduction plan P2, PR #8409's plan).** `prepush_affected_tests.py run --tests-file FILE` runs only the listed tests instead of the affected-test selection: `select_tests` is not called, so there are no registry checks, static checks or companion files. Failed units are still re-run on `--baseline-tree`, and `classify_baseline` sorts them exactly as before. `run` still needs one of `--changed-files-file` / `--paths-file` / `--base`; with `--tests-file` that input only fills `changed_files` (used by the assertion diff). Without the flag, `run` behaves as it did before.
  - Format: one `path[::name]` per line, for example `tests/test_x.py::test_y` or `tests/test_x.py::Case::test_m[param]`. Blank lines and `#` comments are skipped. Lines for the same path are merged, and a line without `::name` runs the whole file. With a `.ai/validate.yml` `prepush_test_command` override, the `{files}` placeholder gets paths only, so `::name` filters are dropped (existing override behaviour).
  - Validation: a line is skipped and listed in `unverified` as `{"item": "tests_file:line<N>", "reason": ...}`, never with its text, when it is longer than 1024 characters (`tests_file_line_too_long`), has a control character (`tests_file_control_character`), is absolute or has a backslash or drive prefix (`tests_file_absolute_path`), has a `..` segment (`tests_file_parent_traversal`), has an empty or `.` segment or one starting with `-` (`tests_file_invalid_path`), resolves outside the repository through a symlink (`tests_file_outside_repo`), is not a regular file (`tests_file_missing`), is not a test file by `is_test_file` (`tests_file_not_test_file`), or has a `::name` that is not an identifier chain with an optional `[param]` (`tests_file_invalid_name`). Valid lines still run, so the status is `unverified` unless a failure the change caused makes it `fail`. A file over 256 KiB (`tests_file_too_large`) or not UTF-8 or unreadable (`tests_file_unreadable`) runs nothing. After 500 entries (valid or rejected) the rest is dropped with one `tests_file_too_many_entries` item. An empty or comment-only list gives `skipped`.
  - Wrapper: `scripts/prepush_test_gate_run.sh --tests-file FILE` requires a regular, non-symlink file of at most 256 KiB, copies it to its private run root with mode 0444, mounts the copy read-only at `/gate/tests.txt` and passes `--tests-file /gate/tests.txt`. A bad file gives a synthetic `unverified` result with `usage_error` (empty value), `tests_file_missing`, `tests_file_not_regular`, `tests_file_too_large` or `tests_file_copy_failed`, and never falls back to the selection. The container flags are unchanged, and without the flag the docker argv is the same as before.
  - Log line: `PREPUSH_TEST_GATE phase=tests_file outcome=loaded|rejected entries=<n> rejected=<m>`. No GitHub API call is added. No caller passes the flag yet; the heal reproduction runner and orchestrator project #8427 P3 reuse this option and must not add a second one.
  - The live `.claude/hooks/prepush_affected_tests.py` copy is not edited by the pipeline (editors cannot write `.claude/**`); the post-merge sync PR copies the template over it.
