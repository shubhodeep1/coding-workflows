- Release back-off counts live queued runs only (issue #10032). The runner-queue back-off in `scripts/auto_release_stable.sh` now compares the number of live queued runs with `AUTO_RELEASE_STABLE_MAX_QUEUED_RUNS`: the repository's queued runs minus those created more than `ZOMBIE_RUN_MAX_QUEUED_HOURS` ago (the #9473 wedged rule). This supersedes the "one call" wording of the runner-queue back-off bullet above. The count comes from `zombie_queued_live_count <repo> <limit> [cutoff_epoch]` in `scripts/gh_helpers.sh`, next to the #9473 helpers; a later caller that needs queue depth uses it instead of reading the raw `actions/runs?status=queued` total. Contract: read 1 (`status=queued&per_page=1`) always; read 2 (`&created=%3C%3D<ISO cutoff>`, `per_page=1`) only when the limit is above 0, the total is at or above it and the filter is on; no pagination. Prints `<live>\t<wedged>` (wedged clamped to `[0, total]`, `0` when read 2 is skipped), exit 1 when read 1 (or the repo argument) is bad, exit 2 when read 2 is unreadable. The release script fails open on both (dispatches) and defines a raw single-read fallback when `gh_helpers.sh` cannot be sourced.

- `AUTO_RELEASE_QUEUE_CHECK` / `AUTO_RELEASE_SKIPPED reason=runner_queue_deep` (issue #10032): `wedged=<n>` follows `queued=` on `AUTO_RELEASE_QUEUE_CHECK outcome=clear queued=<live> wedged=<n> max=<m> last_run=<id> last_age_hours=<n>` and on `AUTO_RELEASE_SKIPPED reason=runner_queue_deep sha=<sha> queued=<live> wedged=<n> max=<m> last_run=<id> last_age_hours=<n> window_hours=<n>`. `queued=` keeps its meaning (the value compared with the limit) and now holds live runs; `wedged=` is the number of wedged queued runs left out. `outcome=read_failed` gains `lookup=wedged_runs` next to `lookup=queued_runs`. No new prefix.
