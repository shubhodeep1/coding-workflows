- `ORCH_POLL_CYCLE_SUMMARY` (`scripts/orchestrate_poll_process.sh`, stdout, exactly one line per script run, printed by the EXIT trap installed right after `set -euo pipefail`: `ORCH_POLL_CYCLE_SUMMARY elapsed_ms=<n|unknown> projects_seen=<n|unknown> projects_processed=<n|unknown> sleep_ms=<n|unknown> exit_code=<n|unknown> terminal_reason=<completed|no_projects|error>`; keys and order are fixed and every value is an integer or enum token. `terminal_reason=error` whenever `exit_code` is not 0, `no_projects` when `projects_seen=0`, otherwise `completed`. `projects_seen`/`projects_processed` stay `unknown` in sweep-only runs that exit before the tracking list is counted. `sleep_ms` sums only the sleep sites in that file that call `"${_ORCH_POLL_CYCLE_SLEEP_CMD:-sleep}"` (gh_retry backoff in `scripts/gh_helpers.sh` is not counted) and is `unknown` when the sleep ledger is unavailable or a duration is not an integer. The wave-dispatch gate's temporary EXIT trap chains to the same handler. Fail-open: no gh/API calls, never changes the exit code; not printed when the run is killed by SIGKILL (catchable signals such as SIGTERM still run the EXIT trap), nor when a test harness `source`s the poller instead of executing it)
- `ORCH_POLL_PROJECT_TIMING` (`scripts/orchestrate_poll_process.sh`, stdout, one line per tracking issue processed by the main tracking loop: `ORCH_POLL_PROJECT_TIMING tracking_issue=<n|unknown> elapsed_ms=<n|unknown>`; printed when the next project starts, after the loop ends, or from the EXIT trap for a project interrupted by an exit, so `continue` paths are covered; fail-open like `ORCH_POLL_CYCLE_SUMMARY`)
