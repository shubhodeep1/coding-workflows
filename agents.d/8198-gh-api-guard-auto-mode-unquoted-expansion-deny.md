`gh api` guard, unquoted argument expansions in Auto mode (#8198). This refines the Auto-mode paragraph from `agents.d/auto-mode-hook-prompts.md`: an unquoted `$` or backtick in a direct `gh api` argument (`_unquoted_gh_api_expansion`) is no longer a no-decision shape doubt there. Bash can split the word into a method flag (`EP="-XDELETE repos/..."; gh api $EP`) that the guard read as a GET endpoint. `evaluate()` in both `gh_api_write_guard.py` copies (byte-identical) now returns `deny` when `permission_mode` is `auto` (`unquoted_auto_deny`), with the existing reason plus `_AUTO_SHAPE_DENY_SUFFIX`, whether or not an allow rule could match. A loop `_is_approvable_read_loop` accepts is still allowed, and every other mode still asks. The check still runs before the write ask, so an Auto-mode write loop over `$i` is denied rather than prompting. CLAUDE.md §23.H's "Auto mode" paragraph still lists an unquoted `gh api` argument expansion among the no-decision doubts. Pipeline editors cannot write CLAUDE.md, so an interactive session updates both copies. Tests: `test_auto_mode_denies_unquoted_gh_api_expansion` and related cases in `tests/test_gh_api_write_guard.py`.
