<!-- agents: section="Workflow architecture" -->
- **Orphan unblock fix-up close.** `close_orphan_fixup_chains_sweep` (`scripts/orchestrate_poll_process.sh`) runs once per tick from the top of `run_unblock_scan` (after `needs_human_digest_prune`, before the `UNBLOCK_JUDGE_ENABLED` check), so the full tick and the `UNBLOCK_SCAN_SWEEP_ONLY` tick both run it. It closes open standalone fix-up issues whose source issue is closed; `scripts/orphan_fixup_close.py` (`select`, `timeline-check`) decides offline and the shell only reads and closes. A fix-up is an open issue whose first body line is exactly `<!-- ai:unblock-fixup:v1 item=<n> round=<k> -->` (`unblock_actions.py` `_fixup_body`); `Re-issued from`, `Accepted with this follow-up`, `Source issue`, `Parent issue` and `Replaces` links are new work and never match. The fix-up closes when issue `<n>` is closed with any reason and has been closed for `ORPHAN_FIXUP_CLOSE_GRACE_MINUTES` (default 60), or when `<n>` is itself an open fix-up that closes in the same pass (cycles and chains over 64 deep close nothing); an open `<n>` that is a real task, a fix-up that is in flight, a pull request, or a number that cannot be read keeps the fix-up. Eligibility: author is the tick's `unblock_trusted_login`; labels are a subset of `ai:blocked`, `ai:scope-blocked`, `ai:destructive-blocked`, `ai:needs-human`, `ai:unblock-closed`, `ai:security`, `ai:done`; no `ai:orchestrator-tracking` / `ai:orchestrator-managed`. Before each close, `_issue_timeline_with_cross_refs_json` must show no open, unreadable or unknown-state linked pull request and no `closed` event (a reopened fix-up is a person's decision and is never closed again). The close is `gh issue close --reason "not planned" -c <comment>` with `GH_RETRY_MAX_ATTEMPTS=1` (one attempt, so a retry cannot repeat the comment); the comment ends in `<!-- ai:orphan-fixup-closed:v1 item=<n> parent=<p> root=<r> -->`. Order is nearest the closed root first, capped by `ORPHAN_FIXUP_CLOSE_MAX_PER_TICK` (default 5). Variables, all optional: `ORPHAN_FIXUP_CLOSE_ENABLED` (default `true`), `ORPHAN_FIXUP_CLOSE_DRY_RUN` (default `false`; logs `outcome=would_close`), `ORPHAN_FIXUP_CLOSE_MAX_PER_TICK`, `ORPHAN_FIXUP_CLOSE_GRACE_MINUTES`, `ORPHAN_FIXUP_CLOSE_MAX_PAGES` (default 5 pages of 100 open issues, code default only). API budget (§15): one REST list page per 100 open issues (no existing call in the tick returns open issue bodies; the scan's search returns at most 30 items without bodies); when a fix-up names a number outside that list, one aliased GraphQL `issueOrPullRequest` query for up to 20 numbers; per fix-up about to close, one timeline read and one close. Every failed read closes nothing that tick (`outcome=skip reason=list_failed|parent_lookup_failed|...`). `orchestrate_poll.yml` passes the variables to "Process each tracking issue" and "Run unblock scan without active projects" and stages the helper next to `unblock_scan.py`. Tests: `tests/test_orphan_fixup_close.py`.
