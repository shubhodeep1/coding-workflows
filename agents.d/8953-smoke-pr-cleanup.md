### Stranded smoke-PR backstop (issue #8953)

`review_autofix_sweep.yml` ("Enumerate open PRs and dispatch internal-review.yml") closes a release-gate smoke PR the gate left open. A PR matches only when all three hold: it carries the `e2e-smoke-test` label, its head is `ai/issue-<N>` (anchored regex), and its author equals the `GH_PAT` user (`gh api user`, read once per tick and only when a labelled `ai/issue-<N>` PR exists). A matching PR is closed (`PATCH pulls/<n> state=closed`, then a best-effort comment saying how to keep it) when issue `<N>` is closed (`reason=issue_closed`, one issue GET per matching PR) or when it is older than `SWEEP_SMOKE_PR_MAX_AGE_HOURS` (`reason=max_age`; default `6`, `0` turns the age rule off, a non-integer falls back to `6`). The check runs after the PR-number and `head_ref_filter` checks and before the `[skip ai]`, merge-queue, capacity and active-run checks, and a PR it chose to close is never dispatched, even when the close fails. `dry_run` logs the decision without closing. Failure modes: a `/user` read failure logs `AUTOFIX_SWEEP_SMOKE_CLOSE_FAILED reason=author_unavailable` and the PR follows the normal path; an issue read failure leaves only the age rule; a close failure logs `reason=close_failed`; none of them blocks the tick. A consumer whose `GH_PAT` user differs from the smoke PR author never matches (no false closes). The open-PR snapshot (also `ci-cancelled-pr-snapshot.json`) gains `created_at` and `author`, and `AUTOFIX_SWEEP_END` gains `closed_smoke=`.

The release gate's own cleanups close these PRs first: "Cleanup test artifacts", when Phase 3b recorded no PR, cancels every still-active (`status != completed`) Implement run created after the smoke issue whose `display_title` is the issue title, then closes any open `ai/issue-<N>` PR (state only, so its body survives, plus a best-effort comment); "Cleanup alt-model artifacts" cancels that issue's active Implement runs (newer than the pre-create snapshot id) before its head lookup. Both lookups page the repo-wide `actions/runs` listing (up to 10 and 5 pages of 100, stopping at a short or failed page, and for alt-model at a page reaching the snapshot id) with Phase 3b's `Implement` name match, because `implement.yml` is `workflow_call`-only and its runs are filed under the caller (`internal-implement.yml`, `ai-implement.yml`); a failed page logs `::warning::Implement run lookup failed`; and "Cleanup orchestrate test issues" closes PRs with base or head `orchestrator/project-<N>` or a child `ai/issue-<M>` head before deleting the integration branch (a `::warning::` after three failed deletes; a ref that reads back HTTP 404 logs `already absent` instead). The poller's judge (`judge_tracking_issue_closed_skip` in `scripts/orchestrate_poll_process.sh`) creates no `judge-addition` or fix-up issues once the tracking issue is closed, and the `in_progress` arm then also skips the wave advance (re-decompose and next-wave sub-issue creation); when the judge proposed no issues the arm makes that one state read itself (`type=wave-advance`). All `AUTOFIX_SWEEP_END` lines, including the zero-candidate and `default_branch_unavailable` exits, carry `closed_smoke=`.
