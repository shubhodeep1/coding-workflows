<!-- agents: section="Workflow architecture" -->
- **Stall recovery keeps green and lease-waiting PRs (issue #9892).** In `scripts/orchestrate_poll_process.sh`:
  - `invoke_stall_judge` picks the linked PR with `_stall_judge_pick_linked_pr`: the lowest-numbered open PR among the `_find_all_linked_prs` candidates that passes `_linked_pr_is_issue_implementation` (the PR `close_linked_pr` would act on), falling back to `_issue_cross_ref_pr_number_last`. It makes the same three lookups itself and fetches `ai/issue-<n>` branch and body close-keyword hits before timeline-only cross-refs (20-fetch cap); after a match it still fetches lower-numbered candidates, so it returns the lowest-numbered match within the cap. The diagnostics add `linked_pr_source` (`implementation|cross_ref_last|none`) and `linked_pr_candidates`.
  - `_stall_pr_ai_hold_reason <pr_json> [stall_minutes]` also prints `merge_lease_wait` for an open PR labelled `${MERGE_LEASE_WAIT_LABEL:-ai:merge-lease-wait}`, but only when a second argument is passed (stall-recovery callers pass the stall clock, the review-blocked judge arm's guard passes `0`; the conflict sweep passes none). `draft` and `skip_ai_title` keep priority. The hold lapses once the label's age, from its last `labeled` event on the PR (`_stall_merge_lease_label_age_minutes`, one GraphQL read only while the label is present, its labeled-at epoch cached per PR per poller process in `_STALL_MERGE_LEASE_AGE_CACHE_FILE`; a failed read keeps the hold until the stall clock passes twice the maximum, then it lapses with `label_age_minutes=unknown`), exceeds `STALL_MERGE_LEASE_WAIT_MAX_MINUTES` (default 1440, `0` = off). `invoke_stall_judge` runs the same check on the picked PR before the judge (`STALL_SKIP ... reason=pr_ai_hold ... source=judge_pick`), only when the pick is the implementation PR, never on the `cross_ref_last` fallback.
  - `_stall_reissue_green_pr_guard <issue> [stall_minutes]` runs at the top of all three `close_and_reissue` arms (managed `execute_stall_recovery_action`, the standalone ladder via a `close_and_reissue_refused` no-op arm, and the review-blocked judge, which passes `0`). Its body close-keyword search runs inline so a failed search refuses instead of reading as empty. It refuses when an open implementation PR is held or has a green head (newest `ai-review/head-gate` status success, plus the required CI check bound to `${REVIEW_FINAL_CI_WORKFLOW:-ci.yml}` runs through `_pr_checks_completed`; `none` counts as satisfied). It fails closed (`check_unavailable`). Kill switch: `STALL_REISSUE_GREEN_PR_GUARD_ENABLED` (default `true`).
