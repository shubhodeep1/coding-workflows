- **Stage switch discovery (#10127).** `scripts/stage_switch_watch.py` `discover_switches(repo_root)` finds the default-on switches the watch covers: `SWITCH_DEFAULT_RE` (`vars.<NAME>_ENABLED || 'true'`, also chained `|| (...) || 'true'` and multi-line) and `SWITCH_NOT_FALSE_RE` (`vars.<NAME>_ENABLED != 'false'`) over `.github/workflows/*.yml` and `*.yaml` with comment lines dropped, plus `_ENABLED` rows with default `true` in the README `#### Variables` and `## Required Variables` tables minus `README_NOT_REPOSITORY_VARIABLES`. It returns `{name: {files, forms}}`, reads files only (no PyYAML, no API call) and fails open (a missing or unreadable file adds nothing). `load_registry(path, repo_root=None)` merges it with `scripts/stage_switches.json`: an entry's `stage` and `on_values` win; a discovered name without an entry, or an entry without `stage`, gets "Turns on <name in words> (<files>); false turns that stage off."; with a repo root the merged list is sorted by name (without one the registry keeps its file order). In each entry only `name` is required; `default` (must be `"true"`), `stage` (non-empty), `on_values` and `pending` (boolean) are optional. The CLI discovers only with `--repo-root`; `scripts/stage_switch_watch.sh` always passes `STAGE_SWITCH_REPO_ROOT` (default: the folder above `scripts/`), so the workflow file is unchanged. `tests/test_stage_switch_registry.py` checks that discovery finds the sample switches and that every registry entry and `off_on_purpose` marker names a discovered switch or carries `pending: true`; it no longer fails when a new switch is unlisted. Remove a `pending` entry once its pull request merges (then it is discovered) or closes.
