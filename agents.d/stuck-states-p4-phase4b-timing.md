- **Phase 4b retry budget counts from leaving the queue (stuck-states P4, Refs #8291).** In `scripts/stable_e2e_step_verify_bait_removed.sh` (the "Phase 4b: Verify editor restored canary (pytest + retry)" step of `test-and-mark-stable.yml`), `E2E_PHASE4B_QUEUED_GRACE_ENABLED=true` (default; truthy = `1`/`true`/`yes`/`on`, any case) latches the first poll of the pinned retry run that reads `in_progress` or `completed` and restarts `EDITOR_RETRY_BUDGET_MINUTES` there (`Retry review run #<id> left the queue after <n>s (run_started_at=<ts>)`; the latch is never reset). Before that the run is bounded by `E2E_RETRY_QUEUED_GRACE_MINUTES` (default 30, bad values fall back to 30 with a warning) and a run never seen leaving the queue whose last successful read was `queued`/`waiting`/`pending`/`requested` fails as `status=retry_queued_timeout` (a run never read at all, because of a rate limit or a failed or malformed GET, reports `retry_timeout`); a started run that does not finish stays `retry_timeout` with a `queued <n>s, ran <n>s` detail. Every deadline is `max(base, min(candidate, RETRY_DEADLINE_CEILING))`, so the 25-minute base is never shortened and the serial budget in "Validate prerequisites" is unchanged. The start comes from the existing run GET's `status`, not `run_started_at` (GitHub fills that in for queued runs; it is logged only after a strict ISO-8601 match), so no API call is added. Any value that is not truthy restores the legacy queued-poll extension byte for byte.
