Per-cycle caches in `scripts/orchestrate_poll_process.sh` (#9927, GH_PAT budget part D):

- **PR JSON cache.** `_fetch_pr_json` serves repeat reads of one PR from `ORCH_POLL_PR_JSON_CACHE_DIR`, a 0700 `mktemp -d` directory that exists only when the poller is executed directly (never when a harness `source`s it) and is removed by the EXIT trap. Entries are `<owner>__<repo>__<n>.json` (line 1 `ts <epoch> gen <token>`, then the JSON). An entry is served only when its gen token is current, it is younger than `ORCH_POLL_PR_JSON_CACHE_TTL_SECS` (default `60`; `0` is the kill switch) and its JSON is an object whose `.number` is the PR. A failed read (`{}`) is never stored, and every cache error falls back to the live GET.
- **Invalidation.** `gh_retry` runs `GH_RETRY_AFTER_CALL_HOOK` (default empty; `scripts/gh_helpers.sh` sets `GH_RETRY_AFTER_CALL_HOOK_SUPPORTED=1`) once per call. The poller sets it to `_orch_poll_pr_json_cache_after_gh_call`, which acts on anything that `_orch_poll_pr_json_cache_gh_call_is_read` does not classify as a read (GET `gh api` / `_safe_gh_jq` with no POST-inferring fields, graphql queries, `gh <noun> view|list|status|checks|diff`). A write that `_orch_poll_pr_json_cache_gh_write_number` ties to one number (`gh issue|pr <edit|comment|…> <n>`, `gh api repos/<repo>/issues/<n>…` or `…/pulls/<n>…`) changes only that PR's token file (`<owner>__<repo>__<n>.gen`); merges, update-branch, mutations and every other write flush the whole cache. Add `_invalidate_pr_json_cache "${GITHUB_REPOSITORY}" [<pr>]` after any new `git push` or PR write that does not go through `gh_retry` (including `gh_retry_to_file`); a push or merge flushes everything (no number), because it can change other PRs' base or mergeability. `test_unwrapped_pr_writes_followed_by_invalidation` enforces this.
- **Mergeability retries.** A loop that re-reads a PR until GitHub settles its mergeability (the standalone-stall retry) invalidates that PR before every attempt, because the live GET is what starts the recomputation.
- **Fresh reads.** A read that guards against a change made by someone else during the tick (the review-blocked race guard and post-judge re-fetches) calls `_invalidate_pr_json_cache "${GITHUB_REPOSITORY}" "${RB_PR}"` on the line before `_fetch_pr_json`; `test_rb_fresh_read_sites_invalidate_before_fetch` pins those sites.
- **Labels.** `_orch_poll_labels_fill_missing <labels_json> <numbers…>` adds missing issues with one `_fetch_issue_labels_batch_graphql` call when two or more are missing, and per-issue REST only for batch misses or a single issue.
- **Default branch.** Use `$(_orch_poll_default_branch_or_live "<fallback>" [quiet])` instead of an inline `GET repos/<repo>`; it reuses the `_review_run_default_branch` memo once that memo holds `ok`, and otherwise makes the site's one original live call (never a second GET, and a failure never records `failed` for the review-run matchers); a valid live result seeds an unresolved memo, so a run makes one GET for it.
- **Hit counts.** `_orch_poll_cycle_cache_hit pr_json|default_branch|labels` appends to a file ledger, reported as `cache_hits_pr_json`, `cache_hits_default_branch` and `cache_hits_labels` at the end of `ORCH_POLL_CYCLE_SUMMARY`.
