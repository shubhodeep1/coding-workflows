- **Release-gate reads wait out rate limits (#10225).** Raw `gh api` reads in `scripts/stable_e2e_step_verify_cancel_on_close.sh`, `scripts/stable_e2e_step_deep_verify.sh`, `scripts/stable_e2e_step_wait_plan.sh` and the inline steps of `.github/workflows/test-and-mark-stable.yml` go through `gh_api_retry` (`scripts/gh_helpers.sh`); the step scripts source the workspace copy when `gh_api_retry` is not defined (a missing helper fails the step), `wait_plan` sources it inside the command substitution so its own shell is unchanged, and each routed inline step starts with `declare -F gh_api_retry >/dev/null || source scripts/gh_helpers.sh`. Each of the seven PAT jobs sets `GH_RETRY_MAX_ATTEMPTS: "3"` and `GH_RETRY_RATE_LIMIT_MAX_WAIT_SECS: "600"`, so a read waits at most (3 - 1) x 600 s for a reset (within `E2E_FINALIZATION_RESERVE_MINUTES` for `e2e-smoke-test`); `orchestrate-decompose-test`, `clarify-rejects-unsolvable-test` and `e2e-alt-model-test` got 20 more minutes of `timeout-minutes` for it (`workflow-log-analysis-test`, `orphan-workflows-test` and `validate-standalone-test` read through neither helper, so they keep their limits and the env only bounds a future read). Phase 7 reads use `phase7_gh_api_read`, which caps each wait at `min(600, (job_cap - now) / 2)` with `job_cap = E2E_JOB_STARTED_EPOCH + (E2E_JOB_TIMEOUT_MINUTES - E2E_FINALIZATION_RESERVE_MINUTES) * 60`. `scripts/stable_e2e_step_deep_verify.sh` uses the same cap through `deep_verify_gh_api_read` and stops its outer retry rounds on rc 75. The always() steps `Cleanup test artifacts` and `Cleanup alt-model artifacts` source the helper fail-soft and fall back to `gh_api_retry() { gh api "$@"; }` when it is missing; `Cleanup test artifacts` also exports `GH_RETRY_RATE_LIMIT_MAX_WAIT_SECS` = min(600, job time left / 8). Writes keep their single attempt. `tests/test_test_and_mark_stable_gh_rate_limit_routing.py` fails on any raw read (`gh api` without a write flag, `gh run view|list|watch`, `gh pr view|list|checks|diff`, `gh issue view|list`) outside its allowlist, where every entry carries a reason and a stale entry fails; `tests/test_test_and_mark_stable_phase7_rate_limit_wait.py` replays the run 46009933351 rate limit against a fake `gh`.
- **Gate `GH_PAT_BUDGET` lines carry numbers (#10225).** The start step of each PAT job makes one `gh api rate_limit --jq '[.resources.core.remaining, .resources.core.reset] | @tsv'` read (it does not use up the core allowance), prints `remaining=<n> reset=<epoch>` when the reading matches `^[0-9]+[[:space:]][0-9]+$` and stores it in `${RUNNER_TEMP}/gh_pat_budget_<job>`; otherwise it prints `unknown`. The end step calls `gh_pat_budget end test-and-mark-stable <job> <snapshot>` when the checkout's `scripts/gh_helpers.sh` defines it (so `used_in_job` and the gh call counter keys come from the helper) and otherwise prints the old `unknown` line. Neither step can fail the job. `validate` holds no PAT and keeps `unknown`. No new log prefix.
