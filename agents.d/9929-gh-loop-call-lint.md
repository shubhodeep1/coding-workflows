- **GitHub API calls inside loops lint (CLAUDE.md §15 enforcement, warning only; issue #9929).** The `pr-body-lint` job of `.github/workflows/pr-checks.yml` has a third step group, step `gh_loop_call_lint` ("Lint new GitHub API calls inside loops (CLAUDE.md §15, warning only)"). It deepens the PR merge commit to depth 2 with `git fetch` and runs `scripts/lint_gh_calls_in_loops.py --base <merge>^1 --head <merge>`, so it makes no GitHub API call and takes no token. For each line the PR adds in a `*.sh` / `*.bash` file or a `run:` block of `.github/workflows/*.yml` / `workflow-templates/*.yml`, it emits `::warning file=<f>,line=<n>::§15: GitHub API call inside a loop ...` when a call (`gh api`, `gh pr view|list|checks`, `gh issue view|list`, `gh run list|view`, `_safe_gh_jq`, `gh_retry`, `gh_api_retry`, `curl ... api.github.com`) sits inside a `for` / `while` / `until` body. Loop depth is a heuristic `do` / `done` scan at command position that skips comments, single-quoted text and heredoc bodies; YAML `run:` lines map back to the workflow file line. Existing code never warns. Suppression: a call through `_fetch_candidate_issue_details_graphql`, `_fetch_linked_pr_status_graphql`, `_fetch_issue_labels_batch_graphql`, `gh_review_pr_state` or `gh_read`, or the annotation `# gh-loop-ok: <reason>` (reason required) on the same line or the line above. The script exits 0 on every path and the step is `continue-on-error`, so it never fails `pr-body-lint` (the §19 merge-gate verdict). It runs on every event of the workflow, `edited` included. Promoting it to failing is a separate decision. Tests: `tests/test_lint_gh_calls_in_loops.py`, `tests/test_pr_checks_workflow.py`.
