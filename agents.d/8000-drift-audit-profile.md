- **Profile-aware consumer drift audit (#8000, Refs #7973).** `scripts/audit_consumer_drift.py` reads each consumer's `WORKFLOW_PROFILE` repository variable once per run (`ConsumerDriftAuditor.fetch_workflow_profile`, `GET repos/<repo>/actions/variables/WORKFLOW_PROFILE` through `_run_gh_api` with its transient retry, cached in `workflow_profile_cache`). The value is stripped, lower-cased and accepted only as `core`, `standard` or `full`; a 404 (unset) means `full`, as in `update_workflows.yml`; any other failure or value means `unknown`. `load_profile_manifests` reads `workflow-templates/profiles/{core,standard,full}.txt` through `_load_named_profile_manifest_names` (`_load_profile_manifest_names` for `full.txt` is unchanged). A template the consumer does not have and that the resolved profile's manifest does not list is skipped (`DRIFT_SCAN_SKIP`), not recorded as a missing `DriftItem`. A template the consumer has is always compared, so out-of-profile drift is still reported. `unknown`, a missing or unreadable manifest for the profile, or an auditor built without `profile_manifests` (no variables read) audits every template as before. `DRIFT_SCAN_START` gains a trailing `profile=<core|standard|full|unknown>`. An `ai-*.yml` template that `full.txt` does not list is skipped for a `full` consumer that lacks it, because the updater would not install it. API cost: one extra REST read per consumer per run; neither the workflow listing nor the content reads return repository variables.
