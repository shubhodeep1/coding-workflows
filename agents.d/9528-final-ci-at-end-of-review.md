**Final CI at the end of review (cut-ci-runner-time Phase 4, step 1 of 2, Refs #9528).** This step ships the mechanism switched off; the switch-over that turns it on is a separate change, because `internal-review.yml` calls `review_autofix.yml@promote-candidate` and may only pass the new input once `promote-candidate` carries it. Until then every PR still gets full CI from `ci.yml`'s `pull_request` trigger.
- `ci.yml` gains `workflow_dispatch` (inputs `pr_number`, required, and `head_sha`, optional, for the run name and logs only), `workflow_call` (input `mode`, `full` by default, or `quick`) and `run-name: CI [pr:<n>]` for dispatch runs. In a dispatch run every job checks out `refs/pull/<pr_number>/merge`, so it tests the same merge result a `pull_request` run tests, and its check-runs (including `lint`) attach to the dispatched branch's tip, the PR head. There is no merge-ref fallback: a PR whose merge ref is missing (conflicts) fails CI and goes back to review, which resolves conflicts. The three shallow-checkout fetch steps fail the job unless the merge commit's second parent is the dispatched head (`GITHUB_SHA`, where the check-runs attach), so a stale merge ref never reports another head's results; they resolve the base as the merge commit's first parent and export `CI_FINAL_PR_BASE_SHA` and `CI_FINAL_PR_BASE_REF` (one `GET pulls/<n>` each), which the Prepare steps and every `CLAUDE_PARITY_PR_BASE_SHA` read as the dispatch equivalent of `github.event.pull_request.base.sha` / `github.base_ref`. The agents.md direct-edit check compares HEAD with its first parent and applies the project and forward-merge skips from the PR's metadata (one read). In `mode: quick` only `static-checks` runs; every other job (and `lint`) is skipped by `if: inputs.mode != 'quick'`.
- Concurrency: a dispatch run joins `ci-final-pr-<pr_number>` and cancels the PR's older final run; a quick run gets `ci-quick-<run id>`; `pull_request` and push runs are unchanged from Phase 2.
- `_pr_ensure_final_ci <repo> <pr> <head sha> [<head ref>]` (`scripts/pr_checks_lib.sh`) is a no-op unless `REVIEW_FINAL_CI_WORKFLOW` names a workflow file. It reads `actions/workflows/<file>/runs?head_sha=<sha>&per_page=20` (or reuses a caller's listing in `PR_FINAL_CI_RUNS_JSON`) and does nothing when a run of that file on the head is not completed or completed `success` / `failure` (a `push` run on an `orchestrator/project-*` head counts). Otherwise (no run, or only `cancelled` / `timed_out` / `startup_failure`) it dispatches the file on the head ref with `pr_number` and `head_sha`, once (no retry). A failed read dispatches anyway. An empty head ref costs one `GET pulls/<pr>`, and a fork head is refused (`reason=fork_head`). A branch created before `ci.yml` had `workflow_dispatch` cannot be dispatched (`reason=dispatch_refused`); updating it from its base fixes that.
- Callers, all off while the variable is empty: the first poll of `_pr_wait_for_required_checks` when the required CI check is `absent` or every CI run on the head was cancelled (reusing that poll's `actions/runs?head_sha=` listing, kept in `PR_CHECKS_RUNS_RAW_JSON` by `_pr_head_ci_runs_pending`; `PR_CHECKS_HEAD_REF` saves the PR read), which then keeps waiting for the dispatched run; `scripts/review_enable_auto_merge.sh` right after it posts `ai-review/head-gate` success on the no-auto-merge and `e2e-smoke-test` paths (the auto-merge path relies on the wait, after the freshness gate); and the review sweep step "Ensure the final CI run on reviewed PR heads" (`scripts/review_final_ci_sweep.sh`).
- `review_autofix.yml` has the `workflow_call` input `final_ci_workflow` (default `''`) and exports it as the workflow-level env `REVIEW_FINAL_CI_WORKFLOW`; the sweep step sets `REVIEW_FINAL_CI_WORKFLOW: ""` for now.
- Red final CI: the `ci.yml` job `final-ci-failed` (dispatch runs only, `needs: lint`, runs when `lint` failed and the run was not cancelled; not in `lint.needs`) checks out the default branch and runs `scripts/review_final_ci_failed.sh`. The script does nothing when the PR is closed or its head moved on (`outcome=superseded`, one `GET pulls/<n>`); otherwise it posts one `<!-- ai:final-ci-failed:v1 pr=<n> head=<sha> -->` comment per head (a bot's or OWNER/MEMBER/COLLABORATOR's marker for that head suppresses a second one, and the dispatch) and dispatches the PR's review workflow in the order `review_freshness_ci_failed.sh` uses (`internal-review.yml` first). Because `_pr_ensure_final_ci` never re-dispatches a head whose run failed, a head the autofix cannot fix stays red. Switch: `FINAL_CI_FAILED_REDISPATCH_ENABLED` (repo variable, default `true`).
- Check-failure triage: `internal-check-failure-triage.yml` job `resolve-final-ci-pr` reads `<n>` from a failed `CI [pr:<n>]` `workflow_dispatch` run's name and keeps it only while PR `<n>` is open with that head (one `GET pulls/<n>`); `triage-final-ci-run` then calls `check_failure_triage.yml` exactly as the `pull_request` job does.
- Sweep safety net budget (§15): one `actions/workflows/<file>/runs?per_page=100` listing per tick, matched against the enumerate step's PR snapshot; for at most `FINAL_CI_SWEEP_MAX_PER_TICK` (default 10, 1-50) heads with no run there, one `commits/<sha>/status` read and, when `ai-review/head-gate` is `success`, `_pr_ensure_final_ci`. `orchestrator/project-*` heads are skipped.
- Tests: `tests/test_review_final_ci.py`, `tests/test_ci_concurrency.py`, `tests/test_ci_shallow_checkout_contract.py`, `tests/test_ci_job_split_contract.py`.
