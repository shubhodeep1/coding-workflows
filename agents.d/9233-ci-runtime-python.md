- **CI runtime Python coverage (#9233).** Every CI test job pins `setup-python` 3.12, but the pipelines run the runner's `/usr/bin/python3` (3.14 on `ubuntu-26.04`), and the sandbox containers run Debian bookworm's 3.11. Two jobs in `.github/workflows/ci.yml` cover those interpreters. Both are in `lint`'s and `budget-watch`'s `needs`.
  - `tests-system-python` has no `setup-python`. Its `Setup Python` step builds a venv from `/usr/bin/python3` and fails when that interpreter or `venv` is missing; there is no fallback. `Install Python CI dependencies` fails unless `sys.base_prefix` is `/usr`. The `System-Python test shard` step collects `tests/` once, fails on any collection error, groups parametrized cases under their function, and runs the functions with `NR % total == index` in one pytest process. Index and total come from `strategy.job-index` / `job-total`, so to change the shard count, edit the `system-python-shard` matrix list and nothing else. The step leaves `TMPDIR` at the runner default `/tmp`: a `RUNNER_TEMP`-based pytest `tmp_path` pushes the heal tests' broker socket past the 108-byte AF_UNIX limit. The `tests/test_*.sh` shell tests stay in their existing jobs (known gap).
  - `tests-sandbox-python` runs one leg for each image family (`clarify`, `review`, `codex-isolated-codex`). Each leg resolves the image through `scripts/sandbox_image.sh` / `codex_isolated_exec.sh image`, as the call sites do, and adds Debian's `python3-pytest` in a throwaway derived image. It then runs that family's covering tests with `--network none`, uid 65534, `--cap-drop ALL`, a read-only root and read-only `/src`, and a tmpfs `/tmp`, deselecting `tests/test_gh_api_write_guard.py::test_template_parity` (parity needs the PR base SHA the container lacks and is checked by the other jobs). The job has `permissions: contents: read` and no secrets.
  - The registry is `SANDBOX_PYTHON_ENTRY_POINTS` in `tests/test_sandbox_python_coverage.py`. It maps each in-container path to its host file, its covering tests and its families; `--print-tests <family>` feeds the job. The guard scans `codex_isolated_exec.sh`, `clarify_isolated_run.sh`, `review_untrusted_sandbox.sh`, `heal_isolated_implement.sh` and `prepush_test_gate_run.sh` for `--mount ...dst=/x.py|.sh` mounts, `install ... "${root}/support/x.py"` copies, and `python3 /x.py` / `bash /x.sh` runs. It fails on an unregistered entry point, a stale entry, a missing file, or a family list that differs from the job's matrix. To add an entry point, add a registry row with tests that run under bookworm's pytest 7.2 as a non-root user without network. Inline `python3 -c` and heredoc code is out of scope (known gap).
  - Failure modes:
    - A new runner image brings a new Python and every shard turns red. The `Setup Python` log names the version. Fix the code; to unblock merges meanwhile, drop the job from `lint.needs`.
    - The GHCR pull and the local build both fail. The leg fails, with no silent skip; rerun once the mirror is back.
    - A shard nears 20 minutes. `budget-watch` reports it; add entries to the matrix list.
