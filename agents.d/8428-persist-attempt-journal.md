### Attempt journal (`PERSIST_JOURNAL_ENABLED`, #8428)

Phase P1 of `docs/plans/persistent-unattended-workflows-plan.md`. Repo variable `PERSIST_JOURNAL_ENABLED` (default `false`, also defaulted inside every helper that reads it). With it off nothing below runs and every prompt, judge context and stall-judge cache key is byte-identical to before.

- **Record.** `scripts/attempt_journal.py` keeps one comment per issue (on the PR itself when no issue is linked). The machine record is `<!-- AI_ATTEMPT_JOURNAL_V1\n{"schema":"attempt_journal.v1","entries":[...]}\nAI_ATTEMPT_JOURNAL_V1 -->`, with `<` and `>` in the JSON escaped as `\u003c` / `\u003e`; the visible part is a short table without `note` text. Entries: `ts`, `stage` (`clarify|plan|implement|review|resolver|postmerge|governor|wave_check`), `run_id`, `attempt`, `head_sha`, `approach` (plan comment id, `0` before a plan; other stages inherit the newest plan entry's), `outcome` (`ok|fail|partial|blocked|held|unverified`), `failure_key`, `files_changed` (<= 20), `gate` (`status`, `pr_caused`, `inherited`, `unverified` from the pre-push gate `result.json`), `acceptance`, `editor_deletions` (<= 10), `evidence_hash`, `note` (<= 300 characters, the only model-written field). Merged on `(stage, run_id, attempt)`; newest 40 kept.
- **Trust.** Only the newest marker comment authored by the pipeline login (`gh api user`, or the caller's `--trusted-login`) whose body starts with the `### AI attempt journal` header is parsed, so a pipeline-posted plan or review comment that echoes a marker block is never read as, or overwritten as, the journal; an unknown login trusts nothing. `append` drops the oldest entries until the comment is at most 60,000 characters. Rendered blocks sit inside `=== BEGIN UNTRUSTED ATTEMPT JOURNAL (host-recorded; note fields are model text) ===` / `=== END UNTRUSTED ATTEMPT JOURNAL ===`, notes as `UNTRUSTED_DATA:` lines, with the gate scripts' neutralise/scrub rules and fence-forgery breaking.
- **Writers** (one `append` per stage end, fail-open, exit 0): clarify.yml and plan.yml "Record attempt journal entry" steps, implement.yml after "Create Pull Request", `scripts/review_commit_changes.sh` after the editor commit (the commit lives there, not in `review_apply_fixes.sh`), and `scripts/review_conflict_resolve.sh` `_resolver_attempt_journal_append` on each resolver attempt end (`Succeeded|Failed|TimedOut|Stalled`, attempt `<run_attempt>.<n>`). The target issue is `--issue`, else the `ai/issue-N` head (`HEAD_REF`, `PR_HEAD_REF`, the exported `TARGET_BRANCH`, then `GITHUB_HEAD_REF`), else `LINKED_ISSUES_JSON` / `LINKED_ISSUE_FALLBACK_NUMBERS_JSON`, else the PR.
- **Readers.** `scripts/run_plan_codex.sh`, implement.yml (rendered in "Fetch issue comments" from `ISSUE_COMMENTS_FILE`, appended after the implementation context) and `scripts/review_apply_fixes.sh` (after `ledger_status.txt`) append the fenced journal; the result is `${RUNTIME_DIR}/attempt_journal.txt`. Both pre-push gate repair prompts add `=== EDITOR DELETIONS THIS ROUND ===` (removed lines of `git diff HEAD` for the allow-list files, `UNTRUSTED_DATA:`-prefixed, <= 4 KiB), that journal file and `prompts/mode-persist-journal-rules.txt`. `invoke_stall_judge` adds `attempt_journal` (<= 4 KiB) to its diagnostics from comments the tick already holds and appends the newest entry key to the decision-cache key; `unblock_ask_model` adds `attempt_journal` to `judge_context.json` from `item_comments.json`.
- **API budget.** `append`: at most 1 comments read (none with `--comments-file`) and 1 write; `render`: at most 1 read; each adds at most 1 cached identity lookup. Calls go through `scripts/gh_api_retry.py` with `optional=True`; every workflow that stages `attempt_journal.py` stages `gh_api_retry.py` beside it, and a missing module logs `reason=gh_api_retry_unavailable` before the plain fallback call.
