Both copies changed and still different (#8405, after #8316 left `main`'s push CI red): `scripts/sync_claude_live_copies.py` `plan()` now also returns a drifted, non-allowlisted path when the push changed both its template and its live copy, or, for a skipped or failed earlier run, when one commit last touched both copies. The template wins (`CLAUDE_LIVE_SYNC both_changed path=.claude/<path> action=template_wins`), and the path goes through the unchanged provenance routing: with no template commit after the live copy's last commit it is held as `reason=no_template_commits`, while a later template-only commit in the same push gets the normal provenance check. A push that changed only the live copy is still left alone. `sync --dry-run` (CI parity prep) does not apply this recovery and logs `action=left_for_parity` instead. In PR mode, `tests/claude_template_drift.py` `pending_template_paths()` no longer tolerates a drifted path when the PR changed both its template and its live copy (`git diff --name-only base...HEAD` over both prefixes), so PR CI fails and names the path. No GitHub API calls are added.
