- **Bound CI re-run supersedes a failed CI check (PR #9839).** `_mark_superseded` in `PR_CHECKS_JQ_SUPERSEDE_DEFS` (`scripts/pr_checks_lib.sh`) also tags each run of the configured CI check name with `_bound_rerun_succeeded`. It is true when the run is bound to CI workflow run ids (`PR_CHECKS_CI_RUN_IDS`) and a newer bound run of the same name (higher `id`, then later `started_at`) completed with `success`. Both gate filters of `_pr_checks_completed` drop such a run from the blocking count, and the CI side channel (`PR_CHECKS_LAST_CI_STATE`) drops a completed non-success run older than the newest bound success. A failure newer than that success, a still-running run (older or newer), unbound name-only matching, and every other required check name keep blocking. Cancelled-run supersession is unchanged. The mirror in `tests/test_review_rb_judge_self_run_exclusion.py` carries the defs verbatim. `_summarize_final_merge_blockers` runs unbound, so it is unaffected. Tests: `tests/test_pr_checks_lib_required_filter.py`.
