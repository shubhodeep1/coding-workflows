<!-- agents: section="Workflow architecture" -->
- **Daily observable operator-step tick (#10118, plan `docs/plans/pipeline-human-wait-elimination-plan.md` Phase 9).** `.github/workflows/workflow-log-analysis.yml` job `collect-logs` runs the step "Tick observable operator steps" (`scripts/operator_step_daily_tick.sh`) only on the `0 6 * * *` schedule (`!cancelled()`, `continue-on-error: true`, 10-minute timeout; no new job). The script skips with no git or API call when `OPERATOR_STEP_DAILY_TICK_ENABLED` is `false` (default `true`), skips on an empty `GH_TOKEN` (`no_pat`) or a missing/symlinked helper (`OPERATOR_STEP_DAILY_TICK_HELPER`, default the sibling `operator_step_issue.py`), fetches the `stable` tag's commit history only (`--filter=tree:0`, `--unshallow` on a shallow checkout), and runs `operator_step_issue.py tick --observable` with the tag commit; it always exits 0. `GH_TOKEN` is `secrets.GH_PAT` and no `--trusted-login` is passed: entries are written under the PAT login, so the trusted login is the `/user` read (passing `github-actions[bot]` would match no entry and would trust unsigned bot comments). Without `--observable` (the promote cycle) `tick` is unchanged. With it, an entry with no source-sha line is ticked only when every unticked step is classified (`_observable_condition`: `conditional_not_a_gate`, `stable_release` with every `#N` merged and its merge commit an ancestor of the tag, `allow_auto_merge` true on the repository read, `credentials` for a set/add/configure/provide/create step naming `GH_PAT` or `OPENROUTER_API_KEY` with a successful `review_autofix.yml`, `internal-review.yml` or `security-audit.yml` run updated within 7 days) and every check passes; any other UPPER_SNAKE name, rotate/revoke/scope/expire/permission wording or a human-object word outside the condition's own vocabulary makes the step unrecognised and keeps the entry open. Checks are cached per run and fail closed (`check_failed`; more than 10 PR reads is `deferred`). The ticked comment reuses `<!-- ai:operator-step:done stable=<sha> -->` with `Done: <reasons>; ticked by the daily operator-step tick.`, then `_close_tracker_when_done` (moved verbatim out of `resolve`, which still logs `OPERATOR_STEP_RESOLVE op=close`) closes an empty tracker as `completed` with the same re-read, reopen and `state_reason=reopened` rules. Output adds `closed` and `observed`.

<!-- agents: section="Stable log prefixes (contractual)" -->
- `OPERATOR_STEP_TICK` (daily observable tick, #10118; the prefix is already registered): `key= outcome=ticked|unrecognised|not_met|check_failed|deferred reason=<conditions>`, `tracker= outcome=closed|open reason=`, and from `scripts/operator_step_daily_tick.sh` `op=daily outcome=skip|error reason=disabled|no_pat|helper_missing|no_stable_tag|helper_exit`.
