- **Activation verification skips plans and raw input drops (refs tele-funtoken-msg-scoring#4726).** In PR mode, `scripts/activation_verify.sh` does not verify a merge whose every changed file matches `ACTIVATION_VERIFY_EXEMPT_GLOBS` (comma-separated, default `docs/plans/**`; a set value replaces the default; matching is path-aware, `**` spans folders and `*` stays in one). Such a merge gets no model call, no verdict comment and no `ai:activation-fix:v1` issue (`ACTIVATION_VERIFY mode=pr item=<n> outcome=skip reason=exempt_paths exempt_files=<count>`), so a merged plan or a designer's raw game build is no longer clarified, planned, implemented and auto-merged with nobody asking. A mixed PR is verified on its other files only: the context's `changed_files` holds them and the matching files go to `exempt_changed_files`, which `prompts/mode-activation-verify.txt` (and its `_templates` twin) tells the model never to report as a gap. A merged PR labelled `ai:skip-activation-verify` (registered in `.github/ai/label_contract.v1.json` and `scripts/label_helpers.sh`) is excluded by the `activation-verify` job's `if:` and again by the script from `PR_LABELS` before any GitHub call (`reason=skip_label`; a missing or malformed `PR_LABELS` means no label). The split uses the file list the job already fetches, so it adds no GitHub API call. A failed split logs a `::warning::` and verifies every file as before. Project mode (`run_project_activation_verify` in the poller) is unchanged. `tests/test_activation_verify.py` covers exempt-only, mixed, near-miss, label and project-mode cases and the workflow wiring.
