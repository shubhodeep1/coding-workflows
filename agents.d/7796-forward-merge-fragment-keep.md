Forward-merge heads in the folded-fragment keep (#7796): on a head ref matching `auto/forward-merge-stable-*` (`TARGET_BRANCH`, else `HEAD_REF`), `scripts/review_conflict_prepare.sh` also keeps a top-level `changelog.d/*.md` or `agents.d/*.md` path in a modify/delete conflict with index stages 1 3 (the head carries the release fold, `main` changed the fragment). It stages the stage-3 copy under the same checks as the stage 1 2 case: a regular file, not a symlink, byte-identical to `:3:<path>`; `README.md` and nested paths stay excluded, and the recount, commit and `orchestrator/project-*` deferral are unchanged. On every other head stages 1 3 still go to the resolver. Switch `CONFLICT_FORWARD_MERGE_FRAGMENT_KEEP_ENABLED`, read only on forward-merge heads and defaulted in the script (`review_autofix.yml` does not forward it, so a repository variable alone does not reach it): unset, empty or `true` (any case) on, `false` off, any other value off with a `::warning::` that does not print the value. `CONFLICT_FOLDED_FRAGMENT_KEEP_ENABLED=false` still turns off the whole block. Log: `Folded fragment keep: kept the base branch's <path>; the forward-merge head had folded and deleted it (index stages: 1 3).`
