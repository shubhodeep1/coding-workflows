- **`/deploy-activate` ticks verified operator steps.** Besides `scripts/operator_step_issue.py`, the `/deploy-activate` command (live and template copies, section `## Human-Steps Issue`) edits the `ai:operator-step` tracker: after a runbook step is confirmed, it changes only the matching `- [ ] **<step title>**` line(s) to `- [x]` in the key's highest-id entry comment by the pipeline account (as `_authoritative_entry_comments` reads it), in the lowest-numbered tracker authored by `github-actions[bot]` or an OWNER/MEMBER/COLLABORATOR (as `_trusted` / `find_issues` select it), via `mcp__github__update_issue_comment`, the same in-place edit as a person clicking the checkbox. It never adds, removes or rewords entries, never edits the tracker body, and never touches the needs-human digest. `operator_step_issue.py tick` copies the newest comment and appends a superseding one, so ticks made by hand or by the command carry over through `tick`. `upsert` compares the whole newest comment with a freshly rendered unticked entry, so a later `upsert` of the same key (an activation-verification re-run) appends an unticked comment; a resumed `/deploy-activate` run re-ticks it. If several trackers qualify, the command takes the lowest issue number, as the helper does. `tests/test_deploy_activate_command.py` pins the contract.
