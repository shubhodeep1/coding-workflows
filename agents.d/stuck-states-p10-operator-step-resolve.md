- **Release-pending activation gaps and operator-step resolve (stuck-states P10, Refs #8291).** This supersedes the "Operator-step drain" sentence above that the verifier prompt never lists promoting `main`, tagging `stable` or the consumer sync as a gap: such work is never an `operator` gap, and work that only takes effect once the next `@stable` release ships it is now one release-pending `code` gap with `dormant_until` `@stable contains <merge commit>`.
  - **Activation routing.** `activation_normalise_verdict` in `scripts/activation_verify.sh` takes the merge commit as an optional third argument (PR mode `MERGE_SHA`, project mode the target `HEAD`, computed before normalising). A gap whose cleaned `dormant_until` matches `RELEASE_CONDITION_RE` (`^@?stable\s+contains\b`, case-insensitive, kept equal to the one in `scripts/operator_step_issue.py` by a test) gets `release_pending: true`, its condition rewritten to `@stable contains <merge commit>` when the commit is 40 lower-case hex, `open_pr` null, and a model `operator` gap carrying it is rerouted to `code` (`rerouted: true`). Release-pending gaps go into no fix issue (no fix-issue search when they are the only code gaps) and no operator step; the verdict comment marks them ` (ships with the next `@stable` release; the promote cycle does this)`, and with no operator gap left the Telegram message stays `DEBUG`. Log: `ACTIVATION_VERIFY mode= item= op=release_pending_gaps count= rerouted= outcome=left_to_release`.
  - **Resolve step.** `orchestrate_poll.yml` step "Resolve released operator steps" (after "Resume dependency waits", before "Find active tracking issues", every tick, `continue-on-error: true`, from `.codex-workflow-src`; a missing, symlinked or older helper without `OPERATOR_STEP_RESOLVE` logs `::notice::OPERATOR_STEP_RESOLVE op=resolve outcome=skip reason=helper_missing`) runs `operator_step_issue.py resolve --repo`. It ticks only `pr-<n>` / `project-<n>` entries whose newest pipeline-login comment has a source-sha line, no `done`/`resolved` marker, and only release steps unticked (the step's own last `Stays off until then:` line matches `RELEASE_CONDITION_RE`, or the step has no such line and its title is a release verb naming `stable`, `AI Update Workflows` or the wrapper/consumer sync; a non-release dormant line makes it a human step whatever its title); entries that mix in a human step, and `unblock-*` keys, are never ticked. Containment is `GET compare/<sha>...stable` (`ahead`/`identical` only), cached per commit, at most 10 per tick oldest entry first, and the first compare error (a 404 where no `stable` tag exists) halts the rest of the tick. A tick appends one superseding comment with every box ticked and `<!-- ai:operator-step:resolved release=stable status=ahead|identical -->`; `tick` treats that marker as done.
  - **Close rule.** With at least one entry, no unticked box left (legacy body sections count for keys with no trusted comment), a tracker whose `state_reason` is not `reopened`, and a comment re-read showing no new key or box, it posts one `<!-- ai:operator-step:auto-closed -->` comment (skipped when a trusted one newer than every entry exists, i.e. an earlier close PATCH failed) and closes the tracker with `state_reason=completed`. A comment read after the close reopens it (`reason=reopened_after_close`) when an entry changed in between, and `upsert` re-lists open trackers after posting and reopens a tracker no longer listed (`OPERATOR_STEP_RESOLVE op=upsert_recheck issue= outcome=reopened reason=closed_during_post`); a pipeline-reopened tracker is never closed automatically again.
  - **Budget and failure modes.** One issue listing per tick when no tracker is open; otherwise one identity read, one paginated comment read, at most 10 compares, one comment write per ticked key, and only when closing two more comment reads, at most one comment write and one PATCH (another only to reopen); `upsert` adds one open-tracker listing after posting. A listing, identity, comment-read or write failure exits 2; the step logs `::warning::OPERATOR_STEP_RESOLVE op=resolve outcome=error reason=helper_exit` and the poll continues; the next tick reconciles from the comments. Kill switch `OPERATOR_STEP_AUTO_RESOLVE_ENABLED` (default `true` in the helper and the workflow; `false` makes no API call).
