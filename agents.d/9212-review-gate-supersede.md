- `_pr_checks_completed` (`scripts/pr_checks_lib.sh`) lets a newer `ai-review/head-gate` success override a failed `review / gate` check-run on the same PR head (#9212). A re-dispatched review run's own `review / gate` check-run lands on the `main` commit it runs on, so it never replaces a gate job that failed on the PR head (PR #9168, run 42736609134: rate-limited in 3 seconds, then every green re-dispatch was refused with `reason=required_checks_failed`). The rule applies only when `review / gate` would block (legacy `*` mode, or it is in the required set) and its newest check-run on the head (ordered by `[id, started_at]`) completed with a conclusion other than success/neutral/skipped. Only then does the gate read `commits/<sha>/statuses?per_page=100` (first page), and it drops that single check-run only when the newest `ai-review/head-gate` status (context pinned in the function, not read from `REVIEW_HEAD_GATE_CONTEXT`) is `success`, its `url` names the full 40-hex head SHA, and its `created_at` is strictly later than the check-run's `completed_at`. Everything else keeps blocking, including an older failed gate run next to the newest one and any other failed required check. `PR_CHECKS_LAST_REASON` values, `PR_CHECKS_LAST_PENDING`/`TOTAL` and the CI side channel are unchanged. A gate that did not fail costs no extra API call.
