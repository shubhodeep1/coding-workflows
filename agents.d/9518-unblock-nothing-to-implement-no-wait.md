- **Unblock judge also closes nothing-to-implement issues with no pending fix-up wait (#9518).** `unblock_main` calls `unblock_nothing_to_implement_close` a second time, with an empty fix-up, after its deterministic exits and before the model verdict. It applies the same checks as the #8470 close (pipeline-login newest block with the exact reason line, no later trusted implementation plan, standalone issue at stop `blocked`) plus one more: when a fix-up wait exists, the block must be newer than the time that wait ended (`wait_ended_at`: the wait comment's last update when it was already `done`, or the current run when the judge times it out). A block filed while the fix-up was still unresolved stays with the judge. The comment says no fix-up is pending, and the marker and the `op=nothing_to_implement` log line carry `fixup=none`; a `fixup=none` marker counts as already posted only when it is no older than the newest block, so a re-block after a reopen gets its own comment. No reads, at most the same three writes (comment, label, close), and no wait-comment update. `UNBLOCK_NOTHING_TO_IMPLEMENT_CLOSE_ENABLED=false` turns off both closes.
