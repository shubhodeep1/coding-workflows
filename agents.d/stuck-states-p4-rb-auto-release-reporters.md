<!-- agents: section="Workflow architecture" -->
- **Auto-release release-blocker reporters (stuck-states P4 / release-blocker Phase 2a, Refs #8291).** `scripts/auto_release_stable.sh` (`.github/workflows/auto-release-stable.yml`, 6-hourly) sends at most one `release_blocker` heal report per tick, always before its unchanged `AUTO_RELEASE_*` line, exit code and `GITHUB_OUTPUT`: `last_gate_failed` when the gate budget is spent on the `stable` tip and the newest failed gate run ended `RELEASE_BLOCKER_GATE_FAILED_MIN_AGE_SECS` (86400) ago (that run goes in `run_refs` when it ended `failure` or `timed_out`; a `startup_failure` run has no failed job and is named in the evidence only); `release_in_flight` when the oldest active gate / `promote-main-to-stable.yml` / `mark-stable.yml` run started `RELEASE_BLOCKER_IN_FLIGHT_MIN_AGE_SECS` (21600) ago (named in the evidence only, because the intake's `bind_report_claims` drops claimed runs that did not fail); and `stable_release_stale`, evaluated only when neither of those reported and no gate run on the tip exists other than completed `cancelled` runs, when `max(tag time, oldest unreleased commit date)` is `RELEASE_BLOCKER_STABLE_STALE_SECS` (86400) old (the gate is still dispatched afterwards). All inputs come from the run lists, the tag object (`.tagger.date`) and the compare response the tick already reads; the only new call is the `POST repos/<self>/dispatches`. The report is built with `workflow_failure_heal.py build-blocker-payload`, signed with `request-report-identity` (the workflow grants `id-token: write`) and wrapped with `wrap-dispatch`. Every reporter function is called as `<fn> || true`, bad thresholds warn and fall back to their defaults, and `RELEASE_BLOCKER_HEAL_ENABLED=false` turns the reporters off.
