Plan auto-approval and `files_touched` (consumer tele-funtoken-msg-scoring #4795): `run_plan_auto_approval_gate` also holds a plan whose "Files ... change" section lists an exact file outside the issue's `files_touched` list, with reason `plan_files_outside_files_touched` and that file in `denied_paths`. The implement-time `files_touched` guard would refuse such a commit and latch `ai:scope-blocked`, so approving the plan only wasted an implementation run. The check uses the implement matcher (`path_in_scope`: lockfiles allowed, `agents.d/*.md` allowed when `agents.md` is listed) and runs only when an earlier gate rule approved, the decision is not a Q108 pipeline plan grant, issue metadata was passed, and the implement guard would block: `ENFORCE_FILES_TOUCHED` exactly `true` (default), `ALLOW_OUT_OF_SCOPE_FILES` not exactly `true`, and `PLAN_FILES_TOUCHED_GATE_ENABLED` not `false`/`0`/`no`/`off` (default `true`). All three are read from the environment; `plan.yml` (job env) and every `orchestrate_poll.yml` step that sets `AUTOMATION_PATH_PLAN_AUTO_APPROVAL_ENABLED` forward them. An issue with no, an empty or a malformed list is not checked (implement skips it too); a directory or glob in the plan is not an exact file and is not checked. Unreadable metadata holds with `plan_gate_error`; a poller call without metadata skips the check. An automation-path hold keeps its own reason. The hold uses the existing paths: `AI_PHASE_GATE_V1 ... reason=plan_files_outside_files_touched outcome=defer paths=<files>`, one `<!-- ai:automation-path-plan-hold:v1 ... reason=plan_files_outside_files_touched ... -->` comment (`source=plan` or `source=poller`) whose text asks a maintainer to add the paths to `files_touched` or narrow the plan, and a WARNING. The workflow-heal gate (`--heal-scope-file`) is unchanged. Tests: `tests/test_files_touched_scope_guard.py`, `tests/test_plan_auto_approve_safe_state_fetch.py`, `tests/test_orchestrate_poll_process.py`.
