**Workflow log analysis section delivery (issue #9503, project #9116 P1b).** In `workflow-log-analysis.yml`, when `commit_report` delivered the report itself (`report_delivery` `pushed` or `pr_merged`, so `committed` and `report_branch` are blank downstream), the steps `Commit and push deep audit section` (`id: deep_audit_section_push`) and `Commit and push API redundancy section` (`id: api_redundancy_section_push`) re-create the run-unique `auto/workflow-log-analysis-report-<run_id>-<attempt>` branch from the target tip their `Sync latest report from target branch` step checked out, which holds the report (after `pr_merged` the run branch may already be deleted). The section commit is pushed there with the unchanged plain push loop (fast-forward only, no `--force`; a leftover branch fails as `push_failed`), never to the default branch. Each job exposes `section_branch` and `section_base_sha` (the tip the section commit sits on). api-redundancy's sync step continues on deep-audit's `section_branch` (`SECTION_BRANCH`), and its commit step reuses that branch and base, writing both outputs even when it adds nothing; when deep-audit pushed nothing it re-creates the branch from its own synced tip. `deliver-report` now also runs when either section job set `section_branch`, and passes `WLA_DELIVER_SECTIONS_ONLY` / `WLA_DELIVER_SECTIONS_BRANCH` / `WLA_DELIVER_SECTIONS_BASE_SHA` to `scripts/workflow_log_analysis_deliver_report.sh`. In that sections-only mode (default off; with it off the full-report delivery is unchanged) the script rejects a non-empty `REPORT_BRANCH` (`report_branch_invalid`), requires a 40-hex base that is an ancestor of both the target and the run branch (`section_base_invalid`; fetched with `--deepen=200` in the shallow checkout, `--depth=200` otherwise), skips the open-PR listing and the collision rename, diffs the run branch against the base (only `REPORT_FILE` may change, as a 100644 file; anything else or a deletion is `unexpected_paths`, an empty diff is `no_section_changes`), lints a sections body with `scripts/lint_pr_body_auto_close.py`, and opens one PR titled `chore: add workflow log analysis report sections (<file>)`. Kill switch: `WORKFLOW_LOG_ANALYSIS_REPORT_SECTIONS_VIA_PR` (default `true`, set in the workflow and in the step bodies; `false`/`0`/`no`/`off` restores the P1 skip, an unrecognized value warns without printing it and keeps delivery on). Contract tests: `tests/test_workflow_log_analysis_report_pr.py` (`test_section_*`) and `tests/test_workflow_log_analysis_report_delivery.py` (`test_delivery_sections_only_*`).

- `WORKFLOW_LOG_ANALYSIS_REPORT_DELIVERY` gains new values under the existing prefix (issue #9503, project #9116 P1b; no new prefix): the section push steps log `WORKFLOW_LOG_ANALYSIS_REPORT_DELIVERY outcome=section_pushed branch=<b> base=<sha> job=<deep-audit|api-redundancy>` after re-creating or continuing the run branch, and `scripts/workflow_log_analysis_deliver_report.sh` in sections-only mode can fail with `::error::WORKFLOW_LOG_ANALYSIS_REPORT_DELIVERY outcome=failed reason=section_base_invalid branch=<b>` or `reason=no_section_changes branch=<b>`. `outcome=skipped reason=no_report_branch job=<job>` now appears only when `WORKFLOW_LOG_ANALYSIS_REPORT_SECTIONS_VIA_PR` is off.
