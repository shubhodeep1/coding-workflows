### Evidence broker (`PERSIST_EVIDENCE_BROKER_ENABLED`, P11 of #8427)

Phase P11 of `docs/plans/persistent-unattended-workflows-plan.md`. Repo variables `PERSIST_EVIDENCE_BROKER_ENABLED` (default `false`), `PERSIST_EVIDENCE_BROKER_MAX_REQUESTS` (default `10`, clamped to 1..10) and `PERSIST_EVIDENCE_BROKER_MAX_BYTES` (default `32768`, clamped to 1024..65536), defaulted in plan.yml, `scripts/run_plan_codex.sh` and `scripts/evidence_broker.py` itself. `PERSIST_EVIDENCE_BROKER_MAX_ROUNDS` is fixed at 1 in this phase and is not read from the environment. With the switch off the request fragment is not appended, no request is parsed, no call is made, the planner runs exactly as before and the prompt is byte-identical.

- **Contract.** `prompts/mode-plan-evidence-request.txt` (byte-identical to `prompts/_templates/mode-plan-evidence-request.txt`) lets the planner end with at most 10 unfenced lines from the menu `EVIDENCE_REQUEST: git_log <path>`, `git_show <40-hex>:<path>`, `git_diffstat <40-hex>`, `run_steps <run_id>`, `run_log_tail <run_id> <job_id>`, `pr_files <n>`, `pr_diff <n>`, `issue <n>`, followed by `PLAN_SELF_CHECK: BLOCKER: evidence needed` and `STATUS: NOT_CLEAR` (the last non-empty unfenced line). Without both closing lines no request is honoured, so a CLEAR plan, or an issue quoting request lines, never causes a host call.
- **Validation (`validate`).** Fixed per-kind regexes; numbers positive without a leading zero (issue/PR numbers at most 10 digits, run/job ids at most 20); SHAs full lowercase 40-hex; paths from a conservative charset, relative, no `.`/`..`/empty part, no `.git`, no leading `-`/`~`, and accepted by `codex_isolated_workspace.readonly_allowed` and not named in `CODEX_ISOLATED_HIDE` (an invalid `CODEX_ISOLATED_HIDE` or a missing filter refuses every path). Refusal tokens, one per line: `unknown_kind`, `malformed`, `other_repo` (repo-qualified references, `#N`, URLs), `path_unsafe`, `credential_path`, `over_cap`, `duplicate`. Fenced lines are ignored (`partial_delivery._unfenced_lines`). Writes `evidence_broker_requests.v1` JSON and prints the count of valid requests.
- **Fulfilment (`fulfil`).** Requests are re-checked. Git kinds read the private ref `refs/persist/history`, fetched with P4's guarded flags when absent and deleted afterwards only when the broker created it (also on SIGTERM); `git_show` and `git_diffstat` need the commit in that history (`(not in default-branch history)` otherwise), `git_show` reads at most 4 KiB of a blob and refuses binary content, and `git_diffstat` shows filtered paths as `(filtered path)`. GitHub kinds make exactly 1 read each through `scripts/gh_api_retry.py` (`optional=True`, `max_attempts=1`, no raw fallback), so at most 10 calls per plan run: `actions/runs/<id>/jobs?filter=latest`, `actions/jobs/<job_id>/logs` (last 4 KiB), `pulls/<n>/files` (no patches, filtered paths hidden), `pulls/<n>` as `application/vnd.github.diff` (sections touching filtered paths dropped), `issues/<n>` (title, state, labels, `author_association`, body capped). A failed read renders `(unavailable)`.
- **Fence and redaction.** Results start with the host note `=== EVIDENCE BROKER ROUND (host note; one round only) ===` (listing refused lines as `refused: line <n> <token>`), then one `=== BEGIN UNTRUSTED BROKER RESULT <kind> <arg> ===` ... `=== END UNTRUSTED BROKER RESULT ===` block per request; every body line has control characters replaced and goes through `attempt_journal._scrub`. `git_show`, `run_log_tail`, `pr_diff` and `issue` text also goes through `workflow_failure_heal.redact_secrets`; without it those kinds answer `(refused: redactor_unavailable)`. Each answer is capped at 4 KiB on line boundaries and the total at `PERSIST_EVIDENCE_BROKER_MAX_BYTES` (`(omitted: byte cap)` stubs). `fulfil` also writes the sha256 of the results.
- **Wiring.** plan.yml stages `evidence_broker.py` in its own optional loop after the P4 loop and installs the fragment after the P2 done-check fragment. `scripts/run_plan_codex.sh` appends the fragment after the P4 evidence-pack block and, after the attempt loop, runs `plan_evidence_broker_round` (between `# BEGIN/END plan evidence broker (#8427 P11)`): `validate` (`timeout 60`), `fulfil` (`timeout 300`, `--default-branch "${PLAN_ISOLATED_BASE_BRANCH}"`), append the results, re-run `sanitize_codex_prompt_file`, and run the planner once more on the engine and model the loop ended with. A non-empty second output replaces `CODEX_OUTPUT_FILE` (the first is kept as `plan_output_first.txt`); otherwise the first output is kept, the hash file is removed, and plan.yml blocks it as before. "Record attempt journal entry (plan)" passes `--evidence-hash-file` (new optional `attempt_journal.py append` flag; anything but 64 hex records `""`) only with the switch on and a non-empty hash file.
- **Rollback.** Unset `PERSIST_EVIDENCE_BROKER_ENABLED` (or set it to anything but `true`).
