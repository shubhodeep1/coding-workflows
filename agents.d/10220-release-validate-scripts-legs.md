- **Budget watch covers release-gate jobs (#10220).** `scripts/ci_budget_watch.py` also reads the latest completed `test-and-mark-stable.yml` run (`actions/workflows/test-and-mark-stable.yml/runs?status=completed&per_page=1`, then that run's `jobs?per_page=100`: 2 extra API reads per budget-watch run) and reports any job at or above `CI_BUDGET_JOB_WARN_RATIO` (default 0.75) of its `timeout-minutes` in that file, measured from the first started step. Matrix legs use the base job's timeout. A run-time job named by the bare id (or display name) of a job that now defines `strategy.matrix` is never measured; unless its conclusion is `skipped` (a post-split matrix job skipped at job level by a failed `needs:`, also listed under its bare name) it belongs to a run from before the split and is counted as stale (`stale_jobs=N` on the `CI_BUDGET_GATE outcome=read` line), so the push that merges a split does not file an issue for the old serial run. A gate issue body names the measured run (`Measured run: <server>/<repo>/actions/runs/<id>`). Gate findings use subject `test-and-mark-stable.yml/<job>` (marker `<!-- ai:ci-budget:v1 kind=job_duration subject=test-and-mark-stable.yml/<job> -->`) and go through the same warning, dedup, cooldown and issue path as `ci.yml` jobs; `ci.yml` findings are unchanged. It logs `CI_BUDGET_GATE outcome=read|no_run|no_workflow|read_failed`; a missing workflow file makes no API call, and a failed read or a non-integer run id is a warning that skips gate jobs (fail-open).
