- The release gate's "Cleanup test artifacts" step (`test-and-mark-stable.yml`) cancels the Phase 3c `workflow_dispatch` review run before it deletes the smoke branch `ai/issue-<N>` (#9418). Closing a PR cancels that PR's `pull_request` runs but not dispatched ones: in release run 43283656910, dispatch run 43300092840 stayed `queued` for 48 minutes after cleanup closed the smoke PR, and it kept holding `review-gate-notice-<repo>-<pr>` the whole time. The step makes one `_safe_gh_jq` listing call to `actions/workflows/${REVIEW_WORKFLOW_FILE}/runs?event=workflow_dispatch&branch=ai/issue-<N>&per_page=20`. Bash then checks each returned run's id (must be numeric), event, branch and status (`queued`, `in_progress`, `waiting`, `pending` or `requested`) before it sends `POST actions/runs/<id>/cancel` for that run. Failure modes, all fail-soft: when the listing fails, the step logs `Warning: could not list dispatch review runs on <branch>` and leaves out the `No active dispatch review runs` line, so a run that may still be active is not reported as absent. When a cancel fails, the step logs `Warning: could not cancel dispatch review run <id>`. When `ISSUE_NUMBER` or `PR_NUMBER` is non-numeric, or `REVIEW_WORKFLOW_FILE` is not a plain `*.yml` basename, the step makes no API call and logs `Skipped dispatch review-run cancel (missing or invalid inputs)`. In every case cleanup continues and goes on to delete the branch.
