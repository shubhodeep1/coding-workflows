<!-- agents: section="Workflow architecture" -->
- Skip-path security pass (#8333): with `SINGLE_ISSUE_SECURITY_PASS_ENABLED` on and `AUTOFIX_SKIP_RUNS_SECURITY_PASS` on (workflow default `'true'`; the gate helper treats anything but an exact `true` as off, so a PR's new helper under `main`'s older YAML keeps the old suppression), an eligible docs-only, small-diff or `freshness_sync` PR keeps the deterministic skip. The gate emits `det_skip_security_pass=true` plus `det_skip_security_pass_pr_json` (the `/pulls/{n}` subset the pass reads, built from the gate's own PR read). `deterministic-skip-merge` checks out the gate head at `.codex-skip-pr-head` (git plumbing only) and runs "Single-issue security pass (deterministic skip)" (`scripts/review_autofix_step_deterministic_skip_security_pass.sh`), which calls `review_single_issue_security_pass.sh gate` with a fresh paginated comments read and one `closingIssuesReferences` read. The merge/label step runs only when the pass is not required or `steps.det_skip_security_pass.outputs.hold == 'false'`. On `exhausted=true` the step re-dispatches review once via `freshness_ci_failed_dispatch_review_workflow` (`scripts/review_freshness_ci_failed.sh`). The step posts no marker comment of its own (the pass still posts its usual exhaustion comment when it applies the label): the `ai:security-pass-failed` label makes the gate suppress the skip (`reason=security_pass_failed`) and the run reaches codex-agent's review-blocked judge unchanged. While the pass is required, the gate's "Withdraw stale auto-merge and publish head-gate status" step gets `DETERMINISTIC_SKIP=false`, so it posts no `ai-review/head-gate` success; the skip step posts that success (`scripts/review_head_gate.sh`, in the job's sparse checkout) only after `hold=false`. With the switch `false`, gate outputs and routing are exactly as before.

<!-- agents: section="Workflow file size limit" -->
- `deterministic-skip-merge` step bodies (#8333) use a third wrapper variant: `REVIEW_AUTOFIX_STEP_SCRIPT="${GITHUB_WORKSPACE}/.codex-freshness-src/scripts/<script>"`, then one verify line (checkout outcome `success`, `REVIEW_SUPPORT_SHA` is 40 hex and equals `git -C .codex-freshness-src rev-parse HEAD`, the file exists) that fails with `::error::`/`exit 1`, then `source`. The job runs no support staging, so the script must be in that job's `checkout_freshness_helper` sparse checkout. Registry: `REVIEW_AUTOFIX_SKIP_MERGE_JOB_STEP_SCRIPTS` in `tests/review_autofix_step_scripts.py` (plus the usual `REVIEW_AUTOFIX_STEP_SCRIPTS` and `REQUIRED_BOOTSTRAP_SCRIPTS` entries).
