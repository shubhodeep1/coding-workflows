**Head-bound `ai:needs-human` latch release (PR #9839).** `release_head_bound_needs_human_latches` in `scripts/orchestrate_poll_process.sh` runs in every repository, after `release_staged_support_needs_human_latches` in the post-loop block and before `run_unblock_scan` in the `UNBLOCK_SCAN_SWEEP_ONLY` idle-tick path. It removes `ai:needs-human` from an open PR whose newest trusted latch comment (a `[bot]` login, or OWNER/MEMBER/COLLABORATOR) is either the workflow-failure-heal non-retryable diagnosis (`<!-- ai:workflow-heal-non-retryable:v1 pr= head= reason= -->`, `scripts/workflow_failure_heal_intake.sh` `_non_retryable_route_apply`) or the review-round cap (`<!-- ai:review-round-cap:v1 -->` plus `<!-- ai:review-round-cap-head:v1 head=<sha> -->`, `scripts/review_sweep_round_cap.sh`). Both writers comment first and label second. The release therefore requires the newest `ai:needs-human` label event to be a `labeled` event by the same login, at most 30 minutes after the comment. It also requires: no later trusted comment, other than a release comment, mentioning `ai:needs-human`; no `ai:scope-blocked` / `ai:destructive-blocked`; and a fresh `pulls/<n>` read showing the PR open, still labelled, on a 40-hex head different from the latch head (read before the events, so a PR parked on its latched head costs no events read). The release-once marker counts only from a trusted author. Right before the write the comments, label events and `pulls/<n>` are read again; a newer trusted latch or needs-human comment, a different newest label event, a head change, or a PR that is closed, unlabelled or newly `ai:scope-blocked` / `ai:destructive-blocked` skips the PR. GitHub has no conditional label delete, so one comments read right after the removal puts the label back (no release comment) when a newer trusted latch or needs-human comment landed between the re-read and the removal; if that read fails, the release goes ahead (a blind re-add would never bind to a latch again) and logs `outcome=post_release_check_unavailable` with a `::warning::`. A cap comment without the head marker is never released. It deletes the label, then posts one comment ending in `<!-- ai:needs-human-auto-release reason=non_retryable_head_moved|review_round_cap_head_moved pr=<n> head=<sha> -->`, at most once per head. Switch: `NEEDS_HUMAN_HEAD_LATCH_AUTO_RELEASE_ENABLED` (default `true`, all three poller env blocks in `orchestrate_poll.yml`). Every read failure skips the PR for the tick (fail open). Tests: `tests/test_needs_human_head_latch_release.py`.
