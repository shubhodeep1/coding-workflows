- **Heal intake accepts `release_blocker` reports (stuck-states P4, release-blocker plan Phase 1, Refs #8291).** `scripts/workflow_failure_heal.py` adds the source kind `release_blocker`: a release or promotion on `stable` / `main` held back by one condition, with no failed run. `validate_payload` accepts only `RELEASE_BLOCKER_PAYLOAD_KEYS` (plus the empty fields its own normalisation adds, so the intake's re-validation stays idempotent), requires `workflow_name`, `blocker_reason` (`^[a-z_:]{1,80}$`) and `head_branch` in `RELEASE_BLOCKER_BRANCHES`, and caps `blocker_evidence` at `BLOCKER_EVIDENCE_LIMIT`. `skip_reason` returns `release_blocker_foreign_repo` for any source other than this repository. Producers (Phases 2 and 3) build the payload with `build-blocker-payload`. In `scripts/workflow_failure_heal_intake.sh` claimed gate runs are bound like a label report's (`BIND_RUNS_HERE`); with readable gate logs the generic log signature decides the fingerprint, otherwise it is `PAYLOAD_WORKFLOW_NAME` / `blocker:<reason>` / `release-blocker:<reason>` (evidence never enters it). On the `open` decision, `verify-release-blocker-reporter-run` binds `reporter_run` with one run GET (repository, `.github/workflows/<producer>` path from `RELEASE_BLOCKER_PRODUCER_SCOPE_PATHS`, display name, attempt, freshness) and adds that producer's fixed paths and the run to the frozen scope next to the engine_fallback inputs; a run-less report skips before the diagnosis (`scope_unavailable_no_runs stage=pre_diagnosis`) with a WARNING. The issue targets `head_branch` (`TARGET_BRANCH_SOURCE=release_blocker_branch`). Duplicates read the heal issue's comments once (`since=` bounded) and `occurrence-throttle` suppresses the comment and alert (`WORKFLOW_HEAL duplicate_throttled`) when a pipeline-authored occurrence comment's last-line `occurrence_at` marker is younger than `WORKFLOW_HEAL_OCCURRENCE_THROTTLE_SECS` (default 86400); a failed read posts (`warn occurrence_throttle_unavailable`). `compose_occurrence_comment` appends that marker as the last line for every kind; line 1 stays the bare occurrence marker `_recovery_occurrence_runs` compares. Filed issues, `consumer-config` / `transient` verdicts and recorded repeats of this kind alert at WARNING. Other kinds are unchanged.
