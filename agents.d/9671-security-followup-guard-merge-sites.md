- `RB_JUDGE_SECURITY_FOLLOWUP_GUARD` (#9671, `scripts/review_rb_judge.sh`, block `# BEGIN/END rb-judge security follow-up guard (#9671)`): `RB_JUDGE_SECURITY_FOLLOWUP_GUARD pr=<n> head=<judged sha> path=merge|terminal|sync result=refuse|unverifiable|unavailable action=skip_merge`. Each judge merge site runs `rb_judge_followup_merge_guard` (which runs `review_single_issue_security_pass.sh followup-guard` on a `/pulls/<n>` payload the judge already fetched) after its checks wait and freshness re-check, before the head-gate success status. Anything but `allow` skips the merge, posts no success status and leaves the PR in `ai:review-blocked`: `judge_merge_status=security_followup_guard` on the `merge` and terminal `fix` paths, `judge_skip_reason=security_followup_guard` on the `merge_with_followup` sync path (no follow-up issue). `unavailable` means the payload had no `.base.ref` (failed fetch), the guard script was missing, or the guard printed no known result. The transient merge retry (`rb_judge_merge_retry_transient`) re-runs the guard on the same payload before each retried merge, with `.base.ref` replaced by the live base from the retry's own PR read when the PR was retargeted during the delay (no extra API call); anything but `allow` there logs `RB_JUDGE_MERGE_RETRY ... outcome=security_followup_guard` after the guard line and stops the retries, so the site's merge-failure branch runs. When the retry's PR read gives no base ref (failed or unreadable read), that attempt's merge is skipped with `RB_JUDGE_MERGE_RETRY ... attempt=<n>/3 note=base_unverified action=skip_attempt` and the next attempt reads again; if no attempt reads a base, the site's merge-failure branch runs. An explicit `SINGLE_PASS_FOLLOWUP_GUARD_SWITCH=false` skips this check, so the retry behaves as before. Sites that never ran the guard keep the old retry behaviour. The guard's kill switch is `SINGLE_PASS_FOLLOWUP_GUARD_SWITCH` (the raw `SINGLE_ISSUE_SECURITY_PASS_ENABLED` repository variable; empty keeps the guard on).
- `AUTOFIX_DET_SKIP_MERGE_BOUND` reason `security_followup_guard_<refuse|unverifiable|unavailable>` (#9671, `scripts/review_autofix_step_det_skip_followup_guard.sh`, sourced by the `deterministic-skip-merge` merge step): logged with `action=refuse` when the security follow-up guard does not return `allow` right before either `gh pr merge --auto`; no merge labels are applied and the PR stays open. An empty `PR_BASE_REF` or `DEFAULT_BRANCH`, a missing library (unverified support checkout) or a missing guard script gives `unavailable`.
- `AUTOFIX_AUTO_MERGE_HEAD_BOUND` refusal `reason=security_followup_guard_<result>` gains a trailing `phase=pre_status|post_wait` key (#9671, `scripts/review_enable_auto_merge.sh`); the keys before it are unchanged.
