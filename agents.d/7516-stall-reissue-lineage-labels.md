Stall-recovery re-issue labels (refs #7516, btc_sweeper#223): both `close_and_reissue` arms in `scripts/orchestrate_poll_process.sh` take the replacement's lineage labels from the source-issue read they already make. The orchestrator arm (`execute_stall_recovery_action`, which standalone stall recovery's stall judge also reaches with an empty `local_id`) adds `ai:orchestrator-managed` only when `local_id` is set or the source already carried that label, and both arms carry `ai:check-triage` from the source (the standalone arm also from `labels_json`). A re-issued check-failure-triage issue therefore still passes `scripts/resolve_integration_ref.sh` CI-triage routing instead of failing with `reason=label_missing`, and triage dedup still sees it. No extra GitHub API calls: the triage label is passed without `ensure_label_exists`, because the source issue proves it exists. Tests: `tests/test_stall_reissue_lineage_labels.py`.
