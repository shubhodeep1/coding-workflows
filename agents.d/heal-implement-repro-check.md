Heal implement reproduction check (P2 steps 5 and 8 of `docs/plans/heal-evidence-reproduction-and-trends-plan.md`, Refs #8434): `scripts/heal_isolated_implement.sh` reads `WORKFLOW_HEAL_REPRODUCE_ENABLED` (default `false` in the script and in `implement.yml`'s `implement_run` step env; only `true`, case-insensitive, turns it on). With the switch on, the heal pre-push gate runs `codex_isolated_exec.sh prepare --workdir <gate-tree> --deps` under an allowlisted `env -i` (the same list `heal_reproduce.sh` uses, so no token reaches it) and appends `--venv <prep>/venv` to its `gate` call; a failed prepare logs `HEAL_ISOLATED_EDITOR phase=prepush_gate_deps outcome=unavailable` and the gate runs as before (fail-open). With the switch off the gate argv is byte-identical to the earlier call. After the gate and before the host transfer, `heal_impl_repro_check` looks up `APPROVAL_COMMENT_ID` in `ISSUE_COMMENTS_FILE`: only an approving comment whose first line starts with `/approved` and whose body contains `[repro-required]` on any line triggers the check (an empty id means not required; an id that cannot be read holds with `approval_unreadable`). Required and switch off holds with `reproduction_disabled` (fail closed, never skipped). Inputs: the test ids from the one unfenced `HEAL_COUNTERFACTUAL: REPRODUCIBLE: <ids>` line of `PLAN_FILE` (parsed with `partial_delivery.py`'s `HEAL_CF_LINE_RE` and `_unfenced_lines`; ids split on whitespace and on commas outside `[...]`, `path[::name]`, relative, no `..`, 1-50 ids, else `plan_tests_unreadable`) and the failing SHA from exactly one pipeline-written `- **Head SHA:** `<40-hex>`` line of `ISSUE_BODY_FILE` (else `failing_sha_unavailable`). The check adds a detached `repro-tree` worktree of the heal checkout's HEAD, copies into it every snapshot-baseline file whose host copy still matches the baseline (untracked, non-ignored host files and uncommitted host edits; regular files only, symlinks never followed, fail-open per file), transfers the final snapshot into it with the heal scope (a transfer refused as `reason=out_of_heal_scope`, or one refused for another reason, such as `host_baseline_changed` from an untracked host file, whose edits a scope-only check of the snapshot against the manifest finds out of scope (including a path the host transfer refuses as unsafe or that strict enumeration rejects), exits 42 like the host transfer; any other failed transfer logs `HEAL_ISOLATED_EDITOR phase=repro_transfer outcome=failed reason=<token>` and holds with `repro_tree_unavailable`, because the clean HEAD tree can differ from the host baseline), and runs `heal_reproduce.sh` twice under the allowlisted `env -i` with `WORKFLOW_HEAL_REPRODUCE_TIMEOUT_SECS` = min((gate budget - elapsed - 630) / 2, 3600) (under 120 s holds with `step_budget`): run 1 `--worktree repro-tree --baseline <failing>` (its `passes_at_failing_sha` token means "passes on the edited tree"); run 2, only when every test passed in run 1, `--sha <failing> --baseline <failing>` (a failing test comes back `pre_existing`, meaning "fails at the failing SHA"). `heal_reproduce.sh` is taken from the trusted support copy, or from the verified `.codex-workflow-src/scripts` checkout when only that copy has the gate module next to it (else `reproduce_unavailable`). The outcome is `fixed` only when every test fails at the failing SHA and passes on the edited tree; a mismatch is `not_fixed` (`still_failing`, `regression`, `passes_at_failing_sha`) and any unverified run, invalid result or flaky re-run is `unverified`. The result goes to `HEAL_REPRO_RESULT_FILE` (default `${RUNNER_TEMP}/heal-repro-result-${GITHUB_RUN_ID}.json`, mode 0600) as `heal_implement_repro.v1` (`{schema, outcome: fixed|not_fixed|unverified, reason, failing_sha, tests: [{test, at_failing_sha: fails|passes|unverified|not_run, on_edited_tree: passes|fails|unverified|not_run}]}`), and the script logs `HEAL_ISOLATED_EDITOR phase=repro_check outcome=<o> reason=<token> tests=<n>`. Anything but `fixed` exits 43 before the host transfer; `implement.yml` maps 43 to `implement_heal_preflight.sh refuse repro_not_fixed` (detail `not_fixed`, `unverified` or `result_unavailable`), which comments the escaped result (at most 20 test bullets) after the existing `ai:workflow-heal-scope-unverified:v1 reason=repro_not_fixed` marker, adds `ai:needs-human` and sets `SKIP_IMPLEMENT=true`. Existing exit codes (42) and refusal reasons are unchanged.
