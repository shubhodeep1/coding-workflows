Standalone stall recovery and non-target merges (PR #7709): when an issue's linked PR is merged, `_reconcile_standalone_merged_pr_issue` adds `ai:merged` only if `_pr_json_base_is_target_merge` accepts the PR's base. It uses the same default-branch / declared-integration-branch / managed rule as `close_merged_issues_sweep` and `issue_pr_status.yml`. A non-target merge gets no label and logs `STALL_SKIP issue=<n> reason=merged_non_target_base pr=<p> base=<ref> declared=<ref|none> phase=<phase> action=<action>`. For an `ai:check-triage` issue, it then runs `scripts/check_triage_resolution.py gate` (staged optionally by `orchestrate_poll.yml`; `CHECK_TRIAGE_RESOLVED_GATE_ENABLED=false` turns it off). The gate closes the issue with evidence once the triaged PR has merged and its check is green on the default branch. A missing base ref (GraphQL `base_ref` / REST `.base.ref`), or a default branch that cannot be read (`CWS_DEFAULT_BRANCH`, else one memoized `repos/<repo>` read), keeps the old behaviour and adds the label. The managed-child stall path (`recover_stalled_issue`) still adds `ai:merged` for any merged linked PR.
