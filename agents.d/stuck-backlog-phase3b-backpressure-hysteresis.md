Queue backpressure hysteresis and repository variables (Refs #9421, stuck-backlog plan Phase 3 steps 2, 3 and 8). This supersedes the phase 3 fragment's "stateless at HIGH" and "a repository variable does not reach them yet" text (`agents.d/stuck-backlog-phase3-queue-backpressure.md`).
- **Variables.** `orchestrate_poll.yml` passes `ACTIONS_QUEUE_BACKPRESSURE_HIGH` (`vars.* || '150'`), `ACTIONS_QUEUE_BACKPRESSURE_LOW` (`vars.* || '50'`) and `QUEUE_BACKPRESSURE_STATE_FILE` (`${{ runner.temp }}/queue-backpressure-state/state.json`) to "Process each tracking issue", "Run standalone stall recovery without active projects" and "Run unblock scan without active projects" (whose post-merge verify re-plans reach `phase_cap_can_dispatch`). The first two also get `QUEUED_RUN_ZOMBIE_MINUTES` (`vars.* || '1440'`); the env-parity contract test keeps their env identical. The script keeps its own defaults (150, 50, empty file); an empty `QUEUE_BACKPRESSURE_STATE_FILE` means no marker, which is the legacy stateless hold at HIGH.
- **Hysteresis.** `queue_backpressure_holds_dispatch` evaluates once per shell per tick: on at `ACTIONS_QUEUED_TOTAL >= HIGH`, off below LOW, and between the two the state the restored marker carries. `queue_backpressure_refresh_tick_state` (reserved action `tick_refresh`, never holds) runs that evaluation in the parent shell right after each main-body `prime_phase_concurrency_snapshot` call (post-merge verify on the unblock-scan path, the full poller) and as the first statement of `run_standalone_stall_recovery` for the idle-tick sweep, whose prime/recover/exit block is pinned by a test. The hysteresis stays inside `queue_backpressure_holds_dispatch` with no helper calls, because `tests/test_orchestrator_concurrency_caps.py` and `tests/test_poll_issue_run_linkage.py` copy that function out alone.
- **Marker.** JSON `{"active": bool, "intervals": [...]}`, written atomically (temp file plus rename) on every evaluated tick. Only a regular file of at most 64 KiB holding one JSON object with `"active": true` reads as active; a missing, unreadable, oversized or malformed marker reads as inactive. An existing `intervals` array is carried forward unchanged (this phase always writes `[]` otherwise; the persistence follow-up fills it and should treat unknown-depth ticks with an active marker as not paused). A failed write warns once and never fails the tick.
- **Cache.** "Restore queue backpressure state" (`actions/cache/restore@v4`, before "Process each tracking issue") and "Save queue backpressure state" (`actions/cache/save@v4`, after "Run worktree registry GC", `if: !cancelled()`), both `continue-on-error`, path `${{ runner.temp }}/queue-backpressure-state`. Cache keys are immutable, so the save key is per run (`queue-backpressure-state-v1-<run_id>-<run_attempt>`) and the restore uses the prefix `queue-backpressure-state-v1-` (the `clarify.yml` pattern), not a fixed day key. A miss (first run, eviction) reads as inactive.
- **Fail open.** Unknown depth: no hold, the marker is left as it is and the tick is not marked evaluated (a later call after the loader still evaluates). Non-numeric HIGH or LOW: one `reason=invalid_threshold` warning, no hold, inactive marker. HIGH < 1 (rollback: repository variable `ACTIONS_QUEUE_BACKPRESSURE_HIGH=-1`): no hold, no log, inactive marker. LOW < 1 or LOW >= HIGH: stateless hold at HIGH with one `outcome=stateless` warning.

- `QUEUE_BACKPRESSURE` additional formats (stuck-backlog Phase 3b, `queue_backpressure_holds_dispatch`; the prefix is already registered): `QUEUE_BACKPRESSURE outcome=<on|off> transition=<off_to_on|on_to_off> queued=<n> high=<h> low=<l>` (stderr, once per tick when the state differs from the restored marker; only when `QUEUE_BACKPRESSURE_STATE_FILE` is set), `::warning::QUEUE_BACKPRESSURE outcome=stateless reason=invalid_low low=<l> high=<h>` and `::warning::QUEUE_BACKPRESSURE outcome=marker_write_failed`. The existing `outcome=on|off|unknown`, `outcome=held` and `reason=invalid_threshold` lines are unchanged.
