### ChatGPT account store in claude-pool-broker (#8970, Phase 1 of `docs/plans/chatgpt-account-reviewer-trial-plan.md`)

- `tools/claude-pool-broker/src/index.ts` adds the `ChatgptAccount` Durable Object (binding `CHATGPT_ACCOUNTS`, migration tag `v1-chatgpt-accounts` in `tools/claude-pool-broker/wrangler.toml`): one instance per account (key `record`: `auth_json`, `seed_sha256`, `generation`, `last_refresh` (broker clock), `last_outcome`, `forced_refresh`, `checked_at`, `usage {five_hour, weekly, resets}`), plus a lower-case `__registry__` instance listing the names (at most 32). `/v1/pool` is unchanged.
- Read routes use the existing coding-workflows check (audience `coding-workflows-claude-pool`, `ALLOWED_WORKFLOW_FILES`): `POST /v1/chatgpt` returns `{account, auth_json}` for the usable account with the lowest weekly usage (then 5-hour, then name), with `tokens.refresh_token` removed, or `503 chatgpt_pool_empty`; `GET /v1/chatgpt/status` returns `{gate, accounts:[{account, generation, last_refresh, last_outcome, forced_refresh, checked_at, usage, usable, reason}]}` and never a token.
- Writer routes `GET` / `PUT /v1/chatgpt/refresh/<NAME>` (`<NAME>` is `^[A-Z0-9_]{1,64}$`, else 400 `invalid_account`) need audience `coding-workflows-chatgpt-pool-writer`, repository `CHATGPT_WRITER_REPOSITORY` (default `shubhodeep1/claude-workers`), workflow `CHATGPT_WRITER_WORKFLOW` (default `chatgpt-pool-refresh.yml`) at `refs/heads/main`, and a `ref` claim of `refs/heads/main`; anything else is 403 (`writer_repo_not_allowed`, `writer_workflow_not_allowed`, `writer_ref_not_allowed`, `wrong_owner`, `bad_audience`). GET returns `{auth_json, generation, seed_sha256}` or `404 not_seeded`. PUT compare-and-swaps on `base_generation` (`409 generation_conflict`; a non-reseed write with another seed is `409 seed_mismatch`; success `200 {generation: N+1}`); a missing `auth_json` keeps the stored one. Safety fields are strict (400), usage / `checked_at` / `forced_refresh` are lenient (malformed values become null / false).
- Usable: written within 7 days, `last_outcome` not `auth_failed` / `quota_exhausted`, and both windows under `CHATGPT_GATE` (default `0.9`); unknown usage and a window whose reset time has passed count as 0. Without the binding every route answers `503 chatgpt_store_unavailable`.
- `.github/actions/chatgpt-pool-token` (runs `scripts/chatgpt_pool_token.sh`; broker URL and OIDC audience from `.github/ai/claude_engine.json`): input `mode` `token` (default) writes `$RUNNER_TEMP/chatgpt-pool/<NAME>/auth.json` (0600, refresh token dropped again, every token masked) or `status` (allowlisted one-line `status` JSON, no file). Outputs `available`, `reason`, `account`, `codex_home`, `status`; it never fails the job (no accounts gives `available=false reason=broker_refused_chatgpt_pool_empty`), and the post step deletes the directory. No workflow calls it yet; `tests/test_chatgpt_pool_token.py` keeps every caller inside `ALLOWED_WORKFLOW_FILES`.
