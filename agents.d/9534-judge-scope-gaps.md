Judge scope gaps (Refs #9534, #9503): judge-written `files_touched` lists get the plan-grant companions, and a planning block caused only by missing scope goes to the unblock judge.

- **Companions.** `scripts/orchestrate_poll_process.sh` runs `apply_judge_files_touched_companions` (which calls the pure `add_files_touched_companions`, one `python3 -I -B` call importing `extract_files_touched`, `normalize_path` and `PIPELINE_PLAN_GRANT_COMPANIONS` from `scripts/files_touched_scope_guard.py`) on the judge-addition `NEW_BODY` and the judge-fix-up `FIX_BODY` before the metadata footer. The first `files_touched:` block gains whichever of `tests/**`, `changelog.d/*` and `agents.d/*` it lacks, after its last entry and at its entries' indent; nothing the judge wrote is removed or reordered, and a body without a block is unchanged. The review-blocked reissue site is not touched. `JUDGE_FILES_TOUCHED_COMPANIONS_ENABLED=false` (default `true`, passed by all three poller env blocks in `orchestrate_poll.yml`) turns it off; a helper failure keeps the original body. 0 API calls.
- **Prompt rule.** `mode-judge` (both copies) requires a new issue that reuses an existing workflow job or step to list every repository script that job or step runs in `files_touched:`. `mode-plan` (both copies) asks for `SCOPE_MISSING: <repo-relative path>` lines after `BLOCKED:` when the only blocker is scope.
- **Planning scope routing.** `plan.yml`'s "Route planning scope block" step (`id: route_scope_block`, same `if:` as "Handle blocked planning output", `continue-on-error: true`) runs `scripts/plan_scope_block_route.sh route` on the fence-stripped parse file. It routes only an issue (no `pull_request` key) whose parse file has exactly one `BLOCKED:` line and no `PLAN_SELF_CHECK: BLOCKER:` line (else `reason=not_scope_only`), with 1 to `MAX_OVERRIDE_PATHS` (20) `SCOPE_MISSING:` lines (counted before dedup) naming exact paths that pass `unblock_ledger._clean_path`, carry no whitespace, glob or trailing `/`, and that no existing `files_touched:` entry covers (`entry_matches`), and outputs `scope_routed` and `scope_marker` (`<!-- ai:guard-rejection:v1 item=<n> guard=scope reason=out-of-scope run=<plan run id> count=<n> truncated=false paths=<base64 compact JSON> -->`, checked against `REJECTION_RE`). The handler then adds `ai:scope-blocked` in the same `gh issue edit` that adds `ai:blocked` (after `ensure_label_exists`), keeps every existing comment line (the first stays `Planning blocked: human input required.`), and ends the comment with `🚨 **files_touched scope guard rejected this planning run.**` and the marker as the last non-empty line. The header, marker and label are added together or not at all, never for a wait-on-PR block: a failed label edit leaves the header and marker out, and a failed comment post removes `ai:scope-blocked` again before the step fails. `PLAN_SCOPE_BLOCK_ROUTING_ENABLED=false` (default `true`) turns routing off. The header is appended to `unblock_ledger.GUARD_REJECTION_HEADERS` as a documentary entry; a planning header without a marker gives `latest_rejection` reason `missing`, a broken marker `malformed`.
- **Resumption.** The item resolves to `stop=scope-blocked` (first in `BLOCK_LABELS`). An `override_guard` grant on `scope-blocked` now goes through `reset_ops` in `scripts/unblock_actions.py`: `/reclarify` with no plan, `/approved` with one, except that a planning scope block (`ai:scope-blocked` with `ai:blocked`) always gets `/reclarify`, so an older plan comment is never approved; for that pair it also removes `ai:blocked` (before the resume command), which neither command clears. A human `/answer` on the `ai:blocked` issue runs `plan_scope_block_route.sh answer-release` on the already-fetched comments (with `PLAN_SCOPE_PIPELINE_LOGIN` from one `gh api user` read, made only when the fetched labels include `ai:scope-blocked`) and also removes `ai:scope-blocked` only when the newest guard rejection by that login (the ledger's trust rule) is the planning `guard=scope reason=out-of-scope` one; anything else, or an unreadable file, keeps the latch. Tests: `tests/test_plan_scope_block_route.py`, `tests/test_plan_clarify_blocked_output.py`, `tests/test_unblock_judge.py`, `tests/test_orchestrate_poll_process.py`.
