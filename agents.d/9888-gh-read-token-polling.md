<!-- agents: section="Workflow architecture" -->
- **Polling reads on the job token (`gh_read`, issue #9888).** `gh_read [--same-repo-only] <gh args…>` in `scripts/gh_helpers.sh` runs a read with `GH_READ_TOKEN` (the job's `GITHUB_TOKEN`, separate 1,000 calls/hour/repo budget) instead of the `GH_PAT` in `GH_TOKEN`. It refuses anything that is not a read (rc 2, no gh call; `api` with a method other than GET/HEAD, field flags without an explicit GET, `--input`, `graphql`, and every subcommand except `run|pr|issue|workflow view|list` and `pr checks`), even with the feature off, because a write made with `GITHUB_TOKEN` does not start other workflows. It is plain `gh` when `GH_READ_TOKEN` is unset or empty, when `GH_READ_TOKEN_ENABLED` is `false`/`0`/`no`/`off`, or once the per-job latch `${RUNNER_TEMP}/gh_read_refused_<run>_<attempt>_<job>` exists (written on a 401 or a non-rate-limit 403). `--same-repo-only` sends targets other than `GITHUB_REPOSITORY` straight to the PAT (the job token cannot read the private consumer repos). On a 401/403/404 or rate limit it drops the job-token output, logs `GH_READ_FALLBACK`, and runs once with the PAT; other failures go back to the caller's `gh_retry`. `gh_retry` replays only `GH_READ_FALLBACK` lines from a successful attempt's stderr. xtrace is switched off before the token is read. The release-gate twin `gh_api_safe_job_token_read` (rc 0 ok, 2 refused, 3 use the PAT, 1 other failure) lives in the self-contained `scripts/comprehensive_test_and_release_gh_api.sh`; `gh_api_safe` tries it first only when `GH_API_SAFE_USE_READ_TOKEN=1` (default 0; `gh_api_safe_quiet_print_read` sets it inline, and `scripts/stable_e2e_step_wait_review.sh` sets it for the whole wait step). Call sites: the promote cycle's idle-wait and gate polls, the heal-queue comment listing and holder-run read, the dispatch watcher's registration and completion polls, the review wait loop, the orchestrate-cancel status poll, and `gh_review_pr_state`. The workflows export `GH_READ_TOKEN: ${{ vars.GH_READ_TOKEN_ENABLED != 'false' && github.token || '' }}` only on the steps/jobs that run these loops; `test-and-mark-stable.yml` adds the top-level read scopes `actions`, `pull-requests` and `issues`. `tests/test_gh_read.py` locks the contract.

<!-- agents: section="Stable log prefixes (contractual)" -->
- `GH_READ_FALLBACK` (`scripts/gh_helpers.sh` `gh_read`, `scripts/comprehensive_test_and_release_gh_api.sh` `gh_api_safe_job_token_read`; stderr: `GH_READ_FALLBACK reason=<401|403|404|rate_limit> caller=<script>`, issue #9888). One line each time a polling read made with the job token (`GH_READ_TOKEN`) is refused or rate limited and is retried once with `GH_PAT`. `reason=401` or `reason=403` also latches the job token off for the rest of the job, so a missing `permissions:` scope logs once per job. The line never carries the token or the command's arguments.
