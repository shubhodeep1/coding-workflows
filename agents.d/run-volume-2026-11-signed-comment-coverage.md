Signed job-token comments, coverage (run-volume plan item 15). Measured on 2026-11-17, after `AI_COMMENT_SIGNING_SECRET` was set here, about 75 % of new pipeline comments that should have been signed (96 of 128, 10:30 to 12:47 UTC) still went out with `GH_PAT`. Part of that was temporary: a run takes its secret values when it is created, so runs queued before the secret existed (much of the review backlog that day) ran with `AI_COMMENT_SIGNING_SECRET` empty and posted with the PAT throughout. Two causes were bugs, both fixed:

- **Oversized orchestrator state parts.** `scripts/orchestrate_state_v2.py` packed each part to within 256 bytes of GitHub's 65,536-character cap, so the signature line (at most about 335 characters) pushed every full part over and the shim kept it on the PAT (`AI_COMMENT_SIG outcome=skip reason=body_too_long`); only the short last part was signed. `DEFAULT_FRAMING_HEADROOM` is now 768, which can add one part to a large state. `tests/test_comment_signature.py` checks that a full part still fits once signed with the longest repository, login and ids.
- **Scripts that post before any step loaded the shim.** The shim reaches a step only when that step, or an earlier step of the job, sourced `scripts/gh_helpers.sh` in its own shell. A job such as review_autofix's `deterministic-skip-merge` sourced it only inside a subshell, so `review_single_issue_security_pass.sh` called the real `gh`. Every bash script that posts comments now starts with `[ -z "${BASH_SOURCE[0]:-}" ] || AI_COMMENT_SIG_ACTIVATE_ONLY=1 source "$(dirname "${BASH_SOURCE[0]}")/gh_helpers.sh" >/dev/null 2>&1 || true`: activate-only mode installs the shim and returns before defining the rest of the library, so a script's own functions are never overridden and a later full source still loads it. The Python scripts that post through `gh` (`attempt_journal.py`, and through it `persist_postmerge_verify.py`; `check_triage_resolution.py`, `operator_step_issue.py`, `provider_outage.py`, `review_security_hold_sweep.py`) call `_activate_signed_comments()` before their first `gh` run, which does the same through `bash` and prepends the shim dir to the process `PATH`. Both are no-ops without the secret or without `gh_helpers.sh` next to the script, and make no API call. `tests/test_comment_signature.py` lists the activated scripts.

Comments the PAT created before the secret was set keep the PAT as author when they are edited in place (standalone stall state, attempt journal, completion status); edits start no workflow, so this costs nothing. `<!-- tg_cleanup:N -->` markers are posted with `curl` by `scripts/tg_helpers.sh` and stay on the PAT.
