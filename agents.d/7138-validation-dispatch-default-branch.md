- The orchestrator poller dispatches the validation wrapper without `--ref` (issue #7138), so GitHub runs the default branch's `ai-validate.yml` / `internal-validate.yml`; `validate.yml` resolves the integration branch from `tracking_issue` and checks it out. Earlier pollers passed `--ref <integration branch>`, which ran that branch's own wrapper and its possibly stale `validate.yml` pin (binance-blessings#249). A project those runs parked with `raw_status=harness_error` is re-dispatched once from the default branch, counters kept, when the failed run's recorded `validation_last_run_head_branch` is not the default branch, or for legacy state (no `validation_last_dispatch_workflow_ref`) when the project has a separate integration branch. Guards: state flag `validation_stale_pin_recovered_ref` and a `<!-- validation-stale-pin-recovery:<sha> -->` comment by the pipeline login; nothing is dispatched until the state flag is written (a failed write retries next tick); an operator `/revalidate` on the same tick wins. Kill switch `VALIDATION_STALE_PIN_AUTO_RECOVER_ENABLED` (default `true`); `ENABLE_VALIDATION=false` also skips it (`reason=validation_disabled`).
