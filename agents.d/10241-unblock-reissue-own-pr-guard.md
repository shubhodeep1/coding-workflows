<!-- agents: section="Workflow architecture" -->
- **Unblock re-issue own-PR guard (issue #10241).** For an issue item, `scripts/unblock_judge.sh` (`unblock_resolve_own_prs`) merges `own_prs` (`{"status": "ok"|"unknown", "prs": [{number, head_sha, mergeable_state, head_gate, ci_final, lease_wait}]}`) into `context.json` and `own_pull_requests` into the judge context. The facts come from `UNBLOCK_OWN_PR_GRAPHQL_QUERY`, the #9809 impl-pr query extended with head SHA, merge state, author, labels and the head commit's `ai-review/head-gate` / `ci/final` statuses; the response is reused when the impl-pr lookup ran, otherwise it is one read. `unblock_actions.py own-prs` keeps only open same-repository `ai/issue-<n>` PRs by the pipeline login, counts a status only from the pipeline login, and returns `unknown` for any unreadable shape, `hasNextPage`, or an empty login with a candidate. A failed read is `unknown`, never "none". `lease_wait` uses `MERGE_LEASE_WAIT_LABEL`; when the step does not export it (`unblock_judge.yml`), `unblock_resolve_own_prs` reads the repository variable once (`GET actions/variables/MERGE_LEASE_WAIT_LABEL`), only when the response has an open same-repository `ai/issue-<n>` node by the pipeline login (fork and other-author nodes never trigger it); a missing variable (HTTP 404) keeps the default `ai:merge-lease-wait`, and any other failed read makes the facts `unknown` (`reason=label_read_failed`). A reply with GraphQL `errors` is `unknown`.
  - G2: before the round marker, a standalone issue's `reissue` asks `unblock_actions.py own-pr-guard --require-facts`. While an own PR has a head-gate success, carries `ai:merge-lease-wait`, has an unreadable (`unknown`) head-gate, or the read was `unknown`, the judge posts one comment ending in `<!-- ai:unblock-wait:v1 item=<n> reason=own_pr_green|own_pr_lease_wait|own_pr_unknown pr=<m|unknown> -->` and stops: no round, no ops. A guard that cannot answer refuses with `own_pr_unknown`. `plan()` applies the same guard as a backstop, ahead of the CI-owner superseded close.
  - G3: a standalone re-issue that goes ahead adds, per other own PR (not the verified open CI-owner PR), a `comment` op with `created_ref: true` ("Superseded by #{created_issue}", filled by `unblock_run_ops` from the same run's `create_issue`) and a `close` op with `pr: true`.
  - G4: the merge-lease tick (`_mt_merge_lease_tick`, `_mt_merge_lease_tick_multi`, Phase 2 only) skips and unlabels a waiter whose same-repository `ai/issue-<n>` source issue is CLOSED / NOT_PLANNED, from one batched GraphQL read per base (`_merge_lease_not_planned_source_prs` in `scripts/pr_checks_lib.sh`, at most 50 issues, fail open; an empty `gh_retry` reply is a logged read failure). The update-mode gate (`_merge_lease_gate`, `_merge_lease_gate_multi`) refuses a free lease to such a caller with outcome `wait`, reason `source_issue_not_planned`, from one read of the caller's own row.
  - Switches: `UNBLOCK_REISSUE_OWN_PR_GUARD_ENABLED` (G1-G3) and `MERGE_LEASE_SOURCE_ISSUE_GUARD_ENABLED` (G4), default `true`; only `false` turns either off. `review_autofix_sweep.yml` does not forward the lease switch, so its tick uses the script default.
