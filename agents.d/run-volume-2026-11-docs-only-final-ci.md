Docs-only final CI (run-volume plan item 4, `docs/plans/reduce-actions-run-volume-plan.md`, decisions D12 and D13). A PR whose changed files are all docs no test reads gets a final CI run without the test jobs:

- `_pr_ensure_final_ci` (`scripts/pr_checks_lib.sh`) reads `GET pulls/<pr>/files?per_page=100` once, only when it is about to dispatch. It passes `-f docs_only=true` when every `filename` and `previous_filename` is on the list in `scripts/ci_docs_only_paths.sh` (`classify`). An unreadable or empty listing, a full first page (100 files, maybe more), or a classifier missing next to `pr_checks_lib.sh` dispatches the full suite. A refused `docs_only=true` dispatch (a branch whose `ci.yml` predates the input) is retried once without it. The classifier is staged with the library: `OPTIONAL_BOOTSTRAP_SCRIPTS` in `scripts/stage_workflow_support.sh` and the `.codex-freshness-src` sparse checkout in `review_autofix.yml`. The sweep checks out the whole default branch.
- `ci.yml` takes the `workflow_dispatch` input `docs_only` (string, default `"false"`). The seven test jobs (`tests-hooks-and-orchestrator`, `tests-heal-plan-and-validation`, `tests-promote-stall-and-review`, `tests-release-and-log-analysis`, `orchestrate-poll`, `tests-system-python`, `tests-sandbox-python`) carry `if: inputs.mode != 'quick' && inputs.docs_only != 'true'` and still have no `needs`. `static-checks` always runs.
- In a docs-only run `lint` checks out `refs/pull/<n>/merge` with depth 2 and runs `scripts/ci_docs_only_paths.sh verify` (step id `docs_only_verify`). It fails unless HEAD is a merge whose second parent is `github.sha` and every file it changes against its first parent (`git diff --no-renames`) is on the list. The aggregate step accepts `skipped` only for the jobs in `CI_DOCS_ONLY_GATED_JOBS`, only when that step succeeded (`CI_DOCS_ONLY_VERIFIED`). Every other job and result still needs `success`, so a wrong input fails `lint` and `final-ci-failed` sends the PR back to review.
- Push runs (`main`, `stable`, `orchestrator/project-*`) are never gated: check-failure triage's base gate reads the newest push run on the base, and heal's stale auto-close counts green push runs (`HEAL_STALE_GREEN_RUNS`).
- Known limits: `verify` runs the copy of `scripts/ci_docs_only_paths.sh` in the merge ref, the same trust as the rest of `ci.yml`, which is read from the PR branch. If `refs/pull/<n>/merge` has not caught up with the dispatched head when `lint` runs, `verify` fails with `reason=head_moved`. `lint` goes red, `final-ci-failed` sends the PR back to review, and the next head gets a new final run.
- Tests: `tests/test_ci_docs_only_final_ci.py`. To change the list, edit `ci_docs_only_path_is_safe` and check that no test job or CI step reads the new path.
