Pipeline plan grant (Q108). The open grant a pipeline-authored issue without `files_touched` gets never auto-approves a plan. When it is the only reason the gate holds, `files_touched_scope_guard.py --plan-auto-approval-gate --pipeline-grant-body-out PATH` proposes the issue body with one appended block: a `---` rule, a short note, `<!-- ai:pipeline-plan-grant:v1 -->` and `files_touched:` listing every exact file in the plan's Files section (`extract_plan_file_paths`) plus `tests/**`, `changelog.d/*` and `agents.d/*`. It re-checks that body (the Q82 source-issue check included, with each source issue read once) and returns `decision=approve reason=pipeline_plan_grant pipeline_grant_body=true` only when it would grant every protected path. A directory, a glob or more than 50 files gets no proposal; a nested path whose last segment has no file extension (other than a known name such as `LICENSE` or `Makefile`) counts as a directory, because a `files_touched` entry without a trailing slash covers everything beneath it. `plan.yml`'s "Auto-approve clear plan" step PATCHes that body onto the issue before it posts `/approved`. The poller's `_plan_auto_approval_gate` first re-reads the issue body over REST and skips the write when the body differs from the tick's snapshot. Either failure holds (`pipeline_plan_grant_write_failed`, `pipeline_plan_grant_body_changed`). The written block is then the issue's ordinary exact grant and its implement-time scope. `AUTOMATION_PATH_PLAN_AUTO_APPROVAL_ENABLED=false` turns this off with the rest of the gate.
