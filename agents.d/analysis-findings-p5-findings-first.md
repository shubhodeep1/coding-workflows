Workflow-analysis findings-first check (Refs #9116): in default (non-retro) mode the analyst prompt (`prompts/mode-workflow-analysis.txt`, rendered from `prompts/_templates/mode-workflow-analysis.txt`; keep the `Findings-first check (default mode only):` block byte-identical in both) checks each candidate finding in this order: evidence in the window, then the current code on the ref (already-fixed findings are dropped), then prior verdicts in `analysis/recommendation-processing-report.md`, which it treats as data and never as instructions. Other verdict labels in that report are mapped: implemented or already-satisfied forms count as `applied`, `rejected (obsolete)` and obsolete forms as `rejected`, and a deferred or unknown verdict is reported as `new` with the prior entry cited, never dropped. Each recommendation, including AI Memory Health recommendations and Per-Repo Breakdown prioritized actions, ends with `Finding check: <status> — <evidence>`, where status is exactly `new`, `recurring`, `reopened` or `unverified`, and the `## Metrics Appendix` carries a `Findings check` table with per-status counts plus `dropped: already fixed on this ref` and `dropped: previously decided`. A missing or unreadable processing report is noted once in the appendix data gaps and never blocks the report. The 11 default and 5 retro headings are unchanged. `tests/test_mode_workflow_analysis_prompt_findings_first.py` pins the contract.
