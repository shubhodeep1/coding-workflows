- **Heal counterfactual hold expiry and implementation-first stall PR resolution (#9986, plan `docs/plans/pipeline-human-wait-elimination-plan.md` Phase 7).** In the `heal_counterfactual_hold` branch of `_plan_auto_approval_gate` (`scripts/orchestrate_poll_process.sh`), after `_heal_stale_close_check` and before `_heal_counterfactual_hold_notify`, `_heal_counterfactual_hold_expiry_check` reads only the gate's comment snapshot. The hold age runs from the earliest trusted `ai:heal-counterfactual-hold:v1 issue=<n> ` marker newer than the latest human answer (OWNER/MEMBER/COLLABORATOR, non-`[bot]`, body starting `/approved`, `/reclarify` or `/answer`; bodies with `[auto-answered-by-`, `_Orchestrator stall recovery` or `_Standalone stall recovery` do not count, because the pipeline login can be the owner). At half of `HEAL_COUNTERFACTUAL_HOLD_MAX_DAYS` (default 3, clamped 1-30) it posts `<!-- ai:heal-counterfactual-hold-escalated:v1 issue=<n> -->` and a Telegram WARNING. At the limit, once the escalation is at least half the limit old, it PATCHes `state=closed`/`state_reason=not_planned` (labels untouched) first, then posts `<!-- ai:heal-counterfactual-hold-expired:v1 issue=<n> days=<d> -->` and a Telegram DEBUG (when that post fails it PATCHes `state=open`, warns, sends a Telegram DEBUG (the single-attempt POST may still have created the marker, which then makes the hold count as reopened; DEBUG because this branch writes no marker and repeats every tick while the POST fails) and logs `skipped reason=expired_marker_post_failed` so the next tick retries; if the reopen also fails it warns, sends a Telegram WARNING telling a maintainer to answer before reopening and logs `expired reason=reopen_failed`); an expired outcome suppresses the hold notice. A trusted expired marker on an open issue means a person reopened it: outcome `kept reason=reopened`, never closed again; each such tick logs a `::notice::` (no Telegram) that the hold will not expire on its own, which also traces a lost response on the expired-comment POST. Markers count only from the gate login, a `[bot]` login or OWNER/MEMBER/COLLABORATOR. Switch: `HEAL_COUNTERFACTUAL_HOLD_EXPIRY_ENABLED` (default `true`). `invoke_stall_judge` calls `_stall_judge_resolve_linked_pr` in the main shell (it sets `STALL_JUDGE_LINKED_PR_NUM` and `STALL_JUDGE_LINKED_PR_JSON`, which the judge reuses instead of a second `pulls/<n>` read): an open `ai/issue-<n>` PR passing `_pr_json_is_issue_implementation_pr`, then the newest (at most 10) cross-referenced PR passing it whose files are not all under `docs/plans/` (skip never applies to an `ai/issue-<n>` head; `_pr_files_all_under_docs_plans` caches per tick in `STALL_PR_DOCS_PLANS_ONLY_CACHE` and fails open), then the last cross-reference unless docs-only. Switch: `STALL_PR_RESOLVE_IMPLEMENTATION_FIRST_ENABLED` (default `true`; `false` keeps `_issue_cross_ref_pr_number_last`). All three variables are forwarded by `orchestrate_poll.yml` next to `HEAL_COUNTERFACTUAL_GATE_ENABLED`.

<!-- agents: section="Stable log prefixes (contractual)" -->
- `HEAL_COUNTERFACTUAL_HOLD_EXPIRY` — emitted once per held heal issue by `_heal_counterfactual_hold_expiry_check` in `scripts/orchestrate_poll_process.sh` (issue #9986). Format: `HEAL_COUNTERFACTUAL_HOLD_EXPIRY issue=<n> outcome=escalated|expired|kept|skipped reason=<token> age_days=<d>`. `reason` is limited to `[a-z_]` (`disabled`, `invalid_issue`, `heal_route_unknown`, `snapshot_unreadable`, `reopened`, `answered`, `no_hold_marker`, `bad_timestamp`, `below_half_limit`, `half_limit`, `escalation_post_failed`, `escalated_awaiting_expiry`, `escalation_window`, `close_failed`, `expired_marker_post_failed`, `reopen_failed`, `max_days`). `age_days` is digits only.
LOG_PREFIX.name=HEAL_COUNTERFACTUAL_HOLD_EXPIRY
- `STALL_JUDGE_LINKED_PR` — emitted once per stall-judge invocation by `_stall_judge_resolve_linked_pr` in `scripts/orchestrate_poll_process.sh` (issue #9986). Format: `STALL_JUDGE_LINKED_PR issue=<n> pr=<n|none> source=branch|cross_ref_impl|cross_ref_last|none|legacy skipped_docs_plans=<k>`.
LOG_PREFIX.name=STALL_JUDGE_LINKED_PR
