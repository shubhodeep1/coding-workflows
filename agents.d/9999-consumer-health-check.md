<!-- agents: section="Workflow architecture" -->
**Daily consumer health check.** In `shubhodeep1/coding-workflows` only, the `poll` job of `.github/workflows/orchestrate_poll.yml` runs `scripts/consumer_health_check.sh` once per UTC day: the step `Look up today's consumer health check` checks for an Actions cache entry `consumer-health-check-<YYYY-MM-DD>`, and `Record today's consumer health check` saves it only after a successful check, so later ticks that day skip without an API call and a failed or missed tick is retried on the next one. For each repository in `.github/ai/consumer_repos.json` the script reads the workflow list, the newest `ai-orchestrate-poll.yml` run (only when that wrapper is active) and the open `ai:orchestrator-tracking` issues, and `scripts/consumer_health_check.py evaluate` decides. A wrapper (a `*.yml` under `workflow-templates/`) in state `disabled_inactivity` is switched back on; one disabled by a person or token, or in any other non-active state, is reported (`workflows_disabled`), as are an active poller with no run in `CONSUMER_HEALTH_POLLER_SILENT_HOURS` (default 6, `poller_silent`), an open tracking issue with `CONSUMER_HEALTH_TRACKING_COMMENT_LIMIT` or more comments (default 2000, `tracking_issue_comments`) and a failed read (`unreadable`). Each consumer and problem gets one `ai:consumer-health` issue in this repository, whose body starts with `<!-- ai:consumer-health:v1 repo=<owner/repo> problem=<key> -->`, and one Telegram WARNING when it opens. Only issues the pipeline account filed with that first line count: an open one suppresses a duplicate, and one whose problem is gone (or whose repository left the consumer list) is closed with a comment. A repository that could not be read keeps its other issues open. `CONSUMER_HEALTH_CHECK_ENABLED=false` turns the check off.
