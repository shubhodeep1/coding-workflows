**A final-CI repair no longer replaces a head whose final CI turned green (Refs #10023, #9725).**
- Gate (`scripts/review_autofix_step_evaluate_gate.sh`, "Final-CI repair" block): the one `GET commits/<head>/statuses?per_page=100` the block already makes now also returns the newest `ci/final` status posted by `github-actions[bot]` (`scripts/ci_final_status.sh` posts it with `github.token`). The Python decision line for `decision=repair` carries `marker_at=<newest trusted ai:final-ci-failed:v1 time>` before `attempt=`. If the head-gate is a pipeline `success` and that `ci/final` is a `success` whose `created_at` is later than `marker_at`, the run ends with `should_run=false` and `skip_reason=final_ci_now_green`: no repair, no reviewer panel, and the approved head is left as it is. In every other case, and whenever a read or parse fails, the old behaviour applies. The check adds no API call.
- Repair step (`scripts/review_autofix_step_prepush_test_gate.sh`, `review_prepush_test_gate_final_ci_finish`): the new helper `review_prepush_test_gate_final_ci_now_green <from>` makes one `GET commits/<from>/statuses?per_page=100` per final-CI repair run, for every outcome except `head_moved`. It prints `green` only when the newest `github-actions[bot]` `ci/final` is `success`, an older one in the same response is `failure`, and that `success`'s `created_at` is later than the newest `ai:final-ci-failed:v1` marker for the head. It reads the marker time from the comments snapshot "Collect PR metadata" already wrote (`PR_ISSUE_COMMENTS_FILE`, no API call), using any author: a later forged or quoted marker only makes green harder. This applies the gate's rule, so a stale `success` left by a failed `ci/final=failure` POST (`scripts/ci_final_status.sh`) cannot drop a repair the gate selected. A missing snapshot or marker time is `not_green`. On green, the step resets any repair commit to `from` and writes `INTEGRATION_TEST_REPAIRED=false` and `INTEGRATION_TEST_REPAIR_ACTIVE=true`, so nothing is pushed and the reviewer/editor steps stay skipped. It posts no `ai:final-ci-repair:v1` marker, so a later dispatch on the same head ends at the gate's green skip instead of `head_cap`. Any other result, including a failed read, keeps today's committed or fallback path.
- Hand-back (`scripts/review_final_ci_failed.sh`): when the classifier verdict on attempt 1 is `abandoned` (only cancelled jobs, no timeout annotation, no failed test), the script still logs `infra_rerun_deferred reason=abandoned` and now also logs `outcome=deferred reason=cancelled_jobs_rerun`. `classify-run` and what the sweep re-runs are unchanged. A job cancelled at its `timeout-minutes` limit is `genuine` and is handed back. The gate and repair-step checks above cover that case once the head turns green.
- Tests: `tests/test_review_autofix_clean_same_head_gate.py`, `tests/test_review_prepush_test_gate.py`, `tests/test_review_final_ci.py`.
