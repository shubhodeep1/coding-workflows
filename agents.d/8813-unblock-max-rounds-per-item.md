- **Unblock judge per-item round cap (#8813, stuck-states P6a, Refs #8291).** `scripts/unblock_ledger.py` reads the cap from the repository variable `UNBLOCK_MAX_ROUNDS_PER_ITEM` (`resolve_max_rounds_per_item`, called by `decide` when no explicit `max_rounds_per_item` is passed), defaulting to `MAX_ROUNDS_PER_ITEM = 3` (was a hardcoded 2). Only an ASCII decimal integer is accepted and it is clamped to 1-5; any other value falls back to 3, and both cases log one `::warning::` line on stderr (never stdout, which is the decision JSON). A digit string with more than 3 significant digits is treated as above the ceiling without calling `int()`, so a very long value cannot raise. `decide` output gains `max_rounds_per_item`. `orchestrate_poll.yml` (the three steps that set `NEEDS_HUMAN_DIGEST_ENABLED`) and `unblock_judge.yml` forward it as `vars.UNBLOCK_MAX_ROUNDS_PER_ITEM || '3'`. The project cap (`MAX_ROUNDS_PER_PROJECT = 6`), the 24-hour rule and the never-repeat-per-fingerprint rule are unchanged.
