- **Clarify-respond answers only the questions comment in orchestrator mode (#8650).** The wrapper filter `contains(github.event.comment.body, 'Clarification required')` is case-insensitive, so any trusted comment quoting the phrase (for example the `ai:clarification` label description "AI clarification required before planning") used to start an orchestrator-mode answer run, and each auto-answer re-triggered the next until the loop breaker escalated. "Check orchestrator metadata" in `orchestrate_clarify_respond.yml` now sets `mode=orchestrator` / `respond=true` only when the comment's first line is `<!-- ai:clarification-questions -->` (clarify.yml's questions comment, kept by the capacity-wait replay). Any other comment gives `is_orchestrator=true`, `mode=skip`, `respond=false`. Logs: `AI_PHASE_GATE_V1 phase=orchestrate_clarify_respond gate=orchestrator_questions reason=clarify_questions outcome=run issue=<n>` or `... reason=not_clarify_questions outcome=skip issue=<n>`. The wrapper `if:` is unchanged. Tests: `tests/test_clarify_respond_standalone.py`, `tests/test_phase_skip_gate_telemetry_contract.py`.
