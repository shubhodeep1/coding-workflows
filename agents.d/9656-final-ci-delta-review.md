**Failed final CI, Phase 3: review the repair commit on its own diff (docs/plans/final-ci-failure-ci-fix-plan.md, Refs #9656).**
- `scripts/review_head_gate.sh final-ci-repair <repo> <pr> <head sha> <author login> <comments json file>`, modelled on `freshness-sync`: exit 0 and print `final_ci_repair_from=<from>` only when a marker by the author login (the gate's `GH_PAT` login, compared case-insensitively) ends in `<!-- ai:final-ci-repair:v1 pr=<pr> from=<sha> repair=<head> attempt=<k> -->`, `GET commits/<head>` shows exactly one parent equal to `from` and a committer of `codex-bot` or `claude-bot` with email `<name>@users.noreply.invalid` (the identities `review_conflict_resolve.sh` commits with), and `from`'s newest `ai-review/head-gate` status (`GET commits/<from>/statuses?per_page=100`) is `success` posted by the author login. Every other outcome exits 1 (full review) and logs `REVIEW_HEAD_GATE mode=final_ci_repair pr= head= outcome=review reason=invalid_input|no_repair_marker|commit_read_failed|head_is_not_the_repair|committer_not_pipeline|from_gate_read_failed|from_not_approved`. The two reads run only when a trusted marker names the head.
- Gate (`scripts/review_autofix_step_evaluate_gate.sh`, after the Phase 2 repair block): when the run will review, it is not itself a repair run, `FINAL_CI_REPAIR_DELTA_REVIEW_ENABLED` (repo variable, default `true`; any value other than `true`/`false` warns and counts as off) is `true`, `HEAD_GATE_HELPER_VERIFIED=true`, and the shared marker comments contain `repair=<head>`, it calls the helper from the verified `.codex-head-gate-src` checkout and sets the new gate output `review_diff_base_sha` (exported by the `gate` job; empty otherwise).
- "Generate diff context" (`scripts/review_autofix_step_generate_diff_context.sh`, env `REVIEW_DIFF_BASE_SHA` from that output): when the value is 40-hex, a strict ancestor of `HEAD`, and `git diff <base>..HEAD` succeeds and is not empty, `LAST_RUN_DIFF_FILE`, `LAST_RUN_CHANGED_FILES_FILE` and `LAST_RUN_DIFF_STAT_FILE` cover `<base>..HEAD` instead of the newest `[ai-autofix]`/`[judge-fix]` commit: the repair commit is the previous AI run, so it becomes the reviewers' primary focus and the editor's oscillation-guard input. `PR_DIFF_FILE`, `ORIGINAL_PR_DIFF_FILE` and `PR_CHANGED_FILES_FILE` keep the whole PR, so the reviewer risk tier, the agents.md materiality check and the panel are unchanged. It logs `REVIEW_DIFF_CONTEXT range=delta base=<sha>`, or `range=merge_base` (with `reason=invalid_base|not_an_ancestor|diff_failed|empty_delta` when a base was given).
- The reviewer panel, consolidator, editor and head-gate posting run unchanged (Q8: A); a clean result posts `ai-review/head-gate` success on the repair head and `_pr_ensure_final_ci` dispatches its full final CI as for any approved head.
- Tests: `tests/test_review_head_gate.py`, `tests/test_review_autofix_clean_same_head_gate.py` (gate output), `tests/test_review_autofix_last_run_diff_oscillation_guard.py` (diff range).
