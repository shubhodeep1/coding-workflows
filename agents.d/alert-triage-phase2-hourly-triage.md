<!-- agents: section="Workflow architecture" -->
- Hourly alert triage (alert triage plan Phase 2, Refs #9394; `docs/plans/alert-triage-auto-heal-plan.md`). `.github/workflows/alert-triage.yml` (cron `17 * * * *` + `workflow_dispatch`, `concurrency: alert-triage` without cancel, job `if: vars.ALERT_TRIAGE_ENABLED == 'true'`, default off) runs `scripts/alert_triage_route.sh fetch|prepare|diagnose|route`; every decision is in `scripts/alert_triage.py` (no model). `fetch` clones `ai/alert-inbox` at depth 1 (token through `GIT_CONFIG_*` env; no branch logs `skip reason=no_inbox`). `prepare` re-validates `alert_inbox.v1` records, takes up to `ALERT_TRIAGE_MAX_ALERTS` (30) unmarked records oldest first, groups them by `sha256("alert_triage.v1\n" + repo + "\n" + workflow + "\n" + normalised message)` (URLs, ISO timestamps, UUIDs, hex SHAs and numbers masked), makes exactly two list calls (open `ai:workflow-heal` issues, open `ai:alert-self-fix` PRs) reused for every group, marks a group `already_tracked` by the heal `fp` marker (`fingerprint(workflow, "alert_triage", "alert-triage:<fp>")`, the intake's inputs) or the Phase 3 PR marker `<!-- alert-triage:fp=<64hex> -->`, re-diagnoses a stalled `ai:alert-triage` issue (`ALERT_TRIAGE_HEAL_STALL_HOURS`, 6), caps a fingerprint at 2 dispatch attempts in 7 days (`ledger/<fp>.json`, `alert_triage_ledger.v1`), maps workflow display names to this repository's workflow paths from `name:`/`uses:` lines, and spends at most `ALERT_TRIAGE_MAX_EVIDENCE_GETS` (5) GETs per run on `select_evidence_jobs` + `filter_log` evidence. `diagnose` runs role `ALERT_TRIAGE` (Claude Opus, read profile, codex fallback under `AI_ENGINE_FALLBACK_POLICY=always`) per group with no GitHub/OIDC/Telegram variables, prompt `prompts/mode-alert-triage.txt`, alert text inside UNTRUSTED fences; the host parses one strict JSON object. The host decides `pipeline_blocked` (`files` ∩ `pipeline_self_files`, a mapped pipeline workflow, or a stalled issue for model `healable`/`pipeline_blocked`; `files` ∩ `pipeline_self_files` or a stalled issue also overrides `noise`/`environmental`, a mapped pipeline workflow alone does not). `route` writes every `done/<record_id>` marker and ledger update in ONE commit, pushes (3 attempts, re-applied on the new tip, never forced), prunes data older than 14 days, and only then dispatches: `healable` -> `workflow-failure-heal` kind `alert_triage` (no `run_refs`; scope = host-resolved `alert_workflow_path`, else escalate `healable_no_scope`), `pipeline_blocked` -> `alert-self-fix.yml` only with `ALERT_TRIAGE_SELF_FIX_ENABLED=true` and the file present, else escalate; `unsure`, model or parse failure and the ledger cap escalate once per group through `tg_send_msg_direct` (tokens only, never alert text). `ALERT_TRIAGE_DRY_RUN` (default `true`) commits markers and occurrences but dispatches and sends nothing. The intake accepts `alert_triage` only when `source_repo` is this repository and the report identity verified against `alert-triage.yml` (`HEAL_ALERT_TRIAGE_KIND_ENABLED`, default `true`), labels the issue `ai:alert-triage`, and passes the diagnosis only as UNTRUSTED evidence. The broker allowlist names `alert-triage.yml`; until the Worker is redeployed the role runs on codex.
