External-finalize delivery check (issue #7611, incident tele-funtoken-msg-scoring#4281). When the external-finalize path in `scripts/orchestrate_poll_process.sh` finds the recorded final PR closed and merged, it runs `external_finalize_delivery_check` after the sub-issue completeness gate and `ensure_security_pass_before_completion`, and before the `.status = "complete"` write. The check compares the merged PR's `head.sha` (from the PR read the block already made) with a fresh `git fetch` of the integration branch tip; it never uses compare-API `ahead_by`, which stays above 0 after every squash merge. Outcomes:
- `delivered` (tip equals the merged head), `branch_deleted` (the branch fetch failed and `integration_branch_exists` reports it absent; the merged head stays authoritative) and `delivered_by_content` (the tip descends from the merged head and `git merge-tree --write-tree origin/<default> <tip>` equals the default branch's tree, for example a post-merge sync merge) complete as before. The completion comment adds ``Delivery check: `<outcome>` — merged final-PR head `<A>`, integration tip `<T>`.`` and, with the security pass on, ``Security pass audited `<sha>`.`` (`SECURITY_PASS_VALIDATED_HEAD_SHA`, set by `ensure_security_pass_before_completion` when it accepts a head).
- `drift` (the tip descends from the merged head and adds content the default branch lacks): the project is not completed. The poller clears `final_merge_pr`, keeps `final_merge_status = "pending"`, writes a `final_merge_error` naming both SHAs, posts one `## ⚠️ Integration branch advanced after PR #<n> merged — project not complete` comment, and ends the project's tick; the next tick's existing final-merge flow opens a fresh final PR for `A..T`. No `ai:merged` label, Telegram cleanup or completion message.
- `diverged` (the tip does not descend from the merged head, so history was rewritten) fails closed: the final PR stays recorded, `final_merge_error` is set, and one `## 🛑 Integration branch history changed after PR #<n> merged` comment plus one Telegram ERROR are sent.
- `unverified` (merged head missing or not fetchable, branch fetch failed while the branch exists, tip unresolved, ancestry check error, or the content check could not run: default-branch lookup, fetch, tree read or `merge-tree` failed) does not complete and retries every tick, with one Telegram WARNING.

`diverged` and `unverified` alerts are deduplicated by the state field `external_finalize_delivery_alert_sig` (sha256 of outcome, reason, merged head and tip); completion and the drift hold reset it to `""`. The fast path adds no GitHub API call.
