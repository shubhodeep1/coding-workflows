- `REVIEW_BLOCKED_STALE_CLEAR` (`scripts/review_autofix_step_post_editor_summary.sh`, #9369): `pr=<n> outcome=removed|kept|error reason=<token> cap_head=<sha|none> cap_support=<sha|none> clean_head=<sha> clean_support=<sha|none>`. Logged once after the editor summary posts with a `review-autofix-clean:v1` marker. The step makes one GraphQL read (PR labels plus the newest 100 comments and their `totalCount`) and removes `ai:review-blocked` from the PR with one DELETE only when the newest `review-autofix-failure-cap:v1` marker from the token's own login (the comment must start with `**AI review/autofix stopped` and end with the marker as its last non-empty line, the gate's rule; a missing `support=` compares as `none`) sits in a cap comment that labeled this pull request (its `- Labeled \`ai:review-blocked\`: this pull request` line) and names a different head or review-support SHA. Newer caps that labeled linked issues are skipped. Reasons: `head_changed`, `support_changed`, `already_absent` (removed; `already_absent` means the DELETE got a 404 because the label was removed concurrently); `same_head_support`, `no_cap_marker`, `cap_not_pr_target` (every trusted cap in the window labeled linked issues, not the PR, and the PR has no older comments), `cap_marker_out_of_window` (no trusted cap that labeled the PR in the newest 100 comments while the PR has more; `cap_head`/`cap_support` name the newest skipped linked-issue cap, if any), `label_absent`, `trusted_login_unavailable` (kept); `lookup_failed`, `delete_failed` (error; the label stays and the step still exits 0). Linked issues are not touched.
