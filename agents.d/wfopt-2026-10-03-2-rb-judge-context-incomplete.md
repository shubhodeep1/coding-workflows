- `RB_JUDGE_CONTEXT_INCOMPLETE` (BUG-002, consumer of the `PR_COMMENTS_CONTEXT_INCOMPLETE` signal). Emitted by both the review-blocked judge (`scripts/review_rb_judge.sh`) and the poller's rb-judge path (`scripts/orchestrate_poll_process.sh`) when the PR comment context could not be fully read: the comments helper returned `"comments_incomplete": true`, or the inline legacy branch saw a paginated comments read (or its jq transform) fail. `reasons=<csv>` holds only `[a-z_]` tokens (at most 8, `unspecified` when none survive the filter). Forms in `scripts/review_rb_judge.sh`: `::warning::RB_JUDGE_CONTEXT_INCOMPLETE pr=<n> reasons=<csv> action=defer_merge` on stderr, once per run when the context is incomplete; `RB_JUDGE_CONTEXT_INCOMPLETE pr=<n> reasons=<csv> action=merge_withheld judge_action=<action>` on stdout when a merge-type verdict (`merge`, `merge_with_followup`, final-attempt `fix`, or a no-change non-final `fix` reported as `fix_no_changes`) is withheld; `RB_JUDGE_CONTEXT_INCOMPLETE pr=<n> reasons=<csv> action=approve_downgraded review_state=<state>` on stdout when an APPROVE / APPROVE_WITH_COMMENTS assessment is posted as COMMENT. A withheld merge sets no auto-merge, direct merge, `ai:ready-to-merge` label or head-gate success status, writes `judge_action=skip` and `judge_skip_reason=comments_context_incomplete`, and leaves `judge_handled` unset so the review-blocked fallback keeps the PR for the next judge cycle. A complete context emits nothing and behaves as before.
