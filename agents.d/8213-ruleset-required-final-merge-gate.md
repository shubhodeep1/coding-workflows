- `scripts/pr_checks_lib.sh` also provides `_pr_ruleset_required_check_blockers HEAD_SHA BASE_REF` (#8213, fun-token-multi-chain#579). `_pr_checks_completed` reads required names only from classic branch protection and judges only check-runs, so it cannot see a repository-ruleset required commit status such as `coding-workflows/workflow-integrity`. The helper reads `GET rules/branches/<base>`, then the combined commit status (and check-runs only for contexts with no status), and sets `PR_RULESET_BLOCKERS_SUMMARY` to `context (failure|error|pending|missing)` entries. It returns 0 (none), 1 (blockers) or 2 (lookup failed; callers fail open). `finalize_integration_merge_if_needed` calls it only when the final PR's `mergeable_state` is `blocked`: a blocker defers with `FINAL_MERGE_BUDGET_ELIGIBLE=0` and logs `[final-merge] PR #N is blocked by ruleset-required check(s): ...`, so the three-attempt budget is not spent on refused merges. `_check_final_merge_ineligibility_alert` appends the same list as `ruleset: ...`. When a merge is still refused, `final_merge_error` and the "Final merge blocked" comment carry `mergeable_state` and GitHub's refusal text.
