- **Stuck `ai:check-triage` issues close from the poll (issue #9481).** Four additions, each extending an existing mechanism; no new log prefix (`CLOSE_MERGED_SWEEP` and `STALL_RECOVERY` already exist).
  - *Marker-PR project base (`check_triage_marker_pr_base`).* When the marker PR (`<!-- check-failure-triage:pr=<N> -->`) has itself merged into a same-repository `orchestrator/project-<M>` branch and issue `<M>` carries `ai:orchestrator-tracking`, `close_merged_issues_sweep` accepts a bound fix PR (same-repository `ai/issue-<n>` head) merged into that branch. `_close_sweep_check_triage_branch` resolves it into `_CLOSE_SWEEP_TRIAGE_MARKER_BASE` (one memoized `issues/<M>` read per project per tick, in `_CLOSE_SWEEP_TRACKING_LABEL_MEMO`), which goes to `_pr_json_base_is_target_merge` as its optional seventh argument. Five- and six-argument callers are unchanged.
  - *Triage-rule diagnostics.* Every early return of `_close_sweep_check_triage_branch` logs `CLOSE_MERGED_SWEEP issue=<n> triage_rule=skip reason=<label|support_missing|login_empty|author_mismatch|marker|marker_pr_cross_repo|marker_head_empty|tracking_unreadable|project_untracked>`. Success logs `triage_rule=ok marker_pr=<N> head=<ref> marker_merged=<bool> marker_base=<ref|none>`, and an unbound candidate of a triage issue logs `triage_rule=skip reason=candidate_unbound head=<ref> head_repo=<repo>`. The candidate's head repository now compares case-insensitively (`_pr_json_head_is_same_repo`).
  - *Gate pass.* After the candidate loop, an open `ai:check-triage` issue in any phase that no accepted merge closed runs `scripts/check_triage_resolution.py gate` through `_close_sweep_check_triage_gate`. It shares `_check_triage_gate_invoke` with `_stall_check_triage_resolution_gate`, whose `STALL_CHECK_TRIAGE_GATE` lines are unchanged. The sweep logs `triage_gate=<status|skip> reason=<r> rc=<rc> pr_state=<s>`, and `resolved` / `already_resolved` count as closed.
    - When the source PR closed without merging (`reason=pr_not_merged`, `pr_state=closed`), the issue gets `ai:closed` and is closed as not planned with `<!-- ai:check-triage-source-closed:v1 issue=<n> pr=<m> -->` (`triage_rule=closed reason=source_pr_closed_unmerged`).
    - That close is held while an open, same-repository `ai/issue-<n>` PR is cross-referenced (`reason=source_pr_closed_unmerged_fix_pr_open fix_pr=<m>`), and fails closed on an unreadable state (`reason=source_pr_state_unreadable`).
    - `CHECK_TRIAGE_GATE_SWEEP_MAX_PER_TICK` (default 10, `0` disables) caps gated issues per tick. The window over the ascending triage issue numbers starts at `(GITHUB_RUN_NUMBER * cap) % total` (`triage_gate_window size= total= offset=`). `CHECK_TRIAGE_RESOLVED_GATE_ENABLED=false` turns the pass off too.
  - *Integration fallback.* After `integration_pr_missing` (the tracking-label check already passed), the gate resolves when `_default_branch_evidence` passes and the triaged PR's content is on that commit: its merge commit is an ancestor (`content_check=ancestor`), or every changed file has the same blob SHA in both recursive trees and removed files are absent (`content_check=tree_match`). The result carries `evidence_ref=default_branch_content:<sha>`. Otherwise the reason is `integration_fallback_default_check_failed` (with `fallback_detail`), `integration_fallback_content_absent` or `integration_fallback_unreadable`. `CHECK_TRIAGE_INTEGRATION_FALLBACK_ENABLED=false` restores `integration_pr_missing`.
  - *Stall judge escalation kept.* In `invoke_stall_judge`, when the judge chose `escalate_human` and `resolve_effective_stall_recovery_action` turned it into `attempt_merge`, the already-fetched linked PR keeps `escalate_human` if it closed without merging or merged into a base `_pr_json_base_is_target_merge` rejects (`_stall_judge_linked_pr_keeps_escalation`). This logs `STALL_RECOVERY issue=<n> reason=judge_escalate_kept linked_pr=<closed_unmerged|merged_non_target_base> pr=<m> base=<ref> phase=<p>`. `orchestrate_lib._linked_pr_evidence` takes the same optional base filter (`default_branch`, `declared_branch`, `is_managed`; a missing base keeps the legacy `attempt_merge`).
