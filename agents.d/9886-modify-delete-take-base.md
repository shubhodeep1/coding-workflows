- **Modify/delete take-base and stage context (issue #9886, plan Phase 4 of `docs/plans/pipeline-human-wait-elimination-plan.md`).** PR #9452 parked because the resolver left a modify/delete path (index stages `1 2`) unmerged on every run.
  - *Take-base (prepare).* The `# >>> non-fragment modify/delete take-base` block of `scripts/review_conflict_prepare.sh` runs after the folded-fragment keep. For each allowlisted path with stages exactly `1 2` that is not a `changelog.d/` / `agents.d/` fragment, not under `.ai/`, not `.gitleaksignore` and not the workspace manifest, is a regular `100644`/`100755` blob and not a symlink, it finds the base commit that deleted the path (`git log --diff-filter=D` over `merge-base..MERGE_HEAD`), which must end in `(#N)`. The PR's changed lines to the path (`git diff -U0 merge-base HEAD`) must number 1..`CONFLICT_MODIFY_DELETE_MAX_CHANGED_LINES` (script-only, default `20`, clamped 1..200), and every non-blank line (sign kept, whitespace stripped, the path removed) must also be changed with the same sign in another added or modified file of the PR that is not itself a `1 2` conflict. Then the path is `git rm`'d, recorded as `path<TAB>#N<TAB>lines` in `RESOLVER_DROPPED_EDITS_FILE` (default `${RUNTIME_DIR}/resolver_dropped_edits.tsv`), and the first 10 dropped diff lines go to `${RUNTIME_DIR}/modify_delete_take_base_comment.md` (marker `<!-- ai:modify-delete-take-base:v1 pr=<n> head=<sha> -->`, 61440-byte cap). The block never commits: the commit tail commits (`Modify/delete take-base`) when nothing else is unmerged, or on `orchestrator/project-*` defers to the integration fingerprint check (`_det_commit_scope=modify-delete-only`). The comment is posted after the commit by `_conflict_prepare_post_modify_delete_comment` or, when the model resolved other paths, by the resolver's take-base comment loop. Every other shape, and any git or parse error, leaves the path to the model.
  - *Stage context and `unmerged_left` (resolve).* `_resolver_modify_delete_context` appends `Modify/delete conflicts (stage context):` to the rendered prompt for every targeted `1 2` / `1 3` path and records them in `RESOLVER_MODIFY_DELETE_PATHS_FILE`. On the workflow source repo only, `_capture_unmerged_left_baseline` records each targeted path's worktree state, and `_verify_no_unmerged_left` (soft-validation success branch, before the provenance check) flags a path the real index still holds unmerged whose worktree state is unchanged. A modify/delete path listed exactly under `Conflicts resolved:` in the model's output is an explicit keep (`RESOLVER_MODIFY_DELETE_KEEP_FILE`), added to the touched set after the loop so it is staged. A flagged attempt sets `_prev_attempt_failure_kind="unmerged_left"` and retries with the inline `unmerged_left-prelude`; on the last attempt it exits with `RESOLVER_TERMINAL exit_class=scope`. `check_resolver_diff.sh` check (4) stays as the backstop.
  - *Switch / rollback.* `CONFLICT_MODIFY_DELETE_TAKE_BASE_ENABLED` defaults `true` in both scripts and in the prepare and resolver steps' `env:` of `.github/workflows/review_autofix.yml`; `false` (any case) restores the previous behaviour, any other value is off with a warning. Tests: `tests/test_review_conflict_modify_delete.py`.
