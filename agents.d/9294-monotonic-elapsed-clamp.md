- `CI_SUBTEST_END` and `CI_SUBTEST_HEARTBEAT` time with a monotonic clock and never print a negative `elapsed_ms` (#9294, `.github/workflows/ci.yml` step "Orchestrate poll single-file module tests"). `sf_now_ms` reads milliseconds since boot from `/proc/uptime`, which a runner wall-clock adjustment does not move, and falls back to `date +%s%3N` when that read does not give an integer. When the end time (or the heartbeat reading) is numeric but earlier than the start, `elapsed_ms` reads `0` instead of the negative difference. Line format, keys, rc handling and pass/fail logic are unchanged.
- `REVIEW_HEAD_CHECKOUT` timings use the same clock (#9294, `review_head_checkout_now_ms` in `scripts/review_autofix_step_checkout_pr_head_branch.sh`): `/proc/uptime` first, then the existing `date +%s%3N` and `date +%s` fallbacks. A negative `fetch_ms`/`switch_ms` difference reads `0` (`review_head_checkout_elapsed_ms`), so `na` still means only that the operation never started; a negative `duration_ms` already read `0`.
