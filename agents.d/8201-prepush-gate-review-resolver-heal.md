- **Review autofix, conflict resolver and heal gates (issue #8201, plan phase P4).** `scripts/review_autofix_step_prepush_test_gate.sh` (in `REQUIRED_BOOTSTRAP_SCRIPTS`; `prepush_test_gate_run.sh` and `validate_changed_files_syntax.sh` are in `OPTIONAL_BOOTSTRAP_SCRIPTS`) carries P3's contract: the same modes, defaults and clamps, the same embedded host helper (status, synthetic, failures, allow, summary), the 16 KiB untrusted failure block, one repair turn and a host-written summary. Log prefix `PREPUSH_TEST_GATE phase=review|resolver|heal`.
  - **Trusted files.** The module, wrapper and repair template come only from an absolute `SUPPORT_SCRIPTS_DIR` / `SUPPORT_PROMPTS_DIR`, the script's own directory (`../workflow-templates/.claude/hooks/`, `../prompts/`), `.codex-workflow-src` or `.codex-workflow-src-main`. They are copied to `${RUNTIME_DIR}/prepush_gate_support/` (or a `RUNNER_TEMP` directory) and never read from the PR checkout. No module or wrapper means `outcome=skipped reason=module_absent`; no template means `outcome=mode_report reason=repair_template_absent`.
  - **Review step.** `review_autofix.yml` runs "Pre-push affected-test gate" between "Decide partial-finalize validation/push safety" and "Commit changes". Its `if:` is the commit step's plus `vars.PREPUSH_TEST_GATE_MODE != 'off'`, with `continue-on-error: true`, `timeout-minutes: 60` and the four `PREPUSH_TEST_GATE_*` variables defaulted.
    - Its wrapper is the standard error-flavour resolving wrapper (`SUPPORT_SCRIPTS_DIR`, then `.codex-workflow-src/scripts`), because `tests/test_review_autofix_step_scripts_contract.py` allows warning-mode skips only on `always()` steps. `continue-on-error` still keeps a missing script from blocking.
    - It skips on `AUTOFIX_PARTIAL_FINALIZE_REQUESTED=true` and on no uncommitted change.
    - It uses `${REVIEW_SANDBOX_ROOT}/image` (shape-checked; `review_image_unavailable` otherwise), the dependency venv `${REVIEW_SANDBOX_ROOT}/source/.review-venv` (`--venv`) and its `source/node_modules` (`--node-modules`).
    - The repair turn is `review_apply_fixes.sh --repair-turn PROMPT OUT`: one `run_editor_codex_attempt` call in a subshell, advertised by the `# supports: --repair-turn` marker. A missing marker logs `outcome=repair_skipped reason=editor_hook_missing`. It adds no `: "${VAR:?}"` guard. The subshell points `GITHUB_ENV` at `${RUNTIME_DIR}/prepush_gate_repair_github_env`, so a Claude capacity wait (exit 80) in this extra turn cannot set `AUTOFIX_FAILURE_REASON=claude_capacity` for the review run.
    - After the turn, stray edits and replaced symlinks are rolled back. A nonzero editor exit reverts the repair. A failure of `${SUPPORT_SCRIPTS_DIR}/validate_changed_files_syntax.sh` reverts it (`repair_reverted reason=syntax`); a missing validator only warns (`reason=syntax_validator_missing`).
    - The summary is appended to `EDITOR_SUMMARY_FILE` only when that file is non-empty. The section is `## Pre-push test gate`, then a `Pre-push test gate results:` line, which ends a preceding `PR comment audit:` section for `review_resolve_review_threads_plan.py`.
  - **Allow-list trust.** A failing file from the container's `result.json` (which tests can rewrite) joins the repair allow-list only when the host selection (`affected_tests`, `companion_files`) already names it; with no selection, no failing file counts.
  - **Mode reach.** The review step and the conflict-resolver step pass `PREPUSH_TEST_GATE_MODE` (`vars.PREPUSH_TEST_GATE_MODE || 'repair'`). The heal editor runs inside `implement.yml`'s "Run Codex implementation" step, which does not pass it, so heal runs in `repair` mode until that step forwards the variable.
  - **Subcommands** (exit codes other than 0 only for missing inputs):
    - `gate --worktree --base --image --out [--venv] [--node-modules] [--phase] [--image-reason]` prints `<status> <pr_caused> <inherited>`.
    - `repair-prompt RESULT OUT [ALLOW_FILE]`
    - `allow-list WORKTREE CHANGED RESULT OUT`
    - `summary RESULT OUT MODE REPAIR INITIAL`
    - `mode`
  - **Resolver.** `_resolver_prepush_test_gate` in `scripts/review_conflict_resolve.sh` runs right before `git commit -m "[ai-merge-resolve] resolve merge conflicts"`, after every existing guard.
    - The gate script and sandbox helper come only from an absolute `SUPPORT_SCRIPTS_DIR`; anything else logs `reason=module_absent`. The allow-list is seeded from `CONFLICTED_PATHS_FILE`, not the merge diff, so base-side files the merge brought in stay outside the extra allowed paths.
    - The image and the dependency venv (`--venv <root>/source/.review-venv`, so pytest suites can fail instead of being `unverified`) come from one full `review_untrusted_sandbox.sh prepare codex` with a private `GITHUB_ENV`, a 300 s install budget and a 600 s bound, cleaned up after the last gate run. When that fails and the 630 s reserve still fits, it falls back to `prepare-ephemeral codex` (image only, no venv). A prepare's `source/node_modules` is passed as `--node-modules`, and a root without a venv logs `outcome=warning reason=venv_absent`. The step passes `DEPENDENCY_PROXY_ALLOWED_HOSTS` to the prepare. The base is the pre-merge PR head (`HEAD`), so PR-side failures count as inherited.
    - On PR-caused failures it records the complete merge index with `git write-tree`, then runs one `_resolver_sandbox_attempt` with the repair prompt: Claude, with OpenCode on exit 75; exit 80 skips.
    - The repair must pass `check_resolver_diff.sh`, with every allow-list path given as `--extra-allowed-file`, and, on integration-sync heads, `_verify_fingerprints_soft`. Its paths are then staged and the index re-checked for unmerged entries. Otherwise `git read-tree` plus `checkout-index` restore the resolution (`repair_reverted`).
    - Step budget: `SECONDS` counts from the resolver script's start against 9,000 seconds (the step's 170-minute cap minus 20 minutes for the commit and the EXIT-trap dispatch). The gate is skipped when one gate run (`PREPUSH_TEST_GATE_TIMEOUT_MINUTES` × 60 + 120 s) plus 630 s for the image prepare (run under `timeout --kill-after=30s 600`) no longer fits (`outcome=skipped reason=step_budget`). The repair, and the OpenCode retry after Claude exit 75, is skipped when one `CONFLICT_RESOLVER_PER_ATTEMPT_TIMEOUT_SECS` attempt plus a gate run plus 630 s for that attempt's own `prepare-ephemeral` (outside its per-attempt timeout; only for the gate's repair attempt it runs under `timeout --kill-after=30s 600`, a timeout being the existing `sandbox_prepare_failed` path) no longer fits (`repair=skipped_step_time_budget`). The second gate run is skipped when it no longer fits.
    - The commit always follows (Q3).
  - **`check_resolver_diff.sh --extra-allowed-file PATH`** (repeatable) widens only invariant 1. Absolute values, `..` segments and control characters are ignored with a warning; a flag with no value exits 2. Without the flag the output is unchanged.
  - **Heal.** `heal_prepush_test_gate` in `scripts/heal_isolated_implement.sh` runs after the `validate_snapshot` loop and before the scoped transfer.
    - It never runs host git on the editor-writable `${root}/source`. It adds a detached worktree of the heal checkout at `HEAD` (`core.hooksPath=/dev/null`) and copies the snapshot onto it with `review_untrusted_workspace.py transfer --scope-file` and a copy of the manifest. It gates that tree with the heal image, with `GIT_DIR` / `GIT_WORK_TREE` / `GIT_INDEX_FILE` unset and `PREPUSH_TEST_GATE_TIMEOUT_MINUTES=10` (the 600 s bound of `validate_snapshot`). The wrapper's own pids, memory and tmpfs limits still apply, not `validate_snapshot`'s. A refused copy logs `outcome=unverified reason=gate_tree_unavailable`.
    - Step budget: elapsed time counts from the job's start (`JOB_START_EPOCH`, which `implement.yml` exports, so a heal retry later in the job does not start a fresh budget; the script's own `SECONDS` when it is unset or invalid) against `HEAL_PREPUSH_GATE_BUDGET_SECS` (default 9000, defaulted in the script; not forwarded by `implement.yml`). The gate is skipped when 750 s no longer fit (`outcome=skipped reason=step_budget`). The repair turn gets the budget left after a 630 s `validate_snapshot` reserve as its editor wall (never more than the normal wall) and is skipped below 300 s (`repair=skipped reason=step_budget`). The turn is a deadline: when Claude exits 75 and `run_editor` falls back to codex, the codex editor gets only what is left of it and is skipped below 60 s (`phase=run engine=codex outcome=skipped reason=step_budget`), so the scoped transfer runs before the 180-minute job cap.
    - On PR-caused failures it builds the allow-list and the repair prompt from the gate tree, saves `source.pre-gate`, runs one `run_editor` turn (either engine) with the repair prompt, then `validate_snapshot` in a subshell. An editor failure, a syntax failure or an unavailable validator restores the saved snapshot (`repair_reverted reason=editor_exit_<n>|syntax|validator_unavailable`), and the transfer still follows.
    - The `cleanup` trap removes the worktree and prunes. The transfer follows as before. Logs: `HEAL_ISOLATED_EDITOR phase=prepush_gate outcome=...`; a kept repair logs `outcome=repaired failures=<n> repair=ran` (the gate is not run again).
  - The review sandbox image (`scripts/review_sandbox/Dockerfile`) installs `shellcheck` and, non-fatally, `ruff==0.17.2`.
