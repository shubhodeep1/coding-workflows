- **Plan autopilot (#10091).** Opt-in with the repo variable `PLAN_AUTOPILOT_ENABLED` (only `true`; default off, so it is not in `scripts/stage_switches.json`). In `orchestrate_poll.yml` the poll job adds two steps straight after `find_tracking`, with no API call: "Check plan autopilot slot" (runs only when `has_tracking=false`) builds the key `plan-autopilot-v1-<github.sha>-<UTC YYYYMMDD>`, and a lookup-only `actions/cache/restore` sets the poll outputs `plan_autopilot_due` / `plan_autopilot_key` / `plan_autopilot_support_ref`. The separate job `plan_autopilot` (`needs: poll`, `timeout-minutes: 90`, concurrency `plan-autopilot-<repo>` with `cancel-in-progress: false`) runs `scripts/plan_autopilot.py` subcommands, each a one-line step: `gate` (re-lists open tracking issues, open pulls, the orchestrate wrapper's runs and the `ai:plan-autopilot` status issue; skips `no_plans`, `no_orchestrator`, `project_open`, `maintenance_pr_open`, `dispatch_pending`, or `read_failed`), `collect` (writes `.plan-autopilot/audit_input.json` with decision answers from OWNER/MEMBER/COLLABORATOR comments on `ai:plan-decision` issues), `engine`, `audit` (role `PLAN_AUDIT`, prompt `prompts/mode-plan-audit.txt`, `codex_isolated_exec.sh --mode workspace`, no GitHub token, 75-minute timeout, result checked against `RESULT_SCHEMA` in the script), `apply` (path allowlist: `docs/plans/*.md` edits, `docs/plans/X.md` to `docs/completed/X.md` moves, pure entry removals from `docs/scripts-pending-removal.md` plus deletion of the paths those entries name, one `changelog.d/plan-autopilot-<YYYYMMDD>-<sha7>.md`; the diff must equal the result; refresh / archive / sweep commits pushed to `ai/plan-autopilot-<YYYYMMDD>-<sha7>` with the extraheader environment, body linted by `scripts/lint_pr_body_auto_close.py`), `decisions` (one `ai:plan-decision` issue per plan, matched by `<!-- ai:plan-decision:v1 plan=<path> -->`), `dispatch` (one `engine=claude` dispatch of `ai-orchestrate.yml`, else `internal-orchestrate.yml`; skipped when a recommended plan was edited by this run; on a 422 for `engine` it dispatches without it and waits up to 10 minutes to label the new tracking issue `ai:engine-claude`) and `report` (status issue body with `<!-- ai:plan-autopilot-tracker:v1 -->` and `<!-- ai:plan-autopilot-state:v1 {json} -->`). The cache marker is saved for a deterministic gate skip or a finished audit, never on `read_failed`, an error, a timeout or a Claude capacity wait (exit 80). `PLAN_AUTOPILOT_MAINTENANCE_PR_STALE_HOURS` (default `24`) flags a long-open maintenance PR on the status issue. Clarify skips issues labelled `ai:plan-autopilot` or `ai:plan-decision`.
