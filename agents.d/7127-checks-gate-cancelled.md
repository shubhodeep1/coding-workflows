- **Cancelled checks block; newest run per name (#7127).** `_pr_checks_completed` (`scripts/pr_checks_lib.sh`) accepts only `success`, `neutral` and `skipped`. A required check-run that ended `cancelled`, `timed_out`, `action_required`, `failure` or `startup_failure` blocks, and in `*` mode any such check-run blocks. The gate evaluates only the newest check-run per name (highest `id`, then latest `started_at`), deduplicated before the unchanged `PR_CHECKS_SELF_RUN_ID` exclusion, so a re-run supersedes a cancelled attempt. `PR_CHECKS_LAST_PENDING` is counted over the same deduplicated set, so a cancelled required check is a settled failure (`blocking`, pending 0) that `_pr_wait_for_required_checks` refuses at once when no other check-run is still running (pending runs, advisory ones included, keep the wait polling). `PR_CHECKS_LAST_TOTAL` keeps the raw non-self count. `_summarize_final_merge_blockers` in `scripts/orchestrate_poll_process.sh` applies the same rules. The noop-suspicious force-merge Gate D there calls `_pr_checks_completed "${N_PR}" "${N_HEAD_SHA}" "${N_BASE_REF}"`, taking the base ref from the Gate A PR read (fallback: the `STANDALONE_PRS` cache), and blocks with `reason=helper_unavailable` when the library is not loaded. This keeps the library the single source of truth for the gate.
