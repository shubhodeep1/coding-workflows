- **Agents file as an index in the self-assembled prompts (#8269, Refs #8253).** `STATIC_CONTEXT_AGENTS_MODE` decides whether a static prompt prefix inlines the agents file or lists its sections: unset, empty or `index` (any letter case) mean index, `inline` restores the full file byte for byte, and any other value inlines with one `::warning::` that never prints the value. Workflows pass `${{ vars.STATIC_CONTEXT_AGENTS_MODE || 'index' }}` (`orchestrate.yml` "Pre-assemble static context", `orchestrate_clarify_respond.yml` "Pre-assemble static context (cacheable across runs)", the six `orchestrate_poll.yml` steps that run `orchestrate_poll_process.sh`, and `validate.yml` "Run validation process"); each script defaults to `index` itself. The index comes from `scripts/build_static_context.sh agents-index <out> [agents.md|AGENTS.md]`; the optional third argument names the file to index (default: `agents.md`, then `AGENTS.md`), and a missing, symlinked or non-regular named file writes empty output with one warning, while any other third value exits 2. Every site skips a symlinked agents file when picking it, so the inline fallback never reads through a link. Each site keeps its own file order: the orchestrate decomposer reads `agents.md` first, clarify-respond, the poller judges (`assemble_judge_static_context`) and `scripts/validate_process.sh` read `AGENTS.md` first. Index mode covers clarify, plan, implement, the orchestrate decomposer, clarify-respond, the wave and stall judges, and validate; each model's sandbox snapshot (the clarify container's `/source` copy, `review_untrusted_workspace.py` for judges, the read-only `codex_isolated_exec.sh` copy for the decomposer and validate) holds the agents file and `agents.d/`. These stay inline: the review-blocked judge (`assemble_judge_static_context "${RUNTIME_DIR}/judge_static_rb.txt" inline`, its own file, because its sandbox snapshots the PR head, so the agents file it would read is PR-controlled), the integration-conflict judge (`inline`, because its merge worktree can hold a different or conflicted `agents.md`), the security-pass exhaustion judge (`assemble_judge_static_context "${RUNTIME_DIR}/judge_static_sec.txt" inline`, its own file, because it runs in the audit worktree `SECURITY_PASS_AUDIT_WORKTREE`, not the tree the index is built from), check-failure triage and the implement heal route (`STATIC_CONTEXT_AGENTS implement mode=inline reason=heal_route`). In consumer implement runs the canonical coding-workflows `agents.md` is indexed only when it is mounted at `/support/static-context/agents_canonical.md` (#8262). An index that cannot be built (helper failure, an older staged `build_static_context.sh` that rejects the third argument, a symlink, a failed `mktemp`) inlines the file with `::warning::Static context agents index unavailable; inlining agents.md.` The judges' shared `judge_static.txt` is reused within a tick, so its line numbers can point at another project's `agents.md`; the headings are still listed, and `STATIC_CONTEXT_AGENTS_MODE=inline` rolls back.
