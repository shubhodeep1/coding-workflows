- **Bounded promote-cycle hold for human-latched tracking issues (stuck-states P4, Refs #8291).** Guard 2 of `scripts/promote_main_cycle.sh` (the `cycle_in_flight` check) projects the labels of the open `ai:orchestrator-tracking` + `ai:comprehensive-test-pending` issues it already lists. With `PROMOTE_CYCLE_HOLD_RELEASE_ENABLED=true` (default), issues carrying a latch label from the fixed list `PROMOTE_CYCLE_HOLD_LATCH_LABELS` (`ai:harness-broken`, `ai:validation-failed`, `ai:security-pass-failed`, `ai:blocked`, `ai:needs-human`) get their `LabeledEvent` history from one aliased GraphQL batch (`promote_cycle_hold_history`, 1 call, only when a latch candidate exists). `promote_cycle_hold_decide` takes the newest event of any present latch label as the latch start; at least `PROMOTE_CYCLE_HOLD_MAX_HOURS` (default 24, bad values fall back to 24 with a warning) old releases the issue (`PROMOTE_CYCLE_HOLD_RELEASED`, `::warning::`, Telegram WARNING via `tg_send_msg`). An unverified alias number, a present latch label with no event, an unparseable timestamp or a failed read keeps the issue holding (fail closed); the age never falls back to the issue's creation time. The skip lists only the issues still holding; when none remain the tick continues with guard 3. `false` (anything not truthy) restores the old guard byte for byte, with no extra API call. While the `promote-cycle-frozen` tag exists and `PROMOTE_CYCLE_PIN_ENABLED` is not `false`, an issue past the cap still holds (one tag-ref read, only when a release is decided; skip detail `tag=promote-cycle-frozen`, no release line or alert; a failed read skips as `guard_unavailable lookup=tag:promote-cycle-frozen`), because the follower keeps `promote-candidate`, which every `internal-*.yml` wrapper calls, frozen on the parked cycle's candidate until it deletes the stale tag after `PROMOTE_CYCLE_FREEZE_MAX_SECS`. The release WARNING is sent in the background and abandoned after 30 seconds (after one timeout the tick sends no further release alerts), and the release reason names the latch label whose newest event set the age. A tick that released an issue runs the cycle unpinned (`PROMOTE_CYCLE_PIN outcome=skipped reason=released_cycle_holds_pin`): the released cycle may still own the shared `promote-cycle-frozen` tag, and the poller's `comprehensive_release_cycle_freeze` deletes that tag without an ownership check when the released cycle ends, so a new pinned cycle would lose its freeze.
