**Check-failure triage review fixes (2026-11-19, Refs #9726, #9673, #9125, #9272).** Found by the review of stable backport #9726 and fixed on `main`:
- **Final-CI skip input.** A `workflow_run` caller (`internal-check-failure-triage.yml` job `triage-final-ci-run`) passes `check_name: ${{ github.event.workflow_run.name }}`, which is `CI`; `CI [pr:<n>]` is only the run's `display_title`. The collect step of `check_failure_triage.yml` sets `CHECK_TRIAGE_RUN_TITLE` from `github.event.workflow_run.display_title` when the run's event is `workflow_dispatch` (empty otherwise, so a PR-controlled `pull_request` title never matches). `scripts/check_failure_triage.sh` matches the `final_ci_repair_owns` regex against it, falling back to `CHECK_NAME` when it is empty. The wrapper is not edited, because it calls the reusable workflow at `@promote-candidate` and an undeclared input would break the call. The skip line gains the additive key `title_source=run_title|check_name`.
- **Failed jobs.** `triage_run_failed_job_names` counts only `failure` and `timed_out` conclusions (`cancelled`, `skipped`, `neutral`, `success`, `action_required` and null do not), on both the PR and the base side of the tracked-base-failure check.
- **Release-download re-run scope.** On the `check_run` path the gate POSTs `actions/jobs/<CHECK_RUN_ID>/rerun`, so a sibling failed job it never classified is not re-run; the `workflow_run` path keeps `actions/runs/<run>/rerun-failed-jobs`. Same 201 check, no retry, same log lines.
- **One jobs read.** The gate saves its validated attempt-1 jobs payload to `${RUNTIME_DIR}/release_download_jobs_<run>.json` (`RELEASE_DOWNLOAD_RERUN_JOBS_FILE` / `RELEASE_DOWNLOAD_RERUN_JOBS_RUN_ID`); `triage_run_failed_job_names` reuses it for the same run and otherwise reads `jobs?filter=latest` as before.
- **Bounds.** The gate's jobs (`total_count < 100`, and each job has a positive integer `id` and a string `name`) and annotations (`length < 100`) bounds match `list_run_jobs()` and `failure_annotations()` in `scripts/ci_cancelled_rerun.py`; each copy carries a comment naming the other.
- **plan.yml.** "Handle blocked planning output" uses the check-triage text and WARNING page only while `UNBLOCK_JUDGE_ENABLED` is not `false` and `CHECK_TRIAGE_RESOLVED_GATE_ENABLED` (new step env, default `true`, read like `scripts/unblock_judge.sh`) is not `false`.
- Tests: `tests/test_check_failure_triage_owned_failures.py`, `tests/test_check_failure_triage_release_download_rerun.py`, `tests/test_check_failure_triage_workflow_security.py`, `tests/test_plan_blocked_wait_on_pr.py`.
