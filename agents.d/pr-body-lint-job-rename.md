- **PR-body lint job is `pr-body-lint` (2026-11-18).** The PR-body lint job (then in `lint-pr-body-auto-close.yml`, now in `.github/workflows/pr-checks.yml`) was named `lint`, the same check-run name as the aggregate `lint` job of `.github/workflows/ci.yml`. The `main` ruleset (`Required checks for default branch`) requires a check named `lint` and cannot tell the two apart, so the PR-body check passing could satisfy the requirement before the full CI had run (PR #9570: about six hours earlier). The job id is now `pr-body-lint`; the rename itself changed neither the workflow name nor the file (the later fold into `pr-checks.yml` did). Readers of the name:
  - `ORCH_FINAL_MERGE_REQUIRED_CHECKS_DEFAULT` (`scripts/pr_checks_lib.sh`, `scripts/orchestrate_poll_process.sh`) now lists `pr-body-lint`. `_pr_checks_completed` matches failed check-runs by check-run name, and a failed PR-body lint used to block only through the shared name `lint`; without the new entry a §19 violation would no longer stop the pipeline's merges. The entry `Lint PR body for auto-close keywords against orchestrator-tracking issues` (the workflow name, which no check-run carries) stays.
  - The `main` ruleset does not list `pr-body-lint`. GitHub's own merge button and auto-merge therefore no longer wait for the PR-body check; adding it to the ruleset is an operator decision. A pull request whose branch predates the rename keeps reporting the check as `lint` until its next `pull_request` event runs the workflow from a merge ref that contains the rename.
  - `lint-plan-archival.yml` kept a job named `lint` (it ran only for PRs that change files under `docs/completed/`) until it was folded into `pr-checks.yml` the same day. The CI-run binding in `_pr_wait_for_required_checks` (`PR_CHECKS_CI_RUN_IDS`) stays as it is: a branch that predates the fold still reports those jobs, and a pull request can add a workflow with a job named `lint`.
