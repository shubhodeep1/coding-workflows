<!-- agents: section="Workflow architecture" -->
**Workflow log analysis window and purge safety (project #9116, plan P4 and P5).** The `collect` step of `workflow-log-analysis.yml` writes `window_end` (its start time, before collection) and `window_start` (the effective start, or `unknown`) as outputs, and the `collect-logs` job exports both. With the dispatch input `since_last_report` (default `false`), the step runs a shallow `git fetch --shallow-since=<8 days ago> origin "${GITHUB_SHA}"`. It then reads at most 50 added `analysis/workflow-optimization-YYYY-MM-DD(-N).md` docs from `git log --diff-filter=A` and takes the largest `window_end` from first lines that match the anchored marker regex. A window older than 7 days is clamped to 7 days. On `no_marker`, `unparseable`, `future` or `git_failed`, the step falls back to `--lookback-days`. The precedence is PAT budget, then `since`, then `since_last_report`, then `lookback_days`. The analyze step re-validates `WLA_WINDOW_START`, `WLA_WINDOW_END` and `GITHUB_RUN_ID`, then writes `<!-- workflow-log-analysis: window_start=... window_end=... run=... -->` as the report's first line (block `# --- window marker (plan P4) begin/end ---`, before the `--insert-data-gap` call). Invalid values or a failed write print a `::warning::`, and the report is published without the marker. A run with a non-blank `repos_override` (`WLA_REPOS_OVERRIDE` in the analyze step's `env:`) also gets no marker, with a `::warning::`, so a later full-roster `since_last_report` run never starts at a single-repo window end. `test-and-mark-stable.yml`'s `Dispatch & snapshot — workflow-log-analysis` passes `--field since_last_report=true` instead of `repos_override=TEST_REPO` when `WORKFLOW_LOG_ANALYSIS_GATE_ALL_REPOS` (default `true`) is on and `TEST_REPO` equals `GITHUB_REPOSITORY`. The `commit_report` purge removes a past-retention doc only when its basename appears (`grep -qF`) in `${APPLY_ANALYSIS_REPORT_PATH:-analysis/recommendation-processing-report.md}`. It keeps unlisted docs, logged `WORKFLOW_LOG_ANALYSIS_PURGE_SKIPPED doc=<path> reason=unprocessed`, and skips the whole purge when that file is missing or unreadable (`WORKFLOW_LOG_ANALYSIS_PURGE_SKIPPED reason=processing_report_unavailable`). The in-flight guard still runs first. Contract tests: `tests/test_workflow_log_analysis_purge_safety.py` and `tests/test_workflow_log_analysis_since_last_report.py`. Refs #9116.
