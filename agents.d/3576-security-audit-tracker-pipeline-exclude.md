- `STALL_RECOVERY_SKIP` — emitted by `_security_audit_tracker_stall_guard` in `scripts/orchestrate_poll_process.sh` when standalone stall recovery meets the long-lived security-audit tracker (label `ai:security-audit`, issue #3576). Format: `STALL_RECOVERY_SKIP issue=<n> reason=security_audit_tracker removed=<comma-list|none> outcome=cleaned|clean|remove_failed action=none`. The guard removes `ai:blocked` and any standalone pipeline phase label in one `gh issue edit`, then skips the issue. While the switch is on, `ai:security-audit` is one more alias in the existing standalone label GraphQL batch, so a tracker that only carries `ai:blocked` is still discovered. It never closes the tracker, edits its body or posts a command. A failed removal logs `outcome=remove_failed` with a `::warning::` and the next tick retries. The same tracker is skipped by `scripts/unblock_scan.py` (skip reason `security_audit_tracker`, also for a failed project since #9730), by the PR-dependency filter in `run_unblock_scan` and by `detect_unrouted_blocked_comments`. Kill switch `SECURITY_AUDIT_TRACKER_PIPELINE_EXCLUDE_ENABLED` (default `true`; since #9730 every site uses one strict rule: unset, empty or `true` in any case is on, `false` is off, and any other value is off with one `::warning::`, including on the sweep-only path; the normalised `true`/`false` is exported to the Python selector). `orchestrate_poll.yml` forwards `vars.SECURITY_AUDIT_TRACKER_PIPELINE_EXCLUDE_ENABLED` (default `'true'`) to the poller steps.
