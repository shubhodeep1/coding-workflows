- **Security audit: one repair turn for a reply with text around the array.** When the Claude reply check in `security_audit_try_claude` rejects a reply as `malformed_output`, `security_audit_repair_claude_reply` resumes the audit's own session once with a request for the JSON array alone (run 40333816067 replied `[]` and then a summary, despite the prompt and §16 of `unattended_system_instructions.md`). The reply check now lives in `security_audit_check_claude_reply <reply_file>`, unchanged, and the repair reply goes through it too, so the check stays as strict as before. The session id comes from the `init` event of `${AI_ENGINE_LAST_RUN_DIR}/successful-transcript.jsonl`, and the repair runs only when `$(ai_engine_claude_home)/projects/*/<id>.jsonl` exists: `claude_run` starts a new session for an id it cannot find, and a session that never audited anything could answer `[]`. The repair `claude_run` uses the audit's read profile and include paths and writes no fallback record (`AI_ENGINE_FALLBACK_RECORDS_FILE=/dev/null`), so the report step counts only the caller's `malformed_output` fallback when the repair is rejected (`outcome=rejected`, plus a second `SECURITY_AUDIT_CLAUDE_REJECTED` line that keeps no copy), fails (`outcome=failed reason=claude_run_rc_<n>`) or is skipped (`outcome=skipped reason=no_session_id|session_not_stored|prompt_write_failed`). When the repair's `claude_run` exits 75, 76 or 80 (its own fallback, such as a capacity wait), the repair returns 2 and the caller records `AI_ENGINE_LAST_FALLBACK_REASON` instead of `malformed_output`, so a capacity wait still exits 80 (issue #7370). The repair prompt tells the model to answer in prose, not `[]`, when its audit did not finish or did not cover every file, so an unfinished audit still fails closed. `missing_output` and `schema_mismatch` get no repair. `security_audit_log_rejected_claude_reply` takes an optional reply path and kept path. Tests: `tests/test_security_audit_workflow_contract.py` (`test_security_audit_claude_repair_*`; the mock CLI's `MOCK_CLAUDE_SESSION=1` writes a session under the mounted `~/.claude`).
