- **ChatGPT account store (trial plan Phase 1, Refs #8969; not wired into any workflow yet).** `tools/claude-pool-broker` holds ChatGPT accounts in the `CHATGPT_ACCOUNTS` Durable Object namespace (class `ChatgptAccount`, SQLite-backed, migration tag `v1`): one object per account name (`^[A-Z0-9_]{1,64}$`) with `auth_json`, `seed_sha256`, `generation`, `last_refresh` (the broker's clock at the last write that stored an `auth_json`), `last_outcome`, `forced_refresh`, `checked_at` and `usage {five_hour, weekly, resets}`, listed in the `chatgpt-registry` instance (at most 32 names). `POST /v1/chatgpt` and `GET /v1/chatgpt/status` use the unchanged `/v1/pool` OIDC check (audience `coding-workflows-claude-pool`, `ALLOWED_WORKFLOW_FILES`, trusted refs, SHA ancestry). `POST` returns `200 {account, auth_json}` for the usable account with the lowest weekly usage (known usage first, ties by name), with `tokens.refresh_token` removed, or `503 {"error":"chatgpt_pool_empty"}`; usable means seeded, an `auth_json` written within 7 days, a last outcome other than `auth_failed` or `quota_exhausted`, and every known window below `CHATGPT_GATE` (default `0.9`). `status` returns per-account `generation`, `last_refresh`, `last_outcome`, `usage`, `usable` and `reason` (`not_seeded`, `auth_rejected`, `quota_exhausted`, `stale`, `gated`), never a token. `GET` / `PUT /v1/chatgpt/refresh/<NAME>` accept only the writer token: audience `coding-workflows-chatgpt-pool-writer`, `repository` = `CHATGPT_WRITER_REPOSITORY` (default `shubhodeep1/claude-workers`), `ref` = `refs/heads/main`, and `workflow_ref` and `job_workflow_ref` both `<repo>/.github/workflows/<CHATGPT_WRITER_WORKFLOW>@refs/heads/main` (default `chatgpt-pool-refresh.yml`; a reusable-workflow caller is refused). GET answers `200 {"auth_json","generation","seed_sha256"}` or `404 {"error":"not_seeded"}`; PUT compare-and-swaps on `base_generation` (`200 {"generation":N+1}`, `409 {"error":"generation_conflict"}`, `404 {"error":"not_seeded"}` for a non-reseed write to an unknown account), a `reseed: true` write replaces the record and its `seed_sha256` but still checks `base_generation` (0 for a new account), a missing `auth_json` keeps the stored file, and `usage.primary` / `usage.secondary` (`used_percent`) become `five_hour` / `weekly` fractions, and a window the write does not report (null `usage`, window or `used_percent`) keeps its stored value and reset, so a timed-out run cannot clear a reading at or above the gate (a reseed never inherits the previous login's usage). A malformed body is `400 invalid_body`, an invalid name `404 not_found`, an invalid writer var `503 writer_config_invalid`, store trouble `503 chatgpt_store_unavailable` (never 500). The broker never refreshes a token. `.github/actions/chatgpt-pool-token` (`scripts/chatgpt_pool_token.sh`) reads `broker_url` and `oidc_audience` from `.github/ai/claude_engine.json` with the same URL pin as `claude_pool_token.sh` and swaps the path; input `mode` `token` (default) writes `$RUNNER_TEMP/chatgpt-pool/<NAME>/auth.json` (0600, directories 0700, refresh token dropped again) and `status` outputs whitelisted one-line `status` JSON with no token. Outputs: `available`, `reason` (`selected`, `status`, `broker_refused_chatgpt_pool_empty`, `broker_refused_<code>`, `broker_unavailable_<http>`, `oidc_*`, `config_*`, `broker_url_invalid`, `pool_dir_invalid`, `mode_invalid`, `script_failed`, …), `account`, `codex_home`, `status`. It never fails the job, and its post step deletes `CHATGPT_POOL_DIR`.
