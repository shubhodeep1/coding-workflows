**Check-failure triage leaves failures another path owns (2026-11-18, Refs #9580, #9581, #9582, #9608, #9618, #9662).** Six triage issues became fix PRs on other PRs' branches (#9597, #9598, #9601, #9603, #9614, #9621), and five of them came from one of two cases. `scripts/check_failure_triage.sh` now skips both right after the PR read and fork guard, before the release-download re-run gate, the routing and integration-branch lines and the base-branch gate, so none of them runs and nothing is diagnosed. Neither gate makes an API call, and both are off in historical mode.
- **Stale head** (`CHECK_TRIAGE_SKIP_HEAD_ADVANCED_ENABLED`, default `true`): when the failing commit (`CHECK_TRIAGE_HEAD_SHA`, a valid SHA) differs from the PR payload's `head.sha`, the script logs `CHECK_TRIAGE skip reason=head_advanced failing_sha=<sha> pr_head_sha=<sha> pr=<n> check=<name>` and exits 0. The new head gets its own CI, and its failure is triaged then. #9580, #9581 and #9582 were filed against moved-on heads, three near-duplicates within three minutes. An empty or invalid failing SHA keeps the old path. The later `context_head_sha= ... pr_head_advanced=` line and the failing-SHA context collection (#6918) still run with the switch off.
- **Final CI run** (`CHECK_TRIAGE_SKIP_FINAL_CI_ENABLED`, default `true`): when the check name is exactly `CI [pr:<this PR>]` or `CI [pr:<this PR>] [<mode>]`, and `FINAL_CI_FAILED_REDISPATCH_ENABLED` (the hand-back's own repo variable, now passed to the triage job) is unset, empty or `true`, the script logs `CHECK_TRIAGE skip reason=final_ci_repair_owns pr=<n> check=<name>` and exits 0. `ci.yml`'s `final-ci-failed` job (`scripts/review_final_ci_failed.sh`) sends that PR back to review/autofix, and the review sweep's base sync (`scripts/review_final_ci_sweep.sh`) updates a head that is behind its base. The `stable` line has no final CI and creates no `CI [pr:<n>]` runs, so on `stable` and in consumers this gate does not fire. #9608, #9618 and #9662 came from such runs.
- Neither skip pages: they are deliberate, so `triage_report_routing_unverified` (the routing WARNING) is not called.
- Not covered: #9585 (fix PR #9601) was a current-head failure on the `integration_branch` route with `main` red. It is still filed.
- Tests: `tests/test_check_failure_triage_owned_failures.py` (both gates, switch values, name matching, ordering, workflow wiring). Mismatched-head cases in `tests/test_check_failure_triage_workflow_security.py` that test other paths (routing `sha_mismatch`, supersede `not_current_head`, #6918 context) pin `CHECK_TRIAGE_SKIP_HEAD_ADVANCED_ENABLED=false`.
