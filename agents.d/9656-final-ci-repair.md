**Failed final CI, Phase 2: a CI-fix commit instead of the reviewer panel (docs/plans/final-ci-failure-ci-fix-plan.md, Refs #9656).**
- Gate (`scripts/review_autofix_step_evaluate_gate.sh`, after every skip decision, only when the run will review): new outputs `final_ci_repair` (`true|false`) and `final_ci_repair_attempt` (`1|2`, empty otherwise), exported by the `gate` job. `final_ci_repair=true` needs all of: `FINAL_CI_REPAIR_ENABLED` (repo variable, default `true`; any value other than `true`/`false` turns it off with a warning); a trusted `ai:final-ci-failed:v1` marker for the PR and head (the `GH_PAT` login or `github-actions[bot]` of type `Bot`); no `GH_PAT`-login review output (clean marker, partial-finalize marker, `review-autofix-failure:v1` comment, no-op or changes-lost comment; a provider-pause notice does not count) newer than that marker, so only the hand-back's first review repairs; a head ref that is not `orchestrator/project-*`; no trusted (`GH_PAT` login) `ai:final-ci-repair:v1` marker with `from=<head>`, whether a repair or a `repair=none` fallback (`reason=head_cap`), and fewer than 2 distinct heads repaired (`repair=<sha>`) on the PR (`reason=pr_cap`); and the head's newest `ai-review/head-gate` status is `success` with creator the `GH_PAT` login. API cost: the marker comments come from the shared `gate_fetch_marker_comments` read (it now also keeps `<!-- ai:final-ci-repair:v1 ` bodies); one `GET commits/<head>/statuses?per_page=100` runs only when every comment-based condition holds. Any failure keeps the full review.
- `review_autofix.yml` step "Integration post-sync test repair": `if:` widened to `((inputs.post_sync_test_repair && startsWith(env.TARGET_BRANCH, 'orchestrator/project-')) || needs.gate.outputs.final_ci_repair == 'true')` with the other guards unchanged; env `FINAL_CI_REPAIR`, `FINAL_CI_REPAIR_ATTEMPT`, `FINAL_CI_REPAIR_FROM_SHA` (the gate's `head_sha`).
- `scripts/review_autofix_step_prepush_test_gate.sh` integration mode, final-CI path (`FINAL_CI_REPAIR=true` on a non-orchestrator head): the checkout must still be `FINAL_CI_REPAIR_FROM_SHA` (else `reason=head_moved`); it gates the head against its merge-base with `BASE_BRANCH` as the orchestrator path does. Only when the gate reproduces failures the head caused does it write `INTEGRATION_TEST_REPAIR_ACTIVE=true` (reviewers and editor skip) and run `review_conflict_resolve.sh --test-repair <result.json> --final-ci`; the re-run gate withholds a repair that leaves failures, as before, and a repair whose re-run was skipped for step time is withheld too. A committed repair posts one comment (up to 3 POST attempts, `GH_PAT`) ending in `<!-- ai:final-ci-repair:v1 pr=<n> from=<approved head> repair=<new head> attempt=<k> -->` before "Push all pending commits" pushes it. Every other outcome resets the checkout to the approved head, writes `INTEGRATION_TEST_REPAIRED=false` and `INTEGRATION_TEST_REPAIR_ACTIVE=false`, posts the same marker with `repair=none` (so the head is never tried again, even when the fallback review posts nothing), and the same run continues with the full review round. The orchestrator path is unchanged.
- `scripts/review_conflict_resolve.sh --test-repair <result.json> --final-ci`: `--final-ci` alone exits 2. The context is the PR's title and body (one `GET pulls/<n>`; failure logs `reason=state_unavailable`) and the first 20000 bytes of `PR_CHECK_RUNS_CONTEXT_FILE`, all fenced as untrusted, rendered into `prompts/final-ci-test-repair.txt` through the same placeholders the integration template uses (`TRACKING_ISSUE_NUMBER/TITLE/BODY` carry the PR's, `MERGED_SUB_ISSUES_LIST` the check-runs). No intent fingerprints (`{}`), so the fingerprint hard gate does not run in this mode only. Commit subject `[ai-merge-resolve] repair final CI failures`, so iteration counting and `sync_claude_live_copies.py` need no change.
- After the push, the repair head gets its own review (the post-push re-dispatch) and, once approved, its own final CI run through `_pr_ensure_final_ci`.
- Tests: `tests/test_review_autofix_clean_same_head_gate.py` (gate truth table), `tests/test_review_prepush_test_gate.py` (final-CI repair path), `tests/test_review_conflict_resolve_sandbox_only.py` (`--final-ci` context), `tests/test_review_autofix_review_pipeline_contract.py` (step `if:`).
