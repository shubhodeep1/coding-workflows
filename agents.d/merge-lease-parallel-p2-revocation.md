- **Merge-lease revocation, grant-time eligibility and skip-until-head-changes (merge-lease parallel merges Phase 2, Refs #9781).** `_merge_lease_pr_eligible <pr> <head> <title> <draft> [<base>] [<trusted_login>] [<hold_since>]` in `scripts/pr_checks_lib.sh` returns 1 (`MERGE_LEASE_INELIGIBLE_REASON=draft|skip_ai|no_head_gate|final_ci_failed`) when a PR can no longer merge, checked cheapest first: draft, a `[skip ai]` title (fixed-string, case-insensitive, never logged), the newest `ai-review/head-gate` status on the head (counted only when the pipeline login created it), then `_pr_wait_for_required_checks <pr> <head> <base> 0` (no final-CI dispatch, no pending marker). A waiter needs a pipeline head-gate success; a holder (`<hold_since>` given) loses the lease for a missing or pending head-gate only after `MERGE_LEASE_IDLE_MINUTES` (180 when that is 0, which turns off only the idle test), so a holder whose updated head is being re-reviewed keeps it. CI runs that were all cancelled or hit startup_failure (`reason=ci_run_cancelled`) are not `final_ci_failed`; they count as eligible, and `MERGE_LEASE_CI_ACTIVE` reflects the runs already read. Every read failure, and an unresolvable login, counts as eligible (fail-open). It also sets `MERGE_LEASE_CI_ACTIVE=true|false|unknown`.
  - `_mt_merge_lease_tick` (`scripts/review_merge_train.sh`) runs Phase 2 only when the staged library has the helper (`declare -F`) and `MERGE_LEASE_REVOKE_ENABLED` is on. A held, unexpired holder found in the open-PR listing is released with `reason=revoked_<why>`, or `reason=revoked_idle` when `MERGE_LEASE_IDLE_MINUTES` (default 180; 0 = off) have passed since `max(updated=, acquired=)` and no CI run or required check is running on its head. A holder missing from the listing keeps the old closed-check only. The grant loop checks up to 10 waiters per base per tick in queue order and unlabels an ineligible one (`outcome=skipped reason=<why>`).
  - Skip list: an `expired` or `revoked_*` release appends `skip=<pr>:<head>` to the lease record (between `updated=` and `paths:`, at most 50, newest kept, header still `merge-lease v1`). `_merge_lease_queue_first <pulls> [candidate] [skips] [exclude_csv]` passes over a row whose number and current head match an entry, in the tick and in the update-mode gate (the tick never grants a skip-held PR on that head; when the queue holds no other waiter, the tick removes the skip-held waiters' wait label so the sweep dispatches them again, and the update-mode gate lets a lone skipped caller acquire, its held write dropping its own entry). The tick prunes entries whose PR is not open on the base with that head, from the listing it already read. `MERGE_LEASE_UPDATED` and `MERGE_LEASE_SKIPS` are parsed by `_merge_lease_read`; a record without these lines parses as before, and old readers ignore them.
  - `_mt_list_open_prs` rows gain `title` (author text; read only through jq).
  - Env, wired as repository variables in `review_autofix.yml`, `orchestrate_poll.yml` and `cancel_on_pr_close.yml` with the helper's defaults (#9821): `MERGE_LEASE_REVOKE_ENABLED` (default `true`; `false` turns off revocation, eligibility, the skip list and `skip=` writes, so the record is byte-for-byte the old format) and `MERGE_LEASE_IDLE_MINUTES` (default 180, 0-1440).
