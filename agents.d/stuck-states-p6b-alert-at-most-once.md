<!-- agents: section="Workflow architecture" -->
- **At most one persisted CRITICAL alert attempt per needs-human parking (stuck-states P6b, Refs #8291).** The page for a parked item is no longer derived from `newly_parked` (one digest read, nothing persisted, so two concurrent judge runs could both page). `needs-human park` (`scripts/operator_step_issue.py`) now also prints `parking`: the digest entry's `parked=` stamp, `overflow` for an overflow or dropped item, or null when disabled. After every successful park that returns a `parking`, the unblock judge (`unblock_needs_human_alert` in `scripts/unblock_judge.sh`) and the poller (`needs_human_park_project` in `scripts/orchestrate_poll_process.sh`) run claim -> send -> confirm. First the Telegram helpers must be loaded (`reason=helper_missing` otherwise) and `tg_alert_configured CRITICAL` (`scripts/tg_helpers.sh`: token, chat ID and `ALERT_MSG_LEVEL` threshold; the poller also honours `_smoke_fixture_alert_silenced`); when it fails nothing is claimed, so the attempt is kept for a run that can send. `needs-human alert-claim` reads the item's comments and skips (`already_attempted`) when a comment by the pipeline login ends with `<!-- ai:unblock-park-alert:v1 item=N parked=<stamp|overflow> state=attempted|confirmed[ message=ID] -->` for the same parking; an `overflow` claim covers every later stamp, so a promoted overflow item is not paged twice. Otherwise it posts one `state=attempted` claim, re-reads, and only the lowest-id matching trusted claim sends (`lost_race` / `claim_unverified` otherwise). The winner calls `tg_send_msg` once, with no retry; a numeric message id is recorded in place by `needs-human alert-confirm` (`state=confirmed message=ID`, one PATCH). A failed claim write or re-read, an empty send result, or a failed confirm never sends again for that parking and never fails the judge op list or the poller tick. Forged claims from other logins are ignored. The `ai:unblock` prefix keeps the claim out of the unblock scan's new-evidence check and the judge's round count. API budget per park that reaches the claim: two paginated comment reads on the item, one comment POST, at most one PATCH. `NEEDS_HUMAN_DIGEST_ENABLED=false` disables park and both subcommands.
