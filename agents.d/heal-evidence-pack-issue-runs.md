Heal intake evidence pack, issue-linked runs and branch divergence (P1 steps 2 and 3 of `docs/plans/heal-evidence-reproduction-and-trends-plan.md`, #8475): behind the same `WORKFLOW_HEAL_EVIDENCE_PACK_ENABLED` switch and inside the same `WORKFLOW_HEAL_EVIDENCE_PACK_MAX_BYTES` cap, `_heal_build_evidence_pack` calls `_heal_fetch_evidence_pack_api` (after its switch-off return, `workflow_run` reports only). `workflow_failure_heal.py evidence-pack-requests` parses the failed jobs' filtered logs for same-repo `issues/<n>` URLs and `issue #<n>` / `on issue #<n>` references (`extract_issue_refs`, newest mention last, at most 2) and the saved jobs JSON for the failed jobs' `started_at..completed_at` window (`evidence_pack_job_window`); the shell never parses log text. The intake then makes at most 5 GitHub REST GETs per report, each a single attempt (`GH_RETRY_MAX_ATTEMPTS=1`): `repos/<source>/issues/<n>` for each issue's title (titles always come from the API, never from the log), one shared `repos/<source>/actions/runs?created=<window>&per_page=100` listing (page 2 only when page 1 is full and `total_count > 100`), and, for a self-repo report whose heal target and default branch (`PROVENANCE_DEFAULT_BRANCH`) are both valid and differ, one `repos/<self>/compare/<target>...<default>`. The target is the one the Route block gives the heal issue: the failed run's `head_branch` (the `promote-candidate` mirror maps to the default branch), else `WORKFLOW_HEAL_TARGET_BRANCH` (default `stable`); a failed run on the default branch therefore gets no compare. The Route block's branch-exists fallback is not applied, so a run branch deleted since the run makes the compare 404 and logs `reason=compare_unreadable`. No issue is read when no failed-job window exists. `evidence-pack` gains the optional flags `--issue-runs NUMBER ISSUE_JSON`, `--issue-runs-page RUNS_JSON`, `--divergence-compare/--divergence-target/--divergence-default` and `--pack-reason TOKEN`; without them the output is unchanged. The pack appends one ``### Runs started for issue `#<n>` `` subsection per readable issue (`issue_linked_runs`: runs whose `display_title` equals the issue title and whose repository is the source, rendered `<id> <status>/<conclusion> <created_at> <run_started_at> <updated_at> <head_sha> <head_branch>`, at most 10) and a `### Branch divergence` subsection (`branch_divergence`: the range files that pass `_safe_heal_path`, at most 20, and the last 10 range commits with `[PR #N]` from a squash subject's `(#N)`; the compare response has no per-commit file attribution, so none is claimed; a `(truncated: ...)` note when `total_commits` exceeds the listed commits (GitHub lists at most 250) or the file list holds 300 entries). Headings hold fixed text and an integer only (the issue number in a code span, so it never autolinks to an unrelated issue of the repository the heal issue is filed in); every value goes through the same `_evidence_pack_clean` (redact, `sanitize_text`, `neutralize_untrusted_routing`, fence escape) and `compose-issue`'s `validate_heal_issue_body_routing`. Fetch and parse failures fail open as new reason tokens on the existing single `evidence_pack` log line (`issue_unreadable`, `runs_unreadable`, `runs_truncated`, `compare_unreadable`, `compare_malformed`, `job_window_unavailable`, `requests_failed`); the earlier P1 timeline reasons still win. Responses stay under `${RUNTIME_DIR}/evidence_pack_api/` and feed neither the scope marker, the fingerprint nor the diagnosis prompt. With the switch off no call is made and the body is byte-identical.
