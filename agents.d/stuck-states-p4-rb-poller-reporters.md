- **Poller release-blocker reporters (stuck-states P4 / release-blocker Phase 3, Refs #8291).** `scripts/orchestrate_poll_process.sh` calls `poller_release_blocker_report <state_key> <reason> <age_secs> <head_sha> [evidence ...]` (always `|| true`) after the terminal promote-cycle state write and before that site's `post_state_comment`. The sites are: `comprehensive_promotion_hold_or_fail` past the hold cap (`promotion_failed:<gate reason>`; `promote_sha` comes from the calling gate's local through bash dynamic scope), `release_workflow_not_pinnable`, `dispatch_failed` (the raw gh stderr `_dispatch_msg` stays out of the evidence), `release_failed`, `hold_timeout` (all with state key `comprehensive_promotion`), `verification_not_dispatched` only when the outcome carries `retries_exhausted=`, and `marker_untrusted` only on the first untrusted-marker alert (both with key `comprehensive_release_callback`; the marker author comes from the new `untrusted_author` field of `comprehensive_cycle_metadata_json`, read from the comments already fetched). `release_workflow_not_pinnable` and `dispatch_failed` now also post state. The gates run in this order: the kill switch `RELEASE_BLOCKER_HEAL_ENABLED` (`RELEASE_BLOCKER_REPORT_SKIPPED reason=disabled`), then the producer gate (`GITHUB_WORKFLOW_REF` must start with `${GITHUB_REPOSITORY}/.github/workflows/internal-orchestrate-poll.yml@`, otherwise `reason=disabled ... detail=producer_unregistered`, so consumer pollers and tests never report), then the once-only guard `<state_key>.release_blocker_reported` (`reason=already_reported`). Every attempt past the gates sets the guard. The chain is the same as Phase 2a: `build-blocker-payload` with `--workflow-name "${GITHUB_WORKFLOW}"`, `head_branch=${DEFAULT_BRANCH_TRACKING:-main}`, no `run_refs` and a sanitised evidence file whose first line is `reason=<token>`, then `request-report-identity` (the caller grants `id-token: write`), then `wrap-dispatch` and `POST repos/<self>/dispatches`. Success logs `RELEASE_BLOCKER_REPORTED ... run_ref=none tracking_issue=<n>`; failure logs `RELEASE_BLOCKER_REPORT_SKIPPED reason=payload_invalid|dispatch_denied` plus a `tg_notify` WARNING. The reporter sets no EXIT trap and removes its `mktemp -d` work dir inline. `orchestrate_poll.yml` maps `RELEASE_BLOCKER_HEAL_ENABLED` and `RELEASE_BLOCKER_HEAL_PY` into both full-poller steps. The test harness records these POSTs in `heal_dispatches` (`fail_heal_dispatch` makes them fail) and drops a CI runner's `GITHUB_WORKFLOW_REF` and `ACTIONS_ID_TOKEN_REQUEST_URL`.
