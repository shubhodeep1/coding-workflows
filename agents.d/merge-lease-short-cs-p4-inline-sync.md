- **Inline update-and-merge after a merge-base update (issue #10198, Phase 4 of `docs/plans/merge-lease-short-critical-section-plan.md`; Refs #10097).** The deterministic-skip-merge job of `review_autofix.yml`, `scripts/review_enable_auto_merge.sh` and `scripts/review_rb_judge.sh` call `_pr_base_fresh_for_merge` with the per-call prefix `PR_BASE_SYNC_INLINE_CALLER=true` (the re-checks after a checks wait in the workflow and the judge, the poller and `scripts/review_merge_train.sh` do not). With `MERGE_LEASE_INLINE_SYNC_ENABLED` on (default `true`; `true/1/yes/on`), the `ai:merge-base-sync:v1` marker then ends ` inline_run=<GITHUB_RUN_ID>` after `merge=<sha>` (existing fields unchanged; without the switch or the prefix the body is byte-identical), and the caller runs `_pr_base_sync_inline_merge <repo> <pr> <approved head> <update head> <base ref>` (`scripts/pr_checks_lib.sh`) when the freshness call returned 1. It acts only when this call posted that marker (`PR_BASE_SYNC_INLINE_MARKED=true`) and `_pr_base_sync_dispatch_final_ci` dispatched or found a quick run (`PR_BASE_SYNC_CI_QUICK=true`, `PR_BASE_SYNC_CI_OUTCOME=dispatched|exists`), then: the `review_head_gate.sh freshness-sync` skip verdict on a fresh comments read; `review_head_gate_post_status ... success "deterministic skip evaluated this head"`; the single-issue security pass when the gate's predicate holds (`review_autofix_step_deterministic_skip_security_pass.sh` on a detached worktree of the update head inside `.codex-skip-pr-head`, which needs `AUTOFIX_SKIP_RUNS_SECURITY_PASS=true` and must write `hold=false`; the snapshot is the observe step's PR read, `PR_BASE_SYNC_PULL_JSON`); `_pr_wait_for_required_checks` on the update head; a second success post (the pushed run's early `pending` may land after the first); then it sets `PR_BASE_SYNC_INLINE_HEAD` and returns 0 so the caller's existing `--match-head-commit` merge runs on the update head. Every failure after the precondition returns 1 and dispatches the review once (the `_mt_dispatch_review` loop over `MERGE_TRAIN_DISPATCH_WORKFLOWS`); an exhausted pass already dispatched it (`dispatch=by_security_pass`). One log line: `MERGE_BASE_FRESHNESS pr=<n> outcome=inline_merge reason=<ok|invalid_input|not_quick|freshness_sync|head_gate_status|security_pass|required_checks> head=<sha> dispatch=<...>`. The marker readers (`_pr_base_sync_count`, `review_head_gate_freshness_sync`) accept the optional field; `review_head_gate.sh freshness-sync-inline-run <pr> <head> <login> <comments file>` prints the trusted marker's run id (no API call). In `scripts/review_autofix_step_evaluate_gate.sh`, a `pull_request` run whose head takes the freshness fast path reads that run once (`GET actions/runs/<id>`) and, while it is `queued` or `in_progress`, sets `SHOULD_RUN=false`, `SKIP_REASON=lease_inline_owner_active` (no deterministic-skip job) and logs `AUTOFIX_GATE_DET_SKIP_EVAL pr=<n> skip=true reason=lease_inline_owner`; a completed run or a failed read (`reason=lease_inline_owner_read_failed`) keeps the fast path, and `workflow_dispatch` runs (the hand-off) never take the owner skip. A head-gate post counts only when `review_head_gate_post_status` prints `state=success outcome=posted` (or `outcome=disabled`), so a failed first or second post is `reason=head_gate_status` and hands off. With `SINGLE_ISSUE_SECURITY_PASS_ENABLED` on and `DEFAULT_BRANCH` empty the pass counts as required (fail closed); the codex-agent callers (`review_enable_auto_merge.sh`, `review_rb_judge.sh`) have no `.codex-skip-pr-head` checkout, so where the pass applies they hand off with `reason=security_pass`. The gate also skips the owner check when its PR read showed auto-merge enabled (the early head-gate call has just withdrawn it), logging `AUTOFIX_GATE_DET_SKIP_EVAL pr=<n> skip=false reason=lease_inline_owner_auto_merge_enabled`, so the freshness fast path redoes the merge. Rollback: `MERGE_LEASE_INLINE_SYNC_ENABLED=false`. `tests/test_merge_lease_inline_sync.py` covers it.
