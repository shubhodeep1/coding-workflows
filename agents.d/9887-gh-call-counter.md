### Per-job gh call counter (issue #9887)

- **What it counts.** `scripts/gh_call_counter/gh` is a `PATH` shim. For each `gh` invocation it appends `v1 cmd=<allowlisted subcommand|other> paginate=<0|1> token=<pat|github_token|other>` to `${GH_CALL_COUNTER_LOG:-${RUNNER_TEMP}/gh_call_counter.log}` and then execs the next `gh` on `PATH`. The token kind comes from variable names only: `GH_TOKEN` set means `pat`, else `GITHUB_TOKEN` set means `github_token`, else `other`. An optional per-step `GH_CALL_COUNTER_TOKEN_KIND` overrides it (for part B, #9888, which moves reads to `github.token` through `GH_TOKEN`). No argument or value is ever logged. `scripts/gh_call_counter/gh-call-counter-summary` turns the log into the three end-line keys.
- **Where it runs.** `gh_call_counter_install` writes both scripts from heredocs embedded in `scripts/gh_helpers.sh` (kept byte-identical to the canonical files by `tests/test_gh_call_counter.py`) into `${RUNNER_TEMP}/gh_call_counter.XXXXXX`. It prepends that dir to `PATH` and appends only the dir to `GITHUB_PATH`. Each instrumented job has one `Install gh call counter` step (`continue-on-error: true`, no token in its env). It sources only that job's trusted helper copy (`GH_CALL_COUNTER_HELPERS`; the per-job list is `GH_CALL_COUNTER_TRUSTED_HELPERS` in `tests/test_review_autofix_sweep_zero_candidate_fast_exit.py`), never a PR-head checkout. The jobs are the 14 existing `GH_PAT_BUDGET` jobs plus the release-gate jobs `e2e-smoke-test`, `e2e-alt-model-test`, `validate-standalone-test`, `workflow-log-analysis-test`, `orphan-workflows-test`, `orchestrate-decompose-test`, `clarify-rejects-unsolvable-test` and `validate` in `test-and-mark-stable.yml`. `validate` holds no PAT, so its budget steps make no API call and print `remaining/reset/used_in_job=unknown`.
- **Ordering with the comment-signing shim.** The counter finds its target on every call and skips its own dir and any `*/gh_call_counter.*` dir, so it may exec the comment-signing shim but never itself. `_ai_comment_sig_activate` and the embedded signing shim skip counter dirs when they resolve the real `gh`. After a fresh signing activation, `_gh_call_counter_refront` moves the counter back to the front of `PATH` (and `GITHUB_PATH`). Signing is never bypassed and no exec loop is possible. Keep this invariant if either shim changes.
- **Counting order.** End steps read the summary before their own `rate_limit` read, so the budget read is not counted. The end step (`if: always()`) must stay after every step that calls `gh`: in the sweep it follows the CI re-run, final-CI and security-hold steps, and in `clarify` / `poll` it follows "Report refused AI engine fallbacks", so their calls are counted.
- **Known gaps.** Calls are not counted when they happen before the install step, call `gh` by absolute path, run under `env -i` without the shim dir on `PATH`, or run inside the isolated agent containers. A `--paginate` call counts once (see `paginated_in_job`). Comment posts the signing shim sends with the job token, and `GH_TOKEN: ${{ github.token }}` steps without the override, count as `pat`; the instrumented steps that set it (clarify's reclarify requeue, the sweep's CI re-run, the release-gate `validate` CI check) set `GH_CALL_COUNTER_TOKEN_KIND: github_token`. These numbers are a ranking signal, not exact request counts.
- **Kill switch.** Repository variable `GH_CALL_COUNTER_ENABLED` (default `true`). With `false` nothing is installed and the keys read `unknown`.
