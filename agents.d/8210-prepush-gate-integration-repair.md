- **Integration-branch post-sync test repair (issue #8210, plan phase P5).** A clean default-branch sync or a sibling squash-merge into `orchestrator/project-*` can leave a test failure `main` does not share; this repairs it once per new integration head.
  - **Poller.** `_dispatch_integration_test_repair <tracking_issue> <integration_branch> <final_pr> [default_branch]` in `scripts/orchestrate_poll_process.sh` runs after `mark_integration_sync_clean` (the pre-flight clean probe and the late-mergeable lifetime-cap path in `heal_integration_branch_conflict`, and the clean merge in `sync_default_into_integration_branch`) and after a sibling squash-merge in the ready-to-merge loop that reports `ORCH_MERGE_BOUND_OUTCOME=merged`. Checks, in order:
    - `PREPUSH_TEST_GATE_MODE` (default `repair`; `off` skips);
    - a numeric final PR (argument, else `.final_merge_pr`);
    - an `orchestrator/project-<N>` branch and a valid default branch (argument, else `CWS_DEFAULT_BRANCH`);
    - the integration head from a local `git fetch` (a failed fetch skips the tick as `fetch_failed`, so a stale ref cannot hide a new head);
    - readable state (fails closed as `state_unavailable`);
    - the state field `integration_test_repair_sha` (equal head skips);
    - the new state field `integration_test_repair_dispatches` against `INTEGRATION_CONFLICT_LIFETIME_MAX`. It is separate from `integration_conflict_total_dispatches`: repair dispatches happen on every new head and no conflict episode releases them, so sharing that counter would let routine syncs park the next real conflict at the cap with no resolver attempt;
    - the first of `ai-review.yml`, `internal-review.yml`, `review_autofix.yml` whose default-branch copy (`git show`) has `post_sync_test_repair:` alone on a line (a `with:` pass-through does not count);
    - the cycle-local `_CONFLICT_DISPATCH_TRACKER`.
    Then exactly one `gh workflow run <wf> -f pr_number -f allow_workflow_edits -f post_sync_test_repair=true` (no `--ref`). Only on success does it record `integration_test_repair_sha` (new state field) and add 1 to `integration_test_repair_dispatches`, then call `post_state_comment` so the dedupe survives the tick (a failed local state write warns that the next tick may dispatch the same head again). No REST or GraphQL read, and `_has_active_autofix_run` is not used. `orchestrate_poll.yml` forwards `PREPUSH_TEST_GATE_MODE` to "Process each tracking issue".
  - **Review run.** `review_autofix.yml` declares `post_sync_test_repair` (boolean, default `false`) under `workflow_call` and `workflow_dispatch`; the consumer `ai-review.yml` declares and forwards it. "Integration post-sync test repair" runs right after "Pre-review deterministic merge-topology gate" when the input is true, the head is `orchestrator/project-*` and `CAN_PUSH=true`. It sources `review_autofix_step_prepush_test_gate.sh` with `PREPUSH_TEST_GATE_STEP_MODE=integration` (`review_prepush_test_gate_integration_main`), which:
    - writes `INTEGRATION_TEST_REPAIR_ACTIVE=true` first, so the 17 `if:` lines that carry `env.AUTOFIX_PRE_REVIEW_RESOLVE != 'true'` also skip on `env.INTEGRATION_TEST_REPAIR_ACTIVE != 'true'` (reviewers, editor, the pre-push affected-test gate and "Commit changes"), and so do "Single-issue security pass", "Review-blocked judge decision", "Enable auto-merge on PR", "Mark linked issues ready to merge" and "Telegram success", because a repair-only run reviewed nothing (on the two merge steps the clause sits before the `steps.single_issue_security_pass.outputs.hold` clause, which stays last). With the judge skipped its outputs are empty, so the exhaustion fallbacks that read them ("Mark linked issues review-blocked (autofix exhaustion)", "Force orchestrate poll after review-blocked exhaustion", "Post review-blocked comment on PR (autofix exhaustion)", "Telegram review-blocked judge decision") carry the clause too; "Mark outage-caused review-blocked labels" needs `rb_judge_provider_unavailable == 'true'` and cannot fire;
    - skips on mode `off` and on the conflict path (`AUTOFIX_PRE_REVIEW_RESOLVE` / `MERGE_CONFLICT`);
    - gates the head against `git merge-base HEAD origin/<BASE_BRANCH>`, with the image and dependency venv of one full `review_untrusted_sandbox.sh prepare codex` (private `GITHUB_ENV`, 1200 s bound; `prepare-ephemeral codex`, image only, when it fails, logged as `outcome=warning reason=prepare_failed fallback=image_only`), cleaned up after the last gate run. The prepare's `source/node_modules` goes to the wrapper as `--node-modules`, a root without a venv logs `outcome=warning reason=venv_absent`, and the step passes `DEPENDENCY_PROXY_ALLOWED_HOSTS` so a private index reaches the install;
    - on PR-caused failures in `repair` mode runs `review_conflict_resolve.sh --test-repair <run1/result.json>` with the remaining step budget (`RESOLVER_TEST_REPAIR_BUDGET_SECS`, step `timeout-minutes: 120`);
    - after a committed repair re-runs the gate into `run2` when the budget allows; when PR-caused failures remain it appends `INTEGRATION_TEST_REPAIRED=false` to `GITHUB_ENV`, so the commit is not pushed (`repair=withheld...`).
    "Push all pending commits" also runs on `INTEGRATION_TEST_REPAIRED=true`; the post-commit re-trigger does not (the next poller tick sees the new head).
  - **Resolver.** `review_conflict_resolve.sh --test-repair <file>` (any other argument exits 2) branches before the conflict-specific top-level code, clears the EXIT trap (no integration-judge dispatch, no retry-state write) and runs `_resolver_test_repair_main`:
    - the result file must be a regular, non-symlink file under `RUNTIME_DIR`;
    - `_resolver_test_repair_context` reads the tracking issue (body capped at 20,000 characters), the pipeline login and the paginated comments, takes the login's newest complete `ORCHESTRATOR_STATE_V2` chain through the trusted `orchestrate_state_v2.py extract` (support copy, else `.codex-workflow-src/scripts`), and falls back to `ORCHESTRATOR_STATE_V1` only without V2 state. An unverifiable login skips (`identity_unavailable`); no readable trusted state skips (`state_unavailable`), so a missing state never bypasses the fingerprint hard gate;
    - it renders `prompts/integration-sync-test-repair.txt` (with `INTEGRATION_FINGERPRINTS_FILE` passed to the renderer, so `{{INTENT_FINGERPRINTS_JSON}}` carries the trusted fingerprints) (from an absolute `SUPPORT_PROMPTS_DIR`, else `.codex-workflow-src/prompts`; the prompt is not in the support staging list yet);
    - the captured failures are framed by `=== CAPTURED TEST FAILURES (UNTRUSTED) ===` / `=== END CAPTURED TEST FAILURES (UNTRUSTED) ===` with every line prefixed `UNTRUSTED_DATA: ` (in `review_prepush_test_gate_build_prompt`, so the review and heal repair prompts get the same framing);
    - the allow-list is the step script's `allow-list` over `git diff --name-only <merge-base> HEAD` (no `.github/workflows/` unless `ALLOW_WORKFLOW_EDITS=true`), and the prompt comes from `repair-prompt RESULT OUT ALLOW TEMPLATE CHANGED` (the new optional TEMPLATE replaces the implement repair template; the failures stay wrapped as untrusted and capped at 16 KiB);
    - one `_resolver_sandbox_attempt` (Claude, then codex on exit 75);
    - `check_resolver_diff.sh` with an empty conflicted set plus `--extra-allowed-file` per allow path, then `verify_integration_fingerprints.py` with `--compare-against-baseline` against a `--baseline-fingerprints-state` capture taken before the model runs (absolute check when the capture fails), so drift already on the head does not reject a repair (exit 1 reverts), staging and an unmerged-entry check;
    - a commit `[ai-merge-resolve] repair post-sync test failures` with the engine's identity, then `INTEGRATION_TEST_REPAIRED=true` in `GITHUB_ENV`. Any rejection restores the pre-repair index and files. The resolver's EXIT trap (integration-judge dispatch) is installed only outside `--test-repair`.
    - API reads per repair turn: the tracking issue, `/user` and the tracking comments (one call per 100 comments). The poller side adds none.
  - **Logs** (existing prefix): `PREPUSH_TEST_GATE phase=integration outcome=dispatched|dispatch_failed|skipped|pass|fail|unverified|no_edits|committed|repair_reverted reason=mode_off|state_unavailable|no_final_pr|no_integration_branch|default_branch_unknown|fetch_failed|head_unavailable|already_dispatched|already_dispatched_this_tick|lifetime_cap|wrapper_input_absent|not_requested|conflict_path|merge_base_unresolved|runtime_dir_missing|no_git_checkout|invalid_input|module_absent|repair_template_absent|identity_unavailable|render_failed|empty_allow_list|repair_prompt_failed|step_budget|index_unavailable|check_resolver_diff|fingerprints|staging|editor_exit_<n>|claude_capacity_wait|commit_failed`.
  - **Known gaps.** `internal-review.yml` does not forward the input yet: it calls `review_autofix.yml@main`, which lacks it until this change is on `main` (PR #4438 startup_failure). Follow-up: add the pass-through once it is. If the review gate job skips a dispatched run (terminal same-head marker, deterministic skip, merge train), the SHA is already recorded and the next head change dispatches again. `integration_test_repair_dispatches` is never reset, so a project gets at most `INTEGRATION_CONFLICT_LIFETIME_MAX` repair dispatches. `review_autofix.yml` grew by 3,468 bytes (17 + 9 repeated `if:` clauses, two input declarations, the step), over the issue's 1,000-byte and the plan's 3,000-byte P4+P5 estimate; the file stays at about 372,900 bytes, far below the 480,000-byte guard.
  - Off switch: `PREPUSH_TEST_GATE_MODE=off` stops both dispatch and repair.
