**Final-CI self-heal: base sync and merge-ref freshness (2026-11-17, Refs #9602, #9614, #9562, #9621, #9454).** A head whose only CI verdict is a failure never got another run: `_pr_ensure_final_ci` answers `exists failure`, and the `final-ci-failed` hand-back's editor makes no edit when the failure comes from the base. Five reviewed PRs sat red that way. The causes: the dispatched `ci.yml` is the head branch's own copy, so a stale head ran a suite that called a deleted test (#9562). A stale base still fired the retired `pull_request` trigger, which gets no hand-back (#9621, #9454). And the final run tested a `refs/pull/<n>/merge` that GitHub had not recomputed after the base fixed the failure (#9602 at 07:21 UTC tested base `df30f80a`, although the base had been at its fix `8a1664a5`, push CI green, since 05:37; #9614 tested a base without `.github/ai/alert_inbox.json`).
- **Sweep base sync** (`scripts/review_final_ci_sweep.sh`, step "Ensure the final CI run on reviewed PR heads" of `review_autofix_sweep.yml`). After the no-run pass, the sweep builds a second candidate list:
  - heads the tick's listing shows with only completed runs, no `success` and at least one failed full (not ` [sync-quick]`) run;
  - heads the no-run pass found with `PR_FINAL_CI_REASON=failure` through `_pr_ensure_final_ci`'s head-SHA read. This covers an old `pull_request` run outside the listing. `_pr_ensure_final_ci` now also exports `PR_FINAL_CI_REASON` and `PR_FINAL_CI_FAILED_AT` (the newest failed full run's `updated_at`) from the read it already makes.
  - Candidates run oldest failure first. Each must clear these checks in order:
    1. the failure is at least `FINAL_CI_SWEEP_BASE_SYNC_MIN_AGE_MINUTES` old (default 30), so the hand-back acts first;
    2. no queued, pending or running `internal-review.yml` / `review_autofix.yml` run for the PR (by head ref or `pr:<n>`) is in the snapshot the step "Enumerate open PRs and dispatch internal-review.yml" now writes to `${RUNNER_TEMP}/final-ci-active-review-runs.txt` (`FINAL_CI_SWEEP_ACTIVE_REVIEW_RUNS`; no extra API call). A missing or `incomplete` snapshot also waits (`review_in_flight`), because a branch update would race that run's push. Checks 1 and 2 make no API call, and a candidate stopped there does not count toward `FINAL_CI_SWEEP_MAX_PER_TICK`;
    3. fewer than `FINAL_CI_SWEEP_BASE_SYNC_MAX` (default 3) sweep syncs exist. `_pr_base_sync_count` now also sets `PR_BASE_SYNC_FINAL_CI_COUNT` from the same read, counting markers that carry `<!-- ai:final-ci-base-sync:v1 pr=<n> -->`, and `PR_BASE_SYNC_LOGIN` (the token's login);
    4. the newest `ai-review/head-gate` status on the head is `success` and its `creator.login` is that login (one `commits/<sha>/statuses?per_page=100` read; otherwise `gate_untrusted`). The marker lets the update skip the reviewers, so a status that any status writer could post does not count, the same rule as the gate-supersede check;
    5. `_pr_base_freshness` says the head is behind (`clean` or `overlap`; `fresh` logs `up_to_date`);
    6. the base's newest completed push run of `ci.yml` did not fail. Only `main`, `stable` and `orchestrator/project-*` have push CI. The listing is read first, then one `runs?branch=<base>&event=push&status=completed` read, cached per base. `ai/issue-<n>` bases are synced anyway.
  - Then the merge-path chain runs unchanged: `_pr_base_sync_for_fresh_ci` (head-bound update-branch), `_pr_base_sync_observe_update_commit`, `_pr_base_sync_marker_post`, `_pr_base_sync_dispatch_final_ci`. For the marker, the new optional `PR_BASE_SYNC_MARKER_LEAD` replaces the "gained N commit(s) that touch files" sentence. The heading and the closing `ai:merge-base-sync:v1` line are unchanged, so `review_head_gate.sh freshness-sync` lets exactly that verified update commit skip the reviewers.
  - An unverified update posts no marker and is reviewed normally. `FINAL_CI_SWEEP_BASE_SYNC_ENABLED=false` turns the pass off. `MERGE_BASE_FRESHNESS_ENABLED=false` also stops it (freshness `disabled`). `DRY_RUN` logs `outcome=dry_run`.
- **Merge-ref freshness** (`scripts/ci_final_merge_ref_fresh.sh`, step "Verify the final-CI merge ref is current" right after each of the ten final-CI checkouts in `ci.yml`, with the checkout's `if` and fetch depth).
  - The step compares the merge commit's first parent, read from the raw commit object because a depth-1 clone hides it from `rev-parse`, with `git ls-remote origin refs/heads/<base>`. The base name comes from one `GET pulls/<n>`. `tests-sandbox-python` passes no token (its coverage test forbids one), so there the script reads that endpoint unauthenticated, which works because this repository is public.
  - If the two differ, each attempt makes one more `pulls/<n>` read, which triggers GitHub's recompute, then re-fetches the merge ref and re-reads the tip, up to `CI_FINAL_MERGE_REF_REFRESH_ATTEMPTS` (6) attempts `CI_FINAL_MERGE_REF_REFRESH_SECONDS` (10) apart. It checks out the new merge once that still merges `GITHUB_SHA` into a tip seen during the step.
  - `mergeable: false` fails at once (`outcome=conflict`). A ref that stays stale fails the job (`outcome=stale`), and the red `lint` goes back through `final-ci-failed`, while the sweep's base sync updates the head.
  - Not a final run, the switch off (`CI_FINAL_MERGE_REF_FRESH_ENABLED`, default `true`), an unreadable base or tip, a checkout that is not a merge of the head, a merge ref that could not be re-fetched at all (`fetch_unavailable`, e.g. a private repository and one of the three checkouts with `persist-credentials: false`), or a head that moved during the refresh: the step logs and passes, and the job tests what it checked out.
- Failure modes: a PR whose own diff is broken and whose base keeps moving is re-synced at most `FINAL_CI_SWEEP_BASE_SYNC_MAX` times, one full final run each. A red push-CI base blocks the sync until the base is green. An update-branch refusal (conflict, or the head moved) logs `outcome=failed reason=update_branch_refused` and leaves the PR to conflict resolution or its new head.
- Tests: `tests/test_review_final_ci.py` (base-sync cases, marker compatibility with the review gate and the merge path), `tests/test_ci_final_merge_ref_fresh.py` (real local origin and `refs/pull/7/merge`, and the ci.yml wiring of all ten checkouts).
