- **Base-sync carry and repeated reviewer failure (#9533).** `single_pass_gate` in `scripts/review_single_issue_security_pass.sh` calls `single_pass_base_sync_carry` when the head has no marker (before the `single_pass_inherited_clean` walk, which is skipped when the carry logs `freshness_unverified`, `parents_mismatch`, `changed_files_differ` or `patch_mismatch`) or only a stale `pending` one. The carry sources the helpers from `SUPPORT_SCRIPTS_DIR` when both are staged there. It sources `scripts/review_head_gate.sh` in a subshell and reuses `review_head_gate_freshness_sync`, which now sets `REVIEW_HEAD_GATE_FRESHNESS_FROM` / `REVIEW_HEAD_GATE_FRESHNESS_BASE_PARENT` on a skip (CLI and log lines unchanged). It then requires a `status=clean` marker for `from=` (via `single_pass_markers`), local parents `[from, base parent]`, a single merge base, equal changed-file sets and equal `-U0` `git patch-id --verbatim` (whitespace-exact) over those files. Kill switch `SECURITY_PASS_BASE_SYNC_CARRY_ENABLED` (default `true`) turns off the carry only, not the inheritance walk. For the review loop, `scripts/review_autofix_step_evaluate_gate.sh` uses `REVIEW_FAILURE_FINGERPRINT_MAX_IDENTICAL_REVIEWERS_FAILED` (default 2) as the cap when the counted reason is `reviewers_failed`; `scripts/review_autofix_step_post_editor_summary.sh` compares this run's fingerprint with the gate's `fingerprint_cap_*` outputs and, on a same-head repeat, skips the "will retry" comment and `AUTOFIX_EDITOR_EMPTY_NOOP` so the workflow-failure steps block; `_issueless_review_retry_decide` skips with `reason=repeated_reviewer_failure` only when both markers carry the still-pinned support SHA (a report-only relabel of `waiting_for_release`; it honours `REVIEW_FAILURE_FINGERPRINT_CAP_ENABLED` only when the poller's environment sets it, which `orchestrate_poll.yml` does not map today). `reviewer-failure-evidence` takes the step stderr as `--stage-stderr-file`, the only source of the one kept plain `ERROR:` line, and `error_signature` has a last-priority bucket for error-shaped bash diagnostics so different shell crashes fingerprint differently. The "Run reviewer models" step tees stderr to `${RUNTIME_DIR}/reviewers_stage_stderr.txt`, and `workflow_failure_heal.py` keeps normalised bash diagnostics (`<script>.sh: line <n>: <msg>`) in the reviewer evidence and uses them as the `failure_headline` fallback.
