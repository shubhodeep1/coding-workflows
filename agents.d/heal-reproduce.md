Heal reproduction helper (P2 of `docs/plans/heal-evidence-reproduction-and-trends-plan.md`, Refs #8434): `scripts/heal_reproduce.sh --tests-file FILE --baseline SHA --out FILE (--sha SHA | --worktree DIR) [--repo DIR] [--remote NAME]` runs a heal's failing tests at the tested commit and at the last green commit in the existing credential-free pre-push gate container, and writes `heal_repro.v1` (`{schema, status: reproduced|not_reproduced|unverified, reason, failing_at, passing_at, tests[{test, status, reason}]}`). The list is the gate's `--tests-file` format (`path[::name]` per line); callers write it from the `pairs` and `files` of `extract_failing_tests` in `scripts/workflow_failure_heal.py`. Steps: resolve both commits and, when there is no merge-base, fetch them from `--remote` (a shallow clone is deepened along the fixed ladder 50/200/1000; a complete clone is never given `--depth`); add a detached `git worktree` at `--sha` (a `--worktree` is used as-is and never removed); `codex_isolated_exec.sh image`; `codex_isolated_exec.sh prepare --deps` (fail-open: without a venv, pytest units come back `pytest_unavailable`); `scripts/prepush_test_gate_run.sh --tests-file`, which runs the list and re-runs failures on the merge-base. Mapping per test: gate `failures` -> `reproduced`/`regression` (a `::name` entry only when pytest's `FAILED` node IDs include it, the unit's tail has an `ERROR <node>` line, or none were parsed; a name missing from a complete list, under 50 names and a tail under 4000 bytes, is `not_reproduced`/`passes_at_failing_sha`, and one missing from a possibly truncated list or a unit without a tail is `unverified`/`names_incomplete`); `inherited` -> `not_reproduced`/`pre_existing` for every entry of the unit; in `ran` only -> `not_reproduced`/`passes_at_failing_sha`; an `unverified` item for the line or path, a gate-level item (`gate`, `merge_base`) or anything else -> `unverified` with the gate's reason (`timeout`, `baseline_error`, `no_merge_base`, `container_rc_<n>`, ...). The run is `reproduced` only when every test is; any unverified test makes it `unverified`; a test that passes at the failing SHA is never `reproduced`. Short-circuits before Docker: `no_tests`, `fetch_failed`, `no_merge_base`, `tests_file_*`, `usage_error`, `invalid_sha`. Wall time `WORKFLOW_HEAL_REPRODUCE_TIMEOUT_MINUTES` (default 10, 1-60) or `WORKFLOW_HEAL_REPRODUCE_TIMEOUT_SECS` (unset by default, 5-3600, for tests): the work runs as an inner pass under `timeout --kill-after=30s`, the gate gets the time left less 180 s, and an expired wall gives `unverified`/`timeout`. The parent's EXIT trap removes the worktree, calls `codex_isolated_exec.sh cleanup` on the prepare root and deletes its private `heal-repro.*` temp root on success, failure and timeout. Security: test code runs only in the gate container (`--network none`, read-only root, `--cap-drop ALL`, no environment, JSON results only); image, prepare and gate run under an allowlisted `env -i`, so no token reaches them; host git calls disable hooks and fsmonitor; support files come from the script's own directory. `tests[].test` holds untrusted test IDs: callers must escape them before rendering an issue or PR body. Always exits 0; no GitHub API calls. The callers (`scripts/workflow_failure_heal_intake.sh` and `scripts/heal_isolated_implement.sh`, both behind `WORKFLOW_HEAL_REPRODUCE_ENABLED`, default `false`) come from sibling issues of tracking #8434.
