**Failed final CI, Phase 1: infra failures re-run, the hand-back reviews the red head (docs/plans/final-ci-failure-ci-fix-plan.md, Refs #9656).**
- Sweep re-run of final-CI runs: `scripts/ci_cancelled_rerun.py` now accepts `workflow_dispatch` runs of `ci.yml` in its run listings (before this, every final-CI run in the 100-run window made the listing `invalid_listing`, so the step skipped every PR). A completed run named exactly `CI [pr:<n>]` on PR `<n>`'s current head is a candidate like an associated `pull_request` run: same listings, same once-per-head `already_retried` cap, same per-tick classification budget. A `failure` run is re-run only for the `shutdown`, `action_resolution`, `checkout_fetch` or `abandoned` verdicts (each with its own switch); a `cancelled` one is re-run as `cancelled_ci`. Any `ci.yml` dispatch on the head (full, `[sync-quick]` or manual) blocks while active; only the PR's own `CI [pr:<n>]` run with `run_attempt` above 1 counts as a retry (an unrelated re-attempted dispatch must not use up the re-run the hand-back deferred to); when the head's newest run is a dispatch that is not a full final run, the step skips with `reason=not_final_ci`. Decision lines for a final-CI candidate end in `final_ci=true`.
- `classify-run --repo <o/r> --run-id <id> [--ignore-job <name>]` prints the classifier verdict (`shutdown|action_resolution|checkout_fetch|abandoned|genuine|unverified`) for attempt 1 of a run and exits 0; bad arguments print `unverified`. `--ignore-job` drops the caller's own in-progress job from the jobs page (the total count must still match the page).
- `scripts/review_final_ci_failed.sh`: after the superseded, sync-quick and existing-marker checks and before the marker POST, attempt 1 of the failed run (`FINAL_CI_FAILED_RUN_ID`, `FINAL_CI_FAILED_RUN_ATTEMPT`, passed by `ci.yml`'s `final-ci-failed` job) is classified with `classify-run --ignore-job final-ci-failed` under a 120-second timeout. An infra verdict posts no marker and dispatches nothing (`outcome=infra_rerun_deferred reason=<verdict>`); the sweep re-runs the failed jobs, and the re-run's own `final-ci-failed` job (attempt 2) hands back as before. Any other verdict, a classifier error, attempt 2 or later, a repository other than `shubhodeep1/coding-workflows` (the sweep's re-run runs nowhere else), `FINAL_CI_FAILED_INFRA_RERUN_ENABLED=false`, or `CI_CANCELLED_AUTO_RERUN_ENABLED` set to anything but `true` (parsed like the sweep) keeps the hand-back. The job gains `checks: read` for the annotation reads.
- Review gate (`scripts/review_autofix_step_evaluate_gate.sh`): `gate_fetch_marker_comments` now also keeps `<!-- ai:final-ci-failed:v1 ` bodies. A marker for the current PR and head, authored by the `GH_PAT` login or by `github-actions[bot]` (type `Bot`, the token `final-ci-failed` posts with), whose `created_at` is at or after the newest clean marker re-arms the clean same-head skip (`AUTOFIX_GATE_CLEAN_SAME_HEAD_CHECK outcome=no_skip reason=final_ci_failed`), and one at or after the newest trusted terminal partial-finalize marker re-arms the terminal same-head skip (`AUTOFIX_GATE_NO_SKIP_TERMINAL_SAME_HEAD ... reason=final_ci_failed`) unless a `GH_PAT`-login failure, partial or no-op comment is newer than the hand-back. The marker also suppresses the deterministic docs-only / small-diff skip, like the freshness marker (`AUTOFIX_GATE_DET_SKIP_SUPPRESSED reason=final_ci_failed`). Ordering against the skip marker bounds this to one review per failure: the review it allows posts a newer clean, partial or failure comment, so the next dispatch skips again. A forged marker can only cause one extra review, never a skip.
- Tests: `tests/test_ci_cancelled_rerun.py`, `tests/test_review_final_ci.py`, `tests/test_review_autofix_clean_same_head_gate.py`, `tests/test_review_autofix_terminal_same_head_gate.py`, `tests/test_review_freshness_ci_failed.py`.

- `CI_CANCELLED_RERUN` also logs `final_ci=true` as the last field for a final-CI (`CI [pr:<n>]` `workflow_dispatch`) candidate, and `action=skip reason=not_final_ci` when the head's newest `ci.yml` run is a dispatch that is not a full final run (`scripts/ci_cancelled_rerun.py`, docs/plans/final-ci-failure-ci-fix-plan.md Phase 1).
- `REVIEW_FINAL_CI_FAILED` also logs `outcome=infra_rerun_deferred reason=shutdown|action_resolution|checkout_fetch|abandoned` (`scripts/review_final_ci_failed.sh`): the run failed for an infrastructure reason, no marker was posted and no review dispatched; the sweep re-runs its failed jobs.
- `AUTOFIX_GATE_DET_SKIP_SUPPRESSED` also logs `reason=final_ci_failed pr=<n> candidate=<skip reason>` (`scripts/review_autofix_step_evaluate_gate.sh`): a trusted final-CI hand-back marker for the head keeps the docs-only / small-diff skip from swallowing the hand-back's review.
- `AUTOFIX_GATE_CLEAN_SAME_HEAD_CHECK` also logs `outcome=no_skip reason=final_ci_failed`, and `AUTOFIX_GATE_NO_SKIP_TERMINAL_SAME_HEAD` ends in `reason=final_ci_failed` when a trusted final-CI hand-back marker for the head is at or after the skip marker (`scripts/review_autofix_step_evaluate_gate.sh`).
