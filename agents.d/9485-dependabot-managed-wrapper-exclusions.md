<!-- agents: section="Workflow architecture" -->
- **Dependabot exclusions for managed wrappers (#9485).** `update_workflows.yml` step `dependabot_sync` (after `changelog_sync`, before `update`) runs `scripts/sync_dependabot_exclusions.py --repo-root . --templates-dir <workflow-templates> --profile <WORKFLOW_PROFILE or full> --changed-paths-file /tmp/dependabot_changed_files.txt`; the commit step stages that list and the signed sync manifest allows `.github/dependabot.yml` / `.github/dependabot.yaml` (`STATIC_ALLOWED_PATHS`, consumer-owned, not managed). The helper only edits `exclude-paths` of existing root `github-actions` entries with a stdlib line editor (no YAML library, so both jobs produce identical bytes) and refuses unsupported layouts. Attestation gate: `verify_release_manifest` (update job) and `verify_release` (verify job) read the helper's entry from the attested release manifest with the same jq expression; the verify job hash-checks it before `verify_reproduce` runs it on the parent tree, and the update job skips it (`reason=helper_unattested`) when the verified manifest does not list it, so the two jobs never disagree. `scripts/release_manifest.py` `SURFACE_RULES` must list the helper before it runs for consumers that verify the release manifest.
