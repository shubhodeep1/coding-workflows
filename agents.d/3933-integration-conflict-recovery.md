- **Integration conflict recovery (refs tele-funtoken-msg-scoring final PR #3933, 2026-10-23).** Three changes stop an `orchestrator/project-*` final PR from looping on a conflict the resolver can never land.
  - `.ai/` take-base: `scripts/review_conflict_prepare.sh` takes the default branch's `.ai/validate.yml` (allowlist `AI_ASSET_TAKE_BASE_ALLOWLIST`) on an integration-sync head before resolver dispatch, because the sandbox excludes `.ai/`. Stages `1 2 3`, `2 3` and `1 3` check out `MERGE_HEAD`'s regular blob; stages `1 2` honour the default branch's deletion; any other shape, a symlink or a non-regular base blob stays fail-closed. The integration branch's dropped diff goes to `${RUNTIME_DIR}/ai_asset_take_base_comment.md` (marker `<!-- ai:ai-asset-take-base:v1 pr= head= -->`), which the prepare script's deferred commit or `review_conflict_resolve.sh`'s commit tail posts once the merge commit exists (`.posted` suffix after a successful post). A take-base that leaves no unmerged path defers the commit until the integration fingerprint check passes, like the manifest and guard-hook cases; a guard-hook-only resolution that coincides with a take-base defers too. Switch `CONFLICT_AI_ASSET_TAKE_BASE_ENABLED` (default `true`).
  - Retry state: `_persist_resolver_retry_state_from_current_failure` writes the PR body with `gh api -X PATCH repos/{owner}/{repo}/pulls/{n} --input` and the `ai:resolver-escalated` label with `POST .../issues/{n}/labels` (both REST; `gh pr edit` failed 5/5 without `read:org`). The block now also carries `last_failure_reason` (isolation reason or `fingerprint_violations`), `non_retryable`, `last_run_id` and `last_conflict_paths` (up to 20 `host_only` paths from the check-paths report, via `RESOLVER_CONFLICT_PATH_REPORT_FILE`). `NON_RETRYABLE_ISOLATION_FAILURE_REASONS` escalate on the first failure (`RESOLVER_NON_RETRYABLE_ESCALATE_ENABLED`, default `true`).
  - Poller: `_integration_conflict_park_if_stuck` runs in `heal_integration_branch_conflict` after the escalated check and before lifetime-cap accounting. On the unchanged head it parks a non-retryable failure or `consecutive_failure_count >= INTEGRATION_CONFLICT_PARK_GATE_CAP` as `integration_sync_status=escalated` without spending a lifetime slot, writing state and one tracking comment only when the parked error changes. `invoke_judge_for_integration_conflict` takes the retry state as a 4th argument and adds the newest failure (`_integration_retry_state_failure_detail`) and its own previous `## Integration conflict diagnosis` for this PR (trusted login only, from the tick's `COMMENTS`) to the prompt. The prompt's leftover edit rules ("only lines taken from either merge side") are replaced by the resolver template's synthesize rule. No new GitHub API calls.
