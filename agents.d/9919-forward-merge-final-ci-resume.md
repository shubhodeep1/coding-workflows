- **Forward-merge heads in the final-CI merge resume (#9919, Refs #9891).** `_mt_final_ci_merge_resume` (`scripts/review_merge_train.sh`) no longer drops `auto/forward-merge-stable-*` heads as `not_eligible`; this supersedes that part of the "Final-CI merge resume" note from `agents.d/merge-lease-final-ci-resume.md`. Forks, drafts, invalid SHAs and integration heads stay `not_eligible`. A forward-merge head goes through every gate an ordinary head does and gets `gh pr merge --merge --auto --match-head-commit <head>`; every other head keeps `--squash`. One variable (`resume_merge_method`), set from the head ref, decides the flag. The `outcome=auto_merge_enabled` line and the `reason=auto_merge_refused` warning end with `method=squash|merge`. When `FORWARD_MERGE_FALLBACK_AUTO_MERGE` is not exactly `true` (default `true`; passed to both release steps in `orchestrate_poll.yml` and `cancel_on_pr_close.yml`), a forward-merge head is dropped with `reason=forward_merge_auto_merge_disabled` before the statuses read. The `auto_merge_disabled` and `blocked_by_<label>` checks still run first.
- **Promote-cycle forward-merge alert (#9919).** `skip_cycle` in `scripts/promote_main_cycle.sh` calls `promote_cycle_forward_merge_pending` after the release-blocker hook. On a `base_not_ancestor` skip whose detail has `ref=heads/` (the stable-branch check, unpinned or pinned), it makes one read of `pulls?state=open&base=<default>&per_page=100`, keeps same-repo heads starting with `auto/forward-merge-stable-`, prints `PROMOTE_CYCLE_FORWARD_MERGE_PENDING`, and sends one WARNING through `promote_cycle_hold_alert` (30-second bound). The alert URLs are built from the PR number, never from `html_url`. It runs once per tick, fails open (`prs=lookup_failed`), and never changes the skip line, the outcome output or the exit code.
