<!-- agents: section="Workflow architecture" -->
- Review-blocked judge settled-check diagnostics (#10137, unblock step for #9502). `_pr_checks_completed` in `scripts/pr_checks_lib.sh` resets `PR_CHECKS_LAST_BLOCKING_NAMES` and `PR_CHECKS_LAST_BLOCKING_RUN_IDS` on entry and, on a blocking result, fills them through `_pr_checks_blocking_detail` from the check-runs listing it already fetched, with the same selection as the blocking count. The values are newline-separated `name:conclusion` lines (running runs report `queued`/`in_progress`) and `run_id:conclusion` lines (`none:` for a non-Actions check, or for a `details_url` outside `PR_CHECKS_REPOSITORY`'s Actions). The return value and `PR_CHECKS_LAST_REASON` do not depend on them. In `scripts/review_rb_judge.sh`, the `merge_with_followup` blocking branch still writes `judge_skip_reason=blocking_check_runs`. It then calls `rb_judge_settled_check_diagnostics`. When `PR_CHECKS_LAST_PENDING=0`, that helper writes `judge_blocking_checks_settled=true` and `judge_blocking_check_names` (cleaned to `[A-Za-z0-9 _./():-]`, at most 20 entries of 120 chars, joined with `, `, plus a final `(N more)` entry past the cap) to `GITHUB_OUTPUT`, and mirrors them to `GITHUB_ENV` as `RB_JUDGE_BLOCKING_CHECKS_SETTLED` / `RB_JUDGE_BLOCKING_CHECK_NAMES`. The review-blocked comment step gets no `rb_judge` outputs in the YAML, so `scripts/review_autofix_step_post_review_blocked_comment.sh` reads the env pair and uses the heading "merge gated by failed required check-runs" with the names as bullets; otherwise the in-flight text is unchanged. When every settled blocking run was `cancelled` or `timed_out`, the judge sends one `POST actions/runs/<id>/rerun-failed-jobs` (`GH_RETRY_IDEMPOTENT=true gh_retry`) per Actions run, for at most 3 runs; a non-Actions entry in the set is skipped on its own and the Actions runs are still re-run. It never re-runs its own run, a non-Actions check, an unresolved head, or a run when the comment snapshot is incomplete. After each attempt, successful or not, it posts a comment ending with `<!-- rb-judge-settled-rerun:v1 head=<40hex> run=<id> -->`. The marker dedupes against `PR_CONTEXT_JSON.comments` and is trusted only from `github-actions[bot]`, `github-actions` or the `_tg_tracking_author_login` login. Off switch: `RB_JUDGE_SETTLED_CHECK_DIAGNOSTICS_ENABLED` (unset, empty or `true` in any case = on; `false` = off; any other value = off plus one warning). No repository variable wires it yet. Tests: `tests/test_review_rb_judge_settled_check_diagnostics.py`, `tests/test_pr_checks_lib_required_filter.py`.
