- **Transient push retry (#7974).** The "Push all pending commits" step of `review_autofix.yml` classifies a failed `git push origin "HEAD:${TARGET_BRANCH}"` in this order: a repository-rule or protected-branch rejection (`GH006|GH013|protected branch|push declined|repository rule`, case-insensitive) fails at once with the existing `::error::` line; a non-fast-forward rejection takes the unchanged fetch-and-merge path (3 attempts); a transient failure (`server_error`: `Internal Server Error`, `The requested URL returned error: 5xx`, `HTTP 5xx`; `remote_rejected_failed`: `remote rejected ... (failed)`; `network`: `RPC failed`, `unexpected disconnect`, `early EOF`, `Connection reset`, `Could not resolve host`, `Operation timed out`) gets its own counter of at most 2 retries; anything else fails as before. Before each transient retry the step sleeps 5 s, then 10 s, and reads `git ls-remote origin refs/heads/<branch>` (stderr discarded, the URL carries the token). A tip equal to `git rev-parse HEAD` counts as a landed push (`Push complete.`, `AUTOFIX_EDITS_PUSHED=true`); otherwise, or when `ls-remote` fails, the same plain push runs again, and a remote that advanced meanwhile is handled by the non-fast-forward path. No `--force`, `--force-with-lease` or rebase. Kill switch `AUTOFIX_PUSH_TRANSIENT_RETRY_ENABLED` (step env `${{ vars.AUTOFIX_PUSH_TRANSIENT_RETRY_ENABLED || 'true' }}`, shell default `true`); only `false` in any letter case turns it off, which restores the previous behaviour exactly.
