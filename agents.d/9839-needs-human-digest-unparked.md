**Needs-human digest, not-parked section.** `needs_human_prune` in `scripts/operator_step_issue.py` (called once per tick by `needs_human_digest_prune` in `scripts/orchestrate_poll_process.sh`) renders the open items that carry `ai:needs-human` but have no digest entry or overflow slot. They go in a section that starts with `<!-- ai:needs-human:unparked:v1 -->` and holds plain `- #<n> (issue|pr|project)` lines, at most `NEEDS_HUMAN_UNPARKED_MAX` (100), then "...and N more." The lines carry no `ai:needs-human:entry` marker, so `parse_digest` and the prune's `items` (the unblock scan's parked list, `NEEDS_HUMAN_PARKED_ITEMS_FILE`) never include them. An empty digest now reads the same paginated `ai:needs-human` listing a non-empty one already read, and returns `reason=empty` without a write when the rendered body is unchanged. `needs_human_park` keeps the section from the current body (`parse_unparked`, minus the item it parks). With entries empty and the section non-empty, the list line reads `_Nothing is parked._`. Tests: `tests/test_operator_step_issue.py`.
