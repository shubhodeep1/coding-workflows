- **Default branch in the sandbox git (fun-token-multi-chain#639).** `codex_isolated_workspace.py seed-git HOST DEST [BASE_REF]` builds, with the same `readonly_allowed` filter and a 2 MiB per-file limit, a second synthetic commit from `BASE_REF`. It becomes branch `isolated-base` and the parent of the `isolated` HEAD commit. The scratch index for it lives outside the sandbox, and only blobs that pass the filter are packed, so a credential that exists only on the default branch is never readable. `codex_isolated_exec.sh` passes `CODEX_ISOLATED_GIT_BASE_REF` (default empty) as `BASE_REF`. The implement step "Run Codex implementation" sets it after `git fetch --no-tags --depth=1 origin +refs/heads/<default>:refs/codex-isolated/base`; that private ref leaves `origin/*` untouched for later steps. A failed fetch logs `::warning::CODEX_ISOLATION base_branch=<b> outcome=fetch_failed` and only leaves the branch out. `seed-git` logs `outcome=ok base=present|none|unresolved`. A base tree that cannot be read or built, or that exceeds the read-only snapshot totals (50,000 files / 512 MiB), logs `seed-git base_skipped reason=<exception>` and is left out (`base=unresolved`); HEAD is still seeded. The implement step logs `::notice::CODEX_ISOLATION base_branch=unset_or_invalid outcome=skipped` when the default-branch name is empty or invalid. `prompts/mode-implement.txt` tells the agent to read production code with `git show isolated-base:<path>`.
