Security-pass failure reasons (#7728, Refs fun-token-multi-chain#579). When the findings-JSON audit exits non-zero, `run_security_pass_inline` reads the last `security-audit: phase=` line of the audit's stderr. The phases `oversized-scope`, `diff-scope`, `prior-findings`, `waived-findings`, `project-spec-preflight`, `prior-findings-preflight` and `waived-findings-preflight` mean `scripts/security_audit.sh` refused its input before any model ran, so the pass fails closed as `SECURITY_PASS_FAILED reason=audit_input_rejected`, and the tracking comment says it is not an engine outage. Any other phase (including `findings-output-preflight`, the output destination check), or no phase line, keeps `reason=engine_unavailable`. Both reasons fail closed the same way: state `failed`, completion gated, one CRITICAL alert per failure streak, retried on every poll. Tests: `test_security_pass_audit_input_rejection_is_not_reported_as_engine_outage` in `tests/test_orchestrate_poll_process.py`.
