<!-- agents: section="Workflow architecture" -->
- Alert inbox capture (alert triage plan Phase 1, Refs #9394; `docs/plans/alert-triage-auto-heal-plan.md`). `tg_send_msg` in `scripts/tg_helpers.sh` applies the level filter, then asks `alert_inbox_mode` (`scripts/alert_inbox_capture.sh`, sourced from tg_helpers.sh's own directory) for `off|capture|route`, read per call from `.github/ai/alert_inbox.json` in the trusted support roots only (`SUPPORT_ROOT_DIR`, `$GITHUB_WORKSPACE/.codex-workflow-src`, the scripts' parent; never `$PWD`; symlinks skipped). Missing capture script, missing/invalid config, a non-boolean switch or no jq mean `off`. Routing: off or DEBUG/unknown level sends to Telegram exactly as before (the send body lives in `_tg_send_now`); `capture` sends then captures WARNING/ERROR/CRITICAL; `route` captures WARNING/ERROR only (empty id) and falls back to Telegram when capture fails; CRITICAL is always sent. `alert_inbox_capture` sends one `repository_dispatch` `alert-inbox` (`client_payload = {schema: "alert_inbox.v1", record: {11 fields}}`, nested because GitHub allows 10 top-level keys) with `curl --max-time 10`, token in a 0600 header file, message capped at 4,000 bytes by `scripts/truncate_to_utf8_byte_cap.py`; it never fails the caller. `tg_send_msg_direct` sends without capture (for the triage system's own messages); `tg_send_report_msg` is never captured. `.github/workflows/alert-inbox-intake.yml` (per-run concurrency group) runs `scripts/alert_inbox_store.sh`: payload only from `$GITHUB_EVENT_PATH`, strict validation (exact key set, regexes, byte caps, `captured_at` within 24 h ago..5 min ahead, `source_repo` in `.github/ai/consumer_repos.json` or this repo, canonical `run_url`), Contents API PUT to `inbox/<YYYY>/<MM>/<DD>/<HH>/<epoch_ms>-<owner-repo>-<run_id>-<id8>.json` on `ai/alert-inbox` with one 409 retry, branch bootstrap from a parentless root commit, existing path = duplicate; never PATCH/DELETE/force. A failed store sends one notice through `tg_send_msg_direct`. Both switches ship `false`; `alert_inbox_capture.sh` is not yet in the explicit staging lists, so staged runs stay off until a later phase stages it.
