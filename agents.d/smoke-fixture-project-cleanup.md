### Smoke-fixture projects never outlive their release gate

The release gate's orchestrate-decompose-test job (`.github/workflows/test-and-mark-stable.yml`) dispatches an orchestrate bootstrap and closes the project it creates in "Cleanup orchestrate test issues" (`if: always()`). On a long Actions queue the bootstrap could still be queued when `scripts/dispatch_and_watch_workflow_run.sh` stopped watching it (50-minute completion timeout). Cleanup then found no tracking issue, and the run created the project hours later with no gate left to close it: gates 43445515854, 43590943288 and 43708007145 left projects #9490, #9523 and #9550, which the poller kept driving (waves, CI triage, implement runs, PRs). Two layers now close that gap:

- **Gate side.** The watcher writes a new step output, `dispatched_run_id`, as soon as the run registers. `run_id` is unchanged: it is still written only once the run completes (or in `--snapshot-only` mode), so steps gated on it behave as before. "Cleanup orchestrate test issues" passes it as `DISPATCHED_RUN_ID` to `scripts/stable_orchestrate_cancel_dispatched_run.sh` before its Phase 1. When the run is not `completed`, the script cancels it, waits up to `SMOKE_CANCEL_WAIT_SECS` (default `120`, polling every `SMOKE_CANCEL_POLL_SECS`, default `10`), then force-cancels once and waits up to `SMOKE_CANCEL_FORCE_WAIT_SECS` (default `60`). These three knobs exist for the tests; the gate sets none of them. When the dispatch step recorded no tracking issue, the script then lists open `ai:orchestrator-tracking` issues, takes the newest one whose body carries the gate's run id, and prints `tracking_issue=<N>` plus `child_issues=<a,b>` (open `ai:orchestrator-managed` issues whose body names `Tracking issue: #<N>`, paginated). The cleanup uses them in its close and PR/branch phases, so children whose model-written titles dropped the run marker are closed too. A failed run read is retried 3 times. The script never fails the step.
- **Poller backstop.** `scripts/orchestrate_poll_smoke_fixture_reap.sh` is sourced by `scripts/orchestrate_poll_process.sh` and staged by `.github/workflows/orchestrate_poll.yml`, next to `orchestrate_stall_retired_conflict.sh`. When it is missing, a stub logs `reason=helper_unavailable` and changes nothing. For each tracking issue `tracking_issue_is_smoke_fixture` matches, `smoke_fixture_reap_if_gate_done` reads the gate run id: first from the title (`E2E Orchestrate Smoke <id>`, any case, or `(run <id>)` on a title that starts with `[E2E `), otherwise from the issue body (one issue GET). It then reads that run in `GITHUB_REPOSITORY` (one run GET). Only a `test-and-mark-stable.yml` run whose status is `completed` triggers a close. The order is: open PRs with base or head `orchestrator/project-<N>`, then open `ai:orchestrator-managed` issues whose body names `Tracking issue: #<N>` (exact number), then the tracking issue (`state_reason=not_planned`), followed by one comment carrying `<!-- ai:smoke-fixture-reap gate_run=<id> -->` (posted only after the close succeeds, so retries never repeat it). The child listing is paginated. Nothing is deleted. A closed or partly closed project is dropped from this tick's `TRACKING_ISSUES` before the per-project loop, so the poller dispatches nothing for it; its alerts stay silenced through `SMOKE_FIXTURE_TRACKING_NUMS`. Failure modes: a running gate, a run that is not the gate, an unreadable run, body or listing, or a title and body with no gate run id leave the project on the normal path (`outcome=skip`). A failed PR or child close keeps the tracking issue open (`outcome=failed`, `::warning::`) and the next tick retries. API cost per smoke project and tick is one run GET (plus one issue GET when the title has no id); a close adds two PR listings, one paginated issue listing, one PATCH per item and one comment. A consumer repository used as the gate's `test_repo` is never reaped, because its own run lookup returns 404.

The review sweep's stranded smoke-PR backstop (issue #8953) still closes `e2e-smoke-test` PRs on `ai/issue-<N>` heads; the poller backstop is what closes the project itself.
