<!-- agents: section="Workflow architecture" -->
- Review-blocked judge crash alert (#9249, `.github/workflows/review_autofix.yml`). Step `rb_judge` also writes `rb_judge_exit_code=<n>` when `review_rb_judge.sh` exits non-zero. The step "Post review-blocked comment on PR (autofix exhaustion)" has `id: rb_blocked_comment` and reads `RB_JUDGE_STATUS` and `AUTOFIX_ITERATION`. A judge crash is `rb_judge_status=failed` (reason `judge_crashed`, which wins over any skip reason) or `judge_skip_reason` `llm_failed*`/`json_parse_failed*` (reason = that value, `unknown` unless it matches `^[a-z0-9_]+$`), with an integer `autofix_iteration` below `MAX_AUTOFIX_ITERATIONS`. On a crash with a 40-hex `AUTOFIX_FAILURE_HEAD_SHA`, `scripts/review_autofix_step_post_review_blocked_comment.sh` appends `<!-- rb-judge-crash:v1 head=<sha> reason=<reason> -->` to the comment and reads the newest comment page through `_tg_newest_comments_json`; a comment that passes `tg_trusted` and contains the same marker skips the POST and writes `rb_judge_crash_repeat=true` (always written, `false` otherwise; every read or parse failure fails open). The "Telegram review-blocked judge decision" step computes the same crash condition after its existing message selection and, only then, replaces the message with the judge-failed text; `RB_BLOCKED_REPEAT=true` suppresses the send only for a crash. Tests: `tests/test_review_autofix_rb_judge_crash_alert.py`.
