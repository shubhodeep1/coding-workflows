- **Docs-only and generated PRs reach `main` through the gated auto-merge route (#10151, 2026-11-26; Refs #9939).** After #9939/#9956, 14 merges still bypassed ruleset 25851281 (`ai-review/head-gate` + `ci/final`). All were docs-only or generated PRs merged directly before review ran: the GH_PAT direct merge in `workflow-log-analysis.yml`, plus hand and session merges.
  - **Head-gate on a deterministic skip.** The gate job's `head_gate` step stays the single poster: `review_head_gate_main` (`scripts/review_head_gate.sh`) posts `ai-review/head-gate=success` on `GATE_HEAD_SHA` when `DETERMINISTIC_SKIP=true`, with the description `deterministic skip: <reason>` from the new optional env `GATE_DET_SKIP_REASON` (the gate's `det_skip_reason` output; empty keeps the legacy text `deterministic skip evaluated this head`). A skip whose security pass is still required gets no success there; `det_skip_security_pass_post_head_status` posts it after hold=false, as before. So the head-gate means "the pipeline's gate approved this head, by review or deterministic skip".
  - **Final CI on the skip path.** `deterministic-skip-merge` relies on `_pr_wait_for_required_checks`, which calls `_pr_ensure_final_ci` (docs-only when every file is on `scripts/ci_docs_only_paths.sh`) on its first poll, then arms `gh pr merge --squash|--merge --auto --match-head-commit`. The two paths that authorize the head without the wait (`ENABLE_AUTO_MERGE != true`, and the forward-merge fallback with `FORWARD_MERGE_FALLBACK_AUTO_MERGE != true`) now call `deterministic_skip_ensure_final_ci` right after `deterministic_skip_head_is_current`, mirroring `review_enable_auto_merge_ensure_final_ci`. It needs `freshness_helper_verified=true`, else logs `REVIEW_FINAL_CI ... outcome=dispatch_failed reason=library_unavailable`. The fail-closed inline `_pr_wait_for_required_checks` stub stays. `review_final_ci_sweep.sh` remains the safety net.
  - **Log-analysis report PRs use auto-merge only (owner Q8 A).** The `commit_report` step no longer tries `gh pr merge --squash` directly; it only arms `--auto --squash --match-head-commit`, keeps the purge-drop refusal and the bounded landing wait, and keeps the `delivery` set `pushed|pr_merged|pr_auto_merge|pr_open` (`pr_auto_merge` = armed, not landed within the wait, exit 0; deep-audit/api-redundancy are skipped for that dispatched run).
  - **Direct-merge sweep.** `tests/test_pr_sync_merge_blocked_guard.py::test_no_unguarded_direct_merge_into_the_default_branch` scans `.github/workflows`, `workflow-templates`, `scripts/**/*.sh` and `scripts/**/*.py` for `gh pr merge` lines without `--auto` (in `.py` files also the argument-list form `"pr", "merge"`). `review_rb_judge.sh` and `orchestrate_poll_process.sh` are covered by the guard-window test; every other hit must be in `DIRECT_MERGE_EXEMPT` with a pinned count and reason (message text in `claude-engine-smoke.yml`, `review_autofix.yml` and `review_autofix_step_post_review_blocked_comment.sh`; `update_workflows.yml`'s consumer-only legacy fallback after GitHub refuses `--auto`).
