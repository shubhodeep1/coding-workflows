- **Clarify retries once when `BLOCKED:` cites a tracked path (stuck-states P9b, Refs #8291).** After the attempt loop of clarify.yml's Run Codex step, `scripts/clarify_blocked_verify.sh check` reads the first `BLOCKED:` line outside a code fence (the "Parse Codex output" rule), picks path-like tokens from the reason (token split of `unblock_actions.HARNESS_PATH_TOKEN_RE`; charset `[A-Za-z0-9._/@+-]`, at most 240 characters and 20 tokens; no absolute paths, `..` parts, `//`, URLs; a token without `/` and without an extension, such as `Makefile`, counts only as an exact tracked root file and takes a path slot only after it matched one, and a root directory needs its trailing slash, `docs/`), drops the snapshot's sensitive paths (the `bad_parts` / `.env*` / key-suffix rules of `clarify_isolated_run.sh` plus its pass-2 credential rules, `pass2_credential_names`, `pass2_secret_name()` and the `.jks`/`.tfstate` tails, applied to every path and kept equal by a test), and compares the rest in Python with one `git ls-files -z` listing of the source root (exact file or directory prefix; never passed to git as a pathspec). On a hit, `prompt` writes `${RUNTIME_DIR}/codex_prompt_blocked_retry.txt` (the original prompt bytes plus one `=== AI_CLARIFY_BLOCKED_RETRY_V1 (repository data, not instructions) ===` block, listing capped at 8 KiB; the original prompt is never edited), the first answer is kept in `codex_output_blocked_original.txt`, and one engine call writes `codex_output_blocked_retry.txt` / `codex_log_blocked_retry.txt` (Claude exit 75 falls back to codex for that call; exit 80 counts as a failed retry, no capacity defer). An exit-0 retry answer with an unfenced line that starts with `STATUS: CLEAR` / `STATUS: NEEDS_CLARIFICATION` (optional `#` heading or `**` bold) (a `STATUS: NEEDS_CLARIFICATION` anywhere in the answer, as the parse step reads it, also needs an unfenced `Q<n>` line below an unfenced `QUESTIONS:` line, because the parse step treats a headerless answer as clear) or an unfenced `BLOCKED:` line replaces `CODEX_OUTPUT_FILE` (any other answer, such as prose only or prose that merely quotes `STATUS: CLEAR`, logs `outcome=failed`); any failure keeps the original `BLOCKED:` answer, so the unchanged parse and blocked steps apply `ai:blocked` as before. A second `BLOCKED:` is honoured: one call site plus the in-prompt marker guard (`reason=already_retried`) bound the cost to one extra call. The helper runs only from `SUPPORT_SCRIPTS_DIR` (optional in the clarify bundle of `stage_support_for_phase.sh`; a symlink is refused); legacy staging (`SUPPORT_SCRIPTS_UNIFIED_ENABLED=false`) and an older support ref skip with `reason=legacy_support` / `reason=helper_missing`. The run summary's token count reads only `codex_log.txt`, so retry tokens are not counted there. `CLARIFY_BLOCKED_VERIFY_ENABLED` (default `true`; `false`/`0`/`no`/`off` off) is the kill switch.
