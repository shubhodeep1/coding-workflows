- `RB_JUDGE_MERGE_RETRY` (`scripts/review_rb_judge.sh`, `rb_judge_merge_retry_transient` between `# BEGIN/END rb-judge merge error capture (#7659)`, #8524: `pr= head= path=merge|terminal|sync attempt=<n>/3 delay_s=10|20|40 reason=transient` before each retry, or `pr= head= path= attempt=<n>/3 outcome=already_merged|auto_merge_enabled|head_moved|not_open` when the REST read of the PR ends the retry; a PR merged at a head other than the judged one is `head_moved`). Runs only after a site's `gh pr merge` attempts all failed and the last attempt's captured stderr shows a GitHub server error (`HTTP 5xx`, `Something went wrong while executing your query`, 502/503/504 gateway text, `connection reset by peer`, `i/o timeout`, `TLS handshake timeout`, `unexpected EOF`). Retries repeat the same `--match-head-commit "${RB_JUDGED_HEAD_SHA}"` attempts. `already_merged` and `auto_merge_enabled` (auto paths only, judged head) count as success; `head_moved` and `not_open` fall through to the unchanged `RB_JUDGE_MERGE_ERROR` / `merge_failed` / `sync_merge_failed` path. With no captured stderr (`mktemp` failed) nothing is retried. One REST read per retry, none for other errors.
