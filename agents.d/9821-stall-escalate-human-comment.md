**Stall escalation explains itself on the issue (#9821).** The `escalate_human` arm of `execute_stall_recovery_action` in `scripts/orchestrate_poll_process.sh` calls `_post_stall_escalate_human_comment` once `ai:needs-human` is confirmed on the issue. It posts one `## Stall recovery: human input needed` comment on the issue itself, because for an orchestrator-managed issue the stall judge's decision comment goes only to the tracking issue (`post_tracking_comment`). The comment carries the judge's justification when the judge's dispatch arm led there (`STALL_ESCALATE_HUMAN_JUSTIFICATION`, set just before `execute_stall_recovery_action` and cleared right after), or "Stall recovery ran out of automatic actions for this phase." for a deterministic escalation. It also points to the tracking issue when there is one, and names the resume step (remove `ai:needs-human`). It ends with `<!-- ai:stall-escalate-human:v1 issue=<n> phase=<label> -->`. Cost: one comment write per escalation, no read (§15). Fail-open: a failed write is logged and the escalation is unchanged. Tests: `tests/test_orchestrate_poll_process.py` (`escalate_human` cases).
