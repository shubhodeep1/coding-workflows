- **Unblock hold re-evaluation (#9967, plan `docs/plans/pipeline-human-wait-elimination-plan.md` Phase 6).** `unblock_hold_condition` in `scripts/unblock_judge.sh` ends two holds that never ended on their own. `pr_on_branch`: when the compare says `ahead`/`diverged`, `unblock_hold_patch_equivalent` fetches the branch (depth 300) and the merge commit (depth 2) into `RUNTIME_DIR/hold-git` (never `TARGET_DIR`; `GH_TOKEN` only in `GIT_CONFIG_*` env) and counts the hold met when `git cherry <branch> <sha> <sha>^` prints only `- ` lines; merge commits stay unmet (`UNBLOCK_HOLD_PATCH_EQUIVALENCE_ENABLED`, default `true`). `placeholder_retired` on a standalone `ai:workflow-heal` issue: `unblock_placeholder_recurrence_check` runs `workflow_failure_heal.py heal-stale-decision --purpose unblock_placeholder` (skips only the awaiting-approval and counterfactual hold-marker gates; `--source-closed` for `#<n>` sources) and, on `close`, the condition prints `impossible` with `RUNTIME_DIR/hold_recurrence.json`; the caller closes the issue first (`state_reason=completed`, labels untouched) and only then marks the hold comment `done` (`UNBLOCK_PLACEHOLDER_RECURRENCE_CHECK_ENABLED`, default `true`). Both switches are forwarded by `unblock_judge.yml`; `false` restores the old holds. Tests point `MOCK_UNBLOCK_HOLD_GIT_REMOTE` at a local `file://` repository so no test reaches the network.
