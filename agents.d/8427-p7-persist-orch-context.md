### Orchestrator context (`PERSIST_ORCH_CONTEXT_ENABLED`, P7 of #8427)

Phase P7 of `docs/plans/persistent-unattended-workflows-plan.md`. Repo variable `PERSIST_ORCH_CONTEXT_ENABLED` (default `false`), defaulted in `orchestrate.yml`, `orchestrate_poll.yml` and in `scripts/persist_orchestrator.py` itself. Only the exact value `true` turns it on, in every reader (the poller, the helper and the `orchestrate.yml` gates); `1`, `yes`, `on` or `TRUE ` leave it off everywhere. The poller stages the helper in its required support list (P6 precedent); the decomposer stages it, `evidence_pack.py`, `attempt_journal.py`, `targeted_file_context.py` and `gh_api_retry.py` in an optional loop that runs only with the switch on (`::notice::` when a support ref lacks one).

- **State field.** The poller records `persist_merged_pr` (integer) on `state.waves[i].issues[j]` in the "Persist reconciled status decisions" loop of `scripts/orchestrate_poll_process.sh`, outside the status-transition branch, so a stored `merged` entry still missing it is recorded on a later tick too. The PR number comes from the in-tick map `PERSIST_ORCH_MERGED_PRS_JSON` (`{issue: pr}`), filled from the existing linked-PR lookup (`LINKED_PR_NUM` with `PR_MERGED=true`) only when the switch is on and never persisted; `PR_STATES_JSON` is unchanged. The plan placed this in `orchestrate_lib.py cmd_check_wave_status`, which never writes state and has no PR number. A recorded field sets `RECONCILE_STATE_CHANGED`, so the existing state post carries it. Prior-wave items the backward scan finds merged get the field from `persist_orch_record_merged_pr` (same switch, only on an entry whose stored status is `merged` and that lacks the field; such an entry, or a non-merged one, logs nothing): the `ai:ready-to-merge` path reuses its verified merged `PW_PR`, and the `ai:merged` path reuses the PR number the fingerprint capture already looked up (only in a project with an integration branch; no new lookup is made otherwise). The backward scan records the field once: the item is terminal afterwards, so an item whose PR number is unknown at that point (no integration branch, an empty lookup, or a failed state write) renders `PR unknown` for good, logging `PERSIST orch_context outcome=skipped reason=pr_unknown issue=<n>` or `outcome=error reason=state_write_failed`. Items merged in already-finished waves before the switch was on also render `PR unknown`.
- **Since-note.** `persist_orch_since_note WAVE [DETAILS_JSON]` (after `persist_budget_govern_issue`) runs `persist_orchestrator.py since-note` and, at both wave-issue creation sites (deferred `CURRENT_WAVE` without a details cache; post-gate `NEXT_WAVE` with `_current_wave_details_json`), appends `## Since this plan was decomposed` after `## Expected files` and before the `---` metadata footer. Content, from state only: merged items of earlier waves (issue, `persist_merged_pr`, allow-listed `files_touched`, at most 10 per item), judge-added items (entries carrying `persist_judge_added: true`, which the four wave-judge state writes in `create_judge_fixup_issues_from_verdict` and the judge new-issue block add only while the switch is on, through `persist_orch_judge_added_json`; state entries never carry a `title`, so items added before the switch was on are not labelled), and the newest journal `stage` / `outcome` (never `note`) when the item's comments are in the details cache and `PERSIST_JOURNAL_LOGIN_CACHE` is set (`attempt_journal.parse`, pipeline login only). Numbers are plain (`issue 123`, `PR 124`), never `#N`, so no cross-reference events or auto-close phrasing. Every line goes through `attempt_journal._scrub`; at most 4096 bytes, cut at item boundaries with a `- ... K more items not shown` trailer. If `attempt_journal` cannot be imported, nothing is rendered.
- **Decomposer.** Step "Build persistence context (P7)" in `orchestrate.yml` (gated on the switch, `continue-on-error`, the only step holding `GH_TOKEN` for this) writes `persist_open_projects.txt` (`open-projects`: open `ai:orchestrator-tracking` issues by OWNER / MEMBER / COLLABORATOR authors, no pull requests, at most 20 titles (titles only, no issue numbers) cut to 120 characters, scrubbed, under `timeout 120`, fenced `=== BEGIN/END UNTRUSTED OTHER OPEN PROJECTS ===`; any failure writes `(open projects unavailable: <reason>)` inside the fence) and, when `scripts/evidence_pack.py` is staged and P4's `PERSIST_EVIDENCE_PACK_ENABLED` is on, `persist_decomposer_evidence.txt` for the paths of the plan file the description names (`plan-path`: first `*.md` that is a regular file in the repo reached without a symlink; a GitHub `/blob/<ref>/` URL counts as its repo-relative path). "Build Codex prompt" appends the non-empty files after the project description, inside a `PERSIST_ORCH_CONTEXT_ENABLED` gate; it holds no token.
- **API budget.** Poller: zero new calls (state, the existing linked-PR lookup, the backward scan's existing fingerprint-capture lookup and the per-tick caches only). Decomposer: 1 REST read through `gh_api_retry.call(optional=True)` (honours the rate-limit breaker), plus the evidence pack's own reads.
- **Switch off.** No Python starts at the creation sites, no state field, no log line; issue bodies and the decomposer prompt are byte-identical (`tests/test_orchestrate_poll_process.py`, `tests/test_workflow_untrusted_input_contract.py`).
