- **Merge-lease expired and idle holders un-parked once per head (issue #10044, follow-up to #9983).** Skip entries with reason `expired` or `revoked_idle` are soft, like `revoked_no_head_gate` and the two-field form: they stop blocking once the PR's pipeline `ai-review/head-gate` is a confirmed `success` on the skip head (`_merge_lease_skip_reason_is_soft` in `scripts/pr_checks_lib.sh` is the one soft set; `_merge_lease_skip_is_soft`, `_merge_lease_skips_hard` and `_merge_lease_skips_soft` use it). `revoked_draft`, `revoked_skip_ai`, `revoked_final_ci_failed` and any other reason stay hard until the head changes.
  - Once per head: `_merge_lease_skip_block` also accepts `<pr>:<40-hex head>`, which `_merge_lease_write` (held writes) and `_merge_lease_write_holders` pass for every holder. All of the holder's entries are still dropped, except its entry on exactly that head: `expired` / `revoked_idle` is rewritten to `expired_unparked` / `revoked_idle_unparked`, and an existing `_unparked` marker is kept. That one marker is the only skip entry a holder can have. `_merge_lease_skip_release_token <pr> <head> <reason>` makes a later `expired` / `revoked_idle` release of a head that already carries a marker write `<reason>_unparked` (hard), whatever the earlier reason was. A `revoked_no_head_gate` release of such a head writes `revoked_no_head_gate_unparked`: soft (it clears on a confirmed head-gate success, as #9983 requires), and `_merge_lease_skip_block` keeps it as `expired_unparked` on the next grant, so a head-gate failure cannot reset the once-per-head budget. A head change prunes the entry (the tick's open-PR/head filter). No new record field or line, no API call.
  - `_mt_merge_lease_tick` / `_mt_merge_lease_tick_multi` write `_unparked` release tokens only when the staged library has `_merge_lease_skip_release_token` and `_merge_lease_skip_reason_is_soft` (`tick_unpark_lib` / `tm_unpark_lib`), and log the un-park after the grant write; the multi-holder tick leaves live holders out of its pass-over list, so a holder's marker never logs it as skip-held.
  - Mixed versions: an older library reads every new and changed reason as hard (today's rule). If an older library rewrites the record during a hold, it drops the holder's marker, which allows at most one extra un-park on that head, never a permanent park. A newer tick with an older library writes plain reasons. The marker is also an ordinary entry under the 50-entry cap of `_merge_lease_skips_normalize`: if 50 newer entries from other PRs build up before the same head is released again, the marker is evicted and that head can be un-parked once more (the same bounded residual, by design).
