Stall recovery honours an owner hold on the linked PR. A PR is held when it is open, unmerged, and either a draft or titled with `[skip ai]` (the same substring match as `scripts/review_autofix_step_evaluate_gate.sh`; the description-line marker is not checked). `_stall_pr_ai_hold_reason <pr_json>` in `scripts/orchestrate_poll_process.sh` prints `draft`, `skip_ai_title` or nothing. It reads the REST `pulls/<n>` payload (`.draft`, `.title`) or the batched linked-PR shape, whose `draft` and `title` keys come from `isDraft title` on the existing `_fetch_candidate_issue_details_graphql` / `_fetch_linked_pr_status_graphql` queries, so it adds no API calls (§15). It runs in four places:
- `recover_stalled_issue` (managed orchestrator-project path), for every non-`skip` action on an `ai:done` issue, before zombie-run cancellation and the stall judge (`invoke_stall_judge`), reading the wave's batched `_current_wave_details_json[<n>].linked_pr` (`STALL_RECOVERY_EFFECTIVE_ACTION=<action>_skipped_pr_ai_hold`; returns 1);
- `run_standalone_stall_recovery`, for every non-`skip` action on an `ai:done` issue, after the merged-PR guard and before the fresh-push guard, so the stall judge (an Opus call), the conflict dispatch and `retrigger_review` are all skipped;
- the inline standalone `retrigger_review` arm, on the resolved implementation-PR payload, before the in-flight check and the dispatch-first / empty-commit fallback (`STALL_RECOVERY_EFFECTIVE_ACTION=retrigger_review_skipped_pr_ai_hold`);
- `execute_stall_recovery_action retrigger_review` (managed path and stall judge), after the merge-train and capacity-wait skips and before conflict routing; it returns 1.

A hold logs `STALL_SKIP issue=<n> reason=pr_ai_hold pr=<m> detail=draft|skip_ai_title phase=ai:done action=none`, dispatches nothing, pushes no empty commit, counts no recovery attempt and does not reset the stall clock, so the issue is checked again on the next tick and recovery resumes on its own once the hold is lifted. A payload without the fields, or a closed or merged PR, is not held (fail open). `_dispatch_review_for_conflicts` and the review gate are unchanged, so a manual `workflow_dispatch` of `internal-review.yml` still overrides `[skip ai]`. Tests: `tests/test_orchestrate_poll_process.py` (`pr_ai_hold` cases).
