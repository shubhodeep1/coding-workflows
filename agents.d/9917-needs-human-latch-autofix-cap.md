**Autofix-cap latch release and infra-failed review rounds (issue #9917).**
- **Third head-bound latch.** `release_head_bound_needs_human_latches` in `scripts/orchestrate_poll_process.sh` also releases the default "AI review/autofix blocked — needs human intervention" comment (`scripts/review_autofix_step_post_review_blocked_comment.sh`, `*` case only), with latch reason `autofix_cap_head_moved`. The comment carries `<!-- ai:autofix-cap-head:v1 head=<AUTOFIX_FAILURE_HEAD_SHA> -->` before the `rb-judge-crash:v1` marker, which must stay last for its dedupe.
- **Legacy comments.** A comment without the marker takes its head from the run its `Run: <server>/<repo>/actions/runs/<id>` line names, only when `<repo>` is this repository. The run is read once per run id per tick (function-local `hl_run_head_cache`). Its `head_sha` counts only for a `pull_request` run whose head branch and head repository equal the PR's `head.ref` / `head.repo.full_name`, which both `pulls/<n>` projections now carry. A `workflow_dispatch` run's `head_sha` is a default-branch commit, so such a latch stays for a person. New skip reasons: `latch_head_unverifiable` and `run_unavailable`.
- **Re-assertion.** A later trusted comment with the "judge omitted follow-up issue details" or "auto-merge is disabled" blocked heading counts as re-asserting the hold, like a later `ai:needs-human` mention. Both headings, the autofix-cap marker and the default heading also count as a re-latch in the revalidation and post-delete reads.
- **Same-login binding.** The six #9862 conditions are unchanged. When `AI_COMMENT_SIGNING_SECRET` is set, the blocked comment may be posted as `github-actions[bot]` with a signature. The poller reads comments through the comment-signature shim (`scripts/gh_helpers.sh`), which returns a verified signed comment with the signing PAT login, so the comment binds to the `GH_PAT` label event. Only a read that cannot verify the signature (secret absent) sees `github-actions[bot]`, and the release then skips with `label_not_bound_to_latch`.
- **No shadowing.** The writer adds `ai:needs-human` only for some `JUDGE_SKIP_REASON` values, so an unlabelled autofix-cap comment can follow the latch that set the label. When the newest latch is an autofix-cap comment and the label does not bind to it, the label still binds when the newest older trusted latch comment it is bound to (same login, within 30 minutes) has a 40-hex head that is not the PR's current head, and no trusted comment between that latch and the autofix-cap comment re-asserts `ai:needs-human` or latches again on the current head or on an unresolved head (otherwise `later_needs_human_comment`). A latch between them on a head the PR has left, such as the writer re-firing on the stale head, does not hold.
- **Marker retention.** The `review-round-infra-failed` artifact is kept 3 days, so the exclusion holds only for `SWEEP_REVIEW_ROUND_WINDOW_HOURS` of 72 or less.
- **Infra-failed rounds.** `review_round_infra_failure_reason` (`scripts/review_sweep_round_cap.sh`) needs two things:
  - no usable editor output;
  - one of four signals: a `REVIEW*` fallback record with action `refused`/`wait` and reason `no_credential`/`all_gated`, the matching `::error::AI_ENGINE_FALLBACK_REFUSED` line (at line start) in the editor or reviewers stage stderr, `CLAUDE_POOL_STEP_AVAILABLE=false` with `broker_refused_<code>`, or a failed all_gated capacity defer (`CLAUDE_CAPACITY_WAIT_STEP_OUTCOME=failure` with pool reason `all_gated`; the classifier step also runs when that defer failed, because the reviewers step is then skipped).
  - The editor's partial-finalize summaries (`unavailable (partial finalize ...)`, `scripts/review_apply_fixes.sh`) count as no usable output.

  `review_autofix.yml` step "Classify infra-failed review round" (`id: infra_round`, `continue-on-error`) runs before the partial-finalize steps. For an infra-failed round, "Commit changes", "Pre-push affected-test gate" and "Prepare done-check (repair loop)" are skipped (`steps.infra_round.outputs.infra_failed != 'true'`), so the iteration counter does not advance and nothing re-triggers. A `workflow_dispatch` run also uploads the `review-round-infra-failed` artifact (3 days). `review_sweep_round_counts` lists those artifacts once per tick and drops the matching run ids. The sweep skips, with no label, a PR whose raw count in the window reaches 2× `SWEEP_REVIEW_MAX_ROUNDS` (`AUTOFIX_SWEEP_SKIP ... reason=review_round_infra_backoff`).
- **Switch and tests.** `REVIEW_INFRA_FAILURE_EXCLUDED_ENABLED` (default `true`) is set in both workflows and defaulted in the helper. Tests: `tests/test_needs_human_head_latch_release.py`, `tests/test_review_round_infra_exclusion.py`.
