- **Unreachable findings (#10057).** `scripts/review_issue_ledger.sh` marks a finding `unreachable` when its cited path is refused by the review editor's write rules: `write_guard_check review_editor` (reason `write_guard`), the consumer protected-prefix rule copied from `scripts/review_commit_changes.sh` (`REVIEW_UNREACHABLE_PROTECTED_PREFIX_RE`, reason `consumer_protected_path`, parity-tested), or `scripts/review_untrusted_workspace.py editor-reachable` (the `_path_rejection_reason()` tokens plus `not_admitted_command`). Files touched scope is not an editor write rule and is not used. A helper that is missing or fails leaves the path reachable. A finding whose block names a `failed[i]` check with conclusion `failure`, `action_required`, `startup_failure` or `stale` in `PR_CHECK_RUNS_CONTEXT_FILE` is never unreachable. The status is sticky (no persist-count growth, never promoted to `accepted-residual`, kept when the finding is absent). Ledger additions, written only for unreachable entries: entry keys `UNREACHABLE_REASON`, `UNREACHABLE_SECURITY` (`true` for the `SECURITY*` / implicit-execution lenses or a SECURITY floor tag), `UNREACHABLE_FOLLOWUP` (`pending` or `#N`), and header key `UNREACHABLE_FOLLOWUP_ISSUE`. Non-security blocks become `=== UNREACHABLE ISSUE <id> ===` stubs in `review_issues.txt`; security blocks stay with an added `UNREACHABLE: security-hold` line. Hand-off files in `RUNTIME_DIR`: `review_unreachable_new.tsv`, `review_unreachable_all.tsv`, `review_issues.pre_unreachable.txt`. `review_unreachable_followup_sync` in `scripts/review_apply_fixes.sh` makes at most one `gh issue create` (label `ai:clarification`, marker `<!-- AI_REVIEW_UNREACHABLE_FOLLOWUP pr=<n> -->`, `Refs #<pr>`) or `gh issue comment` per round, writes the number back before the ledger cache stage-out, and writes `review_unreachable_summary.md`, which `scripts/review_autofix_step_post_editor_summary.sh` appends to the editor-summary comment. The rb judge and consolidator ledger readers emit `prior_decision=unreachable-followup; followup=<#N|pending>; security_hold=<true|false>`; with `REVIEW_LEDGER_REREVIEW_ENABLED` off the rb judge still renders the `status=unreachable` rows (only those). `scripts/review_autofix_step_post_editor_summary.sh` writes no `review-autofix-clean:v1` marker (reason `unreachable_security_hold`) while `review_unreachable_all.tsv` holds a security row, and `scripts/review_enable_auto_merge.sh` (`review_unreachable_security_hold_active`) refuses the head-gate success, merge labels and auto-merge (`AUTOFIX_AUTO_MERGE_HEAD_BOUND ... action=refuse reason=unreachable_security_hold`) while the ledger has a `STATUS: unreachable` entry with `UNREACHABLE_SECURITY: true` or the TSV has a security row. The hold is sticky like the status: no code path clears it inside the PR (releasing it when reviewers stop raising it would let iteration scoping, which skips unreachable rows, drop it silently); a person decides the merge. On a same-head partial resume, which reuses the ledger stage, `_review_unreachable_rebuild_from_ledger` in `scripts/review_apply_fixes.sh` rebuilds `review_unreachable_all.tsv` and `review_unreachable_new.tsv` (pending rows) from the ledger when they are missing. The editor prompt restates the unreachable paths after the "authoritative findings source" line (`_review_unreachable_editor_scope_note`), so raw `reviewer_bundle.txt` findings on them are not acted on. `editor-reachable` leaves an `unsupported_type` name that is not a file on the host (a directory, `N/A`) out of its report, so it stays reachable. `scripts/collect_pr_check_runs_context.py` moves cancelled / timed-out runs to `no_result[i]` (+ `no_result_count:`) only when the caller sets `REVIEW_UNREACHABLE_FOLLOWUP_ENABLED` to a value other than empty / `false|0|no|off` and `CHECK_RUNS_EXCLUDE_SELF_FROM_CONTEXT` is not `true`. Kill switch `REVIEW_UNREACHABLE_FOLLOWUP_ENABLED` (default `true`; `false` keeps the earlier output). Rolling back to code without the feature resets a ledger that carries the new keys once (logged `ledger_reset=1`, fail-open).
