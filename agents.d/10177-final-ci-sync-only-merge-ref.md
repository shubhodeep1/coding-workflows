### Final CI: stale merge ref accepted when only syncs and resolver commits moved the base (#10177)

- **What:** at the only `outcome=stale` exit of `scripts/ci_final_merge_ref_fresh.sh` (the refresh attempts ran out and the local merge could not be built, typically `merge_base_too_deep` on an integration branch that synced `main` many times), `ci_final_merge_ref_sync_only` decides whether the job may test its original checkout anyway (Phase 10 / D10 of `docs/plans/pipeline-human-wait-elimination-plan.md`, Refs #9650, root cause R7).
- **Conditions, in order, first failure wins:** (0) the PR's base is not the default branch (read with `git ls-remote --symref origin HEAD`, no API call; `detail=default_base`); (1) `compare/<tested_base>...<tip>` is `ahead`, at most 250 commits, all listed, under 300 files (`not_ahead`, `truncated`); (2) every commit in range is in `compare/<tested_base>...<default>` (complete, else `truncated`), or is an exact `chore: sync <default> into <base>` two-parent merge whose second parent is in that set, or has a subject starting with `[ai-merge-resolve]` (`foreign_commit`); (3) no file of the range, old rename paths included, is in the PR's paginated `pulls/<n>/files` listing, capped at 3000 via `changed_files` from the existing `pulls/<n>` read (`too_many_files`, `truncated`, `file_overlap`). A base tip that moved during these reads (re-read with `git ls-remote` before accepting) is `truncated`. Unreadable responses, a moved checkout that cannot be restored, or an unreadable default branch are `api_error`.
- **`tested_base`:** the first parent of the commit the job checked out, captured before the refresh loop (the loop reassigns `first`). Accepting keeps that checkout (re-checked out and verified if a failed local merge moved HEAD).
- **Outcome:** accept logs `CI_FINAL_MERGE_REF ... outcome=stale_accepted reason=sync_only_no_overlap tested_base= tip= commits= files=`, writes one `$GITHUB_STEP_SUMMARY` line and exits 0; reject keeps the `::error::` and exit 1 and appends `detail=<token>` to the stale line.
- **Budget:** up to 32 GETs per job (two compares plus at most 30 files pages; a refused authenticated read is retried once without credentials, so at most 64 HTTP requests), on the stale path only; the fresh, refreshed and merged-locally paths make no extra call.
- **Switch:** `CI_FINAL_MERGE_REF_SYNC_ONLY_ACCEPT_ENABLED` (default `true` in the script; true/1/yes/on), wired as `${{ vars.CI_FINAL_MERGE_REF_SYNC_ONLY_ACCEPT_ENABLED || 'true' }}` into all ten "Verify the final-CI merge ref is current" steps of `ci.yml`. `false` restores the old stale line exactly (no `detail=`).
- **Tests:** `tests/test_ci_final_merge_ref_fresh.py` (integration-branch world, fake `gh` fixtures for `compare/...` and `pulls/7/files`, every accept and reject case, the ci.yml wiring of all ten steps).
