- **Static-context files under `/support` (issue #8262).** `scripts/codex_isolated_exec.sh run` reads the host-side variable `CODEX_ISOLATED_STATIC_CONTEXT_FILES` (newline-separated host paths, default empty) and copies each file to `${root}/support/static-context/<name>`, inside the read-only `/support` mount, for both engines. The directory is removed first on every run, because the implement root is reused across attempts. Only regular, non-symlink files named `agents_canonical.md` or `agents.rendered.md` are accepted, each name once; anything else fails the run with `::error::CODEX_ISOLATION static context file rejected`. The variable is never passed into the container, which still runs with `env -i`, `--network none` and no credentials, and the log line `CODEX_ISOLATION static_context files=<n>` prints a count only. The helper advertises the feature with the line `# supports: CODEX_ISOLATED_STATIC_CONTEXT_FILES`. `implement.yml`'s "Pre-assemble static context" step checks for that line in `IMPLEMENT_STAGED_SUPPORT_RUN_DIR/codex_isolated_exec.sh`; when it is there, `${RUNTIME_DIR}/agents_canonical.md` exists (consumer repos) and the mode is `index` (unset, empty or `index` in any letter case; `inline` or any other value mounts nothing, so the rollback copies no file into later isolated runs), it exports the variable through `GITHUB_ENV` and sets `STATIC_CONTEXT_CANONICAL_SANDBOX_PATH=/support/static-context/agents_canonical.md` for `scripts/build_static_context.sh implement`, which then indexes the canonical file (`=== CANONICAL AGENTS.MD INDEX (coding-workflows) ===`) instead of inlining it. Without the marker it passes `STATIC_CONTEXT_CANONICAL_UNAVAILABLE_REASON=helper_unsupported` and the file stays inlined. In index mode (`STATIC_CONTEXT_AGENTS_MODE`, default `index`, forwarded from the repository variable) the local agents file is indexed too; any index failure inlines that file, and with neither file indexed the output is the inline output byte for byte. The heal route forces `inline` (`STATIC_CONTEXT_AGENTS implement mode=inline reason=heal_route`), because the heal editor's own container has no `/support` mount. Check-failure triage still inlines its canonical copy. Log: `STATIC_CONTEXT_SIZE phase=implement mode=<index|inline> canonical=<index|inline|absent> bytes=<n>` plus ` canonical_reason=mount_unconfirmed|helper_unsupported|sandbox_path_invalid|index_unavailable|tmp_unavailable|unknown`, ` fallback=inline reason=index_unavailable|tmp_unavailable` and ` agents=absent`.
