- **Final CI runs bind the required `lint` (2026-11-17).** A run's `name` in the Actions API is its run name, so a final CI run of `ci.yml` is named `CI [pr:<n>]` (or `CI [pr:<n>] [sync-quick]`), never `CI`. `_pr_head_ci_runs_pending` (`scripts/pr_checks_lib.sh`) matched `AUTO_MERGE_WAIT_WORKFLOWS` names exactly, so the final run's `lint` was never bound (`PR_CHECKS_CI_RUN_IDS` empty). Every head whose only CI run was its final run (all heads since #9535 switched PR CI to `CI quick` plus one final run) had its required-checks wait time out after `AUTO_MERGE_CHECKS_WAIT_MINUTES` with `AUTOFIX_AUTO_MERGE_CHECKS ... outcome=timeout ... ci_check=lint ci_state=absent`, and auto-merge was refused; PR #9617 was the observed case. Now a `workflow_dispatch` run whose name is a listed workflow name followed by `[pr:<n>]` and at most one `[<mode>]` counts as a run of that workflow (`PR_CHECKS_JQ_WAIT_WORKFLOW_KEY_DEF`, jq `_wait_wf_key`), for the binding, the pending count and the all-cancelled (`ci_run_cancelled`) grouping, so a cancelled quick final run next to a newer full final run is not "unrun". Runs of other events with that name, and names with any other suffix, still never count. `scripts/unblock_judge.sh` reuses the same ids (`PR_CHECKS_RUNS_IDS`) and gets the same fix. No extra API call.
