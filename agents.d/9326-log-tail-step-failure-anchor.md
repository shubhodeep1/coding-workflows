- **Check-run `log_tail` anchors on the runner's step-failure line (issue #9326).** `_select_log_tail_window` in `scripts/collect_pr_check_runs_context.py` ends the `step_error` window at the first line matching `LOG_TAIL_STEP_FAILURE_LINE_RE` (`##[error]Process completed with exit code N` at the start of the message, optional BOM and runner timestamp first) and falls back to the first `##[error]` line only when the scan has none. `##[error]` lines a passing test prints (for example the `tests/test_lint_pr_body_auto_close.py` self-checks) no longer hide the failing step; step-level messages just before the runner line (`merge-train step shards failed: rest`, `CI jobs that did not succeed: ...`) land in the lead context. Labels (`step_error` / `end_of_log`), byte and line budgets, redaction and the partial-first-line rule are unchanged.
