- **Standalone `ai:ready-to-merge` with a merged linked PR (issue #9482).** A PR merged into an integration branch (`orchestrator/project-*`) never sets `willCloseTarget`, so both GraphQL linked-PR lookups miss it. `run_standalone_stall_recovery` therefore runs the `_resolve_issue_implementation_pr` fallback for `ai:ready-to-merge` as well as `ai:done`, and `attempt_merge` reuses the PR it resolved. When that PR has merged, `_check_merged_pr_guard` skips recovery without touching the stall counters and hands the issue to `_reconcile_standalone_merged_pr_issue`. Each skip logs exactly one `STALL_SKIP` line: the reconcile's `reason=merged_non_target_base` line for a non-target base, otherwise `STALL_SKIP issue=<n> reason=linked_pr_merged pr=<p> phase=<phase> action=<action>` from the caller (gated by `_STALL_STANDALONE_NT_SKIP_LOGGED`). The stall judge's `linked_pr` diagnostics carry `merged` and `merged_at` from the payload `_fetch_pr_json` already returned, and `state` reads `merged` for a merged PR. A judge `escalate_human` is kept, not normalised to `attempt_merge`, only when the linked PR is closed or merged and `_pr_json_is_issue_implementation_pr` accepts it; a closed mention-only cross-reference keeps the old normalisation.
