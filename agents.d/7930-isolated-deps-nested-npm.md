- **Nested Node projects in the dependency phase.** `stage-deps` also stages up to 8 nested projects (`package.json` plus `package-lock.json`, `yarn.lock` or `pnpm-lock.yaml`, at most 4 directories deep, skipping dot directories, `node_modules`, `dist`, `build`, `coverage` and `vendor`) under `STAGE/nested/<n>/`, listed as `<n> <mode> <dir>` in `STAGE/.codex-deps/nested`. The dependency container installs each with `--ignore-scripts` through the registry proxy; `codex_isolated_workspace.py handoff-nested STAGE WORK` then moves each `node_modules` into WORK without following symlinks, never over an existing one, and `prep-finalize` makes it a prep root. Logs: `stage-deps ... nested_node=<n>`, `stage-deps nested_node_skipped=<n> reason=project_limit|node_modules_present|manifest_unavailable` (the cap counts staged projects only, so a skipped project never takes a slot), `CODEX_ISOLATION deps nested_node index=<n> mode=<mode>`, `handoff-nested moved=<n> skipped=<n>` (a symlinked `STAGE/nested` or `STAGE/nested/<n>` is skipped; an unreadable list logs `reason=list_unreadable`).
