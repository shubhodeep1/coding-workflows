### Done-check (`PERSIST_ACCEPTANCE_ENABLED`, P2 of #8427)

Phase P2 of `docs/plans/persistent-unattended-workflows-plan.md`. Repo variable `PERSIST_ACCEPTANCE_ENABLED` (default `false` in plan.yml, implement.yml and `scripts/run_plan_codex.sh`). With it off the planner prompt, the plan comment, the journal entry and every PR body are byte-identical to before, even for plans approved while it was on.

- **Prompt.** `scripts/run_plan_codex.sh` appends `prompts/mode-plan-acceptance.txt` (template in `prompts/_templates/`, byte-identical) after the heal block; plan.yml installs it like the heal counterfactual fragment. A missing fragment logs `PERSIST acceptance outcome=skipped reason=prompt_absent`. The plan writes a `## Acceptance` section after `## Files likely to change` with unfenced lines `ACCEPTANCE: test <repo-path>[::<name>] [red-on-base]` (<= 10), `ACCEPTANCE: check <check-run name>` (<= 5), and exactly one of `ACCEPTANCE: post-merge workflow <.github/workflows/<file>.yml> [job <name>]` or `ACCEPTANCE: post-merge none: <reason>`; at least one test or check line.
- **Validate.** plan.yml "Validate done-check (acceptance)" (after "Parse planning output", fail-open) runs `scripts/acceptance_check.py validate` on the planner output against the checkout, no network. Only lines after the first Files-likely-to-change heading and outside code fences count. Test paths must be safe repo-relative paths of a regular non-symlink file, or be listed in the Files section; check names must equal a job's `name:` (its id when unset) in `.github/workflows/*.yml`, or the part before ` / `; names with `${{` never match. Errors: `unknown_form:<n>`, `missing_test_path:<p>`, `unknown_check:<n>`, `missing_workflow:<f>`, `unknown_job:<f>:<j>`, `too_many_tests`, `too_many_checks`, `no_test_or_check`, `post_merge_count:<k>`, `marker_too_large` (<= 20). Output `acceptance.v1`: `{schema, state: valid|invalid|none, source: plan|heal, tests[{path,name,red_on_base}], checks[{name}], post_merge{workflow,job}|null, post_merge_none, errors[]}`.
- **Heals.** With no ACCEPTANCE lines and a single `HEAL_COUNTERFACTUAL: REPRODUCIBLE: <ids>` line (#8409 P2 grammar; not on `main` yet, so it never fires today), each id becomes a `red-on-base` test, `source=heal`, no post-merge line.
- **Marker.** Only a `valid` result is stored, as `<!-- AI_ACCEPTANCE_V1 {json} -->` (sorted compact JSON, `<`, `>`, `&` escaped, <= 6,000 bytes) on the line directly above the host trailer `<!-- ai:plan-proposal:v1 -->`. `parse` reads only that trailer position of the trusted plan comment implement already extracts (`PLAN_FILE`) and re-checks shape and charset, so a marker the model writes into its plan text is ignored. An invalid done-check never holds or approves a plan: done falls back to "CI green".
- **PR body.** implement.yml appends `render` output (`## Acceptance` table, status `not run`; `--gate-result` reads `acceptance.items[{kind,target,status}]` for P3) after the gate summary and before the auto-close lint. Values go through `partial_delivery.sanitize_item`.
- **Journal.** plan.yml passes `--acceptance-file` to `scripts/attempt_journal.py append`: `invalid` is recorded with its errors as `unmet`; `valid` and `none` stay `none`.
- **Logs.** `PERSIST acceptance outcome=<valid|invalid|none> errors=<n>` (validate), `outcome=<valid|none> reason=parse`, `outcome=skipped reason=prompt_absent`, `outcome=error reason=io`. Tokens only. No GitHub API calls.
