Integration-sync conflict preparation (`scripts/review_conflict_prepare.sh`) reads the newest complete `ORCHESTRATOR_STATE_V2` chain by the pipeline login first, the same way `_resolver_test_repair_context` in `scripts/review_conflict_resolve.sh` does. It runs `orchestrate_state_v2.py extract` from `${SUPPORT_SCRIPTS_DIR}` or `${GITHUB_WORKSPACE}/.codex-workflow-src/scripts/` (absolute paths only, never a symlink, `python3 -I -B`) and falls back to the V1 comment only when there is no V2 state. The merged sub-issue list and `merged_issue_fingerprints` in the resolver prompt now come from current state. Before this, the script read only V1, which the poller never writes, so it saw at most the initial snapshot with nothing merged. Missing or unreadable state still fails open with an empty list and `{}`.
