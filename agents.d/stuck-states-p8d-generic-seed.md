- **Dependency-wait seeding skips every human latch (stuck-states P8d, Refs #8291).** On top of the P8b "Seeding" rule, `seed_candidate()` in `scripts/dependency_wait_resume.py` skips any `ai:blocked` issue that carries a label in `SEED_HUMAN_LATCH_LABELS`: `ai:needs-human`, `ai:check-triage-escalated`, `ai:destructive-blocked`, `ai:scope-blocked`, `ai:harness-broken`, `ai:resolver-escalated` and `ai:security-pass-failed`. The set is a copy of `workflow_failure_heal.HUMAN_NEEDED_LABELS`, not an import, because the helper runs as `python3 -I`. It also covers `orchestrate_lib.STALL_RECOVERY_LATCH_LABELS`, and `tests/test_dependency_wait_resume.py` checks both relationships. A latched issue gets no write at all, including no half-applied-seed recovery. Once a person removes the latch, the next tick seeds it. The check reads only the call-1 snapshot, so it adds no API call. `outcome=` values are unchanged.
