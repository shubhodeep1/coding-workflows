- **Dependency-wait seeding skips every human latch (stuck-states P8d, Refs #8291).** On top of the P8b "Seeding" rule, `seed_candidate()` in `scripts/dependency_wait_resume.py` skips any `ai:blocked` issue that carries a label in `SEED_HUMAN_LATCH_LABELS`: `ai:needs-human`, `ai:check-triage-escalated`, `ai:destructive-blocked`, `ai:scope-blocked`, `ai:harness-broken`, `ai:resolver-escalated`, `ai:security-pass-failed` and `ai:workflow-heal-escalated`. The set is the union of `workflow_failure_heal.HUMAN_NEEDED_LABELS` and `orchestrate_lib.STALL_RECOVERY_LATCH_LABELS`, copied rather than imported because the helper runs as `python3 -I`. `ai:workflow-heal-escalated` stays out of `HUMAN_NEEDED_LABELS` on purpose, because that tuple drives the heal-intake `if:` predicates. `tests/test_dependency_wait_resume.py` checks the union. A latched issue gets no write at all, including no half-applied-seed recovery. Once a person removes the latch, the next tick seeds it. The check reads only the call-1 snapshot, so it adds no API call. `outcome=` values are unchanged.
