<!-- agents: section="Workflow architecture" -->
**Review-blocked reissue adoption (project #8969).** When the review pipeline's review-blocked judge (`scripts/review_rb_judge.sh`, `close_and_reissue`) closes an orchestrator wave issue and opens a replacement, the poller now maps the replacement into wave state on its next tick, the same way its own `close_and_reissue` arm does. In the reconcile loop, a current-wave issue that is closed with no merged implementation PR, and is not `ai:merged`, `ai:implementation-failed`, or stored as `merged` / `skipped`, gets one paginated REST `GET issues/<n>/timeline` (`resolve_review_blocked_reissue_successor`). A cross-referenced issue in the same repository, numbered higher, labelled `ai:orchestrator-managed`, whose body has the lines `- Tracking issue: #<tracking>`, `- Type: review-blocked-reissue` and `- Replaces: #<closed>` (then a space or end of line), is the successor; the highest number wins. `adopt_review_blocked_reissue_successor` rewrites `.issue_number_map[<local_id>]` and the wave entry's `github_issue`, resets it to `pending` (`last_seen_phase=""`, `status_since_ts=now`, `stall_recovery_count=0`), and refuses when the successor is already tracked anywhere in state (an `orphan-rb-<successor>` entry the orphan sweep injected into the current wave is removed instead). The successor also gets a `PR_STATES_JSON` entry for that tick (its implementation PR is looked up when it is closed without `ai:merged`), so a successor whose PR merged before `ai:merged` landed does not read as closed-without-merge. The state comment is posted at once and a healing note is added. The successor's labels and state come from the timeline payload for that tick, so wave status, stall recovery and the wave judge never see the predecessor as closed-without-merge. A lookup failure changes nothing and retries next tick. Before this, the closed predecessor read as a failure and the wave judge opened a second redo for the same work (#8970 → #8994 and duplicate #8995).

`scripts/review_rb_judge.sh` also now carries a wave parent's `Local ID`, `Priority` and `Managed by` lines into the reissue: its parent-metadata parser accepts `- Integration branch: orchestrator/project-<n>` without backticks (the form wave issues use) as well as the backticked form, and always writes it back with backticks.
