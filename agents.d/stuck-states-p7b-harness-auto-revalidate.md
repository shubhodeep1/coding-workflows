<!-- agents: section="Workflow architecture" -->
- **Harness heal auto-revalidate (stuck-states P7b, Refs #8291).** In the per-tracking-issue `/revalidate` block of `scripts/orchestrate_poll_process.sh`, when no `/revalidate` is pending and the tracker carries `ai:harness-broken`, `harness_heal_auto_revalidate` resumes a parked project (status `failed`, `ai:validation-failed` or `ai:validate-failed`, no active `validation_harness_hold`) once its heal issue merges. It takes the heal issue from the newest trusted routing marker (`validation_harness_marker route-latest any`: route login, `workflow-failure-heal:validation-route:v1`, outcome `opened` or `duplicate`, issue `^[1-9][0-9]{0,8}$`), and reads it with the hold's memoized `_validation_harness_hold_issue_state`. That call's cache entry is now `state|state_reason|closed_at|merged` and sets `VHH_ISSUE_MERGED`, which is `true` only when the issue carries `ai:merged`. When the issue is closed with `ai:merged`, it first waits (outside this repository) until the consumer's `validate.yml` pin (`validation_harness_pin`) has a committer date no older than the heal close, read with one memoized `GET repos/shubhodeep1/coding-workflows/commits/<pin>` (`_HHAR_PIN_DATE_CACHE`), the same rule the hold's `heal_closed_after_pin` check uses; then it posts one `/revalidate` comment whose last line is `<!-- AI_HARNESS_HEAL_REVALIDATE_V1 heal=<n> -->`, appends it to `COMMENTS`, and hands it to the unchanged `/revalidate` reset on the same tick through `HHAR_POSTED_COMMENT_JSON` → `REVALIDATE_COMMENT_JSON`. The once-only gate is that marker on a comment by `UNBLOCK_TRUSTED_LOGIN`. The step fails closed when comments (`COMMENTS_FETCH_OK`, `COMMENTS_FOR_TRACKING_NUM`) or the identity are unavailable, and a failed POST leaves no marker, so the next tick retries. API budget: at most one heal-issue GET per tracker per tick (shared with the hold), one pin-commit GET per distinct pin per tick while waiting, and at most one comment POST per heal issue ever. `HARNESS_HEAL_AUTO_REVALIDATE_ENABLED` (default `true`, forwarded by both full-poller steps of `.github/workflows/orchestrate_poll.yml`) set to `false` turns it off silently.
