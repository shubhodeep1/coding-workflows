### Budget and progress governor (`PERSIST_BUDGET_ENABLED`, P6 of #8427)

Phase P6 of `docs/plans/persistent-unattended-workflows-plan.md`. Repo variable `PERSIST_BUDGET_ENABLED` (default `false`) with caps `PERSIST_MAX_APPROACHES` (default `3`, 1..20), `PERSIST_MAX_ROUNDS` (default `5`, 1..50), `PERSIST_MAX_HOURS` (default `48`, 1..720) and `PERSIST_REPLAN_AFTER_FAILED_ROUNDS` (default `3`, 1..20), each defaulted in `orchestrate_poll.yml` and in `scripts/persist_budget.py` itself. `persist_budget.py` is staged by the poller's support list, so P5's `_budget_owner` finds it next to `persist_postmerge_verify.py`.

- **Decide.** `persist_budget.py decide` (pure, no API call, always exits 0) reads the attempt journal (P1; `attempt_journal.parse`, pipeline login only) and returns `{action, reason, basis, approaches, rounds, failed_streak, summary}`. Order: a label `ai:security-pass-failed` or containing `security`, `ai:needs-human` or `ai:closed` → `ignore`; no trusted journal → `ignore journal_absent`; newest entry `stage=governor` → `ignore already_decided`; oldest entry older than `MAX_HOURS` → `escalate max_hours`; on the current approach (newest `plan` entry's `approach`), rounds (stages implement/review/resolver/postmerge) `>= MAX_ROUNDS` (`max_rounds`), the newest `REPLAN_AFTER_FAILED_ROUNDS` rounds all failed (`failed_rounds`), or the newest 2 rounds failed with no progress between them (`no_progress`) → `replan`, or `escalate max_approaches:<trigger>` once `MAX_APPROACHES` distinct approaches exist; a newest failed `postmerge` round with no newer `plan` entry (P5's hand-off) → `replan` / `escalate` `postmerge_recurred`; else `continue within_budget`. A round failed when `outcome=fail` or `acceptance.state=unmet`; progress is a different `failure_key`, fewer unmet items, fewer `gate.pr_caused` (both known) or a different `evidence_hash`. `summary` uses host-computed fields only, never `note`.
- **Act.** `persist_budget_govern_issue` in `scripts/orchestrate_poll_process.sh` (after `run_persist_postmerge_verify`) skips issues in `ACTIVE_WORKFLOW_ISSUES`, defers once 5 decisions acted this tick (`tick_cap`), and reuses the tick's `PERSIST_JOURNAL_LOGIN_CACHE`. `replan` honours `phase_cap_can_dispatch "ai:planning" retrigger_plan`, moves the issue to `ai:planning` when it carries none of `ai:planning` / `ai:clarification` / `ai:blocked` (plan.yml skips `/answer` in any other phase; the plan assumed plan.yml moved the label), then posts the bare retrigger_plan `/answer` with a `_Persistence budget: <reason>. Re-triggering plan generation._` line (managed: `Orchestrator persistence budget`). `escalate` adds `ai:needs-human` (the unblock scan picks it up) and posts `## Persistence budget reached`. Each acted decision journals `stage=governor` (`ok` / `blocked`, gated by `PERSIST_JOURNAL_ENABLED`).
- **Hooks.** Standalone: in `run_standalone_stall_recovery` after the per-issue skips and the `ai:claude-capacity-wait` branch, before `status_since=`; a landed re-plan stores `persist_budget_basis` in `AI_STANDALONE_STALL_STATE_V1` and skips the stall action this tick, an escalation skips it too. Managed: inside the `INVOKE_JUDGE_FOR_STUCK != true` branch before stall detection, for the current wave's non-terminal issues (`merged|closed|skipped|not_created` skipped), with labels from `LABELS_JSON`, comments from `_current_wave_details_json` and the active set built from the per-tick runs cache; a landed re-plan stores `persist_budget_basis` on the wave issue entry and `PERSIST_BUDGET_STATE_CHANGED` makes the existing state post carry it. A stored basis equal to the decision's basis skips the issue (`already_decided`).
- **API budget.** Comments from the caller's cache; one paginated comments read only when the cache is empty or holds 100 comments (the journal comment may sit outside the newest 100). One shared identity read per tick. Writes per acted decision: replan 1 label edit (only when needed) + 1 comment (+ the standalone state comment), escalate 1 label edit + 1 comment, plus the journal append under P1's budget.
- **Switch off.** Neither hook runs: no call, no log line, no state field.
- **Journal off.** With `PERSIST_JOURNAL_ENABLED=false` the governor finds no journal (`journal_absent`) while P5 still defers its re-plan to it; enable the journal first.
