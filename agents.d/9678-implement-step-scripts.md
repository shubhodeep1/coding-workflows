- `implement.yml` uses the same pattern for two step bodies (#9678): "Preflight destructive-commit guard" (`id: preflight_destructive_guard`) lives in `scripts/implement_step_preflight_destructive_guard.sh` and "Attempt post-Codex syntax repair" (`id: post_codex_syntax_repair`) in `scripts/implement_step_post_codex_syntax_repair.sh`. Each step keeps its `name:`, `id:`, `if:`, `env:` and `continue-on-error:` in the workflow. Both steps run after the isolated editor's writes are copied back, so the wrapper sources the script only from the trusted pre-editor copy in `IMPLEMENT_STAGED_SUPPORT_RUN_DIR` and exits 1 when it is unset, missing or a symlink. It has no fallback to `scripts/` or `.codex-workflow-src`. A new implement step script must be added to both required lists, the `for f in gh_helpers.sh ...; do` loop in "Stage workflow support files" and `stage_support_required_scripts` in the `implement)` case of `scripts/stage_support_for_phase.sh` (same order; `tests/test_support_script_single_source.py` pins parity), and to `IMPLEMENT_STEP_SCRIPTS` in `tests/review_autofix_step_scripts.py`. Tests that read the moved bodies use `expanded_implement_text()`. `tests/test_implement_step_scripts_contract.py` pins the wrapper and caps `implement.yml` at 430,000 bytes (`MAX_WORKFLOW_BYTES`).
