- **Stage switch discovery (#10170).** `scripts/stage_switch_watch.py` `discover_switches(repo_root)` finds the default-on switches at run time, standard library only and fail-open: `vars.<NAME>_ENABLED || 'true'` (also chained and multi-line) and `vars.<NAME>_ENABLED != 'false'` in `.github/workflows/*.yml` / `*.yaml` (whole comment lines removed), and `_ENABLED` rows with default `true` in the README `#### Variables` / `## Required Variables` tables minus `README_NOT_REPOSITORY_VARIABLES`. `load_registry(path, repo_root)` merges them with `scripts/stage_switches.json` (sorted by name): an entry's `stage` and `on_values` win; a switch with no entry or no `stage` gets `Turns on <name> (<files>); false turns that stage off.`. Entries need only `name`; `pending` (bool) marks a switch whose PR has not merged, and a `pending: true` `off_on_purpose` marker for an undiscovered `_ENABLED` name is dropped without the daily warning. The `snapshot` and `evaluate` subcommands take `--repo-root` (default empty: no discovery); `scripts/stage_switch_watch.sh` always passes `STAGE_SWITCH_REPO_ROOT` (default: the folder above `scripts/`) to both. A PR that adds a default-on switch edits no JSON unless it wants custom `stage` text or `on_values`; `tests/test_stage_switch_registry.py::test_registry_entries_name_discovered_or_pending` fails on a JSON entry or marker that is neither discovered nor `pending: true` with a valid `_ENABLED` name, so delete stale entries or mark them pending.
