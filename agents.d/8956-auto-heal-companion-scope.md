### Auto-heal remediation companion paths (#8956)

- For an issue authored by the pipeline login (`user.login` from the issue's REST metadata equals the pipeline login, both matching `LOGIN_RE`) whose body carries `<!-- auto-heal-remediation:v1 `, `scripts/files_touched_scope_guard.py` treats `db/contracts/<name>.yml` (one level) and top-level `tests/test_<name>.py` as in scope of the issue-body `files_touched` list. The marker alone grants nothing, and author association is not considered.
- One function decides it: `auto_heal_companions_allowed(issue_body, author_login, pipeline_login)`, passed as `allow_auto_heal_companions` to `path_in_scope`. The plan gate (`plan_files_outside_files_touched`, `_plan_hold_replannable`) and the implement guard (issue-body CLI mode with `--issue-meta-file` and `--pipeline-login`) use it alike. Explicit scopes (`--allowlist-file`: `ai:scope:` labels, heal scopes) never get the companions, and automation-path grants are unchanged.
- `implement.yml` "Fetch issue metadata" exports `IMPLEMENT_SCOPE_PIPELINE_LOGIN` (the login it already reads, written to `GITHUB_ENV` only after `^[A-Za-z0-9][A-Za-z0-9-]*(\[bot\])?$` matches). The preflight guard, `scripts/implement_commit_changes.sh` and `implement_prepush_test_gate_narrow_allow_list` pass `--issue-meta-file "${ISSUE_META_FILE:-}" --pipeline-login "${IMPLEMENT_SCOPE_PIPELINE_LOGIN:-}"`. Unset or empty means no companions (today's behaviour). In CLI mode a metadata `number` that differs from `--issue-number`, or unreadable metadata, also means no companions.
- Plan gate without a pipeline login: when every path outside the list is a companion path, the body has the marker and the author login is valid, the gate holds with `identity_unavailable`, so `plan.yml` reads the login once and re-runs. An approving record that used the rule carries `auto_heal_companions: true`.
- Tests: `tests/test_files_touched_scope_guard.py` (`test_auto_heal_*`, `test_plan_gate_auto_heal_companions`, `test_cli_issue_body_mode_auto_heal_companions`, `test_implement_scope_callers_pass_auto_heal_identity`).
