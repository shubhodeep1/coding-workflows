- **Completed tracking issues close themselves (issue #8685).** `close_completed_tracking_issue_if_ready` in `scripts/orchestrate_poll_process.sh` runs in the terminal-state block of every poller tick, after the backpressure-label removal and the partial-verdict retry, and only for `status=complete`. It closes the tracking issue as completed once all of these hold: `ORCHESTRATOR_CLOSE_COMPLETED_TRACKING` is truthy (default `true`); `COMMENTS` was fetched; the labels were read (they include `ai:orchestrator-tracking`, so a failed read that yields `[]` defers instead of counting as "no pending label"); the activation verdict is final (a trusted `<!-- ai:activation:v1 verdict=LIVE|DORMANT source=project-<N> -->` comment found by the shared `activation_final_verdict_from_comments` helper, or `ACTIVATION_VERIFY_ENABLED=false`; `partial=true` does not count); `ai:comprehensive-test-pending` is absent or `.comprehensive_release_callback.handled` is `true`; no trusted plan-split-source marker exists (shared `_plan_split_source_issue_from_comments` helper) or `.plan_split_source.outcome` is set; and `ai:integration-backpressure` is absent. It reads nothing new and writes one comment ending `<!-- ai:tracking-auto-close:v1 issue=<N> -->`, one PATCH and one state comment, once per project; the outcome is kept in `.tracking_auto_close`, so a reopened issue is not closed again unless that state save failed. A failed PATCH retries next tick without a second comment; a failed comment never PATCHes; a failed state save after the close logs a `::warning::` and `state_persist=failed`, because a reopened issue could then be closed again. Failed, validation-failed and active projects are untouched.

<!-- agents: section="Workflow architecture" -->
- **Check-triage evidence through an integration branch (issue #8685).** `scripts/check_triage_resolution.py` `verify_resolution` keeps the default-branch path for every base except `^orchestrator/project-<N>$`. For such a base, issue N must carry `ai:orchestrator-tracking` and the newest PR from that branch into the default branch must have a same-repository head. Open integration PR: the newest completed `pull_request` run of the same workflow on its head must be `success` with every failed job name present once and `success` (check-run triage: every latest run of the check name on that head), and the head must contain the triaged PR's merge commit. Merged integration PR: the existing default-branch check runs, the integration head must contain the triaged merge commit, and the default-branch evidence commit must contain the integration PR's merge commit. A closed, unmerged integration PR or any read failure stays `unverified`. The verdict JSON and evidence comment carry `evidence_ref=default|integration_pr:<n>`.
