- **Merge-train release: stale untitled runs and the queue-age warning.** `_mt_inflight_review_branches` in `scripts/review_merge_train.sh` classifies each active review run once: counted with its keys, unattributed, or stale. Stale means an untitled default-branch `workflow_dispatch` review run whose own status is `queued`, `requested`, `pending` or `waiting` and whose `created_at` is more than `MERGE_TRAIN_STALE_UNATTRIBUTED_RUN_HOURS` old (default 6, `0` off). A stale run is dropped and logged (`MERGE_TRAIN_RUNS_LISTING outcome=ignored reason=stale_unattributed_run runs=<n> ids=<id,...> max_age_hours=<h>`) instead of making the listing incomplete; an `in_progress` run, a younger run, or one with a missing or malformed `created_at` is still unattributed. Why: GitHub left coding-workflows run 41814678900 `queued` with no jobs and no rendered title from 2026-11-04, and every release pass ended `reason=unattributed_run` for six days (16 PRs queued); the run could not be cancelled (`409 Cannot cancel a workflow run that has not been queued yet`), so no operator action could clear it. `_mt_release_stall_alert` runs at the end of a poll-tick release (no `BASE_BRANCH` filter) and sends one Telegram `WARNING` a day while the oldest still-queued PR has been open `MERGE_TRAIN_STALL_ALERT_HOURS` (default 24, `0` off) or more. Its once-a-day state is a comment on that PR by the pipeline account whose first line is `<!-- merge-train:stalled alert_date=YYYY-MM-DD -->` (`alert_date` is the UTC date the 3-hour slot started, so a slot crossing midnight still sends once), written before the send and updated in place; it is checked only inside the 3-hour UTC slot starting at `MERGE_TRAIN_STALL_ALERT_HOUR_UTC` (default 1), so ticks outside the slot make no API call. `orchestrate_poll.yml` "Release merge-queued PRs (merge train backstop)" passes `TG_BOT_SECRET`, `TG_ADMIN_CHAT_ID`, `ALERT_MSG_LEVEL` and `MERGE_TRAIN_TG_HELPERS` (`tg_helpers.sh` from `.codex-workflow-src`, else `.codex-workflow-src-main`, never the repository's own `scripts/`). Log: `MERGE_TRAIN_STALL_ALERT pr=<n> age_secs=<n> queued=<n> outcome=<sent|not_delivered|already_alerted|outside_slot|telegram_unavailable|telegram_unconfigured|below_alert_level|marker_unavailable|marker_write_failed>`. The warning reports an age and that pass's counters, not a diagnosis: one incomplete listing is routine, so a single tick cannot tell a stall from churn. `cancel_on_pr_close.yml` passes none of the Telegram settings and never sends it.
