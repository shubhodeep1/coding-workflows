- **Cgroup driver for the sandbox daemon (#7063).** Rootless dockerd uses systemd's cgroup driver on a systemd cgroup v2 host, and that driver needs a systemd user session for the sandbox user. `provision` (`sandbox_start_verified_dockerd`) enables linger for the user and waits for `/run/user/<uid>/bus` and `user-<uid>.slice`. It then starts dockerd with `DBUS_SESSION_BUS_ADDRESS` set, or with `--exec-opt native.cgroupdriver=cgroupfs` when there is no session (or `VALIDATION_HARNESS_SANDBOX_CGROUP_MODE=cgroupfs`). It proves the daemon works by running one container from `ai-validation-probe:local`, an image imported from the host's `/usr/bin/true` and its `ldd` libraries, so no registry pull is needed. A `docker run` exit of 125 (the daemon refused) under systemd restarts the daemon with cgroupfs (`outcome=retry reason=container_start_failed_systemd`); a second refusal fails closed with `container_start_failed`. Exit 126/127 or an image that cannot be built is logged as `container_probe_inconclusive` and does not fail provisioning. The daemon's error line is logged as `VALIDATION_HARNESS_SANDBOX phase=provision probe_exit=<n> detail=<text>`. Without cgroups (cgroupfs in rootless mode) container resource limits are dropped; user-namespace isolation and the separate daemon are unchanged.
