- **Rate-limit requeue for clarify and the review gate (#10031).** A GH_PAT primary rate limit used to leave the item idle until a person noticed. Clarify: when "Resolve integration ref" (`id: refctx`) exits on resolver rc=75 with CI-triage routing on, it writes `rate_limited=true` to its outputs (the error line and the refusal to fall back to the default branch are unchanged). The step "Queue rate-limited clarify for poller" (after "Queue failed reclarify for poller") then reads `resources.core.reset` from `GET /rate_limit` (it does not count against the limit; accepted only as a 10-digit epoch no later than now+3900 s, otherwise now+3600), posts the single-line job-token comment `<!-- ai:clarify-rate-limited:v1 run=<run> reset=<epoch> event=<issues|issue_comment|other> source=<comment id|0> -->` and adds the existing `ai:reclarify-requeue` label (same three-attempt loop and `gh label create` fallback); it always exits 0. The poller's `replay_failed_reclarify_commands` (every `AI Orchestrate Poller` tick, idle ticks included) takes the newest `github-actions[bot]`/Bot whole-body marker of either kind; a rate-limit marker goes to `_replay_rate_limited_clarify`, which uses the same issue and comment reads (no new read). In order: marker invalid → skip; `reset` is clamped to the marker's `created_at`+3900; a newer PAT success outcome → `obsolete`, a PAT `<!-- ai:clarify-rate-limit-replay:v1 run=<run> -->` or `<!-- ai:clarify-rate-limit-escalated:v1 run=<run> -->` after the marker → `already_requeued` (both remove the label); a newer trusted human `/reclarify` keeps the label (`newer_request`); authorization comes from live data only: `event=issue_comment` with `source>0` needs that comment to be a trusted (OWNER/MEMBER/COLLABORATOR) User `/reclarify`, otherwise the live issue `author_association` must be trusted (`untrusted_source` removes the label); before `reset + RATE_LIMIT_REQUEUE_GRACE_SECS` (60) → `waiting_for_reset`, label kept; at `RATE_LIMIT_REQUEUE_MAX_ATTEMPTS` (3) PAT replays since the newest PAT success outcome → adds `ai:needs-human`, posts a comment naming the rate limit with the escalated marker (no line starts with `/`) and removes the label; otherwise posts `/reclarify [auto-requeued-by-poller]` plus the replay marker with the PAT and removes the label. Review gate: `scripts/review_autofix_step_evaluate_gate.sh` calls `_gate_write_rate_limit_marker` only when the PR read exits rc=75, just before `AUTOFIX_GATE_PR_READ_FAILED`; it posts, with `AI_COMMENT_JOB_TOKEN` and `AI_COMMENT_SIGNING_POST=false` (so the author stays `github-actions`), a one-sentence comment ending in `<!-- ai:review-gate-rate-limited:v1 head=<sha|unknown> reset=<epoch> run=<run> -->`; no job token logs `reason=no_job_token`; failures never change the gate's exit. The conflict sweep's existing 30-PR GraphQL batch adds `gate`, `gate_retry` and `gate_escalated` to a `_STANDALONE_ISSUELESS_RETRY_STATE` comment item only when that own-line marker is present, and `run_review_gate_rate_limit_requeue_pass` runs right after `run_issueless_review_retry_pass`. `_review_gate_rate_limit_requeue_decide` is pure: the newest `github-actions` gate marker; a later `unblock_trusted_login` `<!-- ai:review-gate-rate-limit-requeue:v1 run=<run> head=<sha> -->` → `already_requeued`, a later `<!-- ai:review-gate-rate-limit-escalated:v1 run=<run> -->` → `already_escalated`, any other later pipeline comment → `later_review`; then `fork_or_unknown_head`, `draft`, `excluded_label` (`ISSUELESS_REVIEW_RETRY_EXCLUDE_LABELS_JSON`), `head_moved` (a SHA gate head that differs from the current head), `waiting_for_reset`, `escalate` (3 requeue markers for the current head) and `eligible`. Linked-issue PRs are included. Eligible PRs are dispatched through `_dispatch_review_for_conflicts` (default branch, in-flight guard), at most `REVIEW_GATE_RATE_LIMIT_REQUEUE_MAX_PER_CYCLE` (5) per cycle; rc=0 posts the requeue marker, rc=2 is `in_flight`, others `dispatch_failed`. Draft `claude/*` and `orchestrator/project-*` PRs are outside the batch and are not requeued. Tests: `tests/test_rate_limit_requeue.py`.
