- **A manual resume ends an open unblock hold (#8287 review).** Before checking an open hold's condition, `scripts/unblock_judge.sh` runs `unblock_hold_resumed_since <hold created_at>` on the item comments it already read (no API call): a comment created after the hold whose body opens with a slash command (`/reclarify`, `/answer`, ...) from the pipeline login or an OWNER/MEMBER/COLLABORATOR author means someone resumed the item while the hold was open. The hold is then marked `expired` (`outcome=expired reason=resumed`) and the item is judged again, so a later block does not inherit the old hold and wait out `UNBLOCK_JUDGE_WAIT_MAX_DAYS`. The hold comments for `placeholder_retired` (`unblock_hold_resume_hint`) now say the step counts as done only once a repository Actions variable or secret with the placeholder name exists, and that any other step ends when the person does it and posts the item's resume command. `unblock_hold_condition` no longer runs `git grep` for `placeholder_retired`; it only checks that `TARGET_DIR` is a git work tree.
