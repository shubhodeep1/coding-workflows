**Approved heads in the review sweep and the merge wait (2026-11-17, PRs #9239, #9579, #9603).**
- `_pr_head_ci_runs_pending` (`scripts/pr_checks_lib.sh`) compares a run's name with `AUTO_MERGE_WAIT_WORKFLOWS` after stripping a trailing ` [pr:<n>]` or ` [pr:<n>] [sync-quick]` (jq def `_pr_ci_run_name` in `PR_CHECKS_JQ_CI_RUN_NAME_DEF`). The runs API reports a run's run-name as `.name`, so the dispatched final-CI runs (`CI [pr:<n>]`) never bound before and the required `lint` read as `absent` on every final-CI head.
- `_pr_wait_for_required_checks` returns `outcome=timeout reason=final_ci_dispatch_failed` on its first poll when the named CI check is absent, no CI run is pending, and `_pr_ensure_final_ci` ended `dispatch_failed` (refused dispatch, fork head, unreadable head ref). The outcome is the same `timeout` callers already handle; only the wait is gone.
- `scripts/review_sweep_head_gate.sh` (sourced by the sweep's enumerate step from `.ci-rerun-support`): `review_sweep_annotate_head_gate` adds `head_gate_state` to each snapshot row from one paginated GraphQL query (100 PRs per call), only when the read's head oid equals the row's `head_sha`; any failure leaves the snapshot unchanged. `review_sweep_final_ci_state` returns `in_flight|success|failure|none|read_failed` for a head with the same decision as `_pr_ensure_final_ci`. The enumerate step skips the dispatch only for `head_gate_state == "success"` with `failure` (switch `SWEEP_SKIP_APPROVED_FINAL_CI_FAILED`, default `true`); the review run's red-final-CI hand-back (`scripts/review_final_ci_failed.sh`) is unaffected.
- `scripts/review_final_ci_sweep.sh` orders candidates known-success first, counts known non-success heads as `gate_not_success` without a status read or a cap slot, and reads `commits/<sha>/status` only for rows without `head_gate_state`.
- Tests: `tests/test_pr_base_freshness_gate.py`, `tests/test_review_final_ci.py`, `tests/test_review_autofix_sweep_merge_queued_skip.py`.
