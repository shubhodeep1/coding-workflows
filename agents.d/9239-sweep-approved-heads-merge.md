**Approved heads in the review sweep and the merge wait (2026-11-17, PRs #9239, #9579, #9603; the run-name binding itself is #9648).**
- `_pr_wait_for_required_checks` returns `outcome=timeout reason=final_ci_dispatch_failed` on its first poll when the named CI check is absent, no CI run is pending, and `_pr_ensure_final_ci` ended `dispatch_failed` (refused dispatch, fork head, unreadable head ref). The outcome is the same `timeout` callers already handle; only the wait is gone.
- `_pr_final_ci_refused_base_update <pr> <approved head> [<base ref>]` (`scripts/pr_checks_lib.sh`, after `_pr_base_fresh_for_merge`): called from that wait when `_pr_ensure_final_ci` set `PR_FINAL_CI_REASON=dispatch_refused`. It acts only when `PR_BASE_FRESHNESS_OUTCOME` is `clean` for the same head (every wait caller runs `_pr_base_fresh_for_merge` first), the head's `REVIEW_FINAL_CI_WORKFLOW` file declares no `workflow_dispatch` and the base's copy does (two contents reads). It then reuses the freshness overlap path: `_pr_base_sync_for_fresh_ci`, `_pr_base_sync_observe_update_commit`, `_pr_base_sync_marker_post` (with `PR_BASE_SYNC_MARKER_LEAD` naming the cause) and `_pr_base_sync_dispatch_final_ci`. After one update the head carries the base's file, so it runs at most once per PR. Switch `FINAL_CI_REFUSED_BASE_UPDATE_ENABLED` (default `true`).
- `scripts/review_sweep_head_gate.sh` (sourced by the sweep's enumerate step from `.ci-rerun-support`): `review_sweep_annotate_head_gate` adds `head_gate_state` to each snapshot row from one paginated GraphQL query (100 PRs per call), only when the read's head oid equals the row's `head_sha`; any failure leaves the snapshot unchanged. `review_sweep_final_ci_state` returns `in_flight|success|failure|none|read_failed` for a head from `_pr_ensure_final_ci`'s own decision jq (`PR_FINAL_CI_JQ_DECISION_DEF`, `scripts/pr_checks_lib.sh`, which the helper sources). The enumerate step skips the dispatch only for `head_gate_state == "success"` with `failure` (switch `SWEEP_SKIP_APPROVED_FINAL_CI_FAILED`, default `true`); the review run's red-final-CI hand-back (`scripts/review_final_ci_failed.sh`) is unaffected.
- `scripts/review_final_ci_sweep.sh` orders candidates known-success first, counts known non-success heads as `gate_not_success` without a status read or a cap slot, and reads `commits/<sha>/status` only for rows without `head_gate_state`.
- Tests: `tests/test_pr_base_freshness_gate.py`, `tests/test_review_final_ci.py`, `tests/test_review_autofix_sweep_merge_queued_skip.py`.
