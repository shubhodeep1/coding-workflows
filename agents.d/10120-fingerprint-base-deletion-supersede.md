<!-- agents: section="Operational lessons learned (categorised)" -->
- **Fingerprint verifier: a base-branch deletion after capture supersedes a must_contain (#10120).** When `main` deletes a file (for example #9698 folding `lint-pr-body-auto-close.yml` into `pr-checks.yml`) while an integration branch still edits it, the resolver must be able to take the deletion. `_base_deletion_superseding_commit` in `scripts/verify_integration_fingerprints.py` treats the missing file as satisfying `must_contain` only when the history ref (the verified `--ref`; else `MERGE_HEAD` during a merge; else `refs/remotes/origin/$BASE_BRANCH` for a safe branch name) resolves, `git ls-tree` shows the path absent there, and the newest `git log --no-renames --diff-filter=D` commit for the path is dated after `captured_at` and is not an `[ai-merge-resolve]` commit. Everything else fails closed: git errors, a missing ref, a bad `captured_at`, a deletion at or before capture, and a resolver deletion. Baseline capture and both compare modes now pass `captured_at` to `_evaluate_fp_state`. Tests: `tests/test_conflict_one_sided_delete_workflow_path.py`.
