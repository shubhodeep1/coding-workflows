- **Merge-lease soft path class (merge-lease parallel merges Phase 4, Refs #9781).** `MERGE_LEASE_SOFT_PATHS` (default `README.md,agents.md,AGENTS.md,docs/INVENTORY.md,CHANGELOG.md,agents.d/,changelog.d/`, set in `scripts/pr_checks_lib.sh` with `${MERGE_LEASE_SOFT_PATHS-...}` and wired as a repository variable on every freshness and lease step of `review_autofix.yml`, `orchestrate_poll.yml`, `cancel_on_pr_close.yml`, while the final-CI step of `review_autofix_sweep.yml` pins `none` because its base sync treats `clean` and `overlap` alike; empty, `none` or `off` turns it off, but only `none`/`off` from a repository variable) lists paths that never count as overlap on their own. Entries ending in `/` are literal prefixes, others exact paths; glob, absolute and `..` entries are skipped with a `::warning::`. Helpers: `_merge_lease_soft_entries`, `_merge_lease_soft_path`, `_merge_lease_split_soft` (sets `_MERGE_LEASE_HARD_LIST` / `_MERGE_LEASE_SOFT_LIST`).
  - `_pr_soft_merge_tree_probe <own> <other>` wraps `_pr_merge_tree_probe` for both soft branches: a clean merge counts only when every path whose merged content matches neither side (`git diff-tree` of each head against the merged tree) is soft; otherwise the result is `unknown` and `_PR_PROBE_HARD_COMBINED` lists the paths. merge-ort follows renames and git before 2.45 cannot turn that off in merge-tree, so this is what keeps a soft-to-hard rename on one side plus an edit on the other from merging unvalidated. The soft split classifies the real shared paths one per line (never the comma-joined `overlap` display string); a shared path holding a newline fails closed.
  - `_pr_base_freshness`: when every shared path is soft, `_pr_soft_merge_tree_probe <head> <PR_BASE_FRESHNESS_BASE_SHA>` decides. `none` gives `clean` reason `soft_paths_merge_clean`; `conflict` gives `overlap` reason `soft_paths_conflict`; anything else (including no complete base tip) gives `overlap` reason `soft_paths_probe_unknown`. Any shared hard path keeps `shared_paths` with no probe. `PR_BASE_FRESHNESS_SOFT_OVERLAP` holds the shared soft paths. The three `MERGE_BASE_FRESHNESS` lines of `_pr_base_fresh_for_merge` end with `soft_overlap=<paths|->` (appended; earlier fields unchanged).
  - `_merge_lease_paths_intersect <left> <right> [<own_head> <holder_head>]`: with four arguments and the class on, a soft-only intersection with two 40-hex heads is probed; only `none` returns 1 and sets `MERGE_LEASE_SOFT_SHARED`. `_merge_lease_gate` merge mode passes `lease_head` and `MERGE_LEASE_HEAD`, and reports `no_overlap` with reason `soft_paths_merge_clean` (log and metric) in that case. `*`, a hard shared path, a short head or an undecided probe still waits. With the class on, `_merge_lease_pr_paths` (and the `PR_BASE_FRESHNESS_PR_PATHS` cache it reuses) returns `*` when any PR path holds CR/LF or is not a string, so a newline-split name never yields soft fragments; with the class off the list is unchanged.
  - `_pr_merge_tree_probe` and its `_pr_mt_git`, `_pr_mt_git_fetch`, `_pr_probe_repo_init`, `_pr_probe_repo_cleanup` helpers are the shared probe (plan D9), taken from the merge train's `_mt_conflict_probe` (issue #6570) without the ignored-path mapping. The private repository chains its cleanup onto the caller's EXIT trap. The train's `_mt_git`, `_mt_git_fetch`, `_mt_probe_repo_init`, `_mt_probe_repo_cleanup` and `_mt_conflict_probe` are thin wrappers over them when `_mt_probe_via_lib` finds all five `_pr_*` helpers plus `_pr_probe_repo_log` (`declare -F`); their own bodies remain only as the fallback for an older staged library. The wrappers set call-scoped `local` overrides read by `_pr_probe_repo_init`: `_PR_PROBE_DIR_PREFIX` (default `pr-merge-tree-probe`, train `merge-train-probe`), `_PR_PROBE_REPO_SLUG` (default `PR_CHECKS_REPOSITORY`/`GITHUB_REPOSITORY`, train `MT_REPO`), `_PR_PROBE_LOG_PREFIX` (default `PR_MERGE_TREE_PROBE_REPO`, train `MERGE_TRAIN_PROBE_REPO`) and `_PR_PROBE_LOG_FN` (default stderr, train `_mt_log` on stdout), so train logs and directory names are unchanged and lease or freshness callers in the same process never see them. One probe repository serves the process; `_PR_PROBE_DIR_ACTIVE_PREFIX` records its prefix for the EXIT cleanup. `ignored` (`MERGE_TRAIN_IGNORE_PATHS`) stays mapped in `_mt_conflict_probe`. Change the fallback bodies only together with the shared copy.
