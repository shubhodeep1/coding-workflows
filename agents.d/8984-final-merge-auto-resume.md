- **Final-merge auto-resume (issue #8984, `FINAL_MERGE_AUTO_RESUME_ENABLED`, default `true`).** `mark_validation_complete`'s exhaustion path (final merge failed `MAX_FINAL_MERGE_ATTEMPTS` times) writes `final_merge_failure_kind="final_merge_exhausted"`, `final_merge_exhausted_head_sha` (the final PR head `finalize_integration_merge_if_needed` last observed, via the `FINAL_MERGE_LAST_PR_HEAD_SHA` global, or `""`) and `final_merge_exhausted_at_utc`. The marker is cleared on a landed merge, on `/judge_resume` and on the resume itself; only the explicit marker makes a project eligible (legacy parks are never inferred from `final_merge_status=failed`). In the terminal-state block, after the `ai:force-merge` bypass, `maybe_auto_resume_final_merge_exhausted` checks, cheapest first: switch, marker plus `final_merge_status=failed` and none of `ai:validation-failed` / `ai:validate-failed` / `ai:security-pass-failed`, a numeric `final_merge_pr` and an integration branch, a 40-hex `validation_last_passed_sha`, then one PR read (head ref is the integration branch, open, not a draft, head not already in `final_merge_auto_resumed_head_shas`, head equals `validation_last_passed_sha`, `mergeable=true` and `mergeable_state=clean`), `_pr_checks_completed` against the PR base, and `compute_cycle_integration_ahead_by` > 0. On a pass it first persists `status=validating`, `final_merge_status=pending`, `final_merge_attempt_count=0` and appends the head to `final_merge_auto_resumed_head_shas` (last 20 kept), then sets `ai:validated` (dropping `ai:blocked`), removes `ai:needs-human` (the per-tick `needs_human_digest_prune` drops the digest entry), posts one `<!-- final-merge-auto-resume:<sha> -->` tracking comment and calls `mark_validation_complete`, so every existing final-merge gate still applies. A failed retry re-parks normally and no further automatic retry runs until the head changes. Note: `handle_comprehensive_release_callback_if_needed` is unchanged; if the exhaustion-time `failed` callback already marked `.comprehensive_release_callback.handled`, the resumed `complete` callback is skipped as before.
