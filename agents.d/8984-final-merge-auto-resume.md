- **Final-merge auto-resume (issue #8984, `FINAL_MERGE_AUTO_RESUME_ENABLED`, default `true`).** `mark_validation_complete`'s exhaustion path (final merge failed `MAX_FINAL_MERGE_ATTEMPTS` times) writes `final_merge_failure_kind="final_merge_exhausted"`, `final_merge_exhausted_head_sha` (the final PR head `finalize_integration_merge_if_needed` last observed, via the `FINAL_MERGE_LAST_PR_HEAD_SHA` global, or `""`) and `final_merge_exhausted_at_utc`. The marker is cleared on a landed merge, on `/judge_resume` and on the resume itself; only the explicit marker makes a project eligible (legacy parks are never inferred from `final_merge_status=failed`). In the terminal-state block, after the `ai:force-merge` bypass, `maybe_auto_resume_final_merge_exhausted` checks, cheapest first: switch, marker plus `final_merge_status=failed` and none of `ai:validation-failed` / `ai:validate-failed` / `ai:security-pass-failed`, a numeric `final_merge_pr` and an integration branch, no handled `.comprehensive_release_callback` (a comprehensive cycle the exhaustion already ended; skip `detail=comprehensive_cycle`), a 40-hex `validation_last_passed_sha`, a `final_merge_auto_resumed_head_shas` that is absent or an array (any other shape skips with `lookup_failed detail=state` rather than being reset), then one PR read (head ref is the integration branch, open, not a draft, head not already in `final_merge_auto_resumed_head_shas`, head equals `validation_last_passed_sha`, `mergeable=true` and `mergeable_state=clean`), `_pr_checks_completed` against the PR base, and `compute_cycle_integration_ahead_by` > 0. On a pass it first writes `status=validating`, `final_merge_status=pending`, `final_merge_attempt_count=0` and appends the head to `final_merge_auto_resumed_head_shas` (every retried head is kept, so no head is ever retried twice) and publishes that state with `post_state_comment` (a failed publish restores the parked state and skips with `detail=state_write`), then sets `ai:validated` (dropping `ai:blocked`) and confirms it with one fresh label read, because `set_issue_phase_label` also returns 0 on its non-fatal "could not remove label" / "not found" path where the whole edit was rejected; the readiness gate in `finalize_integration_merge_if_needed` keys off that label, so a failed or unconfirmed write restores and republishes the parked state with the head kept in `final_merge_auto_resumed_head_shas` (the head's single try is spent, so a permanent label failure cannot re-run every gate each tick), skips with `detail=label_write` and attempts no merge; the in-memory `TRACKING_LABELS` is taken from that confirmed read, never synthesized, removes `ai:needs-human` (the per-tick `needs_human_digest_prune` drops the digest entry), posts one `<!-- final-merge-auto-resume:<sha> -->` tracking comment and calls `mark_validation_complete`, so every existing final-merge gate still applies. A failed retry re-parks normally and no further automatic retry runs on that head; because only the validated head may merge, a new PR head qualifies only once runtime validation has passed on it (for example after `/judge_resume`), otherwise it logs `validation_stale detail=head_mismatch`. `reason=validation_stale` extends the issue's skip-reason list on purpose (plan decision D3). Comprehensive-cycle projects are skipped because the exhaustion-time `failed` callback already released the cycle freeze tag and removed `ai:comprehensive-test-pending`, so a resumed merge would bypass `comprehensive_promotion_gate_before_final_merge` and the verifying-run dispatch.
