Heal regression plan gate (P3 steps 6-8 of `docs/plans/heal-evidence-reproduction-and-trends-plan.md`, Refs #8434): `scripts/partial_delivery.py heal-regression --plan-file F --issue-body-file B [--trend-flag V]` (function `parse_heal_regression`; `--trend-flag` falls back to `WORKFLOW_HEAL_TREND_ENABLED`, default `false`; only the literal `true`, any case, turns it on) prints `{gate, regression, applies, decision, result, reason, detail, line, unmatched_jobs}`. It applies only when the issue body has an unfenced `## Run-time trend` section whose exact machine line reads `regression=true` (any such section counts, so an injected section can only add a hold). The plan must then carry exactly one unfenced `HEAL_REGRESSION:` line in one of two alternative forms, `HEAL_REGRESSION: <file or commit>` (at least one repo-relative path or 7-40 hex SHA token; a value containing `|` is the template copied literally) or `HEAL_REGRESSION: not a regression: <reason>`; otherwise it holds with `regression_line_missing` (`detail` `no_line`, `duplicate_line`, `empty` or `invalid_target`). A valid line of either form still holds with `budget_only_plan` when the plan's first `## Files likely to change` section names only the failing workflow (`.github/workflows/<name>` or `workflow-templates/<name>`, the name from the trend's first `Workflow `<name>` on` caption; for a numeric workflow id, any single workflow YAML basename) and, outside that section, the plan names at least one `timeout-minutes` / `*_TIMEOUT*` / `PHASE_TIMEOUT` / `*_BUDGET*` knob and no other UPPER_SNAKE identifier than knobs and the gate/switch tokens in `HEAL_RG_CONTEXT_TOKENS`. Companion bullets the heal scope always grants (`tests/**`, `changelog.d/*.md`, `agents.d/*.md`) are ignored in that Files section (the failing workflow must still be listed), and identifiers inside the Decisions, Security considerations, Risks and Testing sections count as context, not another change. A companion path the `HEAL_REGRESSION` line names is kept (a plan that fixes that test file does not name only the failing workflow). A Files bullet is read by its first path-like token (backticked spans first, then words), and an indented sub-bullet without one is skipped. Identifiers on a line that says they stay unchanged (`unchanged`, `as-is`, `do not change`, ...) are mentions, not another change; this can only add a hold. A named target must be a file path (no trailing `/`, letter-initial extension when there is no `/`) or a SHA, and a literal `<reason>` placeholder, backticked or not, counts as empty. Otherwise it passes with `regression_named` or `not_a_regression`; with the switch off it reports `gate=off reason=gate_disabled`, and without `regression=true` `reason=no_regression`. Wiring: the "Auto-approve clear plan" step of `.github/workflows/plan.yml` (env `WORKFLOW_HEAL_TREND_ENABLED: ${{ vars.WORKFLOW_HEAL_TREND_ENABLED || 'false' }}`) runs it on the heal route after the counterfactual gate approves and before the automation-path gate, reading the body from the already-fetched `CURRENT_ISSUE_JSON` (no extra GitHub API call). It logs `AI_PHASE_GATE_V1 phase=plan gate=heal_regression outcome=<approve|hold> result=<REGRESSION|none> reason=<token> issue=<n>`; a hold writes `auto_approve_hold_reason=heal_regression_hold` and posts through `heal_counterfactual_plan_hold` with marker `result=REGRESSION` ("Regression line:"); any parser, body or JSON error holds with `heal_regression_check_unavailable`. A human `/approved` still releases a held plan. Known gap: the poller's stall-recovery check (`_plan_heal_counterfactual_check` in `scripts/orchestrate_poll_process.sh`) does not apply this rule.
