- **Guard-hook template merge resolves several conflicted paired hooks in one pass (#9008).** `_conflict_prepare_guard_hook_template_merge` in `scripts/review_conflict_prepare.sh` takes the live and template paths as optional arguments (defaulting to `GUARD_HOOK_LIVE_PATH` / `GUARD_HOOK_TEMPLATE_PATH`). There is no pair list in the script: `_conflict_prepare_guard_hook_pairs` reads `PAIRED_LIVE_COPIES` from the trusted support checkout (`${SUPPORT_SCRIPTS_DIR}/review_untrusted_workspace.py`) into the per-run `guard_hook_template_pairs.tsv`, in registry order (`pr_merge_status_guard.py`, `prepush_affected_tests.py`, `gh_api_write_guard.py`, `pr_watch_guard.py`, `session-start.sh`). The call site loops over that file, runs the merge for each pair whose live path is in `RESOLVER_ALLOWLIST_FILE`, and recomputes the allowlist after each success. To cover a new hook, add its pair to `PAIRED_LIVE_COPIES` only. `test_pair_source_is_trusted_support_dir_and_paired_live_copies` locks the pair source and shape, and `test_both_paired_hooks_conflicting_are_resolved_in_one_pass` (both in `tests/test_conflict_guard_hook_template_merge.py`) covers two pairs conflicting at once.
