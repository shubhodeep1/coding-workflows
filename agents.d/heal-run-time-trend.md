<!-- agents: section="Workflow architecture" -->
Heal run-time trend (P3 steps 2, 3 and 5 of `docs/plans/heal-evidence-reproduction-and-trends-plan.md`, Refs #8434): behind `WORKFLOW_HEAL_TREND_ENABLED` (default `false`; only the literal `true` turns it on, defaulted in `scripts/workflow_failure_heal_intake.sh` and in both the `intake` and `recovery-scan` jobs of `.github/workflows/workflow-failure-heal-intake.yml`), `_heal_build_run_time_trend` runs after `_heal_run_reproduction` and before the diagnosis and calls `workflow_failure_heal.py run-time-trend`. That subcommand classifies the failure with `classify_failure_shape` (signature, `timed_out` when a job of the current failing run, the payload's first `run_refs` entry, timed out; earlier streak runs do not count, failing tests found) and trends `stall` and `timeout` shapes only; any other shape is `skipped reason=shape_<shape>` with no API call and no section. Targets (`trend_workflow_targets`): the failing run, then the linked runs (`${RUNTIME_DIR}/linked_runs/`), then the issue-linked runs of the evidence pack (`${RUNTIME_DIR}/evidence_pack_api/`, only when `WORKFLOW_HEAL_EVIDENCE_PACK_ENABLED=true`); the workflow is the run path's file name (else the numeric `workflow_id`), with the run's branch and event; other repositories and invalid values are dropped; deduplicated, at most 3. `trend_table` reads per workflow at most 2 single-attempt pages of `GET repos/<repo>/actions/workflows/<file|id>/runs?status=success&branch=<b>&event=<e>&created=>=<now-7d>&per_page=100&page=<n>` (at most 6 GETs per report, counted in `GH_PAT_BUDGET`) and renders per UTC day `n`, median and nearest-rank p90 of `updated_at - run_started_at`. A table is `history=truncated` when the runs read do not reach the window start and more pages exist, or a page could not be read; a truncated table never sets `regression`. Regression (`trend_regression`): the latest day's median is at least `WORKFLOW_HEAL_TREND_REGRESSION_RATIO` (default `1.5`; outside `1.0 < r <= 10` gives `1.5`) times the pooled median of all runs on earlier days; the first slow day is the earliest day whose median, and every later day's median, is at least that ratio times the pooled median of all runs before it, else the latest day. The section `## Run-time trend` follows `## Reproduction` (or the evidence pack) and precedes the diagnosis, inside the body `compose-issue --trend-file` checks with `validate_heal_issue_body_routing`, and carries exactly one machine line `- regression=<true|false> first_slow_day=<YYYY-MM-DD|none> history=<complete|truncated>` (combined across tables: `regression=true` when any complete table regressed, `first_slow_day` the earliest among them, `history=truncated` only without a regression) that the heal plan gate parses; table captions never contain `regression=`, and workflow, branch and event values are cleaned and neutralised. With the switch off the intake makes no call, writes no file and logs no line.
