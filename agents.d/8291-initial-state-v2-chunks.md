The first state snapshot on a new tracking issue is written by the "Build and post initial state" step of `.github/workflows/orchestrate.yml`, not by the poller. It uses the same `ORCHESTRATOR_STATE_V2` chain (`scripts/orchestrate_state_v2.py pack`, one comment per chunk, each payload read from a file). A new tracking issue therefore carries no V1 state comment. The step used to post a single V1 comment with the body passed to `jq --arg`, which failed with `Argument list too long` once the state passed 128 KiB (tracking issue #8291, run 40789524145).
