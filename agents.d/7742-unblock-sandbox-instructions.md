- **Sandbox-aware unblock verdicts (#7742, fun-token-multi-chain#639).** `prompts/mode-judge-unblock.txt` (and its `_templates/` copy) carries an "Implementer environment" paragraph: the implementer and every fix-up run with no network, no git remote, no `origin/*` refs, no GitHub token and no `gh`, cannot install packages, and read the default branch with `git show isolated-base:<path>`. `scripts/unblock_ledger.py validate --sandbox-check` (keyword `sandbox_check=True`, default off, so other callers are unchanged) refuses the `instructions` of `retry_budget`, `descope`, `reissue`, `accept_with_followup` and `operator_step` with `sandbox_incompatible:<id>` on the first match in `SANDBOX_INCOMPATIBLE_PATTERNS` (`git_remote_op`, `git_history_deepen`, `origin_ref`, `package_install`, `http_fetch`, `gh_cli`); `operator_instructions` and `answer` are never checked. `scripts/unblock_judge.sh` passes the flag while `UNBLOCK_INSTRUCTION_SANDBOX_CHECK_ENABLED` is not `false` (default `true`, forwarded by `unblock_judge.yml`). On the first such refusal in a run it asks the model once more with `=== PREVIOUS VERDICT REFUSED ===` and a fixed note between the prompt template and the context JSON, reusing the run-log tail and PR diff (no new API call); `UNBLOCK_JUDGE_REASK_NOTE` is reset at start and never read from the environment. A second refusal, or any other validation failure, falls through to the unchanged `invalid_verdict` wait marker. `MOCK_UNBLOCK_JUDGE_JSON_REASK` (tests only) supplies the re-asked answer. Nothing is written to state.
