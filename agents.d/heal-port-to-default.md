<!-- agents: section="Workflow architecture" -->
Heal port to the default branch (P6 step 2, decision D4, of `docs/plans/heal-evidence-reproduction-and-trends-plan.md`, Refs #8434): the heal pipeline never opens PRs on two branches. Instead, the "Open heal port issue on the default branch" step of `.github/workflows/issue_pr_status.yml` (job `sync-issue-status`, right after "Update linked issue labels when PR closes"; `if:` merged and `github.repository == 'shubhodeep1/coding-workflows'`, `continue-on-error: true`, `timeout-minutes: 3`) runs `scripts/heal_port_to_default.sh`. Consumer callers never reach it: the "Fetch memory helper scripts" step stages `scripts/heal_port_to_default.sh` and `scripts/workflow_failure_heal.py` only in this repository, with `fetch_from_ref_or_local ... "false"` (no main fallback), sets `HEAL_PORT_READY`, and keeps both files out of `_fetched_scripts`, so the consumer `.gitignore` is unchanged; a missing copy logs a warning and the step skips. The switch is `WORKFLOW_HEAL_CODE_REF_ROUTING_ENABLED` (default `false` in the script and the step `env:`; compared case-insensitively to `true`); off means no API call, no git call and no output. Eligibility, checked locally before any call: base `stable`, a default branch other than `stable`, a same-repository head `ai/issue-<N>` (the `heal_fix_branch_issue` rule), and a 40-hex merge commit. API budget (CLAUDE.md §14): one GraphQL read (viewer login, issue `<N>` with labels/body/title, and a search for the port fingerprint), then at most one single-attempt `POST repos/<repo>/issues` with label `ai:workflow-heal`. `workflow_failure_heal.py heal-port` (pure, never calls `gh`): `fingerprint` is `fingerprint("heal-port", "<repo>#<N>", "port-to-default")`; `check` gives `not_heal` (issue missing, or `is_heal_route` false), `not_needed` (a search hit of any state authored by the viewer whose first line is the exact port fp marker and that has an exact `Refs #<N>` line) or `candidate`; `compose` renders the five heal header markers (port fp, parent `gen`/`root`/`classification` when valid), `- **Target branch:** \`<default>\``, `Ported from heal`, merged PR, merge commit, a neutralized diff-stat summary and a final `Refs #<N>` line (no auto-close keyword), runs `validate_heal_issue_body_routing`, then appends a scope marker rendered from the merged diff paths and the parent's shape-checked run refs (exit 3 `scope_unavailable` when that fails). The patch is `git diff <merge>^1 <merge>` from depth-limited fetches, checked with `git apply --check` in a temporary worktree of the default branch tip; it is never applied, committed or pushed, and fetch stderr (which can carry the token URL) is never printed. Rebase-merged PRs are covered only by their last commit. The PR close event fires once, so a failed lookup or fetch is not retried. Every error is a warning; the script always exits 0.
