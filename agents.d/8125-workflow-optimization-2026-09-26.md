Fixes from `analysis/workflow-optimization-2026-09-26.md` (project #8125):

- **Check-failure triage dedup fails closed (#8126).** `scripts/check_failure_triage.sh` files no issue when it cannot read the existing `ai:check-triage` issues. A failed or empty paginated listing, a page that is not a JSON array, or a failed merge of the pages logs `CHECK_TRIAGE error reason=dedup_list_failed fp= pr= check= rc=<gh exit code>` and exits 1. The check runs before the base-branch gate, so such a run fails instead of skipping. An empty listing that was read correctly still files the issue. Historical mode is covered too.
- **Merge-train comment writes report their status (#8127).** `_mt_upsert_comment` in `scripts/review_merge_train.sh` returns the PATCH or POST exit status. The gate logs `merge-train gate: could not upsert the queued comment for PR #<n>; continuing.` and the release step logs its existing released-comment warning. Queue and release decisions are unchanged.
- **Candidate issue details ignore cross-repository PRs (#8128).** `_fetch_candidate_issue_details_graphql` in `scripts/orchestrate_poll_process.sh` takes `linked_pr` only from closing PRs whose `repository.nameWithOwner` equals this repository. That is the same rule `_fetch_linked_pr_status_graphql` uses, and the query reads one more field on the existing call.
- **`ensure_label_exists` caches confirmed labels per process (#8129).** `scripts/label_helpers.sh` keeps `_AI_LABEL_ENSURED_CACHE`, keyed `<repo>|<label>`. A label is recorded only when GitHub confirmed it, either created or already existing. A later call in the same shell returns 0 without an API call. Failed creates are never cached, and subshells do not share the cache.
- **Memory write phase timings (#8130).** `persist_memory_operation` in `scripts/ai_memory_lib.py` returns `clone_ms`, `write_ms` and `push_ms` (`push_ms` is `0` when nothing was pushed) on successful returns only; a failed push raises as before, without timings. `record-run-event` and `record-candidate` copy the timings into their `AI_MEMORY_TELEMETRY` lines and default them to `0`.
