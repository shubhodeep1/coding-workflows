Push CI coalesces per branch, and the readiness check ignores most label events (run-volume plan items 14 and 10, `docs/plans/reduce-actions-run-volume-plan.md`, decisions D14 and D15):

- `ci.yml` push runs (`main`, `stable`, `orchestrator/project-*`) share the concurrency group `ci-push-<ref>` (`format('ci-push-{0}', github.ref)`) with `cancel-in-progress: false`. GitHub keeps one running and one pending run per group, so pushes to one branch run one after another and a newer push replaces the run still waiting. The running run always finishes, so check-failure triage's base gate (`workflow_runs[0]` of the base's push runs) reads a real result. A replaced run ends `cancelled`: `internal-check-failure-triage.yml` and `workflow-failure-heal-intake.yml` act only on `failure` / `timed_out`, and `scripts/ci_cancelled_rerun.py` never re-runs it, because the replaced commit is never a PR's current head. Heal's stale auto-close (`heal_stale_decision` in `scripts/workflow_failure_heal.py`) skips `cancelled` push runs, counting them neither as green nor as red, and sees fewer green push runs, so it can take longer to reach `HEAL_STALE_GREEN_RUNS`. The release CI gate (`scripts/release_ci_gate.sh`) needs `lint` on the exact `stable` SHA: a commit whose `stable` push run was replaced gets none, so a release dispatched for it fails closed after the gate's wait. Pull request, final-CI dispatch and quick runs keep their groups (`ci-pr-<n>`, `ci-final-pr-<n>`, `ci-quick-<run id>`).
- `integration-pr-readiness.yml`'s `readiness` job runs on `labeled` / `unlabeled` only for `ai:override-incomplete-merge`, the one PR label `scripts/check_integration_pr_readiness.py` reads. Any other label change is skipped without a runner; the status already posted for the unchanged head SHA stands, and the poller refreshes it when the tracking issue changes (`TRACKING_BODY_READINESS_REFRESH`). A skipped check run is ignored by the final-merge gate (`scripts/persist_orchestrator.py` `WAVE_CHECK_IGNORED_CONCLUSIONS`) and counts as success-like in `scripts/pr_checks_lib.sh`.
- Tests: `tests/test_ci_concurrency.py`, `tests/test_workflow_failure_heal.py` (stale auto-close) and `tests/test_check_integration_pr_readiness.py`.
