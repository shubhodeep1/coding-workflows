<!-- agents: section="Pre-push affected-test gate" -->
Tree parity (#9672): the gate's PR tree and its merge-base baseline hold the same kinds of files, so a test that reads an image, font or other asset is no longer blamed on every change. `scripts/prepush_test_gate_run.sh` calls `review_untrusted_workspace.py snapshot … --include-tracked-assets` (gate-only; the flag is honoured only as the last argument, and the editor and heal snapshots never pass it). With the flag, a tracked file (`git ls-files`, so staged new files count) that `allowed()` refuses only for its suffix is admitted (`allowed(..., admit_any_suffix=True)` skips only the final `ROOT_FILES`/`SUFFIXES`/`Dockerfile` line; the credential filter, `EXCLUDED`, dot paths, `.claude/commands|docs` admission and the hook/audit-test exclusions still apply). Untracked non-allowlisted files stay out. After the `Makefile` / `.ai/validate.yml` overlay, `review_untrusted_workspace.py prune-gate-baseline TREE MANIFEST [KEEP...]` removes from the `git archive` baseline every entry the same predicate (with the command inventory the snapshot froze) refuses, except the overlay paths: symlinks are unlinked, never followed, and emptied directories are removed. Tests that need a file both trees leave out (top-level dotfiles, `.github/ai/…`, committed `dist`/`build`, symlinks) now fail on both trees and are reported as inherited. `MAX_FILE`, `MAX_FILES` and `MAX_TOTAL` still apply: an over-cap tree fails whole as `snapshot_failed` (unverified), never as a partial tree; a prune error gives `baseline_filter_failed` (unverified).
