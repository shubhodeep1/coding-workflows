Heal scope linked workflows (#8360): for a `workflow_run` report whose verified run is a release or promotion workflow of this repository (`RELEASE_WORKFLOW_FILES`, from the authenticated run `.path`; `heal_scope_linked_workflows_gate`), the linked runs of #8248 also feed the frozen heal scope. `_heal_fetch_linked_runs` in `scripts/workflow_failure_heal_intake.sh` now reads each linked run and its jobs before the freeze (same single-attempt reads, order and `warn linked_run_skipped` reasons; ids that passed go to `${RUNTIME_DIR}/linked_runs/fetched_ids.txt`), and `_heal_scope_linked_paths` runs `workflow_failure_heal.py heal-scope linked-workflow-paths` against `HEAD_SHA` (one `_git_fetch_ownership_refs` fetch when the commit is missing; no REST call). Per run it adds (1) the run's workflow file (`.path`, `@ref` stripped, `^\.github/workflows/[A-Za-z0-9_.-]+\.ya?ml$`), (2) the reusable workflows that file calls in `jobs.<id>.uses:` as `./.github/workflows/X.yml` or `<this repo>/.github/workflows/X.yml@<ref>`, one hop only, and (3) the `scripts/...` paths (`_CRASH_ERROR_PATH_RE`, at most 8 per step) in the `run:` body of the first failed or timed-out step, else the longest step, matched by exact step name in those files. Every path is read at the scope commit with `yaml.safe_load` (600,000-byte cap), must pass `_safe_heal_path` and be a regular file there; at most `HEAL_SCOPE_LINKED_PATHS_MAX` (8) paths are appended to `self_workflows` (after the source run's own paths, still within the 20-path marker cap). The fingerprint, the marker format and `render_heal_scope_marker` are unchanged, and the diagnosis never adds a path. Log: `WORKFLOW_HEAL scope_linked outcome=<added|none|disabled|skipped> paths=<n> runs=<n>`, once per intake. Skip reasons in the helper output: `run_malformed`, `other_repository`, `fork_head` (head repository is another repository), `path_malformed`, `path_unsafe`, `file_missing`, `yaml_unavailable`, `yaml_unreadable`, `uses_foreign`, `jobs_malformed`, `step_unmatched`, `script_missing`, `cache_unreadable`, `cap_reached`, `helper_failed`. A failed lookup adds no path (fail open: today's scope). Files reached only through imports or `source` lines still go through the scope hold and the unblock judge's fix-up issue. `WORKFLOW_HEAL_SCOPE_LINKED_WORKFLOWS_ENABLED=false` (default `true`, set in both intake-workflow jobs and defaulted in the script) logs `outcome=disabled` and leaves `scope_inputs_frozen.json` byte-identical to before.
