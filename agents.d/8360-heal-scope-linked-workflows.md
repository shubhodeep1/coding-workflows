Heal scope linked workflows (#8360): for a `workflow_run` report whose verified run is a release or promotion workflow of this repository (`RELEASE_WORKFLOW_FILES`, from the authenticated run `.path`; `heal_scope_linked_workflows_gate`), the linked runs of #8248 also feed the frozen heal scope. `_heal_fetch_linked_runs` in `scripts/workflow_failure_heal_intake.sh` reads each linked run and its jobs before the freeze (same single-attempt reads, order and `warn linked_run_skipped` reasons; ids that passed go to `${RUNTIME_DIR}/linked_runs/fetched_ids.txt`). `_heal_scope_linked_paths` runs `workflow_failure_heal.py heal-scope linked-workflow-paths` against `HEAD_SHA` (one `_git_fetch_ownership_refs` fetch when the commit is missing; no new REST call).

Per linked run, the scope includes its own workflow file (`.path` without `@ref`), the reusable workflows in this repository called by its `jobs.<id>.uses:` entries (local or repository-qualified, one hop only), and the script paths matched by `_CRASH_ERROR_PATH_RE` in the `run:` body of the first failed or timed-out step, otherwise the longest step (at most `HEAL_SCOPE_LINKED_SCRIPTS_PER_STEP`, equal to `HEAL_SCOPE_LINKED_PATHS_MAX`, existing scripts per step; the rest log `cap_reached`). Step names must match the jobs API exactly. Workflow files are read at the scope commit with `yaml.safe_load` (600,000-byte cap); every added path must pass `_safe_heal_path` and be a regular file at that commit. Linked paths follow the source workflow paths in `self_workflows` and count toward the 20-path marker cap, but at most `HEAL_SCOPE_LINKED_PATHS_MAX` (12, the 20 slots less `HEAL_SCOPE_SUBJECT_RESERVE`) are added, and the scope freeze keeps only as many as fit in the 12 slots the source workflow, engine and crash paths leave free, so failing-test subjects keep their 8 reserved slots (#6907/#6916); `render_heal_scope_marker`, the fingerprint and the marker format are unchanged. The diagnosis adds no paths. Files reached only through imports or `source` lines still go through the scope hold and the unblock judge's fix-up issue.

The intake logs `WORKFLOW_HEAL scope_linked outcome=<added|none|disabled|skipped> paths=<n> runs=<n>` once. Helper skip reasons include `run_malformed`, `other_repository`, `fork_head`, `path_malformed`, `path_unsafe`, `file_missing`, `yaml_unavailable`, `yaml_unreadable`, `uses_foreign`, `jobs_malformed`, `step_unmatched`, `script_missing`, `cache_unreadable`, `cap_reached` and `helper_failed`. A failed lookup adds no path. `WORKFLOW_HEAL_SCOPE_LINKED_WORKFLOWS_ENABLED=false` (default `true`, set in both intake-workflow jobs and defaulted in the script) logs `outcome=disabled` and leaves `scope_inputs_frozen.json` byte-identical to before.
