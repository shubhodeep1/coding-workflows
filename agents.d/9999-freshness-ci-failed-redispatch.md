<!-- agents: section="Workflow architecture" -->
A freshness-update head (only GitHub's merge of an approved head with its base, #7084) skips the reviewers and runs `deterministic-skip-merge`, which waits for CI and merges. When that CI fails, the job runs `scripts/review_freshness_ci_failed.sh` (Q103). It posts a PR comment ending in `<!-- ai:freshness-ci-failed:v1 pr=<n> head=<sha> -->` and dispatches the PR's review workflow (`ai-review.yml` / `internal-review.yml` first, then the caller from `github.workflow_ref`, then `review_autofix.yml`). `scripts/review_head_gate.sh freshness-sync` reviews a head carrying that marker by the workflow's login normally (`reason=ci_failed_on_head`), so autofix sees the failing checks. The gate's existing marker-comments read also loads this marker, so no API call is added. If the comment cannot be posted, nothing is dispatched, because the redispatched run would take the fast path again. `FRESHNESS_CI_FAILED_REDISPATCH_ENABLED=false` turns it off. Before this, PR #7153 kept red CI from 2026-10-11 with nothing to re-run review, and its orchestrator project #6664 waited on it.
