- **Activation verification skips consumer workflow-sync PRs (Q224).** The `activation-verify` job of `issue_pr_status.yml` does not run for a merged PR whose head branch is in the same repository (`head.repo.full_name == github.repository`) and starts with `auto/update-workflows-` or equals `ai-sync/stable`, the two branches the consumer updater (`update_workflows.yml`) delivers through; these PRs only refresh upstream-managed wrappers, so grading them opened activation-gap issues (7 of 34 `ai:activation-fix:v1` issues across the consumers on 2026-10-17) and posted verdict comments that were noise. `scripts/activation_verify.sh pr` repeats the check from the optional `PR_HEAD_REF` and `PR_HEAD_REPOSITORY` inputs (a missing or different head repository verifies as before, so a fork cannot claim the skip) before any GitHub call, and logs `ACTIVATION_VERIFY mode=pr item=<n> outcome=skip reason=workflow_sync_pr sync_branch=<auto/update-workflows-|ai-sync/stable>`. Project mode is unchanged. `prompts/mode-implement.txt` (and its `_templates` twin) carries a "Pinned-SHA test discipline" paragraph telling the implementer not to assert a specific upstream commit SHA in synced files and to assert the `^[0-9a-f]{40}$` shape instead; `tests/test_implement_prompt_pinned_sha_contract.py` pins the wording.
