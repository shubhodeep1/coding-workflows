- Rewrite-refused resend (#9713). When the lease-checked refresh of an existing sync branch is refused because the remote will not let it be rewritten (push output matches `GH013`, `Cannot force-push`, `protected branch hook declined`, `denying non-fast-forward`, or `[remote rejected] ... non-fast-forward`; for example a consumer ruleset with `non_fast_forward` on `~ALL`), `commit_push` pushes its rebuilt commit to the first free `auto/update-workflows-<sha12>-r2` .. `-r5` with an empty lease, opens the sync PR from it with the same title and body, and closes the old PR (only one the `GH_PAT` account opened) with one comment linking the new one. It creates at most one new branch per run, fails with `reason=resend_cap_reached` after `-r5` and with `reason=resend_push_failed` when the new push is refused, and never deletes a branch. Other push failures keep `reason=lease_mismatch_or_push_rejected`. Every run first lists `refs/heads/<branch>-r*` (`git ls-remote`, no API call) and continues on the highest `-r2` .. `-r5` it finds, so the updater-closed base PR does not read as `closed_by_human`. The stale-PR sweep matches `^auto/update-workflows-[0-9a-f]{12}(-r[2-5])?$`. The review pipeline's updater-branch guards (`review_autofix.yml` deterministic-skip merge and push skip, `review_rb_judge.sh`, `review_enable_auto_merge.sh`, `review_autofix_step_detect_merge_conflicts.sh`, `review_commit_changes.sh`) and `audit_consumer_drift.py`'s release check accept the same suffix. Tests: `tests/test_update_workflows_resend_branch.py`.
