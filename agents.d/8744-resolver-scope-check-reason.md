- `RESOLVER_SCOPE_CHECK` — emitted to stderr by the scope-guard heredocs `_resolver_scope_state` and `_resolver_attempt_state` in `scripts/review_conflict_resolve.sh`, only on the exit-2 fail-closed path, as one line placed immediately before the unchanged `::error::Resolver scope <action> failed closed (<ExcClass>).` / `::error::Resolver attempt state unavailable or unsafe: ...` lines. Format: `RESOLVER_SCOPE_CHECK guard=<scope|attempt_state> action=<action|-> reason=<code> exc=<ExceptionClassName> attempt=<int|-> allowed_paths=<int|-> changed_paths=<int|-> merge_state_changed=<true|false|->`. `reason` comes from a hard-coded allowlist (`_SCOPE_CHECK_REASON_CODES`, identical in both heredocs): tagged codes `unsafe_path`, `symlink_parent`, `unsupported_path_type`, `conflicted_paths_missing`, `snapshot_copy_mismatch`, `worktree_changed_during_snapshot`, `merge_state_changed`, `invalid_conflicted_paths_snapshot`, `snapshot_content_mismatch`, `restore_blocked_symlink`, `restore_blocked_directory`, `restore_mismatch`, `unknown_action`, `attempt_snapshot_exists`, `attempt_restore_failed`, `worktree_root_mismatch`, plus fallbacks `os_error`, `key_error`, `type_error`, `json_error`, `subprocess_error`, `unclassified` for untagged exceptions. Tagged raises stay plain `ValueError` (the code rides on a `resolver_scope_reason` attribute), so the existing `::error::` text is byte-identical. `action` is kept only when it matches `[a-z_-]{1,32}`, else `-`; `attempt` is read from the optional `RESOLVER_SCOPE_CHECK_ATTEMPT` env var (default inside the helper: the retry loop's `attempt` counter, else `-`) and kept only as 1-6 digits; counts are integers or `-`. The line carries counts only: never raw paths, file contents or exception text. Building it is fail-open (`except Exception: pass`), so the `::error::` line and `sys.exit(2)` always follow. Pinned by `tests/test_review_conflict_resolve_retry_prelude_render.py`.
