- **Release notes from folded fragments (issue #9846).** The `release` job of `.github/workflows/test-and-mark-stable.yml` and `.github/workflows/mark-stable.yml` runs `scripts/assemble_changelog.py assemble --repo-root . --notes-out "${RUNNER_TEMP:-/tmp}/release_fragment_notes.md"`. `--notes-out` (optional; only these two workflows pass it, never `update_workflows.yml`) writes the bodies of exactly the fragments being folded: `### <Category>` blocks in Keep a Changelog order, or a plain list in date-heading repos. It writes under `--dry-run` too, always rewrites the file (empty when no usable fragment exists), caps it at `RELEASE_NOTES_CHAR_LIMIT` = 120,000 characters at whole-fragment boundaries with a `...and N more; see CHANGELOG.md.` trailer (a first fragment that alone passes the cap is instead cut to the cap, marked `...(truncated; see CHANGELOG.md)` and counted as written), and only warns (`::warning::Could not write --notes-out`, exit 0) when the write fails. The `CHANGELOG_ASSEMBLE_V1:` summary line gains ` notes_written=<n>` only when the flag is passed. "Extract changelog for this version" (`id: changelog`, output `notes_file=/tmp/release_notes.md`, both unchanged) uses, in order: a hand-written `## [vX.Y.Z]` section, the non-empty notes file, then the placeholder `No changelog fragments were folded for vX.Y.Z.` Tests: `test_notes_out_*` in `tests/test_assemble_changelog.py`; `test_release_assembly_writes_fragment_notes` and `test_release_notes_extract_fallback_order` in `tests/test_changelog_fragment_contract.py`.
