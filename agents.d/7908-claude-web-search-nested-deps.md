- **Claude provider web search (tele-funtoken-msg-scoring#4770 follow-up).** `.github/ai/claude_engine.json` `web_search` (boolean, default `true`; any other value keeps the default and is reported as invalid) adds `WebSearch` to the Claude tool list of every profile on all three launch paths: `claude_run` (`scripts/ai_engine.sh` → `codex_isolated_exec.sh run --engine claude --claude-web-search`), `scripts/clarify_isolated_run.sh` and `scripts/review_untrusted_sandbox.sh`. The `read` profile's settings get a matching `WebSearch` allow rule (`claude_engine.py settings --web-search`), since `dontAsk` refuses any tool it does not allow. Each path starts the host broker with `claude_anthropic_relay.py broker … --allow-web-search`, which admits only the tool the pinned CLI 2.1.289 sends: `type` `web_search_20250305`, `name` `web_search`, `max_uses` 1–8, optional `allowed_domains`/`blocked_domains` (≤ 100 entries matching `WEB_SEARCH_DOMAIN_RE`) and `search_profile`, and no other keys. Web fetch, code execution, MCP connectors, a newer search tool version and any other provider tool stay refused; without the flag the relay refuses web search too. The search runs at the provider: every Claude container keeps `--network none`, and `WebFetch` is never added. The system note `scripts/ai_engine.sh` appends to every Claude run follows the same switch: `AI_ENGINE_CLAUDE_WEB_SEARCH_NOTE` (WebSearch available, no web fetch) while it is on, `AI_ENGINE_CLAUDE_NO_WEB_NOTE` while it is off or unreadable, and the clarify, plan and orchestrate prompts defer to that note. The relay requires `max_uses` and matches domains and the search profile with `fullmatch`. Set `web_search` to `false` to turn it off everywhere. Codex is unchanged (`web_search=live` outside implement, `disabled` in implement).
- **Nested Node projects in the dependency phase.** `codex_isolated_workspace.py stage-deps` also stages up to `MAX_NESTED_NODE_PROJECTS` (6) subdirectory Node projects that hold a `package.json` and a lockfile (`package-lock.json` → `npm ci`, `yarn.lock` → yarn, `pnpm-lock.yaml` → pnpm), at most `MAX_NESTED_NODE_DEPTH` (4) levels down, skipping hidden directories, `node_modules`, symlinks, credential-looking paths and projects that already have `node_modules`. Each is staged alone under `.codex-deps/nested/<n>/` (manifest and lockfile only) and listed in `.codex-deps/nested.json` (written only when non-empty). `codex_isolated_exec.sh prepare --deps` copies that list to the host before the install container runs, installs each project with `--ignore-scripts` (after the root Node and Python installs) in the same `--network none` container through `dependency_registry_proxy.py`, then runs `handoff-nested-deps STAGE WORK LIST`, which moves each `node_modules` into the disposable work copy only when no stage directory on the way is a symlink and the listed path is still a safe directory with a regular `package.json` and no `node_modules`. `prep-finalize` records the moved directories as prep roots, so they are never transferred back to the host.
