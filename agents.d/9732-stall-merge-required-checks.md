- **Standalone `attempt_merge` uses the review auto-merge rule (#9732).** `run_standalone_stall_recovery`'s `attempt_merge` arm (`scripts/orchestrate_poll_process.sh`) calls `_standalone_attempt_merge_required_checks` when `_stall_merge_required_checks_enabled` (env `STALL_MERGE_REQUIRED_CHECKS_ENABLED`; unset, empty or `true` is on, `false` or any invalid value is off with a warning for the invalid case). The chain stops at the first refusal: state open, mergeable, 40-hex head, `_pr_base_fresh_for_merge`, `PR_CHECKS_HEAD_REF=<head.ref> _pr_wait_for_required_checks <pr> <head> <base_ref> 0`, then `_orch_squash_merge_bound <pr> <head> auto` without `|| true`. It sets `STALL_MERGE_REFUSAL_REASON` and `STALL_MERGE_CHECKS_IN_FLIGHT`. The arm records `STALL_RECOVERY_EFFECTIVE_ACTION=attempt_merge_refused_<reason>`; a `timeout` with final CI in flight (`PR_FINAL_CI_OUTCOME=dispatched`, `PR_CHECKS_RUNS_PENDING>0` or `PR_CHECKS_LAST_CI_STATE=pending`) does not increment the recovery count, a merge-lease wait keeps `attempt_merge_skipped_merge_lease_wait`, every other refusal increments. With the flag off the legacy chain (two-argument `_pr_checks_completed`, freshness, merge `|| true`) runs unchanged. `REVIEW_FINAL_CI_WORKFLOW` is set in both stall-recovery steps of the reusable `orchestrate_poll.yml` ("Process each tracking issue" and "Run standalone stall recovery without active projects", env parity) as `github.repository == 'shubhodeep1/coding-workflows' && 'ci.yml' || ''`, not in `internal-orchestrate-poll.yml`, which only calls `orchestrate_poll.yml@promote-candidate` and has no poll step.
