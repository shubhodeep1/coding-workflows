- **Standalone `attempt_merge` uses the review auto-merge rule (#9732).** `run_standalone_stall_recovery`'s `attempt_merge` arm (`scripts/orchestrate_poll_process.sh`) calls `_standalone_attempt_merge_required_checks` when `_stall_merge_required_checks_enabled` (env `STALL_MERGE_REQUIRED_CHECKS_ENABLED`; unset, empty or `true` is on, `false` or any invalid value is off with a warning for the invalid case). The chain stops at the first refusal: state open, mergeable, 40-hex head, `_pr_base_fresh_for_merge`, `PR_CHECKS_HEAD_REF=<head.ref> _pr_wait_for_required_checks <pr> <head> <base_ref> 0`, then `_orch_squash_merge_bound <pr> <head> auto` without `|| true`. It sets `STALL_MERGE_REFUSAL_REASON` and `STALL_MERGE_CHECKS_IN_FLIGHT`. The arm records `STALL_RECOVERY_EFFECTIVE_ACTION=attempt_merge_refused_<reason>`; a `timeout` with final CI in flight (`PR_FINAL_CI_OUTCOME=dispatched`, `PR_CHECKS_RUNS_PENDING>0` or `PR_CHECKS_LAST_CI_STATE=pending`) does not increment the recovery count, a merge-lease wait keeps `attempt_merge_skipped_merge_lease_wait`, every other refusal increments. With the flag off the existing chain runs unchanged (the #9715 refusal-recording `elif` chain: two-argument `_pr_checks_completed`, freshness, bound merge, logged as `STANDALONE_STALL_MERGE`). `REVIEW_FINAL_CI_WORKFLOW` is set in both stall-recovery steps of the reusable `orchestrate_poll.yml` ("Process each tracking issue" and "Run standalone stall recovery without active projects", env parity) as `github.repository == 'shubhodeep1/coding-workflows' && 'ci.yml' || ''`, not in `internal-orchestrate-poll.yml`, which only calls `orchestrate_poll.yml@promote-candidate` and has no poll step. Both steps also pass `AUTO_MERGE_REQUIRED_CI_CHECK` and `AUTO_MERGE_WAIT_WORKFLOWS` from the repository variables, so the wait resolves the same required check as the review path. The arm passes `head.ref` only for a same-repository head; with an empty ref the merge chain runs the wait with `REVIEW_FINAL_CI_WORKFLOW` empty, so a fork or deleted-fork head (null `head.repo`, which `_pr_ensure_final_ci`'s own fork check lets through) never gets a final-CI dispatch. Right after sourcing `pr_checks_lib.sh` the poller copies `REVIEW_FINAL_CI_WORKFLOW` into `_OPP_STALL_MERGE_FINAL_CI_WORKFLOW` and unsets it, so every other caller of the shared helpers (noop-suspicious gate D, the base-freshness branch update, the flag-off chain) keeps its pre-#9732 no-dispatch behaviour; only `_standalone_attempt_merge_required_checks` passes the captured value, by prefix assignment, to its `_pr_base_fresh_for_merge` and wait calls.
