<!-- agents: section="Workflow architecture" -->
**Workflow log collection coverage (project #9116, P3).** `scripts/collect_workflow_logs.py` writes an additive top-level `coverage` object into `workflow_log_report.json` (and the `--log-output-dir` `summary.json`): `repositories_requested` (order-preserving dedupe of `--repo`), `repositories_failed` (`[{"repository", "message"}]`, message passed through `_sanitize_diagnostic_text` and cut to `COVERAGE_MESSAGE_MAX_CHARS` = 300; the raw text stays in `errors[]` as before), `repositories_truncated` and `page_limit_reached`. A repo is failed when its run listing raised at the repo level (on the PAT-budget path: when every per-workflow listing failed); it is truncated when the listing hit `--max-runs`, the page limit, or on the PAT-budget path when any per-workflow listing raised, capped or hit the page limit. Failed and truncated are disjoint. `build_report(..., coverage=None)` adds the key only when supplied; `schema_version` is unchanged. Exit codes are unchanged (1 only when every repo failed). The `collect` step captures the collector's exit code, runs the block between `# --- collection coverage (P3) begin ---` and `# --- collection coverage (P3) end ---` (fail-open `jq`; prints `WORKFLOW_LOG_COLLECT_COVERAGE`, one `::error title=Workflow log collection::` per failed repo and one `::warning title=Workflow log collection::` per truncated repo; writes outputs `coverage_failed_count`, `coverage_truncated_count`, `coverage_failed_repos`, `coverage_truncated_repos`), then `exit "${collect_rc}"`. Step `coverage_alert` ("Alert on workflow log collection gaps", after the artifact uploads, `always()`, `continue-on-error: true`, skipped on the `0 6 * * *` PAT-budget schedule) sends one Telegram message at WARNING through `scripts/tg_helpers.sh`, so `ALERT_MSG_LEVEL=SILENT` holds it back; `TG_BOT_SECRET` never shares a step with `GH_PAT`. Annotations, the log line, outputs and the alert carry only regex-validated repo names and counts. `scripts/analyze_workflow_logs.py` `prepare_analysis_context` copies a normalized `coverage` into `analysis_context.json` only when the collector supplied one, and `prompts/mode-workflow-analysis.txt` (and its template) require every failed or truncated repo to be named in `## Executive Summary`. Contract tests: `tests/test_workflow_log_analysis_failure_contract.py`, `tests/test_collect_workflow_logs.py`, `tests/test_analyze_workflow_logs.py`. Refs #9116.
