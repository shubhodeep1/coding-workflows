- **Unblock judge closes nothing-to-implement issues after their fix-up (#8470).** When a fix-up wait ends (merged, or closed as already implemented) and the judge would post the stop's resume command, it first checks the item comments it already read (no API call). If the item is a standalone issue (no tracking issue) at stop `blocked`, and the newest comment from the pipeline login that opens with `Planning blocked: human input required.` has the line `Reason: work is already on the planning ref; nothing to implement`, the judge posts one comment ending in `<!-- ai:unblock-nothing-to-implement:v1 item=<n> fixup=<f> -->` (not posted again when a trusted copy exists), adds `ai:closed`, closes the issue as completed and marks the wait `done`. Resuming such an issue with `/answer` only stopped planning again: #8470 blocked twice, before and after fix-up #8471. A failed write keeps the wait open, so the next scan retries. The protected-path handoff and the operator-step hold still run first; orchestrator items and every other reason resume as before. `UNBLOCK_NOTHING_TO_IMPLEMENT_CLOSE_ENABLED=false` (default `true`) restores the resume. At most three writes, no reads.
