**Stable rollback and hold (issue #9342).** `.github/workflows/rollback-stable.yml` (`workflow_dispatch` only; inputs `target_version` (blank = automatic), `reason` (required, at most 200 characters) and `dry_run`; concurrency group `stable-rollback`; kill switch `STABLE_ROLLBACK_ENABLED`, default `true`) runs `scripts/rollback_stable.sh`. It refuses any dispatch ref other than `refs/heads/main` / `refs/heads/stable`, and it refuses any target that is not lower than the current stable version, is in another major, is not reachable from `origin/stable`, or whose GitHub Release lacks an uploaded `sync-manifest.json` **and** `release-manifest.v1.json`. A release lookup error stops the run; it never falls through to an older release. Order: hold first → cancel queued or running `auto-release-stable.yml` / `test-and-mark-stable.yml` / `mark-stable.yml` / `promote-main-to-stable.yml` runs and wait for them to stop (`STABLE_ROLLBACK_CANCEL_WAIT_SECS`, default 300) → set the hold again → `git tag -f stable|v<MAJOR> refs/tags/<target>` pushed with the copied `publish_tag_with_remote_verification` (keep it in step with the release job's copy) → `coding-workflows-stable-released` to each valid `.github/ai/consumer_repos.json` entry. It is idempotent per tag, a blank target while a hold for the current version is active re-confirms that version, and the `stable` branch is never written.
- Hold: `scripts/stable_hold.sh read|set|clear`, `stable-hold.json` (schema `stable_hold.v1`) on the orphan branch `ai/stable-hold` (`STABLE_HOLD_BRANCH` / `STABLE_HOLD_FILE`). Writes go through the contents and git-data API with `github.token` (no workflow is triggered, and the branch only moves forward). `read` prints `active <v>`, `inactive` (404, or `active=false`) or `unknown` (any other error or schema mismatch).
- Readers fail closed: `scripts/auto_release_stable.sh` (right after its kill switch) and `scripts/promote_main_cycle.sh` (right after its kill switch, before guard 1 and any pinned-mode freeze) skip on `active` and on `unknown`. Their test mocks must answer the hold contents path, by default with a 404 (`inactive`).
- Clear: the `release` jobs of `test-and-mark-stable.yml` and `mark-stable.yml` run the step "Clear stable rollback hold" directly after "Tag version and update stable pointer", with the same `if:`. A failure only warns. A poller-dispatched `promote` run is a deliberate release and is not gated.
