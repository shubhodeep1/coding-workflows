<!-- agents: section="Workflow architecture" -->
**A red final CI goes to repair, not to a judge `merge` (issue #10063, Refs #9669).**
- Gate (`scripts/review_autofix_step_evaluate_gate.sh`, final-CI repair decision): a trusted hand-back marker for the head now is any of `ai:final-ci-failed:v1`, `ai:freshness-ci-failed:v1` (a base-update head, the PR #9679 root cause) and `ai:final-ci-repair-request:v1` (posted by the review-blocked judge). Trust is unchanged: the `GH_PAT` login, or `github-actions[bot]` of type `Bot`. The judge's request also stands in for the `ai-review/head-gate` success (`approval=judge`, no statuses GET) and is exempt from `already_reviewed`; `head_cap` (one attempt per head) and `pr_cap` (two repaired heads per PR) still apply. An `orchestrator/project-*` base qualifies (only an `orchestrator/project-*` head is excluded), and used-up `MAX_AUTOFIX_ITERATIONS` / `MAX_REVIEW_BLOCKED_RETRIES` are not read. The request marker is kept by `gate_fetch_marker_comments`, re-arms the terminal same-head skip (`reason=final_ci_failed`) and the clean same-head skip (`reason=final_ci_repair_request`), and suppresses a deterministic skip (`AUTOFIX_GATE_DET_SKIP_SUPPRESSED reason=final_ci_failed`).
- Judge (`scripts/review_rb_judge.sh`, block `rb-judge red-check repair (#10063)`): `render_review_rb_ci_failures_file` turns `PR_CHECK_RUNS_CONTEXT_FILE` into the untrusted prompt section `CI FAILURES ON THE JUDGED HEAD` (only when its `head_sha:` is the judged head; at most 10 jobs, 5 failed steps and 20 test ids per job, 15 error lines of 300 characters; test ids from `workflow_failure_heal.py heal-scope failing-tests`; at most 3 `GET actions/runs/<id>/jobs?filter=latest` for step names; fails open). Step output `judge_ci_failure_summary` holds names and test ids only (500 characters). The snapshot's `log_tail (N chars):` block is consumed as exactly N characters of log text, so a log line shaped like a snapshot header sets no field. With the switch off, nothing is rendered or read.
- Where the merge path sets `RB_MERGE_STATUS=checks_failed` (`merge`, and the final `fix` treated as merge), and where `merge_with_followup` is refused with no check pending and failed check-runs listed for the judged head (`judge_skip_reason` is then the new status instead of `blocking_check_runs`), `rb_judge_route_red_checks` runs: with no request for the head, no repair marker for the head and fewer than 2 repaired heads, it posts a comment ending in `<!-- ai:final-ci-repair-request:v1 pr=<n> head=<sha> -->` and dispatches a review run through `freshness_ci_failed_dispatch_review_workflow` (`judge_merge_status=final_ci_repair_requested`); otherwise, or with `FINAL_CI_REPAIR_ENABLED=false`, it posts one comment ending in `<!-- ai:final-ci-handover:v1 pr=<n> head=<sha> -->`, adds `ai:needs-human` to the linked issues (the PR without one) and the alert step sends one ERROR (`final_ci_handover`). Hand-over and request markers count only from the Actions bot (`github-actions[bot]`, GraphQL `github-actions`, `app/github-actions`) or the `GH_PAT` login, repair markers only from the `GH_PAT` login (the gate's rule); one `GET /user` runs only when a non-bot author must be checked. A trusted request younger than 180 minutes with no repair marker for the head is a repair in flight (`final_ci_repair_requested`, no post). When the dispatch fails, the posted request is deleted so the next run asks again. With `ENABLE_AUTO_MERGE=false`, the `merge` and final `fix` branches call `rb_judge_manual_merge_red_check` before the head-gate success: when the snapshot lists failed check-runs for the judged head, one `_pr_checks_completed` read runs, and a failed required check with nothing pending routes the same way (no head-gate success, no `ai:ready-to-merge`); otherwise `manual_merge_required` is unchanged. Comments read incomplete, a failed post or a failed dispatch keep `checks_failed`. Before the LLM call, a trusted hand-over for the judged head ends the run with `judge_skip_reason=final_ci_handover_posted` and no alert.
- Switch `RB_JUDGE_RED_CHECK_REPAIR_ENABLED` (default `true`; `false` keeps the `checks_failed` page).
- Tests: `tests/test_review_rb_judge_red_check_repair.py`, `tests/test_review_autofix_clean_same_head_gate.py`.
