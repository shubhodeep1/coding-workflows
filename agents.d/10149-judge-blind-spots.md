<!-- agents: section="Workflow architecture" -->
- **Judge blind spots: queued review runs and an issue's open PR (#10149, re-implementation of #9546).** Stall judge (`invoke_stall_judge` in `scripts/orchestrate_poll_process.sh`): with `STALL_JUDGE_LIVE_REVIEW_RUNS_ENABLED` (default `true`) and an open linked PR, one `gh run list --branch <head_ref> --limit 100` (fails open) adds the branch's review-family runs (the five names `_direct_inflight_review_run_on_branch` uses) to `recent_review_workflow_outcomes` (each entry gains `head_sha`; up to 5, newest first) and sets the diagnostics boolean `review_waiting_for_runner` when a run of the current head is `queued`/`waiting`/`pending`/`requested` and not older than the wedged-queued cutoff (`zombie_queued_jq_def`, applied to all four statuses). While it is true, an effective `escalate_human` or `close_and_reissue`, and the judge's own `escalate_human` whatever ladder action it normalizes to (`ENABLE_STALL_HUMAN_TERMINALIZATION=false`), is held: the judge comment posts with `(held: review_waiting_for_runner)`, nothing is dispatched, `STALL_RECOVERY_EFFECTIVE_ACTION=<action>_held_review_waiting_for_runner` and the function returns 1 (the owner-hold precedent; never mapped to `skip`, which can close the PR). The judge-failure and unparseable-output fallbacks hold an `escalate_human` or `close_and_reissue` ladder action the same way. Switch off: outcomes and diagnostics are unchanged. Unblock judge (`scripts/unblock_judge.sh` `unblock_linked_open_pr`): with `UNBLOCK_JUDGE_LINKED_PR_ENABLED` (default `true`), an issue item's open PR on this repository's own `ai/issue-<n>` branch is written to `linked_pr.json` (`{}` when none, on a failed read, or for a fork's PR); its number joins the fingerprint evidence as `linked_pr`, its diff goes under the PULL REQUEST DIFF header, the context carries `linked_open_pr` (`null` when none), and `unblock_ledger.py validate --linked-pr-file` refuses `retry_budget` and `reissue` with `linked_open_pr:<n>`, which gets one re-ask (sharing the sandbox re-ask's single pass) before the invalid-verdict handling. Switch off: no lookup, context and fingerprints unchanged.
