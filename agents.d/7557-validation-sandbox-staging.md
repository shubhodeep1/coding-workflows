- **What the screened copy contains (staging note).** `STAGE_PY` in `scripts/validation_harness_sandbox.sh` lists names with `git ls-files -z --cached --others --exclude-standard`, so untracked files that `.gitignore` / `.git/info/exclude` do not ignore are staged too (for example the `scripts/run_validation_repo_checks.sh` stub that `scripts/validation_template_bootstrap.py` seeds untracked, which compose healthchecks wait for); ignored files stay out. Every name is still screened by `codex_isolated_workspace.readonly_allowed`, which is unchanged because agent sandboxes share it. Staging alone admits two kinds of files that predicate refuses, only when git lists the name (the `validation/` walk can add ignored files, which never get these admissions) and every parent directory passes it:
  - env templates with the exact basenames `.env.example`, `.env.sample` and `.env.template`, in any directory; `.env`, `.env.local`, `.env.production` and every other `.env*` name stay dropped;
  - `.npmrc` in any directory, only when it is a regular file (not a symlink), at most 64 KiB, valid UTF-8 without NUL bytes, and no line (stripped, lower-cased) starts with `//` (a scoped `//host/:` key), contains URL userinfo (`://…@`), contains any of `_authtoken`, `_auth`, `_password`, `password`, `username`, `email`, `certfile`, `keyfile`, `cafile`, `token`, `secret`, `${` or `-----begin`, or has the key `cert`, `key`, `ca` or `otp`. The file is read once with `O_NOFOLLOW` and those exact bytes are staged.

  `*.pem`, `*.key`, `.config/`, `secrets/` and the other exclusions are unchanged. Each admission logs `VALIDATION_HARNESS_SANDBOX phase=stage outcome=ok reason=env_template_admitted|npmrc_admitted path=<name>`, each env template that is not a regular file (a symlink) logs `outcome=skip reason=env_template_not_regular path=<name>`, and each dropped `.npmrc` logs `outcome=skip reason=npmrc_credential|npmrc_symlink|npmrc_too_large|npmrc_undecodable|npmrc_not_regular|npmrc_changed|npmrc_unreadable path=<name>`; file content is never logged. In `validate.yml` the untracked files now include the workflow support files staged into the consumer checkout (`scripts/`, `prompts/`, `workflow-templates/`, `ai-memory/schemas/`), which the harness also saw when it ran on the host before the sandbox. Tests: the `test_stage_copy_*` cases in `tests/test_validation_harness_sandbox.py`.
