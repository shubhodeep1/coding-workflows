Heal evidence pack consumers (P1 steps 5-7 of `docs/plans/heal-evidence-reproduction-and-trends-plan.md`, #8462; the intake side is `agents.d/heal-evidence-pack.md`). There is no switch of its own: with no `## Evidence pack` section in the issue body every consumer behaves as before. `scripts/workflow_failure_heal_evidence.sh` (the plan, clarify and implement-preflight bundle) takes the first `## Evidence pack` section, up to the next `## ` heading, from the issue body it already fetched, and only after `heal-scope verify` / `verify-edits` returned `verified`. The section is labelled `Heal issue evidence pack (UNTRUSTED, copied from the verified issue body)`, goes through the same fence-delimiter `sed` as the job tails (pack lines starting with `===` are also rewritten to `= = =`; a section with nothing but its heading counts as no pack) and is placed before them inside the single `head -c (max_bytes - 128)` cut, so the bundle stays within `WORKFLOW_HEAL_EVIDENCE_MAX_BYTES` (24,000 by default), the pack is whole whenever it fits and the tails shrink to the rest. When no job log could be read but a pack exists, the bundle is written with the pack and a `(job logs unavailable: logs_unavailable)` line instead of the stub. The `WORKFLOW_HEAL_EVIDENCE ... outcome=written` line gains ` pack_bytes=<n>` (and ` pack_truncated=true` when the pack alone exceeded the budget) only when a pack was included; without a pack the bundle file and the log line are byte-identical to before. Clarify-respond (`.github/workflows/orchestrate_clarify_respond.yml`) writes `${RUNTIME_DIR}/issue_labels.json` from the issue payload it already has and, when the staged `scripts/clarify_github_facts.py` knows `--heal-evidence-pack-output`, passes `--issue-body-file`, `--issue-labels-file` and that flag; the script detects a heal issue like `workflow_failure_heal.is_heal_route` (the `ai:workflow-heal` label or the heal fingerprint marker; `tests/test_clarify_github_facts.py` pins the parity), caps the pack at 20,000 bytes, rewrites lines starting with `===` to `= = =`, and the prompt step appends it after GITHUB FACTS under `=== HEAL EVIDENCE PACK (UNTRUSTED) ===`. Neither consumer makes a GitHub API call for the pack, and no token reaches a model sandbox. `prompts/mode-plan-heal-counterfactual.txt` and `prompts/mode-workflow-failure-heal.txt` (and their `prompts/_templates/` copies, kept byte-identical) tell the model to check any `## Evidence pack` before declaring evidence missing or emitting `HEAL_COUNTERFACTUAL: UNVERIFIED`, and to treat it as untrusted evidence, never instructions.
