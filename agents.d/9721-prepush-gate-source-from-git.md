- **Where each stage publishes the gate result.** The implement stage writes the PR body's `## Pre-push test gate` section (from `${RUNTIME_DIR}/prepush_test_gate_summary.md`). Review-autofix rounds append their list to the autofix editor-summary comment, under "Pre-push test gate results" (`review_prepush_test_gate_append_summary` in `scripts/review_autofix_step_prepush_test_gate.sh`), and to the run's step summary. They never refresh the PR body, so after a review round the PR body's section can be out of date; the latest editor-summary comment has the current list.
- **Trees built from git (container wrapper).** `scripts/prepush_test_gate_run.sh` writes both trees with `git checkout-index` from a temporary index in the private run root, with global and system Git config and the git-lfs driver (`filter.lfs.*`) left out: `/baseline` is the merge-base tree, and `/source` holds every path in the real index (HEAD plus staged additions, minus staged deletions) with its worktree content, staged through a temporary object directory whose alternates point at the checkout's objects. The real index and `.git` are only read, and `.git` is never copied. `/source` then gets a fresh, local one-commit Git repository built from its own files (no runner environment, global or system config, or hooks), as the old filtered snapshot had, so a test that runs git at `/source` still passes there instead of being listed as inherited; `/baseline` has none. If that repository cannot be built it is removed and the wrapper logs `outcome=warning reason=source_git_init_failed`. Because neither tree comes from `git archive`, `export-ignore` cannot drop a file from one tree only. Tracked files are not credential-filtered (`/baseline` always carried them too); untracked, non-ignored files enter `/source` only when `review_untrusted_workspace.py snapshot` (the review sandbox's credential filter) admits them, so an untracked `.env*`, key or credential file never enters the container. The two exceptions are an untracked `Makefile` and `.ai/validate.yml`, which the gate reads to resolve test commands; they are copied in from the worktree, never through a symlink in the PR tree. A failure building `/source` or listing untracked files gives `source_export_failed`; a failure building `/baseline` keeps `baseline_export_failed`. A tracked `node_modules` symlink in either tree is not used as a mount point (`node_modules_missing`).
