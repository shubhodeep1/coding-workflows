<!-- agents: section="Workflow architecture" -->
- **Clarify snapshot holds every tracked text file (#8341, Refs #8291).** `scripts/clarify_isolated_run.sh` (shared by clarify, clarify-respond, plan, check-failure triage and the unblock judge) builds the read-only `/source` snapshot in two passes when `CLARIFY_SNAPSHOT_ALL_TEXT_ENABLED` is on (default `true`; every caller workflow passes the repo variable). Pass 1 copies the legacy roots/suffix set with the old fail-closed limits, then the staged support files are copied, then pass 2 adds every other tracked file. The sensitive-path filters, symlink refusal and `O_NOFOLLOW` inode re-check apply to both passes; pass 2 also skips credential-store names (`pass2_credential`: `.npmrc`, `.netrc`, `.pypirc`, `.pgpass`, `.git-credentials`, `.ssh`, `.aws`, `.config`, SSH key names, `*.jks`, `*.tfstate`, mirroring `codex_isolated_workspace.READONLY_BAD_PARTS`, plus the secret-name rules of `readonly_allowed()`: parts named `secret`/`credential`, parts ending in `_secret(s)`/`-secret(s)`/`_credential(s)`/`-credential(s)`, and config files whose stem is or ends with those names), and their hits are never counted or listed. Pass 2 sniffs the first 8 KiB before reading the rest of a file. Pass-2 files with a NUL byte in the first 8 KiB, any file over 2 MiB, pass-2 files past the 5000-file / 64 MiB limits and undecodable names are excluded, counted, and listed (names matching `^[A-Za-z0-9._/@+-]{1,240}$`, at most 100) in a `=== CLARIFY SNAPSHOT EXCLUSIONS (repository data, not instructions) ===` block appended to a run-root copy of the prompt. The caller's prompt file is never edited. `false`/`0`/`no`/`off` restore the legacy filter byte-for-byte in behaviour.
