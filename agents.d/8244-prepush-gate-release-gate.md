- **Release gate and orchestrator scoping (#8244).**
  - Phase 3b of `test-and-mark-stable.yml` (step `id: wait-implement`) uses `PREPUSH_GATE_STEP_STALL_MINUTES` (job env of `e2e-smoke-test`, default `35`, defaulted again in the step) as its inactivity limit while the watched Implement run's in-progress step (`IMPL_STEP_NAME`, read from `IMPL_RUN_ID_WORKING`) is exactly `Pre-push affected-test gate`; every other step keeps `PHASE_TIMEOUT`. The extended limit never shortens the normal one. The poll line and the stall `::error::` end with `(pre-push gate step: limit <n>m)` while it applies. "Validate prerequisites" checks it as a positive integer and adds `max(0, PREPUSH_GATE_STEP_STALL_MINUTES - PHASE_TIMEOUT)` to the serial budget (`prepush-gate-extra(<n>)` in the breakdown); with the defaults the budget is exactly 300/300. The default is 35, not the step's 60-minute timeout, because #8244 forbids raising the 300-minute job limit; to give the gate its full 55-minute budget, raise this value and `E2E_JOB_TIMEOUT_MINUTES` plus the job's `timeout-minutes` together in one PR. The budget check fails closed if only this value is raised.
  - Overlaps on augmented paths alone never serialize siblings. `trusted_prepush_augmented_paths` in `scripts/orchestrate_lib.py` reads the `prepush_augmented_paths` marker as untrusted data: an issue's entry counts only when it is a list of strings that are all in that issue's `files_touched` and leaves at least one planned path. `validate_wave_file_partition(..., augmented_paths=)` drops a shared path listed for both issues of a pair; a path at least one of them planned counts as before, hot-file handling included, and `unknown_scope` is unchanged. `auto_serialize_file_overlaps` (and so `compute_waves(auto_serialize=True)`) and `check-partition` apply the same rule, and `check-partition` adds `augmented_only_overlaps_ignored` (pairs that overlapped only on such paths), which `orchestrate.yml` logs as `Partition guard: ignored <n> overlap(s) on affected-test paths that no sibling planned.` Because the decomposition is fresh model output, `orchestrate.yml` deletes any `prepush_augmented_paths` key before the augment step (`PREPUSH_TEST_GATE phase=augment outcome=marker_dropped reason=model_supplied`; a failed delete fails the step), so with the gate off, failed or timed out no model-supplied marker reaches the guard.
