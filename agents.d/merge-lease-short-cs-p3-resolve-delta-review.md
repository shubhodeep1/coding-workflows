- **Resolution-only review of a conflict-resolver head (issue #10169, Phase 3 of `docs/plans/merge-lease-short-critical-section-plan.md`, decision D4; Refs #10097).** After "Push all pending commits" in `review_autofix.yml` pushes the resolver's `[ai-merge-resolve]` commit, a one-line call runs `_pr_merge_resolve_marker_post` (`scripts/pr_checks_lib.sh`). It posts one comment ending in `<!-- ai:merge-resolve from=<pre-resolution head> resolve=<new head> base=<base tip> -->` through the same single-attempt comment path as `_pr_base_sync_marker_post`, and only when `CONFLICT_RESOLVED=true`, the pushed HEAD has exactly two parents, `HEAD^1` is the run's starting head (`LOCAL_HEAD_SHA`), its subject starts with `[ai-merge-resolve]`, and that head's newest `ai-review/head-gate` status is a `success` posted by the `GH_PAT` login. Autofix commits around the resolution or a push-retry merge fail these checks, so no marker is posted. On the synchronize run, the gate (`scripts/review_autofix_step_evaluate_gate.sh`, after the final-CI repair delta block) runs `scripts/review_head_gate.sh merge-resolve <repo> <pr> <head> <base ref> <login> <comments file>` when a marker names the head. The helper accepts the head only when all of these hold: the newest trusted marker has `resolve=<head>` as the comment's final line; the parents are exactly `[from, base]`; the committer or author is `codex-bot`/`claude-bot` at `users.noreply.invalid`; `from` has a pipeline head-gate `success`; and `compare/<base>...<base ref>` is `ahead` or `identical`. It then writes the gate output `review_remerge_head=<head>`, but only when set, so with the switch off the outputs are unchanged. `scripts/review_autofix_step_generate_diff_context.sh` builds `LAST_RUN_DIFF`, its file list and its stat from `git show --remerge-diff --format=` (fetching both parents and deepening until their merge base is present). It falls back to the normal diff on an empty diff, a git error, git older than 2.36 or a head other than HEAD. `PR_DIFF_FILE`, `PR_CHANGED_FILES_FILE`, the panel, the editor and the head-gate posting are unchanged. `single_pass_base_sync_carry` (`scripts/review_single_issue_security_pass.sh`) verifies the head again after the freshness check refuses it. A verified head whose `from` is clean is never released without an audit: it skips with `merge_resolve_audit`, which also skips the inheritance walk, and is dispatched as a delta audit since `from`. In `_pr_wait_for_required_checks`, `_pr_merge_resolve_final_ci_quick` sets `PR_FINAL_CI_SYNC_QUICK=true` only when all of these hold: the head is still `REVIEW_REMERGE_HEAD`; the `ci_sync_quick.sh delta-supported` probe passes; `MERGE_BASE_SYNC_DELTA_CI_ENABLED` is on; and `full-ci-green` passes for `from`. Any commit on top gets the full review and the full run. Rollback: `MERGE_RESOLVE_DELTA_REVIEW_ENABLED=false`. `tests/test_merge_resolve_delta_review.py` covers it.
