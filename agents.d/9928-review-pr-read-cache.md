<!-- agents: section="Workflow architecture" -->
- **Run-local PR read cache (issue #9928, GH_PAT budget part E).** `gh_pr_cached_read <kind> <repo> <number> [<head_sha>]` in `scripts/gh_helpers.sh` (kinds `pull`, `issue_comments`, `reviews`, `review_comments`, `files`, `check_runs`) fetches each PR resource once per job and head SHA into `${RUNNER_TEMP}/gh_pr_read_cache/` (mode 700), under one flock per entry so concurrent reviewer subshells make one call. `pull`, `check_runs` and entries with no head SHA expire after 120 s; a non-open `pull` payload is never stored. Every cache error falls back to a live read; `REVIEW_RUN_READ_CACHE_ENABLED=false` (job env from the repo variable, default `true`) turns it off.
  - **Eviction:** `gh_retry`, `gh_retry_to_file` and `gh_api_retry` call `_gh_pr_cache_evict_for_cmd` after every attempt, so a PR write through them (`gh api` non-GET on `repos/<o>/<r>/(issues|pulls)/<n>…`, a GraphQL mutation, `gh pr|issue edit|comment|close|reopen|merge|ready|review|lock|unlock`) evicts that PR's entries; the push step calls `gh_pr_cache_evict` after a successful push, and `_pr_base_sync_marker_post` in `scripts/pr_checks_lib.sh` evicts `issue_comments` after its single-attempt marker POST. Other bare `gh api` writes outside the wrappers do not evict (the final-CI marker POST in `scripts/review_autofix_step_prepush_test_gate.sh` is one); keep new PR writes in the review job on the wrappers, or follow them with `gh_pr_cache_evict`.
  - **Read sites:** codex-agent's "Check PR state", `scripts/review_collect_pr_metadata.sh` (pull, comments, reviews, review comments), the reviewer pre-flight fallback in `scripts/review_run_reviewers.sh`, and the `_pr_base_freshness` files read and `_pr_base_sync_count` comments read in `scripts/pr_checks_lib.sh`. The `pr_checks_lib.sh` sites use the cache only when `GH_PR_READ_CACHE_JOB` is non-empty (set to `codex-agent` in that job's env), so the orchestrator, sweep and other callers keep live reads.
  - **Merge invariant:** `scripts/review_enable_auto_merge.sh` never reads through the cache: its `pulls/N` reads (the top-level read before `gh pr merge --auto`, and the label-authorisation head read in `reviewed_head_is_current_for_labels`) all stay live, and `--match-head-commit` stays the guard. The failure-path "Check PR state before failure alerts" read also stays live.
