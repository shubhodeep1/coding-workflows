Stall-recovery clarification answers (consumer tele-funtoken-msg-scoring #4815): both `auto_respond_clarify` paths in `scripts/orchestrate_poll_process.sh` (tracking-issue `recover_stalled_issue` and standalone stall recovery) build their `/answer` through `stall_recovery_clarify_answer`. When a trusted (`...[bot]` login or OWNER/MEMBER/COLLABORATOR) `/answer [auto-answered-by-orchestrator]` or `/answer [auto-answered-by-poller]` comment that decides at least one `Q<n>` is newer than the latest clarification-questions comment, its text is re-posted verbatim without the command line's `/answer` and marker (so REFRAME / DERIVE_FROM_REPO / SYNTHESIZE execution plans and the RATIONALE survive, and plan.yml's one-line `/answer Q1: A ... [marker]` keeps its decisions). Only when no such answer exists does it fall back to the RECOMMENDED letters from `extract_recommended_answers`, which now takes an optional pre-fetched comments file so the recovery reads the 50 newest comments once. An answer older than the latest question round is never repeated.

Completed projects drop `ai:integration-backpressure` (consumer #4038): `reconcile_integration_backpressure_label` only runs for active projects, so the poller's "project already terminal" branch removes the label from a `complete` project's tracking issue (read from `TRACKING_LABELS`, one write only while the label is on) and logs `BACKPRESSURE_CLEARED tracking_issue=<n> reason=project_complete`. A `failed` or `validation-failed` project keeps it.

The issue's own fragments are always in scope (consumer tele-funtoken-msg-scoring #4815, run 40055496344): for an issue-body `files_touched` list, `files_touched_scope_guard.py --issue-number <N>` also allows `changelog.d/<N>-<slug>.md` and `agents.d/<N>-<slug>.md` (top-level `.md` only, that issue's number only), because CLAUDE.md §20/§30 require one fragment per behaviour change.
