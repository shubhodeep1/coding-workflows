<!-- agents: section="Workflow architecture" -->
Persistence budget queue pause and inherited-round exemption (Refs #9421, stuck-backlog plan Phase 3 steps 10-14):
- **Marker.** Phase 3c reuses the Phase 3b hysteresis marker (`QUEUE_BACKPRESSURE_STATE_FILE`, written by `queue_backpressure_holds_dispatch`, which carries `intervals` forward) and its existing cache pair in `orchestrate_poll.yml`: "Restore queue backpressure state" (`actions/cache/restore@v4`, key `queue-backpressure-state-v1-<run_id>-<attempt>`, `restore-keys: queue-backpressure-state-v1-`) and "Save queue backpressure state" (`actions/cache/save@v4`). It adds no restore or save step of its own. "Create runtime workspace" also exports `QUEUE_BACKPRESSURE_STATE_FILE=${RUNNER_TEMP}/queue-backpressure-state/state.json` (outside the checkout) to `GITHUB_ENV`; it must equal the per-step env of the poller steps. One key per run, because cache entries cannot be overwritten; the `poll` job's concurrency group (`cancel-in-progress: false`) keeps a single writer. Format: `{"active": bool, "intervals": [[on_ts, off_ts|null], ...]}`. A legacy one-line value (`true|false|on|off|1|0`) reads as that state with no intervals; a missing or corrupt marker reads as inactive with no intervals.
- **Recording.** `queue_backpressure_record_pause_interval` in `scripts/orchestrate_poll_process.sh` runs once per poller process, right after the top-level `prime_phase_concurrency_snapshot` of the standalone-recovery sweep and of the main path. It samples `QUEUE_BACKPRESSURE_ACTIVE` through `queue_backpressure_sample_state` (a wrapper of `queue_backpressure_holds_dispatch` with its stdout dropped) and runs `scripts/persist_budget.py record-pause --state-file F --active true|false`. That opens `[now, null]` when the queue turns active, closes the open interval at now when it turns inactive, drops closed intervals older than `2 * PERSIST_MAX_HOURS`, keeps the newest 200 (`PAUSE_INTERVALS_CAP`) and writes atomically. It is not gated on `PERSIST_BUDGET_ENABLED`, so the history exists when the governor is switched on. An unknown queue depth, an unset marker path or a missing helper leaves the marker unchanged. No API call.
- **Governor.** `persist_budget_govern_issue` first samples the state; while the queue is under backpressure it logs `PERSIST governor outcome=skipped reason=queue_backpressure_pause issue=<n>` and returns before the tick cap, the comments read and `decide` (no API call, `PERSIST_BUDGET_LAST_*` stay empty). Otherwise it copies the marker's `intervals` into the scratch file `persist_budget_paused.<n>.json` in `RUNTIME_DIR`, passes it as `decide --paused-intervals-file`, and removes it right after `decide`.
- **decide.** The `max_hours` check subtracts the overlap of the intervals with `[oldest, now]` (an open interval ends at now; overlapping intervals are merged). A missing or bad intervals file, or a malformed pair, means no pause. With `PERSIST_INHERITED_ROUNDS_EXEMPT` on, a round whose gate shows `pr_caused == 0` and an integer `inherited > 0` is left out of the `max_rounds` count only; `failed_rounds` and `no_progress` still see it. The decision JSON always carries `rounds_exempt_inherited` (0 when off or before the rounds check), and `summary` adds `Rounds left out of the round limit (only inherited base failures): <n>.` when it is above 0.
- **Switches.** `PERSIST_QUEUE_PAUSE_ENABLED` and `PERSIST_INHERITED_ROUNDS_EXEMPT`, both default `true` in `orchestrate_poll.yml` (`vars.X || 'true'`), in `scripts/persist_budget.py` and in the poller (`_is_truthy` set: 1/true/yes/on). `false` restores the earlier `max_hours` (no skip, no subtraction, nothing recorded) and `max_rounds` behaviour.
- **Fail-open rules.** A cache miss or failed save loses pause history only, so queue time counts again (the earlier behaviour). Accepted residual: an interval left open while the queue depth stays unknown keeps pausing `max_hours` until a tick with a known depth closes it.

Tokens and numbers only.
