- **Final CI on a branch whose CI wiring is behind its base (#9993, 2026-11-23).** The final CI is dispatched on the PR's head ref, so GitHub runs the branch's own `.github/workflows/<REVIEW_FINAL_CI_WORKFLOW>` while the jobs check out the merge ref and run the base's scripts. A branch without the base's commits to that file failed falsely (CI [pr:9725], run 45159799693: `not our ref` after #9727) or never posted `ci/final` (branches cut before #9956).
  - **Rule.** `_pr_final_ci_wiring_behind_update <pr> <head> <base> <workflow> dispatch|blocked_status` (`scripts/pr_checks_lib.sh`) calls a head "behind" when the base-side file list of `compare/<head>...<base>` holds `.github/workflows/<workflow>` (G5: a PR that edits the file itself is not forced). It reuses `PR_BASE_FRESHNESS_BASE_PATHS` (new side channel of `_pr_base_freshness`, `__truncated__` at 300+ files) when the freshness check covered the same head and base; a truncated list asks for the newest base commit to the file and compares it with the head. Only that one path is checked: `ci.yml` calls no local reusable workflow (pinned by `tests/test_review_final_ci.py`).
  - **Action.** When behind: a recorded refusal for the head (comment ending in `<!-- ai:final-ci-wiring-behind:v1 pr=<n> head=<sha> reason=update_branch_refused -->`, counted only from the token's own login) holds; otherwise `_merge_lease_gate ... update`, then the freshness chain (head-bound `update-branch`, `_pr_base_sync_observe_update_commit`, `ai:merge-base-sync:v1` marker, `_pr_base_sync_dispatch_final_ci`, which now skips the check with `PR_FINAL_CI_WIRING_SKIP=true`). A refused update posts that comment once (only when the comment read succeeded), after one PR read: a head that already moved holds with `head_moved` and a PR GitHub reports `mergeable: true` holds with `update_branch_failed`, neither recording the marker, so the next call retries. Outcomes: `current`, `updated`, `requested`, `held`, `unknown` in `PR_FINAL_CI_WIRING_OUTCOME` / `PR_FINAL_CI_WIRING_REASON`.
  - **Hooks.** `_pr_ensure_final_ci` runs it before every dispatch (base ref: `PR_FINAL_CI_BASE_REF`, else the freshness side channel, else the PR read); on `updated`/`requested`/`held` it dispatches nothing and sets `PR_FINAL_CI_OUTCOME=deferred` `PR_FINAL_CI_REASON=ci_wiring_behind`, and `_pr_wait_for_required_checks` then stops at once with `AUTOFIX_AUTO_MERGE_CHECKS ... outcome=timeout ... reason=final_ci_wiring_behind` (no pending mark). `_pr_sync_merge_blocked_guard`, and the poller's final merge when `_pr_ruleset_required_check_blockers` returns 1 (`scripts/orchestrate_poll_process.sh`, before its "Will retry next poll" return), run it with `blocked_status` when the blockers are exactly `<FINAL_CI_WIRING_STATUS_CONTEXT> (missing)` (default `ci/final`) and the head's final CI run succeeded; both still defer. `scripts/review_enable_auto_merge.sh` passes `PR_FINAL_CI_WIRING_SKIP=true` on its auto-merge-off and `e2e-smoke-test` exits, which never merge, so they take no lease and push no new head. Fail-open: an unreadable comparison dispatches (or defers) as before. Switch: `FINAL_CI_WIRING_BEHIND_UPDATE_ENABLED` (default `true`; off makes no call).
