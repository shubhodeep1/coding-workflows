Heal counterfactual `REPRODUCIBLE` value (P2 steps 6, 7 and 9 of `docs/plans/heal-evidence-reproduction-and-trends-plan.md`, Refs #8434): a workflow-heal plan may end its `## Counterfactual check` with `HEAL_COUNTERFACTUAL: REPRODUCIBLE: <test ids>` only when the heal issue body's `## Reproduction` section reads `status: reproduced` (prompt: `prompts/mode-plan-heal-counterfactual.txt` and its `_templates/` copy). `parse_heal_counterfactual` in `scripts/partial_delivery.py` takes an optional third argument `reproduce_flag`; the `heal-counterfactual` CLI takes `--reproduce-flag` and otherwise reads `WORKFLOW_HEAL_REPRODUCE_ENABLED` (default `false`; only `true`, any case, turns it on). Outcomes: a valid list with the switch on gives `result=REPRODUCIBLE decision=approve_pending_repro reason=reproducible`; with it off `decision=hold reason=reproduction_disabled`; a missing colon or an empty/invalid list gives `result=FAIL decision=hold reason=reproducible_test_list_invalid`. `HEAL_COUNTERFACTUAL_GATE_ENABLED=false` still wins (`approve`/`gate_disabled`, no tag). `PASS`, `PARTIAL`, `FAIL` and `UNVERIFIED` are unchanged and the JSON keys are the same. Test-id grammar (1-50 ids, split on whitespace and on commas outside `[...]`, one backtick pair dropped, path `^[A-Za-z0-9_./+-]+$` without a leading `/` or a `..` segment, optional `::name` matching ``^[^\s`<>]+$``) is a copy of `cmd_tests` in `scripts/heal_isolated_implement.sh`; change both together. `.github/workflows/plan.yml` "Auto-approve clear plan" passes `WORKFLOW_HEAL_REPRODUCE_ENABLED: ${{ vars.WORKFLOW_HEAL_REPRODUCE_ENABLED || 'false' }}`, accepts `approve_pending_repro` (decision sanitised with `tr -cd 'a-z_'`), runs the automation-path / heal-scope gate as for `PASS`, and posts `/approved [auto-approved-by-plan] [repro-required]`; every other approval body is unchanged. The heal editor then re-runs the listed tests before the PR opens. The poller's `_plan_heal_counterfactual_check` (`scripts/orchestrate_poll_process.sh`) is not taught the new decision and fails closed (`reproduction_disabled` or `heal_counterfactual_check_unavailable` hold), so a stalled repro plan needs a human `/approved`. No extra GitHub API calls.
