- Merged-PR re-issue base-branch routing (#9170, `scripts/resolve_integration_ref.sh` `resolve_ci_reissue_base_branch`). For a merged PR on a non-default branch, this replaces the rule that an unblock-judge re-issue with a lone `check-failure-triage:pr=<n>` marker "is not routed and keeps the default branch". `CI_TRIAGE_PARSE_PY` prints `reissue <pr>` only for the exact unblock-judge shape: no `ai:check-triage` label; line 1 is `<!-- check-failure-triage:pr=<n> -->` and the body has no other marker; line 2 is `Re-issued by the unblock judge from #N.`; the issue is not a PR; the author is `OWNER`, `MEMBER` or `COLLABORATOR`; there is no `ai:orchestrator-managed` label and no tracking line. Any other body still skips, with no log line. The resolver then reads `pulls/<n>` once, through `ci_triage_gh_get`. A PR that did not merge, or whose `base.ref` equals `base.repo.default_branch`, keeps the empty (default-branch) result. A merged same-repository PR with a safe base ref that still exists (checked through `git/ref/heads/` with `CI_TRIAGE_REF_MATCH_PY`) prints that base branch. When the base branch read returns 404, the resolver runs the sibling `scripts/retarget_merged_base.sh resolve` on it with `RETARGET_MERGED_BASE_ENABLED=true` and `RETARGET_MERGED_BASE_MAX_HOPS=3` pinned, so the caller's own setting of that switch never changes the answer: if that branch's own merged PR went into the default branch (orchestrator finalize deletes it with `--delete-branch`), the result is empty (default branch) with `::notice::CI_TRIAGE_PR_BRANCH_ROUTING ... outcome=skipped reason=base_branch_merged_into_default`. A missing helper, no helper output, or a helper lookup that failed (its `RETARGET_MERGED_BASE ... reason=lookup_failed` line, which the resolver passes through to stderr) refuses with `branch_lookup_failed`; a lookup that worked and found no merge into the default branch (an abandoned branch, or a merge into another branch) refuses with `branch_missing`. A failed PR read, a missing `default_branch`, a mismatched PR number, a cross-repository PR, an unsafe base ref or any other branch-read failure refuses with exit 3; it never returns 2 or falls back to the default branch. A rate-limited PR or branch read exits 75, and `resolve_ref` passes 75 through. An explicit `Integration branch:` / `Target branch:` line in the re-issue (open-owner re-issues) still wins first. The gate is `CI_TRIAGE_PR_BRANCH_ROUTING_ENABLED` (default `true`); there is no separate flag.

<!-- agents: section="Stable log prefixes (contractual)" -->
- `CI_TRIAGE_PR_BRANCH_ROUTING` also logs `outcome=routed branch=<base ref>` for an unblock-judge re-issue whose PR merged into a non-default branch (#9170), using the same `echo` literal as the labelled path, adds the refusal reason `reason=base_ref_invalid` (an unsafe merged-PR base ref), and logs `::notice::CI_TRIAGE_PR_BRANCH_ROUTING issue=<n> pr=<n> outcome=skipped reason=base_branch_merged_into_default branch=<ref>` when the deleted base branch was merged into the default branch.
