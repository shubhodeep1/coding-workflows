- Merged-PR re-issue base-branch routing (#9170, `scripts/resolve_integration_ref.sh` `resolve_ci_reissue_base_branch`). For a merged PR on a non-default branch, this replaces the rule that an unblock-judge re-issue with a lone `check-failure-triage:pr=<n>` marker "is not routed and keeps the default branch". `CI_TRIAGE_PARSE_PY` prints `reissue <pr>` only for the exact unblock-judge shape: no `ai:check-triage` label; line 1 is `<!-- check-failure-triage:pr=<n> -->` and the body has no other marker; line 2 is `Re-issued by the unblock judge from #N.`; the issue is not a PR; the author is `OWNER`, `MEMBER` or `COLLABORATOR`; there is no `ai:orchestrator-managed` label and no tracking line. Any other body still skips, with no log line. The resolver then reads `pulls/<n>` once, through `ci_triage_gh_get`. A PR that did not merge, or whose `base.ref` equals `base.repo.default_branch`, keeps the empty (default-branch) result. A merged same-repository PR with a safe base ref that still exists (checked through `git/ref/heads/` with `CI_TRIAGE_REF_MATCH_PY`) prints that base branch. Every other outcome fails open, as the approved plan requires (`docs/plans/ci-reissue-branch-routing-and-sandbox-solc-plan.md`, "Fail-open, not fail-closed"): before this routing the reissue always kept the default branch, so a lookup that cannot be verified keeps it too. `resolve_ci_reissue_base_branch` prints nothing, returns 0 and logs one `::warning::CI_TRIAGE_PR_BRANCH_ROUTING issue=<n> pr=<n> outcome=skipped reason=<token>` line (`ci_reissue_skip`) for a failed PR read (`pr_lookup_failed`, with gh's stderr echoed first; a missing `default_branch` also uses it), a mismatched PR number (`pr_association_mismatch`), a cross-repository PR (`pr_cross_repository`), an unsafe base ref (`base_ref_invalid`), a parse failure (`issue_parse_failed`) or a branch read that fails (`branch_lookup_failed`) or names another ref (`branch_missing`). It never returns 2 or 3. When the base branch read returns 404, the resolver runs the sibling `scripts/retarget_merged_base.sh resolve` on it with `RETARGET_MERGED_BASE_ENABLED=true` and `RETARGET_MERGED_BASE_MAX_HOPS=3` pinned, so the caller's own setting of that switch never changes the log: if that branch's own merged PR went into the default branch (orchestrator finalize deletes it with `--delete-branch`), it logs `::notice::CI_TRIAGE_PR_BRANCH_ROUTING ... outcome=skipped reason=base_branch_merged_into_default`. A missing helper, no helper output, or a helper lookup that failed (its `RETARGET_MERGED_BASE ... reason=lookup_failed` line, which the resolver passes through to stderr) skips with `branch_lookup_failed`; a lookup that worked and found no merge into the default branch (an abandoned branch) skips with `branch_missing`. A rate-limited PR or branch read exits 75, and `resolve_ref` passes 75 through. An explicit `Integration branch:` / `Target branch:` line in the re-issue (open-owner re-issues) still wins first. The routing runs only while `CI_TRIAGE_PR_BRANCH_ROUTING_ENABLED` (default `true`) is on, and has its own off switch, `CI_TRIAGE_REISSUE_BASE_BRANCH_ROUTING_ENABLED` (`ci_triage_reissue_base_routing_enabled`; unset, empty or `true` in any case is on, `false` is off, any other value is off with a `::warning::`). Off keeps the default branch for every such reissue and logs `CI_TRIAGE_PR_BRANCH_ROUTING ... outcome=skipped reason=flag_off`, without touching the labelled triage routing. The resolver reads it from its environment, and the five resolver workflows (clarify, plan, implement, orchestrate_clarify_respond and validate) forward the repository variable `vars.CI_TRIAGE_REISSUE_BASE_BRANCH_ROUTING_ENABLED` (default `true`) in their "Resolve integration ref" step, so setting it to `false` turns this routing off.

- `CI_TRIAGE_PR_BRANCH_ROUTING` also logs `outcome=routed branch=<base ref>` for an unblock-judge re-issue whose PR merged into a non-default branch (#9170), using the same `echo` literal as the labelled path, logs `::warning::CI_TRIAGE_PR_BRANCH_ROUTING issue=<n> pr=<n> outcome=skipped reason=<pr_lookup_failed|pr_association_mismatch|pr_cross_repository|base_ref_invalid|issue_parse_failed|branch_lookup_failed|branch_missing>; keeping the default branch` when that reissue cannot be verified, `CI_TRIAGE_PR_BRANCH_ROUTING issue=<n> pr=<n> outcome=skipped reason=flag_off` when `CI_TRIAGE_REISSUE_BASE_BRANCH_ROUTING_ENABLED` is off, and `::notice::CI_TRIAGE_PR_BRANCH_ROUTING issue=<n> pr=<n> outcome=skipped reason=base_branch_merged_into_default branch=<ref>` when the deleted base branch was merged into the default branch.
