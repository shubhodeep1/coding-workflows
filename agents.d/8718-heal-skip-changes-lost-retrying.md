The review/autofix heal reporter (`scripts/workflow_failure_heal_autofix_report.sh`) does not report an `editor_changes_lost` run whose `CHANGES_LOST_REDISPATCHED` is `true` or `skipped_peer_inflight` (`WORKFLOW_HEAL_AUTOFIX_REPORT skip reason=changes_lost_retrying pr=<N> redispatched=<value>`). That run already handed the PR to a fresh review, posts no failure comment and ends `success`, so the intake's provenance gate could only reject it as `not_failed` and send a WARNING (PR #8718, run 41564230342, 2026-11-03). The retry-unavailable values (`skipped_budget_unavailable_or_exhausted`, `false`, and unset when push is disabled) still report because a person must act; those runs also end `success`, so the intake accepts their report only while the run is still in progress and may still reject it as `not_failed`.
