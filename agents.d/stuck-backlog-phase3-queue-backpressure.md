Issue run linkage and queue backpressure (Refs #9421, stuck-backlog plan Phase 3):
- **Run-name convention.** `internal-clarify.yml`, `internal-plan.yml`, `internal-implement.yml` and the templates `ai-clarify.yml`, `ai-plan.yml`, `ai-implement.yml` set a `run-name` on the line after `name:` that renders `<workflow name> [issue:N]` (`format('<workflow name> [issue:{0}]', github.event.issue.number)`). All six trigger only on `issues` / `issue_comment`, so the number is always set. Exception: an issue whose title starts with `[E2E ` keeps the issue title as its run title, because the stable release gate (`test-and-mark-stable.yml`, `find_latest_scoped_run_field` in `scripts/comprehensive_test_and_release_gh_api.sh`) finds smoke runs by `display_title == issue title`. Drop the exception only after those readers also accept the tagged form. `tests/test_poll_issue_run_linkage.py` pins the strings and checks that every gate smoke title starts with `[E2E `.
- **Linkage.** `build_active_issue_set` unions the head_branch matches with tagged runs. A run is tagged only when `.event` is `issues` or `issue_comment` and `.display_title` equals `.name + " [issue:N]"` exactly, with N matching `^[1-9][0-9]{0,9}$`. A pull-request title carrying a forged tag never links. Tagged runs come from the fresh in-progress and queued runs, plus tagged queued runs younger than `QUEUED_RUN_ZOMBIE_MINUTES` (default 1440; a value that is not a positive integer falls back to `STALL_THRESHOLD_MINUTES`). Untagged runs are unchanged.
- **Queue depth.** `_load_actions_runs_cached` keeps `total_count` from its existing `status=queued&per_page=50` read in `ACTIONS_QUEUED_TOTAL`. It is empty (unknown) on a memory-cache hit, a 304 reuse, a mktemp failure or an unconfirmed fetch. The blob shape is unchanged and no API call is added.
- **Backpressure.** `queue_backpressure_holds_dispatch` runs first in `phase_cap_can_dispatch`, so it covers stall-recovery re-dispatch, wave issue creation, validation dispatch and the review-blocked judge. It holds (the caller sees 1) when `ACTIONS_QUEUED_TOTAL >= ACTIONS_QUEUE_BACKPRESSURE_HIGH` (default 150, set in the script). Exempt actions: `attempt_merge`, `escalate_human`, `skip`. Fail open: an unknown depth, a threshold below 1, or a non-integer threshold (one `::warning::`) keeps the legacy result. The check is stateless at HIGH; hysteresis and passing the variables through `orchestrate_poll.yml` are not part of this phase.
- **Heal readers.** `_issue_linked_run_matches` (`number=`), `_trend_issue_linked_runs` and `select_failed_runs` (through `tracking_issue`) in `scripts/workflow_failure_heal.py` also accept the tagged title of an `issues` / `issue_comment` run, so heal reports keep these runs.
