**Stall recovery dispatches review before any empty commit (cut-ci-runner-time Phase 3, Refs #9528).** In both `retrigger_review` arms of `scripts/orchestrate_poll_process.sh` (`execute_stall_recovery_action` for project items, `run_standalone_stall_recovery` for standalone issues), `_dispatch_review_for_conflicts "${pr_num}" "${head_ref}"` is now the first re-trigger step for every stalled PR, not only when the last review run concluded `failure` / `cancelled` / `timed_out`.
- Guards in front of it are unchanged: merge-train queued, Claude capacity wait and the conflict override (managed arm), the implementation-PR gate (standalone arm), the PR-named dispatch listing check, the default-branch provenance check, and both in-flight checks (cached `_load_actions_runs_cached` scan and `_direct_inflight_review_run_on_branch`). The failed-last-run path still dispatches before the in-flight checks, as before.
- rc `0`: `STALL_RECOVERY_EFFECTIVE_ACTION=redispatch_review_autofix`, one recovery attempt spent, log `dispatched the review workflow instead of pushing an empty commit`. rc `2` (active run or already dispatched this cycle): `redispatch_review_autofix`, no attempt spent (standalone: `took_action=true`, so the stall clock resets).
- Any other rc: log `dispatch helper returned rc=<n>; falling back to empty-commit push.`, then the existing head-advanced check and empty-commit push. A successful push sets `STALL_RECOVERY_EFFECTIVE_ACTION=retrigger_review_empty_commit_fallback` and logs `pushed the empty-commit fallback (action=retrigger_review_empty_commit_fallback)`. The managed arm tries the dispatch at most once per call (`_rtr_dispatch_attempted`), so a failed-run redispatch that fails falls straight to the fallback.
- API budget (§15): a re-trigger that used to push now costs the helper's `_has_active_autofix_run` guard (up to three branch-scoped `gh run list` reads, plus the PR-named dispatch lookup when they find nothing) and one `workflow_dispatch`, in place of a full CI run on the empty commit. The in-flight checks' results cannot be handed to the helper, so its reads repeat; a comment at each call site records that audit. Tests: the `retrigger_review` / `standalone_retrigger_review` cases in `tests/test_orchestrate_poll_process.py`.
