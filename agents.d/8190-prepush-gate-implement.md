- **Implement gate (issue #8190, plan phase P3).** `implement.yml` runs the step "Pre-push affected-test gate" (`id: prepush_test_gate`, `continue-on-error: true`, `timeout-minutes: 60`, `if: env.SKIP_IMPLEMENT != 'true' && env.HEAL_ROUTE != 'true'`) between "Enforce syntax validation outcome" and "Commit changes". Its body sources `scripts/implement_step_prepush_test_gate.sh` from `IMPLEMENT_STAGED_SUPPORT_RUN_DIR` (fallback `.codex-workflow-src/scripts/`). "Stage workflow support files" copies the step script, `prepush_test_gate_run.sh` and the module into the run dir, and `prompts/mode-implement-repair-tests.txt` into `${RUNTIME_DIR}/staged_support_run/prompts/`. These are pre-editor copies outside the workspace, because the wrapper refuses a module inside the tested worktree. The PR checkout's copies are never read.
  - Modes: `PREPUSH_TEST_GATE_MODE` is `off|report|repair`, default `repair`; an unknown value logs `outcome=mode_invalid` and acts as `repair`. `PREPUSH_TEST_GATE_TIMEOUT_MINUTES` (15), `PREPUSH_TEST_GATE_LARGE_FILE_TESTS` (50) and `PREPUSH_TEST_GATE_SHARDS` (4) are defaulted in the workflow and the script; a timeout above 53 minutes is clamped to 53 (`outcome=config_invalid ... clamped=53`) so one run fits the 60-minute step. Before the first run the timeout is also lowered to what is left of the step budget after image build and setup (`outcome=warning reason=step_budget timeout_clamped=<n>`); when not even one minute is left, no container starts and the result is a synthetic UNVERIFIED one (`outcome=skipped reason=step_budget`), and zero-padded values (`08`) are read as decimal in the step script and the wrapper.
  - Run: the image comes from the new `codex_isolated_exec.sh image` action, the base is `HEAD` (the change is still uncommitted), and the deps venv of `CODEX_ISOLATED_IMPLEMENT_ROOT` is passed with the new wrapper flag `--venv`, together with `--shards` and `--large-file-tests`; its Node prep root (`work/node_modules`) is passed with the new flag `--node-modules`, which the wrapper mounts read-only at `/source/node_modules` and `/baseline/node_modules` (the snapshot leaves `node_modules` out); `--nested-node-modules-root work` also mounts up to 6 nested projects' `work/<project>/node_modules` read-only at `/source/<project>/node_modules` and `/baseline/<project>/node_modules` (a project path with a comma, a quote or a control character is skipped with `reason=nested_node_modules_unsafe_path`; a symlink on the mount path or a failed `mkdir` logs `reason=nested_node_modules_mount_skipped detail=symlink_in_path|mkdir_failed`). The wrapper mounts the venv read-only at `/opt/codex-venv` and forwards the values with `--env`; values that are not plain digits are dropped. Self-repo staged copies are bracketed with `implement_staged_support_workspace.sh restore|reinstall`. The image now carries `shellcheck` and `ruff==0.17.2` for the gate's static checks.
  - Repair: in `repair` mode, a `fail` result with PR-caused failures (not `inherited`) gets one editor turn through `codex_thread_reuse.sh direct-run` (state key `implement-repair-tests`, the syntax repair's isolation env and `env -u STAGED_SUPPORT_*` wrapping). The prompt is the trusted template, then `=== CAPTURED TEST FAILURES (UNTRUSTED) ===` (16 KiB cap, `::` neutralised), the changed files, the allow-list (changed files, plus the trusted module's `select --paths-file` affected tests and companions, plus failing files; `.github/workflows/` dropped unless `ALLOW_WORKFLOW_EDITS=true`) and the current diff. The allow-list is narrowed before the turn: paths other than the changed files must pass `files_touched_scope_guard.py --issue-body-file` (unless `ENFORCE_FILES_TOUCHED` is off or `ALLOW_OUT_OF_SCOPE_FILES=true`), and automation paths (`.github/`, `.claude/`, `scripts/`, `prompts/`, `workflow-templates/`) must pass the commit step's own `files_touched_scope_guard.py --check-automation-paths` check against `AUTOMATION_PATH_GRANT_FILE` and `ALLOW_WORKFLOW_EDITS` (`reason=allow_list_narrowed`), so a compliant repair is never refused at commit. The revert baseline is a `git stash create` of the pre-repair tree; when that fails while tracked changes exist the repair is skipped (`reason=baseline_unavailable`) instead of falling back to `HEAD`. A sandbox root the step prepares itself is cleaned up after the turn. The turn runs with `CODEX_THREAD_REUSE_TIMEOUT_SECS` set to what is left of the step budget after the re-run reserve, so the step's kill never lands before the rollback; under 300 seconds left skips the turn (`reason=step_budget`). A failed rollback writes `${RUNTIME_DIR}/prepush_gate_restore_failed.flag` and the summary's repair line says `rollback incomplete`; the backup of a restored tracked symlink lives under `RUNTIME_DIR`, never in the worktree. Afterwards edits outside the allow-list are rolled back and replaced or retargeted tracked symlinks are restored. A nonzero editor exit reverts every repair edit (the isolated runner writes edits back even after a failed attempt). Then `validate_changed_files_syntax.sh` re-runs: a failure reverts every repair edit (`outcome=repair_reverted reason=syntax`). Only a kept repair gets a second gate run, and there is never a second repair. A 55-minute budget inside the 60-minute step skips the repair turn (`reason=step_budget`) or the re-run when the remaining time cannot hold them.
  - Output: the host writes `${RUNTIME_DIR}/prepush_test_gate_summary.md` from the final `result.json` with the trusted module's `write_summary`, never from the container's `summary.md`. It lists the tests and checks run (first 50), and says when a skipped re-run leaves a result from before the repair. Changed pre-existing assertions are listed by file and kind only, never with their source text. Fields are normalised, `<!--`, `#<digits>` and `@login` are broken up, and the file is capped at 8 KiB. The PR-body pre-flight step appends it before `lint_pr_body_auto_close.py`.
  - "Build implementation context" runs `implement_step_prepush_test_gate.sh expected-files PLAN ISSUE_BODY`. For a standalone issue (no `**Orchestrator metadata**` footer, mode not `off`) this prints an advisory `EXPECTED FILES (ADVISORY)` section from `select --paths-file` over the plan's paths that `git ls-files` lists.
  - Every path ends with status 0, so the push is never blocked. Log lines: `PREPUSH_TEST_GATE phase=implement outcome=pass|fail|unverified|skipped|mode_invalid|repair_skipped|repair_reverted reason=...`. The step makes no GitHub API call.
