- **Implement gate (issue #8190, plan phase P3).** `implement.yml` runs the step "Pre-push affected-test gate" (`id: prepush_test_gate`, `continue-on-error: true`, `timeout-minutes: 60`, `if: env.SKIP_IMPLEMENT != 'true' && env.HEAL_ROUTE != 'true'`) between "Enforce syntax validation outcome" and "Commit changes". Its body sources `scripts/implement_step_prepush_test_gate.sh` from `IMPLEMENT_STAGED_SUPPORT_RUN_DIR` (fallback `.codex-workflow-src/scripts/`). "Stage workflow support files" copies the step script, `prepush_test_gate_run.sh` and the module into the run dir, and `prompts/mode-implement-repair-tests.txt` into `${RUNTIME_DIR}/staged_support_run/prompts/`. These are pre-editor copies outside the workspace, because the wrapper refuses a module inside the tested worktree. The PR checkout's copies are never read.
  - Modes: `PREPUSH_TEST_GATE_MODE` is `off|report|repair`, default `repair`; an unknown value logs `outcome=mode_invalid` and acts as `repair`. `PREPUSH_TEST_GATE_TIMEOUT_MINUTES` (15), `PREPUSH_TEST_GATE_LARGE_FILE_TESTS` (50) and `PREPUSH_TEST_GATE_SHARDS` (4) are defaulted in the workflow and the script.
  - Run: the image comes from the new `codex_isolated_exec.sh image` action, the base is `HEAD` (the change is still uncommitted), and the deps venv of `CODEX_ISOLATED_IMPLEMENT_ROOT` is passed with the new wrapper flag `--venv`, together with `--shards` and `--large-file-tests`. The wrapper mounts the venv read-only at `/opt/codex-venv` and forwards the values with `--env`; values that are not plain digits are dropped. Self-repo staged copies are bracketed with `implement_staged_support_workspace.sh restore|reinstall`. The image now carries `shellcheck` and `ruff==0.17.2` for the gate's static checks.
  - Repair: in `repair` mode, a `fail` result with PR-caused failures (not `inherited`) gets one editor turn through `codex_thread_reuse.sh direct-run` (state key `implement-repair-tests`, the syntax repair's isolation env and `env -u STAGED_SUPPORT_*` wrapping). The prompt is the trusted template, then `=== CAPTURED TEST FAILURES (UNTRUSTED) ===` (16 KiB cap, `::` neutralised), the changed files, the allow-list (changed files, plus the trusted module's `select --paths-file` affected tests and companions, plus failing files; `.github/workflows/` dropped unless `ALLOW_WORKFLOW_EDITS=true`) and the current diff. Afterwards edits outside the allow-list are rolled back and replaced or retargeted tracked symlinks are restored. Then `validate_changed_files_syntax.sh` re-runs: a failure reverts every repair edit (`outcome=repair_reverted reason=syntax`). The gate runs once more, and there is never a second repair.
  - Output: the host writes `${RUNTIME_DIR}/prepush_test_gate_summary.md` from the final `result.json` with the trusted module's `write_summary`, never from the container's `summary.md`. Fields are normalised, `<!--`, `#<digits>` and `@login` are broken up, and the file is capped at 8 KiB. The PR-body pre-flight step appends it before `lint_pr_body_auto_close.py`.
  - "Build implementation context" runs `implement_step_prepush_test_gate.sh expected-files PLAN ISSUE_BODY`. For a standalone issue (no `**Orchestrator metadata**` footer, mode not `off`) this prints an advisory `EXPECTED FILES (ADVISORY)` section from `select --paths-file` over the plan's paths that `git ls-files` lists.
  - Every path ends with status 0, so the push is never blocked. Log lines: `PREPUSH_TEST_GATE phase=implement outcome=pass|fail|unverified|skipped|mode_invalid|repair_skipped|repair_reverted reason=...`. The step makes no GitHub API call.
