- **Support helpers staged from HEAD (#8065, unblock fix-up for #8064).** `cmd_run` in `scripts/validation_harness_sandbox.sh` passes `STAGE_PY` one `head-support:<path>` argument for each of four fixed paths: `scripts/validate_process.sh`, `scripts/validation_harness_sandbox.sh`, `scripts/codex_isolated_workspace.py` and `scripts/templates/slot_manifest.schema.json`. For each one that git lists and `readonly_allowed` admits, `STAGE_PY` (`head_blob`) reads the HEAD entry with `git ls-tree -z HEAD -- <path>` and `git cat-file blob <oid>` under the same hardened environment as its `ls-files` call (`GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, no prompts or locks, fsmonitor and hooks off), and stages those bytes with the blob's mode (`100755` → `0755`, `100644` → `0644`) instead of the working-tree file a staging step may have overwritten. It logs `VALIDATION_HARNESS_SANDBOX phase=stage outcome=ok reason=support_from_head path=<path>`. Only regular blobs count: an untracked path, a symlink (`120000`), a gitlink, a repository with no commit or any git error keeps today's working-tree behaviour. The trusted `scripts/validate_driver.sh` overlay still wins. A `head-support:` path that is absolute or has a `..` part is ignored. Off switch `VALIDATION_SANDBOX_SUPPORT_FROM_HEAD_ENABLED`, defaulted in the script (`validate.yml` does not forward it, so a repository variable alone does not reach it): unset, empty or `true` (any letter case) on, `false` off, any other value off with `::warning::VALIDATION_HARNESS_SANDBOX phase=stage outcome=skip reason=support_from_head_invalid_switch` (the value is never printed). `scripts/stage_workflow_support.sh` and `validate.yml` are unchanged.
