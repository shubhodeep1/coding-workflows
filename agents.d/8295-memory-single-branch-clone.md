- Off switch for the single-branch memory clone (#8295, unblock fix-up for #8287). `_clone_for_memory_branch` in `scripts/ai_memory_lib.py` keeps the #8287 fast path by default: an `ls-remote` probe, then a depth-1 `--single-branch --no-tags` clone of the memory branch, and the full clone (`_full_repo_clone_for_memory_branch`: clone, `ls-remote`, explicit-refspec fetch and `checkout -B`) when the branch does not exist yet or the shallow clone fails. `AI_MEMORY_SINGLE_BRANCH_CLONE_ENABLED`, defaulted in the helper and read with `parse_bool`, switches the fast path off: unset, empty or a true word keeps it on, a false word runs the full clone directly, and any other value also runs the full clone with one `::warning::` on stderr (non-printable characters in the echoed value become `?`). Fallback diagnostics stay behind `AI_MEMORY_CLONE_DIAGNOSTICS=1`, because fail-open callers such as the fingerprint verifier's quarantine persist require an empty stderr. Both memory steps of `.github/workflows/memory_maintenance.yml` map the switch from the repository variable (`${{ vars.AI_MEMORY_SINGLE_BRANCH_CLONE_ENABLED || '' }}`; empty keeps it on). The "Extract repository learnings (fail-open)" step of `.github/workflows/memory_maintenance.yml` has `timeout-minutes: 10` inside the 20-minute job cap.
