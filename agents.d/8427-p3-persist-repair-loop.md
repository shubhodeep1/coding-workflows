### Repair loop (`PERSIST_REPAIR_LOOP_ENABLED`, P3 of #8427)

Phase P3 of `docs/plans/persistent-unattended-workflows-plan.md`. Repo variables `PERSIST_REPAIR_LOOP_ENABLED` (default `false`) and `PERSIST_REPAIR_MAX_TURNS` (default `3`; integers clamped to 1..5, anything else is 3), both also defaulted inside every helper that reads them. With the switch off the gate argv, `result.json`, repair prompt, gate summary and PR body are byte-identical to before.

- **Done-check source.** Implement: `PLAN_FILE` (the author-verified plan comment) through `acceptance_check.py parse`. Review: the "Prepare done-check (repair loop)" step (token-bearing, fail-open, before the credential-free gate step) runs `acceptance_check.py fetch-plan`, which reuses `attempt_journal.py`'s `resolve_target`, `resolve_login` and `load_comments` and parses the newest plan-proposal comment authored by the pipeline login into `${RUNTIME_DIR}/prepush_gate/acceptance.json`; anything else is state `none`.
- **Gate inputs.** `acceptance_check.py gate-files` writes `prepush_gate/tests.txt` (every test target) and `baseline_fail.txt` (red-on-base targets). `scripts/prepush_test_gate_run.sh --tests-file / --expect-baseline-fail-file` copies them (regular, non-symlink, <= 64 KiB, else `reason=tests_file_rejected`) into a private directory mounted read-only at `/inputs`. The module's `run --tests-file / --expect-baseline-fail-file` validates each `path[::name]` (safe relative path of a regular non-symlink file under the repo root, <= 50 targets; else an `unverified` item `tests_file_invalid|tests_file_missing|too_many_targets`), adds the targets to the selection without `select_tests` (`selected` still counts path-selected files only), re-runs red-on-base targets on the merge-base tree and adds `acceptance: {"<target>": {"head", "base", "base_reason"?}}` to `result.json` (schema stays `prepush_test_gate.v1`). A red-on-base file absent on the merge-base is `base_reason=absent_on_base` and counts as red on base.
- **Scoring.** `acceptance_check.py gate-result` writes `${RUNTIME_DIR}/acceptance_result.json` (`acceptance_result.v1`: `state` `met|unmet|not_run|none`, `unmet_count`, `extra_unmet`, `acceptance.items[{kind,target,status}]`, the shape `render --gate-result` reads). Statuses: head pass `met`; head fail `unmet`; red-on-base head pass + base fail/absent `met`; red-on-base head pass + base pass `unmet (passes on base)`; anything else `not run`. Checks stay `not run`. Only plain `unmet` adds to `extra_unmet`: `unmet (passes on base)` comes from the merge-base tree, which no repair on head can change.
- **Loop.** Both gate step scripts (`implement_prepush_test_gate_persist_loop`, `review_prepush_test_gate_persist_loop`) repair while `pr_caused + extra_unmet` is above zero, strictly drops after the first turn, the turn count is below the cap and one editor turn plus one run fits the step budget. A repair that is not `ran` ends the loop. Runs land in `prepush_gate/run1..run6`; the repair-turn summary reads `ran x<N>` (plus `; <last reason>` when the loop stopped early). Unmet targets reach the repair prompt only inside `=== BEGIN UNTRUSTED DONE-CHECK STATUS (host-computed; targets are plan text) ===` / `=== END UNTRUSTED DONE-CHECK STATUS ===`, as `UNTRUSTED_DATA:` lines (<= 10). The resolver keeps its single repair; the `gate` subcommand only passes the two options through.
- **Label.** `ai:acceptance-unmet` (catalog: `.github/ai/label_contract.v1.json`, `scripts/label_helpers.sh`) is advisory, not a merge gate. Implement adds it at `gh pr create` (or on an existing PR, warning only) when the state is `unmet`; review's "Sync done-check label" step, after a commit, adds it on `unmet` (after `ensure_label_exists` when `label_helpers.sh` is staged) and removes it on `met`, reading the PR's labels from `PR_PAYLOAD_FILE` (the full PR payload; `PR_META_FILE` is a projection without labels) and never deleting when they are unknown. Implement appends `--label` only after `ensure_label_exists` succeeds, so a missing label never fails `gh pr create`. `not_run` never labels.
- **API budget.** Review: at most 1 comments read and 1 cached identity read (prepare step) plus at most 1 label write per round. Implement: no new reads; at most 1 label create through `ensure_label_exists` plus the `--label` flag.
- **Known gap.** `scripts/review_commit_changes.sh` still records the attempt journal's gate fields from `run2`/`run1` only, so a review round that ends in `run3`+ journals the second run's result. implement.yml reads `run6..run1`.

- `PERSIST` repair-loop components (#8427 P3): `PERSIST repair_loop outcome=<pass|fail|unverified|skipped> turns=<n> stop=<met|clean|no_progress|max_turns|budget|reverted|skipped|report_mode> acceptance=<met|unmet|not_run|none>` (also `outcome=skipped reason=<helper_absent|switch_off>`) from both gate step scripts, and `PERSIST acceptance_label outcome=<added|removed|unchanged|skipped|error> reason=<token>` from the review label step. `scripts/acceptance_check.py fetch-plan` logs `PERSIST acceptance outcome=<valid|none> reason=<ok|plan_absent|identity_unavailable|fetch_failed>`. Tokens only, never target names or comment text.
