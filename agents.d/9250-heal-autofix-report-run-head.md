Autofix failure report head (issue #9250): the `autofix_failure` payload's `head_sha` is the failed run's own head, not always the PR's current head. `scripts/workflow_failure_heal_autofix_report.sh` takes it from `REPORT_RUN_HEAD_SHA` (optional, default empty, a test override) or else from `.pull_request.head.sha` of `GITHUB_EVENT_PATH`, but only when `GITHUB_EVENT_NAME` is `pull_request`, the event's `.pull_request.number` equals `PR_NUMBER` and the value is 40 lowercase hex. It passes the head as `build-autofix-payload --run-head-sha`, only when the staged `workflow_failure_heal.py` contains `run-head-sha`, so an older helper does not lose the report. `build_autofix_failure_payload(run_head_sha=...)` re-checks it with `is_valid_sha` and uses it for `head_sha` and the `review-autofix-failure:v1` marker lookup in `run_refs`; `head_branch` stays the PR's. Every other case (dispatch, `pull_request_target`, no usable event head) keeps the PR head. The value is untrusted, and the binding stays safe because the intake does not change: `verify_run` still requires `actions/runs/{id}.head_sha == payload.head_sha`, and `bind_report_claims` with `--head-ancestor` (the intake's `compare` call) still requires the reported head to be the PR head or an ancestor of it. After a force-push the run head is not an ancestor, so the report is rejected and the CRITICAL stays (accepted). The reporter's `dispatched` line ends with `run_head=<sha|none> run_head_source=<override|event|none> pr_head=<sha|none>`.
