- **Nothing-to-implement planning block verify (#10015, plan `docs/plans/pipeline-human-wait-elimination-plan.md` Phase 8a).** `plan.yml` step "Verify nothing-to-implement block" (`id: nothing_to_implement_verify`, `continue-on-error: true`) runs after "Validate done-check (acceptance)" whenever `parse_plan` reports a block. It runs `.codex-workflow-src/scripts/plan_nothing_to_implement_verify.sh` from the trusted workflow-source checkout (absent file: logs `outcome=skipped reason=helper_absent` for the matching reason only). The script acts only on the exact reason `work is already on the planning ref; nothing to implement` (trailing whitespace and CR removed; same literal as `UNBLOCK_NOTHING_TO_IMPLEMENT_REASON` in `scripts/unblock_judge.sh`). `acceptance_check.py verify-targets` picks the targets: the plan's `ACCEPTANCE: test` lines whose file exists, else `extract_issue_test_paths` over the issue body from `ISSUE_META_FILE` (no API call), at most 10, schema `plan_verify_targets.v1`. `heal_reproduce.sh --sha HEAD --baseline HEAD` runs them in the gate container (`WORKFLOW_HEAL_REPRODUCE_TIMEOUT_SECS=600`, outer `timeout 900`). Only when every listed test is `not_reproduced`/`passes_at_failing_sha` and the count matches does it post the `<!-- ai:implement-success-noop:v1 issue=<n> -->` comment, `gh issue close --reason completed`, then swap labels as `implement.yml` Guard 0 does (plus `--remove-label ai:blocked`; closing first, as `scripts/check_failure_triage.sh` does, means a failed close never leaves the terminal `ai:closed` label on an open issue, and a failed swap after the close is only a `::warning::`) and delete the progress comment; outputs `outcome=closed|blocked|skipped` and a one-line `note`. "Handle blocked planning output" skips on `outcome == 'closed'` and otherwise prints the note after the `Reason:` line (header and `Reason:` line unchanged for `unblock_nothing_to_implement_blocked`). A comment failure (`detail=comment_failed`) or close failure (`detail=close_failed`, marker already posted, labels untouched) keeps the block. Switch: `PLAN_NOTHING_TO_IMPLEMENT_VERIFY_ENABLED` (default `true`; `false` restores today's blocked comment). Test seams: `PLAN_NOTHING_TO_IMPLEMENT_VERIFY_ACCEPTANCE_HELPER`, `PLAN_NOTHING_TO_IMPLEMENT_VERIFY_REPRODUCE_SCRIPT`.

- `PLAN_NOTHING_TO_IMPLEMENT` — emitted once per plan run whose block reason is exactly the nothing-to-implement literal, by `scripts/plan_nothing_to_implement_verify.sh` (or the `plan.yml` step's `helper_absent` fallback; issue #10015). Format: `PLAN_NOTHING_TO_IMPLEMENT issue=<n> outcome=closed|blocked|skipped reason=passed|no_tests|failed|timeout|disabled|helper_absent tests=<k>[ detail=<[a-z_]+>]`. `detail` tokens include `comment_failed`, `close_failed`, `helper_absent`, `support_missing`, `count_mismatch`, `invalid_result`, `head_unavailable`, `tmp_unavailable` and the gate's unverified reasons (for example `image_unavailable`).
