- `SANDBOX_SOLC_VERSIONS` (default empty: off; set at workflow level in `implement.yml`) opts the `scripts/codex_isolated_exec.sh` image into `solc`. `sandbox_solc_resolve_versions` accepts up to 5 comma- or whitespace-separated, deduplicated versions matching `^0\.[0-9]{1,2}\.[0-9]{1,3}$`, and passes them on only as the build arg `SANDBOX_SOLC_VERSIONS=<v1>_<v2>`. An invalid value (including a separator-only one) warns and is dropped, and so does any value on a runner whose `uname -m` is not `x86_64`. The installer follows redirects only on `https://binaries.soliditylang.org`. When the variable is off, `write_image_context` writes the same single Dockerfile as before, so the `codex-isolated-*` input hashes and the prebuilt images do not change. When it is on, the context also holds a generated `solc_install.py`. It takes each sha256 from `binaries.soliditylang.org/linux-amd64/list.json`, verifies every binary before writing anything (a mismatch fails the build), and installs into `/opt/solc/hardhat-nodejs/compilers-v2/linux-amd64` plus `/usr/local/bin/solc-<v>` and `/usr/local/bin/solc`. Both inner scripts link that directory into `$HOME/.cache/hardhat-nodejs/compilers-v2/linux-amd64`, guarded so the step does nothing without solc. Foundry is not installed.
