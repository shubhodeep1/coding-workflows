<!-- agents: section="Workflow architecture" -->
- **Workflow log analysis report delivery through a PR (#8963).** The default-branch ruleset requires `lint` and `ai-review/head-gate` with no bypass actors, so `.github/workflows/workflow-log-analysis.yml` never pushes to the base branch. Step `Commit and push report` pushes `HEAD` to `refs/heads/auto/workflow-log-analysis-report-<run_id>-<run_attempt>` and exposes job outputs `committed`, `report_branch` and `purged_docs` next to `report_file` and `analysis_status`. Both `Sync latest report from target branch` steps check out that branch when `report_branch` is set, and both section push steps push to it; with no report branch they log `outcome=skipped reason=no_report_branch` and push nothing. The `deliver-report` job (`needs: [analyze-commit-notify, deep-audit, api-redundancy]`, `if: always() && … committed == 'true'`, `contents: read`, `persist-credentials: false`) runs `scripts/workflow_log_analysis_deliver_report.sh` with GH_PAT only. The script makes 1 paginated open-PR list call, checks collisions against the base branch and other open `auto/workflow-log-analysis-report-*` branches with one `git fetch`, renames the report to the next free `-N` in a temporary worktree, lints the PR body with `scripts/lint_pr_body_auto_close.py` before any push, and runs `gh pr create` once with a `gh pr list --head` fallback. Run branches are left in place (the ruleset blocks deletion).
- **Processed-only purge.** The age-based purge in `Commit and push report` deletes `analysis/workflow-optimization-<date>(-N).md` only when its basename appears in `analysis/recommendation-processing-report.md` (the `grep -qF` test of `unprocessed_docs()` in `scripts/apply_analysis_on_main.sh`), after the in-flight-project and date checks. A missing processing report skips the whole purge. Deletions ride in the report PR.
