Workflow failure heal provenance for green sandbox-excluded runs (PR #9112): the #8321 sandbox-excluded escalation writes its `review_editor_sandbox_path_excluded` marker on a review run that ends `success`, and the identical-failure cap run that reports it ends `success` too. `verify_run_provenance` therefore accepts a completed `success` run for an `autofix_failure` report only when the trusted account's canonical (trailing) `review-autofix-failure:v1` marker names that run, the report's `head_sha` and a reason in `SUCCESS_RUN_FAILURE_MARKER_REASONS` (only `review_editor_sandbox_path_excluded`). The run still has to pass the workflow-path and PR-link checks, and it is listed in `marker_head_run_ids`. Any other green or `cancelled` run is still rejected as `not_failed`. Before this, every such cap report ended in `skip reason=provenance_rejected detail=no_verified_runs` (intake run 42583232747) and never reached the non-retryable route.
