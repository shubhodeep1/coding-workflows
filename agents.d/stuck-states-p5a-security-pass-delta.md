- **Single-issue security pass delta re-audit with prior-finding carry-forward (stuck-states P5a, Refs #8291).** Switch: `SINGLE_ISSUE_SECURITY_PASS_DELTA_ENABLED` (default `true` in `scripts/review_single_issue_security_pass.sh` and in every workflow row; `false` restores today's dispatch arguments, pending comment and report body byte for byte).
  - **Gate.** When the latest trusted completed (`clean`/`findings`) marker is for an older head, `single_pass_gate` dispatches the audit with `-f audit_diff_since=<that head>` and, for `findings`, `-f prior_findings=<that comment id>` (`single_pass_delta_source`, no API call). The first cycle, a completed result for the current head and the exhausted-head retry keep today's exact arguments, so the final audit of an exhausted head stays a full merge-base..head audit. A rejected delta dispatch (a consumer wrapper without the inputs) is retried once with today's arguments (`outcome=delta_fallback reason=dispatch_rejected`); only a second failure takes the `dispatch_failed` path.
  - **Delta step.** `.github/workflows/security-audit.yml` step "Resolve single-issue security pass delta" runs the trusted support copy of the helper (`delta` mode, never audit-data). The dispatch inputs are requests: it re-derives the source from the pipeline account's markers, requires the inputs to match, the checkout HEAD to be the audited head and the since commit to be its ancestor, and, for `findings`, the result comment's `Audited findings (base64 JSON):` payload to match `Audited findings sha256:`. Only then does it write `SECURITY_AUDIT_DIFF_SINCE` / `SECURITY_PASS_DELTA_SINCE` (and `SECURITY_AUDIT_PRIOR_FINDINGS` / `SECURITY_PASS_PRIOR_FINDINGS_FILE`) to `GITHUB_ENV`. Any doubt writes nothing and the audit runs in full (`mode=delta outcome=full reason=<r>`).
  - **Audit.** `scripts/security_audit.sh` accepts `SECURITY_AUDIT_PRIOR_FINDINGS` in issues mode only with `SECURITY_AUDIT_TARGET_REF`, renders the same untrusted prior-findings block (no money lens), and writes the surviving findings to `SECURITY_AUDIT_PASS_FINDINGS_OUT` when set (issues mode; a write error only warns).
  - **Report.** A prior finding that was not re-reported, whose file is untouched since the delta base and whose follow-up is still open is carried into the result (IDs, count and status); a follow-up listing or git failure carries every candidate. A `findings` result stores the audited findings above the unchanged final marker (omitted over 40,000 encoded bytes, `reason=prior_findings_omitted`, which makes the next cycle a full audit). The marker regex and the `Finding IDs (base64 JSON):` line are unchanged.
