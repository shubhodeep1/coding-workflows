- **Review merges re-read the PR's live state (issue #10260, re-issued from #10049).** A review run merged tele-funtoken-msg-scoring PR #5800 22 minutes after a maintainer closed it: the gate passed while the PR was open, the merge job started after the close, and GitHub accepts a merge of a closed, unmerged PR whose branch still exists (`--match-head-commit` binds only the head). `_pr_merge_open_guard <pr> <bound_sha> <phase> [<pr_json>]` in `scripts/pr_checks_lib.sh` lets a merge proceed only when the PR is `open`, not a draft and still at the bound head. Otherwise it refuses with `pr_closed`, `pr_merged`, `pr_draft`, `head_moved` or `pr_state_unavailable`. A failed or malformed read fails closed. It costs 0 calls with JSON input and 1 GET otherwise, and it never runs inside a wait loop.
  - Read points: in the `deterministic-skip-merge` job (both the squash and forward-merge branches), the guard runs at `start`, before the first freshness/lease call, and at `pre_merge`, right after the required-checks wait and before the post-wait freshness re-check and `gh pr merge`. `scripts/review_enable_auto_merge.sh` checks `start` on its existing PR read (no call) and makes one live `pre_merge` read at the same place; when the post-wait freshness re-check took the inline merge (branch update plus a checks wait on the update head), it reads once more, bound to the update head, before the merge. A failed initial PR read there logs `reason=pr_state_unavailable`. `scripts/review_rb_judge.sh` (`rb_judge_merge_open_guard`) checks `start` on the judge's own PR read (no call) before the first freshness/lease call in the merge and terminal arms, logs `pr_closed`/`pr_merged` on that read (and gives back a held lease) when the PR was already closed, and checks again right after the required-checks wait, before the post-wait freshness re-check and the head-gate success status, at the merge and terminal sites, and after the freshness gate at the `merge_with_followup` site; a failed judge PR read logs `reason=pr_state_unavailable`. The deterministic-skip head refresh on the no-merge paths carries `closed_at`/`merged_at` on its existing read, so it logs `pr_closed closed_at=<iso>` or `pr_merged`. The final-CI resume in `scripts/review_merge_train.sh` checks before its lease request and merge.
  - On a refusal nothing is merged, no merge-phase label is applied, and the job ends with success. On `pr_closed` the job releases the merge lease when it holds one (`_pr_merge_open_guard_release_lease`, logged `MERGE_LEASE ... mode=release outcome=released reason=pr_closed`). If that release fails, the merge-train tick frees the holder as `holder_closed`.
  - Judge mapping: `pr_closed` and `pr_merged` set `judge_merge_status=not_open`; any other refusal sets `mergeability_pending`. At the `merge_with_followup` site they emit `judge_skip_reason=pr_not_open` (with `PR_CLOSED=true`) or `mergeability_pending`. The resume tick logs `FINAL_CI_MERGE_RESUME ... outcome=dropped reason=pr_closed|pr_merged` or `outcome=waiting reason=pr_state_unavailable`.
  - Switch: `PR_MERGE_OPEN_GUARD_ENABLED` (default `true`, read only in the helper). Only `false`, `0`, `no` or `off` turns it off.
  - Cancel-on-close coverage: GitHub empties a run's `pull_requests` list once the PR is closed, so `.github/workflows/cancel_on_pr_close.yml` used to match nothing on a close. On a `pull_request` close it now also cancels runs on the closed head branch whose list is empty, provided their `head_repository.full_name` equals the PR's head repository (`PR_HEAD_REPO`) and they were created at or after the PR was opened (`PR_CREATED_AT`) and before it was closed (`PR_CLOSED_AT`), so the runs the close event itself starts (AI Issue PR Status, the post-merge AI Review) are left alone. This includes a review run whose gate is done and whose merge job is still queued. On a merged close (`PR_MERGED=true`) only linked runs match, so the run that merged keeps its post-merge work. When any of the three values is missing or malformed, only linked runs match, as before.
