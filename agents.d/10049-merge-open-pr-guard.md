<!-- agents: section="Workflow architecture" -->
- **Merge paths re-read the PR's state; cancel-on-close cancels unlinked runs at the closed head (#10049, 2026-11-24).** tele-funtoken-msg-scoring PR #5800 was squash-merged 22 minutes after a maintainer closed it without merging: the review gate passed while the PR was open, the `deterministic-skip-merge` job started after the close, and no merge path re-read the PR (`--match-head-commit` binds only the head; GitHub merges a closed, unmerged PR whose branch still exists).
  - **State guard.** `_pr_merge_state_check <pr> <bound_head_sha> <start|pre_merge> [<pr_json>]` (`scripts/pr_checks_lib.sh`) returns 0 only for an open, non-draft PR on the bound head. It reuses a passed PR object or makes one `pulls/<n>` read. A failed read or an object without `.state` is `unavailable` and fails closed. Outcomes land in `PR_MERGE_STATE_OUTCOME` (`open|closed|draft|head_moved|unavailable`), `PR_MERGE_STATE_CLOSED_AT` and `PR_MERGE_STATE_BASE_REF`. A closed PR leaves the merge lease on its base through `_merge_lease_release_for_pr <pr> <base> <reason>` (one lease read, one write, one retry after a lost compare-and-swap, `MERGE_LEASE ... mode=release outcome=released|not_held|unavailable`; fail open, `review_merge_train.sh release` stays the `holder_closed` backstop).
  - **Where it runs.** `start`: the `deterministic-skip-merge` step (after the head-SHA check, before the freshness gate, lease, checks wait and labels; its own read is handed once to the next `_pr_base_freshness` call through `PR_MERGE_STATE_PR_JSON` / `PR_MERGE_STATE_PR_FOR`, so it adds no call there) and `scripts/review_enable_auto_merge.sh` (reuses `_ORCH_PR_META_JSON`, before the security follow-up guard and the success status), and the `scripts/review_rb_judge.sh` `merge` and `merge_with_followup` chains (reuse the judge's own `_pr_json` read, no API call, before `_pr_base_fresh_for_merge`; the `terminal` chain already requires `.state == open` from the read right before it). `pre_merge`: right before every merge call in the deterministic-skip step (both strategies), `review_enable_auto_merge.sh` (squash and merge-commit), `scripts/review_rb_judge.sh` (`merge` and `terminal` chains, `RB_MERGE_STATUS=not_open|mergeability_pending`; `merge_with_followup`, `judge_skip_reason=pr_not_open|draft_pr|pr_state_unavailable`; each before its `ai-review/head-gate` success post) and the `FINAL_CI_MERGE_RESUME` merge in `scripts/review_merge_train.sh` (`outcome=deferred reason=pr_<outcome>`; its one read runs after `_pr_base_fresh_for_merge` and is the last call before the merge, because `--match-head-commit` binds only the head; the start check there is the tick's open-PR listing, and a PR closed after that listing releases the lease the gate gave it; on the gate's overlap path (branch update requested) the read does not run and `review_merge_train.sh release` frees that lease as `holder_closed`). After the pre-merge check the judge's two later merge attempts are guarded too: `_pr_sync_merge_blocked_guard` defers (`state=not_open`) when its PR JSON carries a `.state` other than `open`, so a PR closed before the direct fallback is not merged; and `rb_judge_merge_retry_transient` sends no `--auto` request when its per-attempt PR read is unreadable (`RB_JUDGE_MERGE_RETRY ... outcome=state_unavailable`, then the next bounded attempt; it sets `RB_SYNC_MERGE_DEFERRED=true`, so running out of attempts is `RB_MERGE_STATUS=mergeability_pending`, not `merge_failed`). When a retry read finds the PR closed without merging (`RB_MERGE_RETRY_GIVEUP=not_open`, checked before the moved-head test, so a closed PR whose head also moved is `not_open` too), the `merge` and `terminal` sites end with `RB_MERGE_STATUS=not_open` and the `merge_with_followup` sync site with `judge_skip_reason=pr_not_open`; all three pass that read to `_pr_merge_state_check` (no extra call), which logs `AUTOFIX_MERGE_SKIPPED ... reason=pr_closed closed_at=<iso>` and releases the lease; the retry read carries `.closed_at` as its last tab-separated field (`RB_MERGE_RETRY_CLOSED_AT`). The blocked-merge guard's own read records a closed, unmerged PR (`SYNC_MERGE_BLOCKED_GUARD_PR_CLOSED=true`, `SYNC_MERGE_BLOCKED_GUARD_CLOSED_AT`): the `merge` and `terminal` sites take the same closed-PR branch when the retry gave up `non_transient` before reading the PR (`RB_MERGE_RETRY_PR_READ` empty; a later retry read that shows the PR open wins), and the `merge_with_followup` sync site's guard deferral ends with `judge_skip_reason=pr_not_open` instead of `mergeability_pending`; both log the skip and release the lease from that read (no extra call). An unreadable retry read also sets `SYNC_MERGE_BLOCKED_GUARD_STATE=unreadable`, so the `mergeability_pending` message names it, except over a `blocked` state: that one is kept, so a later non-transient `--auto` refusal on the auto-only path stays `merge_failed` (#9939). The label-only paths (`ENABLE_AUTO_MERGE != true`, suppressed forward-merge, e2e smoke) read state, draft and head in their existing single head read and withhold the labels unless the PR is open and ready. Fallback stubs: without the library the deterministic-skip `start` check only warns (its checks-wait stub already refuses the merge) and every `pre_merge` check fails closed. No kill switch.
  - **Cancel on close.** For `pull_request` events, "Cancel queued/in-progress runs for closed PR branch" (`cancel_on_pr_close.yml`) also cancels a run on the closed PR's branch whose `pull_requests` list is empty when its `head_sha` equals the closed PR's 40-hex head (`PR_HEAD_SHA`, new job env) and its `created_at` is before the PR's `closed_at` (`PR_CLOSED_AT`, new job env; a missing or malformed value turns the unlinked match off), and only when the PR closed without merging (`PR_MERGED`, new job env: on a merge the review run that merged the PR is unlinked too and keeps running its post-merge labelling). GitHub links a run only to PRs that are open now, so the review run whose gate finished and whose merge job was still queued was skipped before. The `closed_at` bound keeps the runs the `closed` event itself starts on the same branch and SHA (AI Issue PR Status, the post-merge AI Review): they are created at or after the close and keep running. Runs linked to another PR, runs at another SHA and the scheduled sweep are unchanged; no new API call.
