Classification decision tree (apply before status selection):
- Classify as `harness_error` (NOT `needs_fixes`) when ANY of these are true:

- Classify as `needs_fixes` ONLY when ALL are true:

  - The test correctly exercises documented/expected application behavior
  - Test infrastructure (Docker/networking/assertions) is demonstrably sound
  - Failure persists regardless of equivalent assertion style or harness expression
- When in doubt, prefer `harness_error`. False `harness_error` is cheaper than false `needs_fixes`.
