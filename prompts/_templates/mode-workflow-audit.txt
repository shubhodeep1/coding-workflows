### Section 1: Bug & Correctness Sweep
For every workflow and script, check for:
- Unquoted variables in shell — especially in command arguments and test expressions where word-splitting or glob expansion could bite (note that `[[ ]]` is generally safe).
- Missing error handling — commands without `set -euo pipefail`, unchecked return codes, missing `|| true` on intentionally-failable commands.
- Race conditions — concurrent label mutations, parallel issue comment writes, TOCTOU on file/branch existence checks.
- Logic errors — inverted conditionals, unreachable code after early returns, wrong variable referenced (copy-paste from adjacent block).
- Broken pipes / silent failures — `jq` on empty input, `grep` returning non-zero killing the script under `set -e`, `head`/`tail` on empty streams.
- Environment variable misuse — vars referenced but never exported, vars with missing defaults that could be empty in certain trigger contexts.
- YAML structure issues — incorrect indentation of multi-line `run:` blocks, `if:` conditions that always/never match, missing `shell: bash` on multi-line runs, expressions that need explicit `${{ }}` wrapping.
- Security — secrets leaked to logs, command injection via unsanitized issue titles/PR bodies in shell interpolation, tokens in `run:` blocks visible in logs.

### Section 2: GitHub API Call Redundancy Audit
Per CLAUDE.md §15, audit every `gh api`, `gh_retry`, `_safe_gh_jq`, `gh issue`, `gh pr`, `gh run`, and `curl_gh_api` call:
- Duplicate fetches — same endpoint/fields fetched more than once in the same execution path.
- Unbatched REST calls — N individual REST calls that could be replaced by a single GraphQL query with aliases. Document current call count vs. projected call count after batching.
- Missing cache reuse — data already available in a variable/file from an earlier step but re-fetched via API.
- Tight retry loops — retries without exponential backoff or retries on non-transient errors.
- Per-iteration API calls inside loops — any `gh`/`curl` call inside a `for`/`while` loop that processes multiple issues/PRs (review-blockers per §15).

For each finding, specify: current call count, proposed call count after fix, and which existing batching pattern (if any) from `gh_helpers.sh` or `orchestrate_poll_process.sh` to extend.

Note: this section identifies candidates. A separate conservative API-redundancy pass runs after you and applies stricter safety gating. Do not self-censor findings here on safety grounds — flag them with `[NEEDS VERIFICATION]` if uncertain, and let the downstream pass decide actionability.

### Section 3: Code Duplication & Modularization Opportunities
Identify:
- Duplicated functions — same or near-identical function bodies appearing in multiple files.
- Duplicated inline shell blocks — similar `run:` blocks across workflows that could be extracted to a shared script.
- Repeated patterns — label check-and-create, comment-post-and-update, branch-existence-check, jq-filter-and-validate patterns that appear 3+ times.
- Near-duplicate workflows — workflows whose structure is >70% identical and could share a common base.

For each finding, propose: which shared module (`scripts/*_helpers.sh` or a new module) should own the code, the function signature, and which callers would be updated.

### Section 4: Expression Size Limit Risk Assessment
GitHub Actions enforces a hard limit of 21,000 characters per template expression (any single `${{ }}` block, including interpolated `run:` bodies). The runner rejects the entire workflow with `Exceeded max expression length 21000` if any expression exceeds this.

This repo has already hit this limit at least 3 times:
- `review_autofix.yml:2370` — step split after hitting 24.6 KB.
- `review_autofix.yml:2576` — prompt heredoc moved to external file.
- `orchestrate_poll_process.sh:3` — extracted from `orchestrate_poll.yml`.

Audit each workflow:
- For every `run:` block that contains `${{ }}` interpolations, measure the total character count of the fully-expanded expression. Flag any block where the expression body exceeds 18,000 characters (85% threshold) as High risk, and any exceeding 15,000 characters (71% threshold) as Medium risk.
- Flag large `if:` conditions with complex expressions approaching the limit.
- Flag inline heredocs and prompt templates embedded in `run:` blocks that could grow with future edits and push the expression over the limit.
- `run:` blocks with no `${{ }}` interpolation are NOT subject to this limit and must be excluded from the count.

For every flagged block, propose one of:
- Extract to an external script under `scripts/` (preferred), OR
- Split into multiple smaller steps, OR
- Move large string literals (prompts, templates) to files under `prompts/` and read them at runtime.

State estimated current character count and headroom remaining for each finding.

Additionally, note the overall workflow file size limit of 1 MB (1,048,576 characters). Flag any workflow exceeding 800 KB.
