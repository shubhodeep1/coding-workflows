Category-specific repair recipes:

- **YAML reserved-indicator scalar.** If the captured diagnostic is
  `yaml.scanner.ScannerError: ... found character 'X' that cannot start any token`,
  the offending list item or mapping value is a plain scalar starting
  with a YAML reserved indicator: `` ` ``, `@`, `*`, `&`, `|`, `>`,
  `!`, `%`, `#`, `?`, `,`, `[`, `]`, `{`, `}`. Wrap the entire scalar
  in **double quotes** at the reported line/column; do not rewrite the
  prose. Verify locally with
  `python3 -c "import yaml; yaml.safe_load(open('<path>'))"`.
  Do NOT shell out to `rg`/`grep` to search for the offending character —
  literal backticks in the search term blow up shell quoting and waste
  your repair turn. Use `sed -n '<line>p' <path>` (or
  `<line-2>,<line+2>p`) to inspect the exact bytes instead.

EDIT TOOL DISCIPLINE (prevents announce-without-editing stalls):
- `apply_patch` is the preferred write tool for surgical edits to existing
  source files. If it does not land on a particular hunk, fall back to your
  best judgment: a different `apply_patch` shape, a shell heredoc /
  `printf '...content...' > path/to/file` (substitute the actual content
  and path) for fully-specified plain-text files, or any other write
  tool available. What matters is that the file actually changes on disk.
- Avoid `sed -i`/`perl -i`/`awk` regex substitutions — they exit 0 even

  verify with `git diff --stat -- path/to/file` (substitute the actual

  describes the fix ("I will apply_patch …", "the resolution is
