## Lessons
- [source:intervention] A fail-safe loop that skips an item on a read failure must still list the failure in `errors[]` with the item it concerned, including the failure of any follow-up check used to classify it; a silent `continue` hides the miss from the report. (files: scripts/claude_checker_restart.py)
- [source:intervention] Routine names in `list_triggers` come both whole (over 60 characters) and cut with a trailing `…`; name matchers should accept a full-name prefix and a cut stem with or without a marker. (files: scripts/claude_checker_restart.py)
- [source:intervention] A stage session that runs past the 3-hour claim lease loses its head to the catch-all sweep's fixer; re-read the PR head before pushing, and never push a duplicate round over a newer head. (files: .claude/commands/implement-plan-claude.md)
- [source:intervention] A listing read that feeds a "which items to check" set must paginate; a single `per_page=100` page silently drops every item past the first page. (files: scripts/claude_checker_restart.py)
- [source:conformance] A fail-safe guard that one decision path honours (an incomplete listing page keeps the item) must also gate every sibling path that relies on the same listing; here the re-queue path read the trigger page without its `has_more` guard. (files: scripts/claude_checker_restart.py)
- [source:intervention] A resume gate that reads the committed progress log can see a stale `Status:`, because a blocked stage cannot commit its log without moving a PR head; the blocker comment and the operator's answer are the fresher source. (files: .claude/commands/implement-issue-claude.md)
- [source:intervention] A test for an early-exit guard must also make the later guards' conditions true, so the expected skip reason fails if the guards are reordered; an otherwise-empty fixture passes either way. (files: tests/test_claude_checker_restart.py)
- [source:conformance] A liveness decision built from listings read earlier in the same run must count the subject's own latest activity: anything it did after the read is invisible, so "no other session is active" alone lets a checker that just acted look dead. (files: scripts/claude_checker_restart.py)
- [source:intervention] A freshness guard is only as fresh as the record it reads: when one input comes from an earlier listing and another from a later lookup, the decision must use the later one, and a subject known only from the listing must be kept rather than acted on. (files: scripts/claude_checker_restart.py)
- [source:plan-deviation] The plan looked up only checkers missing from the session page; a page-listed checker that looks restartable is looked up too, within the same cap, so no restart is decided from a listing read before the lookups. (files: scripts/claude_checker_restart.py)
- [source:intervention] Gate a paid read on the free checks that already decide the outcome: when a later free guard keeps the item whatever the read returns, run it before the read, but keep a free check that gives the more accurate reason ahead of it. (files: scripts/claude_checker_restart.py)
- [source:conformance] A fail-safe that needs a complete listing (a paginated API page with `has_more`) must read every page, bounded, or the feature goes dormant as the listing grows; check it against the live count, not the count seen when the plan was written. (files: scripts/claude_checker_restart.py, .claude/commands/claude-issue-pickup.md)
- [source:intervention] A loader that fails safe on an incomplete listing must also fail safe when the pagination field is missing: defaulting an absent `has_more` to false turns "unknown" into "complete". Require the field and count a page without it as incomplete. (files: scripts/claude_checker_restart.py)
- [source:intervention] A bounded paginated read is incomplete when its last page still has `has_more`; every consumer of that listing, not only the one the bound was added for, must say what it does then, and a branch that deletes or creates on "not found" must not act on a listing that cannot prove absence. (files: .claude/commands/claude-issue-pickup.md)
- [source:intervention] `ci.yml` runs `ruff --select E,F` on `scripts/*.py` only for PRs into `main`, so a mixed tab-and-space docstring indent (E101) on a project-branch PR passes there and fails only on the final PR; run that ruff selection before every push. (files: scripts/claude_checker_restart.py)
- [source:intervention] A bounded paginated read must name every way it can stop short, not only the page cap: a call that fails or returns a page without the pagination field ends the read just as surely, and each consumer has to treat that the same as "more pages left". (files: .claude/commands/claude-issue-pickup.md)
