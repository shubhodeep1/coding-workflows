## Lessons
- [source:plan-deviation] Re-read the source issue's owner comments before arming a wait on a phase held for a twin sync: comments posted during the hold can change the twin-first code, and folding them in before the sync saves a second sync. (files: docs/implement-plan/issue-5660-resume-usage-limit-stops.md)
- [source:plan-deviation] A selector that resumes stopped sessions must treat any trigger bound to a checker as a live chain (its triggers are its own check-ins), or a resume starts a second send_later chain. (files: workflow-templates/.claude/scripts/usage_limit_resumes.py)
- [source:plan-deviation] A `rejected` rate_limit_info snapshot does not mean a session stopped: turns completed on overage record it too, so it may only select checkers with no bound trigger. (files: workflow-templates/.claude/scripts/usage_limit_resumes.py)
- [source:intervention] A consumer of a listing paged "while the oldest entry is inside the window" must apply the window itself: the last page fetched crosses the boundary. (files: workflow-templates/.claude/scripts/usage_limit_resumes.py)
- [source:intervention] A long-lived supervisor's own session is not on a recent-sessions listing; when its logic depends on its own entry, pass its own `get_session` result explicitly. (files: workflow-templates/.claude/scripts/usage_limit_resumes.py, .claude/commands/claude-issue-pickup.md)
- [source:intervention] In a command file, state the success path's "continue with step N" before a failure branch that ends the turn, and mark the failure branch as the exception ("Only if … instead"); a "Then continue" sentence after "end the turn" reads as part of the failure branch to reviewers and models. (files: .claude/commands/claude-issue-pickup.md)
- [source:intervention] When a reviewer repeats a misreading of a dense one-liner across rounds and no verdict bot can answer it, rewrite the line into a form that cannot be misread; a base merge only restarts the same review. (files: workflow-templates/.claude/scripts/usage_limit_resumes.py)
- [source:intervention] When one script creates Routines by name and another sweeps them by name, match both with the same anchored pattern (and test that they agree), or a lookalike name is honoured by one and never cleaned up by the other. (files: workflow-templates/.claude/scripts/usage_limit_resumes.py, workflow-templates/.claude/scripts/stale_routines.py)
- [source:conformance] A claude.ai session id has two forms, `session_<x>` and `cse_<x>` (a trigger's `persistent_session_id` can carry either); a script that joins sessions with triggers, or recognises its own session, must compare both in one form, as `scripts/claude_session_janitor.py` does. (files: workflow-templates/.claude/scripts/usage_limit_resumes.py)
- [source:intervention] After a `[claude-twin-sync]` commit lands on a held PR, update the PR body's twin-first paragraph to say the sync landed: a body that still says the root copy waits for the sync leads reviewers to flag the sync commit itself as a twin-first violation. (files: docs/implement-plan/issue-5660-resume-usage-limit-stops.md)
