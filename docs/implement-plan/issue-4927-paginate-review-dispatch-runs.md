## Lessons
- [source:intervention] A `^[0-9]+$` env check does not make a value safe for bash arithmetic: leading zeros pass it and `$(( ))` then reads the value as octal or fails on 08/09. Normalise with `$(( 10#${VAR} ))` right after the check. (files: scripts/orchestrate_poll_process.sh)
- [source:intervention] Keep an input's validation on the line after its fallback, not after an unrelated early return: two reviewers read a re-validated env fallback as unchecked because the check sat several lines further down. (files: scripts/orchestrate_poll_process.sh)
- [source:intervention] When a change narrows a helper's fail-open contract, grep the helper's own body and the README section that documents it for "fail open" / "fails open" as well, not only the callers' headers: the in-function diagnostics comment and the README paragraph kept the old blanket claim. (files: scripts/orchestrate_poll_process.sh, README.md)
- [source:conformance] When a helper's return codes or API-call budget change, update the header comments of every caller that restates them, not only the helper's own docstring; grep the callers for phrases like "one extra call" and "Returns 0 if". (files: scripts/orchestrate_poll_process.sh)
- [source:conformance] A lookback window chosen for live runs (the poller's zombie cutoff) is too short for a caller that looks for completed failures: a run can end at its job timeout just before it leaves that window. Size a failed-run lookup's window as the run budget plus the retry cadence. (files: scripts/orchestrate_poll_process.sh)
- [source:intervention] When a change rewrites a helper, grep the whole repo (including `.claude/scripts/` and `workflow-templates/`) for the helper's name: another file's comment that says it mirrors the helper's listing goes stale silently, and a reviewer later reads the mirror as behind. (files: scripts/orchestrate_poll_process.sh, .claude/scripts/check_in_status.py)
- [source:plan-deviation] Shell code that accumulates GitHub API JSON across pages must feed jq through stdin, never `--argjson`: about 1,000 runs exceed the kernel's 128 KiB single-argument limit, and a failed `x="$(jq …)"` aborts a `set -e` script. (files: scripts/orchestrate_poll_process.sh)
- [source:plan-deviation] An issue-mode project stacked on another project's branch cannot run runtime validation until `validate.yml` authorizes non-default targets (#4734); ask once and record the parent project's validation as the cover instead of dispatching a run that is bound to fail. (files: .github/workflows/validate.yml, .claude/commands/implement-plan-claude.md)

- [source:intervention] On a project stacked on another project's branch, the whole-project reviewer reads the parent issue's requirements as task gaps of this diff; list the parent's already-landed requirements with `file:line` in the final PR body so reviewers stop re-raising them. (files: workflow-templates/ai-review.yml, .claude/scripts/check_in_status.py)
