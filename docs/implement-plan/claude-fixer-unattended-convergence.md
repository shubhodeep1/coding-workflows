## Lessons
- [source:plan-deviation] Consumer wrappers pin the library workflow by 40-hex release SHA (`@<sha> # stable`), not `@stable`, so any `referenced_workflows` trust check must accept SHA pins or every consumer run fails verification. (files: scripts/review_claude_fixer_evidence.py, scripts/workflow_wrapper_refs.py)
- [source:plan-deviation] The review_autofix.yml gate job checks out no support scripts (only a sparse fingerprint-cap helper), so any artifact or API verification a gate decision needs runs in a codex-agent step before the step that acts; the gate only binds comment markers and passes run ids on. (files: .github/workflows/review_autofix.yml, scripts/review_autofix_step_claude_fixer_judge.sh)
- [source:plan-deviation] "Enable auto-merge on PR" and the evidence upload run before the review-blocked judge step, so a judge that merges or writes evidence must call scripts/review_enable_auto_merge.sh itself and upload in its own later step. (files: scripts/review_rb_judge.sh, .github/workflows/review_autofix.yml)
- [source:intervention] A side effect that records an outcome (a follow-up issue saying the PR merged, a verdict saying auto-merge is on) must run after the step that decides the outcome, and its text must name what actually happened on that run. (files: scripts/review_rb_judge.sh, scripts/review_claude_fixer_judge.py)
- [source:intervention] A reviewer can re-report a finding fixed in the previous round with the previous round's line numbers (round 2 of PR #4691 repeated round 1 almost verbatim, including a path that does not exist); check every finding against the current head before fixing, and reject with the commit that fixed it. (files: scripts/review_rb_judge.sh, scripts/review_claude_fixer_judge.py)

- [source:plan-deviation] On a Claude-fixer head a merge conflict is found by the pre-review merge-topology gate, not "Detect merge conflicts" (which Claude-fixer mode skips), and the hand-off step runs before the resolver steps, so a change to Claude-fixer conflict routing belongs in the topology gate's Claude-fixer branch plus a step after the resolver. (files: scripts/review_autofix_step_merge_topology_gate.sh, scripts/review_autofix_step_claude_fixer_handoff.sh, .github/workflows/review_autofix.yml)
- [source:intervention] Reviewers repeatedly flag a `review_autofix.yml` step for not setting `PR_NUMBER` when it inherits it from the `codex-agent` job env; reject with the job-level env line and the contract test that pins it, and do not add a redundant step-level copy. (files: .github/workflows/review_autofix.yml, tests/test_review_autofix_claude_fixer_mode.py)
- [source:plan-deviation] A project-branch sync with main that conflicts in `.claude/**` cannot be finished by an unattended stage: resolve it on a side branch with the `.claude/**` files taken from the twins, and have the supervising session copy the twins and fast-forward the project branch; a direct push of the sync to the project branch can also be refused by the Auto-mode classifier as "Auto-Mode Bypass" (#5018). (files: .claude/commands/implement-plan-claude.md)
- [source:plan-deviation] Live claude.ai session titles drift from the documented formats (`Issue #N — implement`, fixers without a repository, `#N · ` prefixes, project checkers renamed with a `PR #N — ` prefix), and a saved `list_sessions` result is wrapped in the harness's untrusted-data text; any script that selects sessions by title must parse the wrapper and match the live variants without catching a renamed checker. (files: .claude/scripts/stale_sessions.py)
- [source:intervention] A fallback that scans wrapper text for a JSON payload must accept only a line that passes the payload's shape check and reject more than one match, or a stray `[]` line reads as an empty page and the run silently does nothing. (files: .claude/scripts/stale_sessions.py)
- [source:intervention] Skipping an unparseable or malformed candidate line still lets a stray valid line stand in for a truncated real payload; a fallback parser must fail on any line that could be the real result but does not validate, and skip only lines that cannot be it. (files: .claude/scripts/stale_sessions.py)
- [source:conformance] A janitor or matcher that selects sessions by title must be checked against the live session list after every title-convention change on main (#4943 put `#<issue> · PR #<pr> — ` in front of stage and issue titles); a plan-time pattern silently matched 5 of 100 live sessions. (files: .claude/scripts/stale_sessions.py)
- [source:conformance] Text a model returns must be collapsed to one line before it goes into a comment that carries a marker the workflow later parses, or the model can add a forged marker line. (files: scripts/review_claude_fixer_judge.py)
- [source:intervention] A review round whose fix is the `MAX_AUTOFIX_ITERATIONS`-th consecutive `[claude-autofix]` commit is labelled `ai:review-blocked` without that head ever being reviewed; when no finding is left open, the intervention only has to record the round in a `[claude-intervention]` commit, which restarts the count and gets the head reviewed. (files: .github/workflows/review_autofix.yml)
- [source:intervention] Collapse model text with `" ".join(text.split())`, not `.replace("\n", " ")`: `str.splitlines()` also splits on `\r`, `\x0b`, `\x0c`, `\x1c`–`\x1e`, `\x85`, ` `, and ` `, so any of them can still start a forged marker line. (files: scripts/review_claude_fixer_judge.py)
- [source:intervention] When one trust set (comment `author_association` values) is enforced in both a Python helper and a workflow-step jq filter, add a test that parses the jq `IN(...)` list and compares it to the Python constant, so an edit to one side cannot silently widen the other. (files: scripts/review_claude_fixer_judge.py, scripts/review_autofix_step_claude_fixer_judge.sh)
- [source:intervention] A crashed reviewer slot makes the Claude-fixer ledger not clean, so a round with zero findings still gets a findings hand-off and converges only through the verdict bot or a human (files: scripts/review_autofix_step_claude_fixer_handoff.sh)
- [source:conformance] When a change makes a "never runs" statement false, grep every doc that repeats it (README sections, command-file intros, CLAUDE.md, agents.md) for the whole statement, not just the files the plan names; run 1 fixed the copies in CLAUDE.md, agents.md, and implement-plan-claude.md but missed README.md and fix-claude-pr.md. (files: README.md, .claude/commands/fix-claude-pr.md)
