## Lessons
- [source:conformance] When a change moves paths from one class to another (here scripts from auto-merged to owner-merged guard paths), grep every prose description of both classes repo-wide, including comments in other workflows and operations tables, not only the docs the plan lists. (files: .github/workflows/review_autofix.yml, docs/operations/master-session.md)
- [source:intervention] A review sweep re-dispatch (`review_autofix_sweep.yml`, which dispatches from the default branch with no `--ref` since #4618) attaches its check runs to the default branch's SHA, not the PR head, so a failed `review / codex-agent` from an earlier outage stays on the head even after a clean re-review. Only a run on the PR head clears it: a new push, or a dispatch with `--ref <head branch>` such as the orchestrator's conflict-recovery dispatch (`_dispatch_review_for_conflicts`). (files: .github/workflows/review_autofix.yml, .github/workflows/review_autofix_sweep.yml, scripts/orchestrate_poll_process.sh)
- [source:intervention] A dated note that contradicts the sentence it annotates makes a row worse, not safer: when a correction negates a claim, change the claim in place and keep the original wording in a dated marker. (files: docs/operations/master-session.md)
- [source:intervention] A change to which paths need the owner also changes every standing approval that lists the old set (here Q46's "no hooks or settings.json" merge rule): grep operator decisions and their procedures for the old path list, because an approval left as is lets a session that acts as the owner skip the new gate. Dated "Learned" bullets that a session still follows are rules, not history. (files: docs/operations/master-session.md)
- [source:intervention] When a change moves paths into a stricter merge class, keep "how the duty is done today" separate from "who merges after the automation lands": moving scripts into the approval-window row made a table claim script copies need a non-Auto window, which a reviewer then propagated to the operator's Q67 rule. (files: docs/operations/master-session.md)
- [source:intervention] A stage that commits the progress log before arming its wait should create the hand-back Routine and the safety net first (neither depends on the push), so the committed `Check-in:` line carries real trigger ids; only the checker-instructions trigger must wait for the push. (files: .claude/commands/implement-plan-claude.md, docs/implement-plan/issue-5609-guard-synced-claude-scripts.md)
- [source:intervention] Archived plans in `docs/completed/` are reference docs too: when a later change makes one stale, add a dated `> **Extended by #<N>**` (or `Superseded`) note below the stale line instead of rewriting the record of what that project shipped. (files: docs/completed/issue-5246-guard-sync-provenance-plan.md, docs/completed/issue-5247-stable-twin-guard-check-plan.md)
- [source:intervention] When a sync PR's merge class depends on both the paths and a conflict list, every prose description of "who merges it" must name both conditions. Describing the auto-merged class as "commands" alone misstates conflict-only syncs, which go to the owner. (files: .github/workflows/review_autofix.yml, scripts/claude_twin_sync.py)
- [source:intervention] When prose lists a guard set that code defines, copy the whole set from the constants (`GUARD_PATH_PREFIXES` and `GUARD_PATH_FILES`), not from the sentence being edited: extending "hooks or settings.json" with scripts kept the older omission of `settings.local.json`. (files: scripts/claude_twin_sync.py, docs/operations/master-session.md)
- [source:plan-deviation] A project that changes a shared constant must re-run the base project's parity tests after every sync merge: #5607 tied `update_workflows.yml`'s shell guard pattern to `GUARD_PATH_PREFIXES` with a test, so a textually clean merge failed until the consumer pattern gained `scripts/*`. A plan's non-goal can be overtaken by a later base change. (files: .github/workflows/update_workflows.yml, scripts/claude_twin_sync.py, tests/test_update_workflows_guardrails.py)
