## Lessons
- [source:plan-deviation] GNU diff has no `--ignore-space-at-eol` (that is a git diff flag), so a `diff -q --strip-trailing-cr --ignore-space-at-eol` guard exits 2 and every file counts as changed; use `--ignore-trailing-space` (`-Z`) or `cmp` and test the shell step end to end (files: .github/workflows/update_workflows.yml)
- [source:intervention] In a POSIX shell `case` pattern `*` also matches `/`, so `hooks/*` covers nested paths; pin shell-vs-Python path rules with a test that runs the pattern through `bash` and `sh` against the Python classifier, not just a string match (files: .github/workflows/update_workflows.yml, tests/test_update_workflows_guardrails.py)
- [source:intervention] `! cmp -s a b` treats a read error (exit 2) like a difference; capture the status (`cmp -s a b || st=$?`) and branch on 1 vs 2+, and test the error path with a stub `cmp` on PATH, since root in CI can read chmod-000 files (files: .github/workflows/update_workflows.yml, tests/test_update_workflows_guardrails.py)
- [source:intervention] A sync that picks a reviewed source per file must also enumerate the reviewed tree: a loop driven only by the unreviewed tree cannot see the reviewed files that tree lost (files: .github/workflows/update_workflows.yml, workflow-templates/.claude/commands/seed-repo.md)
- [source:intervention] When a step gains a second pass over a different tree, re-check every early `exit 0` above it: an exit keyed on the first tree's absence silently skips the second pass; guard the first loop instead, and test the step with the first tree missing (files: .github/workflows/update_workflows.yml, tests/test_update_workflows_guardrails.py)
- [source:intervention] A "keep the consumer's file" check must use `[ -e p ] || [ -L p ]`: `-e` is false for a dangling symlink, and GNU `cp` then refuses to write through it and aborts a `set -e` step; test with a dangling symlink on the destination side, not only the source (files: .github/workflows/update_workflows.yml, tests/test_update_workflows_guardrails.py)
- [source:intervention] A `find -type f` enumeration skips symlinks, while `[ -f ]`, `cmp`, and `cp` follow them; when one pass of a sync accepts symlinked sources, every other pass over the same tree must list `\( -type f -o -type l \)` and skip a link that does not resolve to a regular file, or `cp` aborts the step (files: .github/workflows/update_workflows.yml, tests/test_update_workflows_guardrails.py)
- [source:intervention] A reviewed tree that ships symlinks must check where each one resolves, not only that it resolves to a regular file: a link into the unreviewed twin passes `-f` and `cmp` (same file on both sides) and `cp` installs the twin; resolve with `realpath -e` and require the physical reviewed root as a prefix, so a link on a parent directory is caught too (files: .github/workflows/update_workflows.yml, tests/test_update_workflows_guardrails.py)
- [source:intervention] A boundary check for owner-reviewed files must allow only the reviewed paths inside the tree, not the whole tree: other files there may be merged without the owner, so a symlink into them launders content. And a pass that should skip "what the other loop handled" must record what that loop handled, not re-test the path, because `-f` follows parent-directory symlinks that `find` never descends (files: .github/workflows/update_workflows.yml, tests/test_update_workflows_guardrails.py)
