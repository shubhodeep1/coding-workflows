## Lessons
- [source:plan-deviation] A twin-first phase whose `[claude-twin-sync]` waits a day conflicts with main's edits to the same `.claude/` commands. The resumed stage must merge the synced base into the phase branch before arming the wait, and a second twin sync follows. (files: .claude/commands/implement-plan-claude.md, .claude/commands/claude-issue-pickup.md)

- [source:intervention] When a rule lists the id sources whose deletes need an ownership read first, grep every `delete_trigger` in the flows the rule covers and state the read at each call site. A rule stated only in the definition, plus a skip-on-denial note at each site, leaves by-id deletes that do not say to check the owner. (files: CLAUDE.md, workflow-templates/.claude/commands/implement-plan-claude.md)
- [source:intervention] Routine names are capped at 60 characters (`implement-plan <long slug>: safety net` reads back as `…: safety…`), so an ownership check matches the `implement-plan <slug>:` prefix, never the full name. (files: workflow-templates/.claude/commands/implement-plan-claude.md)
- [source:intervention] A skip-on-denial rule for a singleton's own cleanup must say which copy stands down while the cleanup is skipped. Otherwise both copies keep working, as two pickups reading the same queue did. (files: .claude/commands/claude-issue-pickup.md)
- [source:intervention] A command file's claim about concurrent sessions must name the window it does not cover (a wake already running when a restart lands), and name which check actually guards it; reviewers read an absolute "no target gets two sessions" as a promise the code cannot keep. (files: .claude/commands/claude-issue-pickup.md)

- [source:intervention] A duplicate guard made of a read and a separate write (a claim comment) is not a lock. Keep two copies of a singleton from overlapping at the source, for example by deferring the new copy's first run past the old copy's in-flight one, rather than relying on downstream claim checks. (files: .claude/commands/claude-issue-pickup.md, .claude/scripts/claude_fix_claim.py)
- [source:conformance] When a rule names the call sites it covers, list every site in each flow that runs the same calls, including the per-stage ones (a context-step delete, a rename on opening a PR), and test that each named site still exists in the command. (files: CLAUDE.md, .claude/commands/implement-plan-claude.md)
